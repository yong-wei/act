# Codex 命名子代理 Harness

## 核心合同

1. 主线程负责需求、证据取舍、最终判断和合并准备度。
2. 用户授权后，匹配的项目任务必须派发给命名角色。
3. 子线程 `agent_role` 必须非空，并与预期 TOML、模型和推理强度一致。
4. 写任务优先下放，写代理串行；读代理可并行。
5. 实现代理和独立 reviewer 必须是不同的新子线程。
6. 子代理输出是证据，不能替代主线程裁决。

## 派发 Brief

每次派发至少包含：

```md
目标：
范围内：
范围外：
已知文件/模块：
允许权限：read-only / workspace-write
禁止事项：
输出格式：
验证命令或停止条件：
父线程已知假设：
```

## 调用校验

派发成功后检查：

- `agent_role` 等于目标命名角色，不是 `null` 或 `default`。
- `model` 与 `model_reasoning_effort` 符合对应 TOML。
- `sandbox_mode` 满足任务权限，不得把只读 reviewer 当写代理。
- 子代理深度为 1，不允许继续派发。

任一项不满足时停止该子线程并报告运行时不支持，不得改用继承主线程模型的自由派发继续执行。

## 标准执行序列

1. 主线程确认授权、目标和风险。
2. 只读角色收集完成任务所需的最小证据。
3. 一个命名写代理完成范围内修改并报告文件与验证。
4. 新的 `independent-reviewer` 审查实际 diff。
5. 按领域和风险追加 reviewer；高风险才使用 `critical-reviewer`。
6. 写代理修复阻断问题，新的独立 reviewer 重新审查。
7. 主线程核验测试、未验证事项和最终状态。

## 主线程汇总

主线程必须说明：采纳或拒绝了哪些发现及理由、运行了哪些验证、还存在哪些未验证假设，以及是否满足提交或合并条件。
