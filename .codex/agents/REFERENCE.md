# Codex 子代理设计参考

## 本项目目标

本项目的子代理体系服务于 AI-OBE 船舶智控平台的长期开发，不追求插件化、跨工具兼容或通用多智能体框架。目标是通过 Codex custom agents 的 TOML 定义、AGENTS.md、ROUTING.md 和 HARNESS.md 规范行为。

## 项目风险结构

本项目不是普通 Next.js 应用，而是以下系统叠加：

- Next.js / React / TypeScript 全栈应用。
- 课程作者态与 runtime 双轨内容体系。
- 精品互动课、课堂同步和教师/学生流程。
- Rust/WASM 控制与仿真数值内核。
- Arena 官方评测、榜单和黑箱实验。
- 学习事件、事实物化、学生画像、班级洞察和推荐链路。
- AI 课程上下文、仿真伴学、画像摘要和模型供应配置。
- Podman 生产部署、worker/scheduler、PostgreSQL、Redis 和 Prisma。

因此 agent 不按目录拆，而按“行为类型 + 风险类型”拆。

## 模型分配原则

| 模型 | 用途 |
| --- | --- |
| `gpt-5.6-sol` | 高语义风险、高正确性风险、复杂规划、终审、教育/控制/AI/数据领域判断 |
| `gpt-5.6-terra` | 工程实现、测试、复杂排障、性能和可靠性审查 |
| `gpt-5.6-luna` | 路由、读扫、路径映射、UI 轻审、复盘和低风险小补丁 |

## 推理强度原则

| 字段值 | 中文 | 用途 |
| --- | --- | --- |
| `low` | 低 | 只给 `spark-coder`，用于边界明确、可快速验证的极小改动 |
| `medium` | 中 | 路由、读扫、路径映射、UI 轻审和复盘 |
| `high` | 高 | 规划、实现、测试、排障、领域审查、发布审查 |
| `xhigh` | 超高 | 只给 `critical-reviewer`，用于高风险终审 |

`max` 与 `ultra` 不作为常设角色默认值，只用于有明确风险依据的一次性自由派发。

## 为什么新增 course-pedagogy-reviewer

课程链路存在作者态、互动设计、互动实现、运行态和内容审查多层边界。现有 UI reviewer 只能检查交互路径，simulation reviewer 只能检查控制领域正确性，无法系统审查教学活动顺序、认知负荷、显影链、媒体与知识图谱语义。因此需要独立课程与教学 reviewer。

## 为什么新增 ai-context-reviewer

AI 能力嵌入课程、仿真、画像、推荐、管理员模型配置和通用 API。它的风险不是单纯安全或数据治理，而是上下文真源、事实口径、AI 输出边界和学生/教师可见误导。需要独立审查角色。

## 为什么替换 starter 为 agent-router

`starter` 容易变成泛化起步助手，任务职责和 skill 分流混在一起。当前需求需要的是标准 Codex 子代理选择器：只做调度建议，不做业务判断、不写代码、不终审。
