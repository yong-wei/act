# 统一离散化与关卡体系整改方案

## Goal
- 以 Tustin 方法为核心实现全平台统一离散化，并支持非线性仿真；Control Odyssey 扩展到 15 关且保持现有评分机制不变。

## Scope
- In-scope
  - 统一仿真内核：固定步长时钟 + 统一接口 + Tustin 离散化（线性）+ 非线性积分器。
  - Control Odyssey 物理引擎迁移到统一内核，关卡扩展到 15 关（不包含纯比例开环）。
  - 全平台互动仿真模块迁移到统一内核（按 1.2 范围）。
  - 文档更新（含 `docs/ProjectDescription.md` 与相关设计说明）。
- Out-of-scope
  - 不改评分公式与积分方式。
  - 不新增与本次无关的玩法/模块/UI 重构。

## Steps
1) 现状盘点与统一接口设计
   - 全仓检索仿真/物理引擎入口，建立资源清单与依赖矩阵。
   - 设计统一接口：线性模型（TF/零极点/增益/延时）与非线性模型（状态微分函数）。
   - 确认固定采样步长与积累器策略（1/60s）及跨模块时间基准。

2) 仿真内核实现（统一离散化）
   - 在公共库中实现 SimulationClock（固定 dt + accumulator）。
   - 线性模型：TF -> 状态空间 -> Tustin 离散化系数；支持输入/输出延时缓冲。
   - 非线性模型：统一 state 结构，提供数值积分器（RK4/半隐式欧拉）。
   - 统一噪声/扰动注入接口，保证不同模块的性能可比性。

3) Control Odyssey 迁移与 15 关重构
   - 替换现有 `physics.ts`，用统一内核驱动对象与控制回路。
   - 重新规划 15 关模型与难度梯度（保持既有评分公式）。
   - 校验 Smith 预估器、延时处理、AI 提示词上下文的一致性。

4) 其他互动/虚拟仿真模块迁移
   - 按清单逐一替换为统一内核，实现相同的时钟与离散化机制。
   - 确保各模块不修改评分方式或用户可见玩法。

5) 体验与性能校验
   - 对关键关卡/资源做标定：响应速度、震荡表现、噪声鲁棒性一致。
   - 记录关键指标基线，确认升级不会破坏现有体验目标。

6) 文档与测试
   - 更新设计文档与项目说明。
   - 运行 `npm run lint`、`npm run test`、`npm run build`、`npm run test:integration` 并修复问题。

## Acceptance
- 全平台仿真统一使用固定步长内核与 Tustin 离散化（线性），非线性模型可用且共享接口。
- Control Odyssey 15 关完成且符合新模型能力，不包含纯比例开环对象。
- 评分与积分规则保持现状不变。
- 文档更新完成，全部测试通过。
