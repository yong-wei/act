# 讲义润色技能（Refine）

## Overview

把 `course-content/authoring/lessons/{unit}/design/handout.md` 直接润色成学生可直接阅读的最终讲义，并回写到同一个 `handout.md`。保留知识内容、公式、图表、表格、章节层级和单元边界，只调整文风、句法与叙述密度，让讲义更紧凑、更直接、更容易抓住重点。

本技能的核心目标不是“把讲义写得更像老师在课堂上说话”，而是“把讲义写成学生拿到后能顺畅阅读、快速定位重点的文本”。

本技能是整条生成链中的**最后一道文风清扫工序**，不负责替代 `lesson` 的结构生成。若污染来自上游 brief、段落骨架或知识组织方式，优先返回 `lesson` 的生成阶段重写，不靠润色强行补救。

## Workflow

### 1. 确认目标文件

优先处理用户明确指定的单元；若未指定，再列出 `course-content/authoring/lessons/*/design/handout.md` 供选择。

读取这些文件：

1. `course-content/authoring/lessons/{unit}/design/handout.md`
2. `course-content/syllabus-refactor/main.md`
3. `course-content/syllabus-refactor/unit-design-details/module{N}.md`

若目录下已有历史 `course-content/authoring/lessons/{unit}/design/handout-refine.md`，只能把它当作旧措辞参考；最终必须以当前 `handout.md` 为准重新整理，并直接回写 `handout.md`，不要再生成、刷新或维护 `handout-refine.md`。

### 2. 先判边界，再动表达

在动笔前先确认三件事：

1. 当前课次在模块中的定位和后续接口；
2. 本单元“必须首次出现”的知识点；
3. 哪些内容明确留给后续单元，不能因润色而偷跑。

如果原稿已经与大纲边界高度一致，润色只改表达，不重构知识顺序。

### 3. 先抽主线，再逐段压缩

在正式改写前，先从原稿中提取：

1. 本讲的中心结论；
2. 支撑该结论的 3–5 个关键小点；
3. 哪些段落只是重复提醒、课程调度语或作者态解释。

改写时遵循下面顺序：

1. 先保留知识骨架和证据链；
2. 再删除作者态、教师态、课程编排元叙述；
3. 再压缩绕行句、对比句和口头动作词；
4. 最后统一语气、检查图表公式与编号。

若发现原稿缺少以下任一结构性要件，默认判定为**生成阶段问题**，不靠润色强行补救：

- 没有明确的问题 / 任务引入；
- 没有前置知识缺口与能力目标；
- 没有锚点案例；
- 没有最小例题；
- 没有分层练习。

遇到这类问题时，应在结果中明确标记“需回到 `lesson` 的讲义生成阶段重写结构”，而不是只做句法压缩。

若原稿的主要问题不是句法，而是以下任一污染来源，同样默认返回 `lesson`：

- brief 本身带着流程控制口吻
- 正文按“本讲 / 下一步 / 产出 / 交付”推进
- 大量工程性检查表被直接翻译成自然段
- 相邻段落反复解释课程编排而不解释对象

这类问题属于生成阶段失真，`refine` 只负责标记和清扫尾部残留，不负责重新发明知识结构。

输出直接覆盖到 `course-content/authoring/lessons/{unit}/design/handout.md`，不要另存为 `handout-refine.md` 或其他平行副本。

## 润色规则

### 规则 1：只保留学生真正需要的信息

删除或改写这类内容：

- “本节课的教学目的是……”
- “入口课要先把一个动作立住”
- “真正要被学生带走的是……”
- “教师要追问……”
- “从课程结构看……”
- “不急着讨论……先把……立住”
- “这一讲只负责……”
- “后续哪一课再处理……”（除非确有必要帮助定位边界）

判断标准：如果一句话主要是在解释课程怎样设计、教师为什么这样安排、作者此处准备怎么讲，而不是帮助学生理解知识本身，就删掉或改写成知识内容。

新增判断：如果某一节大篇幅在说明“上一课讲了什么、这一课承担什么课程接口、下一课会怎么接”，而没有尽快回到当前问题、对象或案例，也应优先压缩或标记为结构性问题。

### 规则 2：以“我们”视角写内容，不写课堂指挥语

- 主导视角用“我们”；
- 偶尔可用“你”做提醒；
- 不用“您”；
- 不用命令式教师口吻；
- 不要把“我们”写成“老师带着学生做动作”，而要写成“我们一起理解内容”。

示例：

- “本课先并排回收两个对象” -> “我们先并排回看两个对象”
- “入口课最重要的是” -> “最重要的是”
- “当前先观察，不急着当结论” -> “先持续观察，暂不写成结论”

### 规则 3：删掉 AI 味重的绕行句

重点压缩下面几类高风险表达：

1. **先否定再肯定**：

   - “不是……而是……”
   - “不先……先……”
   - “不是要……而是要……”

   除非确实存在必要对比，否则直接改成正面陈述。

   示例：

   - “我们把任务表达卡固定成七项，而不是只留抽象标题”
     -> “任务表达卡采用七个字段。”
   - “4-1 产出的不是控制器方案，而是后续设计共享的输入卡”
     -> “4-1 的产出是后续设计共享的输入卡。”

2. **元说明过多**：

   - “这一讲真正要做的是……”
   - “到了这里，需要带走的是……”
   - “这一步的作用是……”

   能并入标题或小结，就不要在正文中反复解释。

3. **口头动作词堆积**：

   - “立住、钉死、压住、压成、压实、回收、接走、写浅一层”

   这些词一般不够精确，优先替换为更直接的书面表达，例如：

   - “明确”
   - “写清”
   - “概括为”
   - “整理为”
   - “归纳为”
   - “作为后续输入”

### 规则 4：每段只做一件事

每段优先完成一个明确功能：

- 给出结论；
- 解释原因；
- 呈现证据；
- 归纳比较；
- 提醒误区。

不要在同一段里同时做下面四件事：

- 讲知识；
- 讲教学安排；
- 提前铺垫后文；
- 防御可能误解。

如果一段承担任务过多，就拆句或删去元说明。

### 规则 5：优先正面陈述，少用防御性修辞

以下句式慎用：

- “不要急着……”
- “不能直接……”
- “先别……”
- “不要把……等同于……”
- “这并不意味着……”

这些句式只有在“纠正常见误判”部分才适合集中出现。普通正文优先直接说明结论。

示例：

- “这并不意味着客船场景不追求速度”
  -> “客船场景仍追求速度，但速度必须服从于平顺和储备边界。”

若正文长期停留在“你要怎样 / 不能怎样 / 应当怎样”的训导句式，而没有及时落到对象、证据或案例，同样应视为结构失衡，不只做措辞润色。

### 规则 6：标题承担信息，正文不重复喊口号

如果标题已经表达了本节主旨，例如：

- “指标不是并列名词，而是任务书的最小语言”
- “可行域、满意域与最优域必须分层”

那么正文第一段应直接解释内容，不再用近义句重复一遍标题。

### 规则 7：压缩重复强化，避免原地打转

遇到同一结论在相邻段落反复出现时：

- 保留第一次完整表达；
- 后文只在需要推进论证时简要引用；
- 不重复使用同一套强调句式。

重点检查这类重复主张：

- “同图异读”
- “任务排序会改变”
- “先守底线，再争收益”
- “这一讲不讨论控制器结构”
- “本讲产出是输入卡”

### 规则 8：让重点前置，不把结论藏在铺垫后面

段落优先采用以下顺序：

1. 先给结论句；
2. 再给原因或证据；
3. 最后补充例子或说明。

避免把真正有用的信息放在：

- 段末；
- 多层铺垫之后；
- 对比句的后半截；
- 长串“先……再……最后……”之后。

### 规则 9：讲义是书面文本，不是课堂讲稿

润色后的讲义应偏向学生自读文本，而不是教师讲述稿。可以保留少量自然引导语，但不要让全文充满如下课堂声口：

- “接下来我们先……”
- “到这里……”
- “这一讲先……”
- “我们还要再把一个边界……”

若这些句子不影响知识表达，优先删除；若需要保留，只保留最低限度。

### 规则 10：这些内容不改

以下内容原样保留，除非原文本身有明显错字：

- 所有数学公式与推导；
- 所有图片引用及其属性；
- 表格结构、列数和核心数据；
- 章节编号与大标题层级；
- 例题计算步骤；
- 单元知识边界。

### 规则 11：允许的结构微调

可以：

- 合并同层含义的相邻短段；
- 删除纯重复结论；
- 把过强的教学提示改写成自然过渡；
- 将长段落重写为“结论句 + 解释句 + 证据句”的短段结构。

不可以：

- 删除知识点；
- 调换主要章节顺序；
- 新增原稿没有的知识结论；
- 把本单元边界外的内容提前写进来；
- 为了“简洁”而删掉必要的证据链。

## 风格目标

润色后的文本应同时满足以下目标：

1. **学生一眼能看到重点**：中心句前置，少绕行。
2. **像成熟讲义，不像提示词产物**：少口头动作词，少模板腔。
3. **像书面讲解，不像课堂指挥**：少“先……再……”“不急着……”。
4. **保留工程判断感，但不过度喊口号**。
5. **读起来有推进感，但不靠重复强调制造推进感**。

## 快速检查

完成后至少检查这些项目：

- 回写后的 `handout.md` 仍覆盖原稿全部公式、图片和表格；
- 不再出现“您”；
- “我们”成为主导视角；
- 教师态/作者态句式显著减少；
- 高密度“不是……而是……”结构已明显压缩；
- “立住/钉死/压住/压成”等口头动作词已删除或大幅减少；
- 每节开头能直接看出重点；
- 相邻段落没有围绕同一结论反复绕写；
- 后续单元编号引用没有在正文里滥用；
- 行文不违背 `main.md` 与对应 `module{N}.md` 的边界。

## 输出说明

完成后向用户汇报四类信息：

1. 主要删改了哪些元叙述、教师态和 AI 味表达；
2. 哪些高频绕行句被改成了直接表述；
3. 是否保留了公式、图片、表格和章节结构；
4. 是否已直接回写 `handout.md`，且没有再生成或更新 `handout-refine.md`。
