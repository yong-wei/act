# 浏览器闭环验收参考

## 适用场景

当互动课程已经进入实现收尾，或共享 manifest runtime、教师控制、学生作答和课堂数据采集刚完成改动时，使用本参考文件。

自由浏览只证明页面可以渲染，不能证明课堂同步、教师释放、学生提交、教师聚合和数据库采集成立。涉及共享组件、manifest runtime、教师控制或学生作答的课程，必须以真实课堂链路作为最终验收口径。

## 身份与上下文

- 使用数据库中的固定验收账号，优先采用互动实现技能中记录的教师账号与学生账号。
- 教师端和学生端必须使用不同浏览器上下文，不能在同一个登录态里切换角色。
- 教师端先创建课堂并取得课堂码，学生端必须通过课堂码加入同一课堂。
- 演示模式只用于静态页面巡检，不得替代教师 / 学生双身份验收。

## 闭环流程

每一页都按同一顺序验收：

1. 教师进入当前页，等待当前页状态同步到学生端。
2. 学生端出现不同步提示时，点击“跳到教师当前页”。
3. 教师按契约执行本页控制，例如发放作答、开放浏览、推进显影或显示答案。
4. 学生端确认作答区解除锁定，再完成选择、填空、参数调节、表格填写或其他互动。
5. 教师端检查本页是否出现学生提交汇总、参数设计提交汇总、表格记录汇总或选项统计。
6. 当前页无缺失面板、无仍锁定作答区、无浏览器错误后，教师进入下一页。

教师翻页后不要立即点击发放按钮。学生端的释放判断通常依赖教师同步状态中的 `activeStepId`，过早点击可能把释放状态写到尚未被学生识别的步骤上，导致脚本误判为“教师已发放但学生仍锁定”。验收脚本应先等待学生端识别教师当前页，再执行释放动作。

## 必查证据

- 页面总数、步骤标题和下拉菜单顺序与 contract / manifest 一致。
- 教师端和学生端均无 `尚未支持`、`不支持的`、`missing renderer`、`暂无可渲染` 等缺失组件信号。
- 互动页释放后，学生端不再显示“教师尚未发放”或“教师尚未开放”。
- 学生提交后，教师端能看到对应汇总，不只是在学生端显示提交成功。
- `StudentState` 中存在 `teacher-sync` 与 `course` 两类状态；`course.responses` 至少覆盖所有需要提交的互动步骤。
- `InteractionLog` 中存在教师 `view/interact/complete` 与学生 `view/interact/submit/param_change` 等事件。
- 浏览器 `console.error` 与 `pageerror` 为空；可接受非阻断性性能提示，但必须记录。

## 对设计真源的反向要求

- 哪些页面需要教师释放，哪些页面进入即开放，必须在 `teacher_controls` 中语义分离。
- 学生作答区默认隐藏或锁定时，页面静态证据仍必须完整可读。
- 前测、后测、参数调节、表格构建等活动要能形成教师端聚合，不只定义学生端表单。
- 使用共享组件时，contract 必须给出足够 payload，让浏览器验收可以检查题面、选项、参考答案、表头、参数控件和汇总标题。
- 设计稿中不得把“自由浏览可见”当作课堂链路通过；必须明确真实课堂中的释放、提交、聚合和埋点验收点。
