# 验证与笔记更新规则

## 设计稿对照验证

实现完成后，先重新做一次“设计稿 vs 实现稿”核对，再做浏览器闭环验收。至少检查：

1. 课程入口是否正确挂到互动课程目录、预置教案和课堂码链路。
2. 步骤数、标题、顺序、时长是否与 `interactive-page.md` 一致。
3. 每一步是否先承担完整课件职责：
   - 标题层级
   - 正文说明
   - 公式
   - 表格
   - 图示
   - 例题或结论
4. 哪些位置被升级为互动，升级是否合理，是否没有把关键知识转嫁给互动组件。
5. 教师端控制流是否匹配：
   - 推进步骤
   - 释放活动
   - 显示答案
   - 查看统计/词云
   - 结束课堂
6. 学生端是否形成完整闭环：
   - 进入页面
   - 作答/操作
   - 提交反馈
   - 等待教师释放或答案揭示
   - 回看/修正
7. 页内 AI 是否为当前课程当前步骤的真实上下文，且以页内弹窗/抽屉方式出现。
8. 媒体是否来自 runtime 正式资源，是否已杜绝 ASCII 图。
9. 课程事件、进度保存、会话同步是否复用统一框架。
10. 若扩展了事件或 payload，是否同步覆盖事件分类、治理映射与测试。
11. 是否复用了统一 session / Redis / SSE 链路，而不是新写单课同步方案。
12. 学生端是否采用“不同步提示 + 手动跳转”，而不是强制追页。

## 推荐核对方式

- 读取设计文档、runtime lesson bundle 与 review 产物
- 读取当前实现代码与课程笔记
- 按步骤列差异
- 如有条件，打开首页、教师端、学生端逐步核查
- 至少验证一次教师翻页后的学生不同步提示
- 至少验证一次教师释放活动、学生提交、教师查看汇总
- 若有答案揭示，至少验证一次教师点击后学生端变化

## 推荐守卫测试

至少保留一类文本级或单测级守卫：

- AI 助手必须页内打开，不能跳转旧助手页
- 课堂页必须复用统一事件链
- 学生提交后必须显示提交状态
- 教师端必须保留统计/词云/答案揭示
- 首页必须消费 runtime 讲义、知识图谱和知识卡预览

## 课程笔记格式

每个课程笔记建议包含以下部分：

```markdown
# <lesson> 课程实现笔记

## 课程信息
- 课次：
- 标题：
- 设计源：
- 当前实现入口：
- runtime：

## 当前状态
- 未开始 / 进行中 / 已实现 / 待优化

## 本次实现内容
- ...

## 设计差异与实现约束
- 已消除差异：
- 仍存在差异：
- 有意偏离：

## 复用基线
- 参考了哪些现有课程或共享能力：

## 媒体资源状态
- 已具备：
- 缺失：
- 占位路径或导出路径：

## 验证记录
- 设计稿核对：
- 页面验证：
- 测试命令：
- 结果：

## 下次优化建议
- ...
```

## 更新时机

以下场景必须更新笔记：

- 新课第一次开始实现前
- 完成一轮主要实现后
- 完成设计差异核对后
- 用户要求优化现有课程后
- 课程规范发生整体变化后

## 差异记录要求

差异必须写清：

- 来自哪份设计文档
- 当前实现位于哪里
- 是遗漏、降级、替代实现，还是有意优化
- 如果有意偏离，为什么更适合当前平台

## 当前应额外记录的规范事实

对 `1-1`、`1-2`、`1-3` 一类新体系课程，笔记中应优先写明这些事实是否成立：

- 页面是否先承担完整课件职责
- 是否有页内 AI 上下文更新
- 是否有 `SubmissionStatus` 和等待/揭示反馈
- 教师端是否有统计、词云、答案揭示
- 是否默认折叠在线学生列表
- 是否复用了统一课程事件链
- 是否复用了 session / Redis / SSE 同步底座
- 媒体是否按 `processed -> runtime` 规范导出
