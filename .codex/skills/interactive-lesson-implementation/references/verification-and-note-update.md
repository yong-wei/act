# 验证与笔记更新规则

## 设计稿对照验证

实现完成后，重新做一次课程核对。至少检查：

1. 课程入口是否正确挂到互动学习/互动课程
2. 步骤数、标题、顺序、时长是否与 `interactive-page.md` 一致
3. 每一步的页面类型是否一致：
   - 纯文本
   - 静态图
   - 视频
   - 问答
   - 测验
   - 工作区探索
4. 教师端控制流是否与设计稿匹配
5. 学生端是否形成提交、记录、汇总、反馈闭环
6. 媒体是否可读取，占位是否已给出明确路径
7. 埋点、进度保存、同步机制是否复用现有服务
8. `dashboard`、通用加入页、课程入口页的课堂码加入是否统一落到正确课程
9. 教师端是否能结束课堂，教师后台是否能停止进行中的课堂
10. 学生端是否采用“不同步提示 + 手动跳转”而不是强制追页

## 推荐核对方式

- 读取外部设计文档
- 读取当前实现文件
- 按步骤逐项列出差异
- 如有条件，打开页面做浏览器核验
- 若课程包含课堂码链路，至少验证一次从 `dashboard` 或 `/classroom/join` 输入课堂码的真实跳转
- 若课程包含教师/学生双端同步，至少验证一次教师翻页后的学生不同步提示

## 课程笔记格式

每个课程笔记建议包含以下部分：

```markdown
# <lesson> 课程实现笔记

## 课程信息
- 课次：
- 标题：
- 外部文档目录：
- 当前实现入口：

## 当前状态
- 未开始 / 进行中 / 已实现 / 待优化

## 本次实现内容
- ...

## 与设计稿差异
- 已消除差异：
- 仍存在差异：
- 有意偏离：

## 媒体资源状态
- 已具备：
- 缺失：
- 占位路径：

## 验证记录
- 设计稿核对：
- 页面验证：
- 测试命令：
- 结果：

## 下次优化建议
- ...
```

## 更新时机

以下场景必须更新笔记：
- 新课第一次开始实现前
- 完成一轮主要实现后
- 完成差异核对后
- 用户要求优化现有课程后

## 差异记录要求

差异必须写清：
- 来自哪份设计文档
- 当前实现位于哪里
- 是遗漏、降级、替代实现，还是有意优化
- 若有意偏离，为什么偏离更合适
