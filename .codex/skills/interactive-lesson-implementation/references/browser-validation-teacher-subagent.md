# 教师端浏览器验收子代理规范

## 适用范围

本文件只给教师端浏览器验收子代理使用。主代理不需要读取本文件，只需在分派教师端角色时把本文件一并下发。

## 启动基线

- 浏览器验收默认基线是 `npm run startup`
- 若主代理尚未启动基线服务，先回报，不要自行切到 `npm run start`
- 若页面只显示 SSR HTML、交互未 hydration，优先怀疑启动基线异常或资源未就绪，不要直接判课程实现失败

## 账号与浏览器前置处理

- 教师账号：`test_teacher`
- 教师密码：`TestTeacher@Just2026!`
- 使用独立浏览器 profile，避免与学生端串会话
- 登录后若浏览器弹出“保存密码”“密码过于简单”“密码已泄露”之类提示，优先关闭或拒绝，再继续验收
- 在准备点击“结束课堂”前，必须提前处理页面对话框；若出现 `window.confirm`，应显式接受，不要让它阻塞后续点击

## 教师端主流程

1. 登录教师端并进入目标课程入口页。
2. 创建课堂，记录课堂码、教师页 URL 与步骤总数。
3. 验证教师端可见课堂码、在线人数区默认折叠、结束课堂入口存在。
4. 每到一页先核对标题、步骤序号、主要教师操作是否与设计稿一致。
5. 若当前页是选择题或测验页：
   - 等待学生提交后检查教师端统计
   - 题目有标准答案时，执行“显示答案”，再让学生端验证答案同步
6. 若当前页是文本题：
   - 检查词云是否生成
   - 检查学生回复列表是否默认折叠且按提交时间排序
7. 若当前页需要教师观察学生结果：
   - 检查任务一/任务二/后测回看等汇总模块
   - 只记录是否闭环，不要在子代理上下文里展开冗长复述
8. 最后一页执行“结束课堂”：
   - 先确认 `window.confirm` 已被处理
   - 接受“确定要结束课堂吗”之类确认框
   - 检查课堂是否成功结束，以及学生端是否进入结束后的预期状态

## 必报缺陷

- 建课失败、课堂码为空或教师页 URL 异常
- 教师翻页后学生端没有出现不同步提示或无法跳转
- 选择题没有统计、显示答案后学生端无同步结果
- 文本题没有词云，或回复列表默认展开
- 在线学生清单默认展开
- `window.confirm` 阻断结束课堂，导致流程无法收束

## 回报格式

- 只汇报：页面编号、通过/失败、阻断点、复现动作、必要截图
- 若缺陷已定位为浏览器弹窗或环境基线问题，要明确标注“环境阻断”，不要误报为课程功能缺陷
