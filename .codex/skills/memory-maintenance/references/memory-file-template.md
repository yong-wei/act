# Memory File Template

以下模板用于维护 `.codex/memory/`。优先复制最接近的模板，再根据实际主题删减，不要每次从零发明结构。

## 1. 通用叶子文件模板

```md
# 标题

状态: active
最后更新: YYYY-MM-DD
摘要: 用 3-6 行说明该文件回答什么问题，以及为什么值得跨会话保留。
上游:
- [父级索引]
下游:
- [如果没有可写 []]
相关:
- [相关架构/事故/决策/流程]

## 结论

- 先写稳定结论
- 一条结论一个点

## 关键事实

- 只写支撑结论的高价值事实
- 避免抄原始日志

## 风险或后续动作

- 可选
```

## 2. `00-index.md` 模板

```md
# 目录索引标题

状态: active
最后更新: YYYY-MM-DD
摘要: 说明这个目录回答哪类问题，什么场景下应该读这里。
上游:
- [上一级索引]
下游:
- [叶子文件 A]
- [叶子文件 B]
相关:
- [相邻目录或关键入口]

## 何时读这里

- 场景 1
- 场景 2

## 目录内容

- `文件 A`: 回答什么问题
- `文件 B`: 回答什么问题
```

## 3. Incident 模板

```md
# YYYY-MM-DD 问题标题

状态: active
最后更新: YYYY-MM-DD
摘要: 一句话说明是什么问题、最后归因到哪里。
上游:
- [事故索引]
下游:
- []
相关:
- [相关架构文件]
- [相关运维文件]

## 结论

- 最终判断是源码、部署、配置、数据还是混合问题

## 关键证据

- 证据 1
- 证据 2

## 后续建议

- 建议 1
- 建议 2
```

## 4. Decision 模板

```md
# ADR-YYYY-MM-DD-主题

状态: active
最后更新: YYYY-MM-DD
摘要: 用一句话说明做了什么决策。
上游:
- [决策索引]
下游:
- []
相关:
- [相关架构文件]
- [相关流程文件]

## 背景

- 为什么需要这个决策

## 决策

- 具体采用什么方案

## 影响

- 会影响哪些代码、流程或维护方式
```

## 使用提示

- 新增叶子文件后，别忘了回补对应目录的 `00-index.md`
- 同一条事实只保留一个主文件，其余地方用链接引用
- 完成维护后，运行：

```bash
python3 .codex/skills/memory-maintenance/scripts/validate_memory.py
```
