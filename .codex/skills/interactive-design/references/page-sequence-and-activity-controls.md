# 页面顺序、公式表格排布与作答控制约束

## 1. 页面必须自包含到可脱离讲稿独立阅读

- 每一步至少回答四个问题：对象是什么、正在判断什么、关键证据在哪里、它如何接回本课主线。
- 若学生离开讲稿后无法回答这四问，说明页面缺少题面、前提、图后解释、结论桥接或目标提示。
- 任何“课堂上教师会补充说明”的默认假设，都不能当成作者态设计成立的前提。

## 2. 页面顺序以讲义证据链为准

每一步都要写成明确顺序：

`先出现什么 -> 再出现什么 -> 最后出现什么`

不得只写“主阅读顺序”或“内容见讲义”。
互动课程是逻辑与内容导向的课件，不是视觉效果导向的海报。若讲义先给原理、公式、题面或推导，再给结构图或对比图，互动页必须先承载这些逻辑证据，再呈现图片。

## 3. 图片不得默认抢占页面顶端

- 只有当图片本身就是题面或首个证据时，才允许放在最上方。
- 若讲义顺序是“公式 -> 文案 -> 图片 -> 表格”，互动页必须照此落页。
- 若讲义顺序是“原理 -> 题面 -> 推导 -> 图像验证”，互动页不得改成“图像 -> 原理 -> 题面”。
- 若讲义顺序是“原理逐步显影 -> 结构图 -> 分析逐步显影 -> 对比图片”，互动页必须显式拆成这四段，不得把结构图或对比图提到首屏。
- 共享媒体槽、封面图、hero 图或视觉模板不得覆盖步骤级证据顺序；图片位置只能由当前步骤的证据链决定。

## 3.5 模板名同时声明区域拓扑

- 在 `interactive-contract.yaml` 中，模板名不仅是视觉名，还意味着区域顺序与模块归宿。
- 设计稿若使用 `boundary_case_board`、`worked_example_compare`、`task_card_workspace` 这类模板，必须写清每个区域先后承载什么证据，不能只写成“综合比较页”“联动工作区”。
- 若模板把 `problem`、`media`、`interaction` 拆成独立区域，human-readable prose 也必须保持这种拆分，不得在页面蓝图里重新糊成一个大面板。

## 3.6 同区域多模块必须分别表达

- 若同一区域声明多个 `must_be_visible` 模块，设计稿与契约都要分别写出每个模块承担的教学职责。
- 不能把两个独立模块偷写成一句“这里放一个双栏联动面板”或“这里展示综合比较结果”。
- 只有当 contract 明确把多个内容封装成一个复合模块时，才允许在 prose 中按一个模块叙述。

典型例子：

- 若 `media` 区域同时有时间域对比和频域对比两个模块，应分别说明“学生先看什么曲线证据、再看什么频域证据”，而不是笼统写“综合比较面板”。

## 4. 公式与表格必须拆开命名

- 公式密集区必须按条目或成组关系拆开，并配名称或说明文案。
- 表格默认保留名称、作用与适用边界。
- 若表格承担结构工具箱职责，必须完整保留每个结构的数学表达式；不得只给结构名和语义标签。
- 若讲义要求并排比较，两张表可左右并排，但不得挤成一整块文字。
- 若讲义中的图本身不承担首个阅读任务，必须先落公式与文案，再落图；图中的解释性文字应优先迁移到同页控件面板或说明模块，而不是继续塞回图片本体。
- 若公式或符号是本页核心证据，优先按原生 LaTeX 组件与原生 HTML 表格设计，不要默认退回 Markdown 大段公式或 Markdown 表格承载整页关键证据。

## 5. 后测与收束默认分离

- 后测是检查学生判断链是否形成。
- 收束是总结与去向说明。
- 默认应分成两个步骤；若必须同页，必须在设计稿中写明理由与语义边界。

## 5.5 可行域图层必须有讲义依据

- 只有当讲义或设计稿明确讨论可行域、满意域、约束域或指标设计域时，才允许在互动图中绘制对应区域。
- 若案例只讨论对象、指标趋势、频域/时域曲线和结构选择，不得为了复用其他课次组件而带入可行域。
- 若使用共享曲线工作区，契约中必须写明 `feasible_region: not_applicable` 或等价说明，避免实现侧继承旧夹具。
- 不得把另一个课次的可行域参数作为“默认视觉层”带入当前案例。

## 6. 学生作答默认隐藏

若页面存在作答区，必须写明：

- `default_visibility: hidden | locked`
- `release_required: true | false`
- `browse_required: true | false`

默认推荐：

- `default_visibility: hidden`
- `release_required: true`
- `browse_required: false`

## 7. 作答卡约束

每个作答卡至少写清：

- `id`
- `prompt`
- `response_kind`
- `submit_scope`
- `layout_span`

推荐取值：

- `response_kind`: `fill_text` / `single_choice` / `multi_choice` / `match` / `drag_sort`
- `submit_scope`: `per_card`
- `layout_span`: `one_third` / `half` / `full`

补充默认约束：

- 除前测 / 后测 / 专门题组页外，单页作答卡默认不超过 `2` 张。
- 若单页作答卡恰为 `2` 张，且页面不是前测 / 后测 / 专门题组页，默认按双栏半宽并排设计；除非设计稿显式声明通栏或非对称布局，否则不得回退为上下单栏堆叠。
- 同页若同时存在正文、例题、比较表与作答区，默认顺序是“正文在前、作答在后”；只有纯题组页才允许作答卡置顶。
- 展示页不要额外附加“无需提交”占位模块；无作答即不渲染作答壳层。
- 作答卡标题直接写题面或判断动作，不得使用“卡片 1 / 卡片 2 / 题面卡”这类无教学语义的泛称。
- 单卡提交按钮默认统一写为`提交答案`，不要在同一课内混用“提交本卡”“保存本题”等不同口径。

## 7.5 后测页标题卡

- 后测若独立成页，默认先放一张“后测名称 / 本页任务”标题卡，再放题卡区。
- 除纯题组页外，不要把后测题卡直接顶到整页标题下方而没有任何静态过渡。

## 8. 教师控制字段

`teacher_controls` 至少明确：

- `release_activity`
- `open_browse`
- `teacher_step_reveal`
- `reveal_reference_answer`

若页面不需要其中某项，也要显式写明 `not_applicable`，不要留空让实现侧猜测。

## 9. 学生访问字段

若页面有浏览限制或作答限制，`interactive-contract.yaml` 中至少写清：

- `student_access.default_visibility`
- `student_access.release_required`
- `student_access.browse_required`
- `student_access.can_view_problem_statement`
- `student_access.can_view_derivation_steps`
- `student_access.can_submit_without_browse`

## 10. 人读稿最低结构

每一步至少包含：

- 页面骨架
- 模块清单
- 静态承载内容
- 混合证据顺序
- 互动升级点
- 教师控制
- 学生默认状态
- 本页脱离讲稿后的自包含检查
- 预览口径

## 11. 典型禁例

- 统一媒体槽位把图片自动插到正文前面
- 为追求首屏视觉效果，把大图、结构图或对比图固定放在讲义原理之前
- 模板明明声明了多个区域，却在页面蓝图 prose 中写成一个模糊“大面板”
- 同一区域已有两个必显模块，却只在 prose 里保留一个笼统“联动比较面板”
- 案例没有可行域讨论，却因为复用旧曲线夹具而绘制可行域
- 一整页只给一个“学生作答区”标题和一个统一提交按钮
- 例题题面、原理说明、作答区三者边界不清
- 机读契约里没有教师控制与学生访问字段，只写互动类型
- 页面只写“见讲义”“教师补充说明”“学生讨论后理解”，却没有把关键证据真正落在当前页
