# 曲线互动面板与设计页拆分约束

## 1. 曲线页首先服从讲义顺序

- 公式、对象、文字说明、设计目标、步骤链与图的顺序，默认服从讲义。
- 图片或曲线图不得为了首屏视觉而抢到页面顶部。
- 曲线图、根轨迹图、结构图和四联对比图均属于证据链的一环，不是页面装饰；只有当讲义把它们作为首个题面证据时，才允许先于原理或公式出现。

## 2. 曲线图不能吞掉完整方法过程

若讲义中某一节已经给出完整设计过程，例如：

- 基于时域指标的 `PI` 设计
- 基于时域指标的滞后校正
- 基于频域指标的 `PI` 设计
- 另一类频域设计对照链

则互动页必须先分别给出这些方法页，再允许给出比较页。

## 3. 方法页与比较页的职责必须分离

### 方法页

至少包含：

- 题面或对象
- 设计目标
- 关键公式或关键步骤
- 逐步显影的推导/判断链
- 最后才出现验证图或对比图

### 比较页

只承担：

- 指标并列
- 收益/代价对照
- 结构抓手对照
- 方法选择判断

比较页不得承担完整求解链的首次出现。

## 4. 图像出现时机

- 若图像是验证或结果对照，应放在关键推导节点之后。
- 若图像本身是题面的一部分，才允许在题面模块中较早出现。
- 不得把多个不同方法的图强行拼在一页，用图代替过程。

## 5. 曲线互动镜像原则

若讲义曲线图需要升级为互动面板，必须写清：

- 基线参数
- 默认结构组合
- 子图排布
- 轴范围策略
- 指标覆盖层
- 控件位置
- 读图口令
- 本页要回答的判断问题

默认状态必须复现讲义静态图。
默认状态之外，还必须让学生脱离讲稿也知道“先看哪张子图、再看哪个指标、最后得到什么结论”，不能只给一个可操作面板。

优先实现策略：

- 讲义章节中已有响应曲线、根轨迹、Bode/Nyquist、参数扫描或同类数值曲线时，互动页优先采用 Rust 驱动图形面板。
- Rust 图形面板的默认布局必须复现讲义静态图的子图布局、默认参数和主要标注。
- 控件必须放在图形下方，作为参数调节区，不得挤占主证据图。
- 页面设计必须写明控件设计意图：每个可调参数改变哪一类证据、对应哪一条判断链、学生应观察什么。
- 有互动图形的页面，不再设普通互动题；互动提交内容改为当前参数、观察记录、选定状态或基于调参后的判断。
- 若不采用 Rust 面板，必须说明原因，例如该图不是数值曲线、只承担静态示意、或当前课程尚无对应 Rust 模型。

## 5.5 可行域、满意域与约束域

- 可行域不是曲线面板的默认装饰层。只有讲义明确讨论可行域、满意域、约束域或指标域时，设计稿才允许加入。
- 若当前案例没有明确讨论可行域，`interactive-contract.yaml` 应写出 `feasible_region: not_applicable` 或同等约束。
- 复用其他课次的曲线请求构造器或夹具时，必须检查是否携带可行域参数；不得让旧课次的可行域语义泄漏到新课。

## 6. 与 3-7 类问题对应的硬约束

- 若讲义将 `3.2` 与 `3.3` 分成两类时域设计，互动页不得只留一张“时域设计比较页”。
- 若讲义将 `3.4` 与 `3.5` 分成两类频域设计链，互动页不得只留一张“频域比较页”。
- “比较”必须建立在“两个方法都已完整落页”的前提上。

## 7. 机读契约建议字段

曲线或设计页建议补齐：

- `interactive_figure_spec`
- `rust_panel_spec`
- `evidence_sequence`
- `comparison_role`
- `method_role`
- `baseline_media`
- `validation_media`
- `feasible_region_policy`
- `parameter_controls`
- `parameter_submit_spec`

其中：

- `method_role` 取值示例：`time_domain_pi_design`、`time_domain_lag_design`
- `comparison_role` 取值示例：`time_domain_method_compare`

## 8. 典型禁例

- 先上图，后补公式
- 一页同时塞入两种方法的完整过程和比较结论
- 用一张总图替代本应分开的两类设计页
- 把“验证图”当成“方法过程”的全部内容
- 案例未讨论可行域，却在根轨迹或指标图上绘制可行区域
- 只给曲线控件，不给基线说明、读图顺序和结论回接
- 有 Rust 互动图形，却仍附加普通问答题
- 控件放在图形上方或图内，遮挡主曲线证据
- 默认状态不能复现讲义静态图布局
