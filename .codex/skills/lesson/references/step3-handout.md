# Step 3：讲义文档生成规格

> 目标：基于Step 2确认的概念结构，生成完整、高质量的教学讲义。

## 生成前必做

1. 先读取范文：`course-content/authoring/lessons/legacy/L-2a/design/handout.md`
2. 只提炼文风感受，不继承具体内容：
   - 叙述节奏是否平稳
   - 工程引入是否自然
   - 概念解释是否通俗
   - 图表与正文如何配合
   - 小结与过渡如何收束
3. 读取后立刻回到当前单元真实内容，避免复制范文的结构、例题、措辞与论证顺序
4. 禁用词和句式：
   - 钉死，不是……而是，不在于……而在于，以及任何类似的先否定再肯定句式。直接写出事实。

## 核心标准

- **独立可读**：讲义必须写成“学生不看课件、不听老师补充，也能基本学懂”的完整文本
- **双重任务**：既讲清知识，也训练能力；至少覆盖“理解、计算/判断、迁移应用”中的多个层次
- **单一逻辑主线**：围绕当前单元主题组织一条稳定的逻辑链，例如“问题提出 → 关键概念 → 规律/公式 → 判断/计算 → 工程意义”，避免零散堆点
- **篇幅服从完整性**：不对正文做机械字数压缩；为了讲清完整知识链和能力链，可以适当放开篇幅
- **附录分流复杂内容**：过于复杂、但又值得保留的长推导、补充证明、拓展案例、学生复现代码等，可放入附录，不打断正文主线
- **可读性**：逻辑顺、术语稳、通俗但不失严谨，避免堆砌定义
- **多表征**：正文中主动安排配图、表格、对照表、结构图或示意图；正式编号由导出模板按出现顺序自动生成，正文只负责写清题名内容
- **图题不手写序号**：Markdown 中图片标题和表题文字只写标题内容本身，不写“图1”“表2”等硬编码序号；最终编号交给导出模板自动生成
- **图示解释不能停留在口头**：凡是用图像解释概念、机理、规律、性能或近似时，正文必须同时给出能与图逐项对照的解析对象，例如系统模型、传递函数、模态展开、时域解析式、幅频特性表达式、性能指标表等；禁止只写“从图上可以看出……”
- **正文引用必须可追溯**：正文中凡引用图、表、公式或文献，必须使用标签 + 交叉引用，不得写死“图1”“表2”“上图”“下图”“上式”“下式”等依赖排版顺序的表述
- **图像形式合规**：图像只能使用代码直出图或 AI 生成图，禁止 ASCII 字符图形
- **可验证**：凡涉及控制系统计算、曲线、性能指标、稳定性判断，必须用 `Octave` 脚本验证
- **优先原生函数**：时域响应、Bode 图、Nyquist 图、根轨迹、频率裕度等，默认优先使用 `step()`、`bode()`、`nyquist()`、`rlocus()`、`lsim()`、`margin()` 等 `Octave` / control 包原生函数，不手写同类底层计算
- **公式统一**：行内公式使用 `$...$`，行间公式使用 `$$...$$`
- **成品化表达**：正式讲义中不得保留“图示建议”“待制作”“占位说明”“脚本验证”等创作过程文本

## 讲义标准结构

根据知识类型[C/X/D]调整各章节权重。

在正式正文前，默认包含以下前置信息区：

1. 标题
2. 课次信息节（课型、学时、知识类型、前置/后续位置等）
3. **封面图片占位**
4. **信息图占位（附录前）**

其中，**课次信息节**默认遵守以下硬约束：

- 学时固定写为 `90分钟`，不再按单元单独改写其他时长表述
- “前置”只写当前主线课程中的前置知识或前置课次，不写任何 `legacy` 课程编号或 `legacy` 来源说明
- “讲义定位”只需用**面向学生的口吻**写明“这份讲义要带你学习什么主题/解决什么问题”，不要写“本讲义承担本主题的唯一事实来源责任”或同类作者态声明

推荐写法示例：

```markdown
- 学时：90分钟
- 前置：已掌握二阶系统的标准形式、典型性能指标与基本结构图含义
- 讲义定位：这份讲义将带你建立“频率响应怎么看、典型环节怎么画、标准对象怎么做粗粒度识别”的入门框架。
```

封面图片占位必须放在“讲义信息节”之后、“引入案例”之前，默认使用如下引用形式：

```markdown
![封面漫画：单元导入](../media/processed/[单元编号]-cover-comic.png)
```

后续媒体制作完成后，直接按该占位文件名回写，即可在 Markdown 与 PDF 中正常显示；不要在讲义完成后再临时改结构腾位置。

封面漫画在 Step 3 默认**只产出提示词文件** `media/raw/[单元编号]-cover-comic-prompt.md`，不要求在讲义起草阶段立即生成 `[单元编号]-cover-comic.png`。讲义正文保留图片占位，待图片制作完成后再回写并导出正式 PDF。若交付的是中文定稿提示词，其首句必须固定为“以哆啦A梦中的人物为原型”，且后续整段设计都要保持该系列漫画画风。

---

在正文结束、附录开始之前，固定预留信息图占位：

```markdown
![本讲信息图总结](../media/processed/[单元编号]-info.png)
```

`[单元编号]-info.png` 默认不要求在 Step 3 同步生成提示词；讲义先保留占位，待后续多媒体制作或人工制作完成后回写，再导出最终 PDF。

### 3.1 引入案例（工程背景/问题提出）

- 以船舶航向控制或其他工程场景开篇
- 提出本节要解决的核心问题（"为什么需要这个知识？"）
- 连接上节课的输出，体现知识的递进性
- 篇幅以把问题讲清为准，不设硬上限；至少需要 1 个情境问题
- 优先配置 1 张引入图或 1 个场景表，使学生进入问题而不是直接掉进定义堆

---

### 3.2 核心内容（按知识类型定制）

#### [C] 计算型内容要求

- 给出严格的数学定义和推导过程
- 标明计算步骤（Step 1→2→3→...）
- 提供典型数值示例，验证计算过程
- 指出常见错误和边界情况
- 对所有计算结论，用 `Octave` 补做数值或曲线验证；手算与脚本结果不一致时，以查清原因为先，不得直接忽略
- 若图像承担解释任务，必须把“图像现象”和“解析表达”显式对照，例如极点图对应时域模态、Bode 图对应幅频表达式、时域曲线对应性能指标或解析解

#### [X] 跨域型内容要求

- 明确指出两个领域之间的映射关系（A域→B域）
- 给出直觉性解释（"为什么这个映射关系存在"）
- 给出定量关系公式和适用范围（层0速通单元标注"→完整推导见单元X-X"）
- 类比说明（找一个学生熟悉的跨域映射作为类比）
- 提供真实图片与表格对照，供读者无需平台即可建立直觉
- **不在讲义中出现**：平台操作步骤、演示说明、课堂活动——这些内容属于教案
- 至少有 1 处图表或对照表，把“概念对应关系”可视化

#### [D] 设计型内容要求

- 以工程任务为驱动（给定目标和约束）
- 展示设计决策过程（不只给结论，要给决策逻辑）
- 讨论多方案比较（至少两个方案，说明权衡）
- 包含"工程判断要点"专栏
- 指出无唯一解的原因和处理方式
- 对方案对比结果，优先使用表格呈现评价维度、优点、风险与适用场景

---

### 3.3 例题精解

- 至少2道例题，由浅入深
- 例题1：验证性（确认计算/关系正确）
- 例题2：拓展性（涉及本节重点的综合运用）
- 每题包含：题目陈述 → 解题思路 → 详细求解 → 结论与工程意义
- 若例题适合学生自行复现，可在正文中点名 MATLAB/Octave 文件名，并把最基本 MATLAB/Octave 代码放入附录；不要在正文单列“脚本验证”小节

---

### 3.4 工程视角导入（按需嵌入）

- **仅当大纲、单元目标或课程要求中确有相关导向时生成**
- 要求：自然融入工程故事、科学家工作场景、职业判断、安全边界、责任后果等正文语境，不生硬说教
- 禁止单独写出“课程思政”“思政融合”等显式标题，可改写为“工程判断”“工程视角”“为什么不能只追求……”等学生更容易接受的自然导入
- 篇幅：约100-200字，作为正文内容的一部分；如有必要可独立成节，但节名仍应保持工程语境

---

### 3.5 本节小结与前后衔接

- 3-5条核心要点总结（条目式）
- 明确说明：本节知识在全局框架地图中的位置
- 前衔接：承接了哪里的知识
- 后铺垫：为哪里的学习做铺垫

### 3.6 附录（按需生成）

- 适用内容：复杂推导、补充证明、拓展案例、长表、MATLAB/Octave 复现代码、额外练习
- 原则：附录服务正文，不喧宾夺主；正文仍需独立可读
- 若正文中省略了部分长推导，必须明确标注“详见附录 X”

---

## 图片、表格与验证脚本要求

1. 至少安排以下其一：
   - 1 张结构/关系示意图 + 1 张响应/规律图
   - 1 张示意图 + 2 张表格
   - 3 张以上图表混排
2. 图表不能只是“装饰”，必须承担解释任务：
   - 图：帮助学生看出结构、趋势、机制或现象
   - 表：帮助学生做对比、归类、记忆或判断
3. 每幅图、每张表都要有正式编号与题名，不得用“图示建议”“待制作”等过程性说明替代；其中编号由导出模板自动生成，正文里不再手写重复的“图1.”“表1.”行。
4. 封面图与课末信息图固定按正文版心全宽导出；其余图片默认必须根据图中文字与正文的视觉字号关系单独设置 `width=...`，不要把所有图都机械地塞满整行。
5. 线框图、方框图、结构图若图中文字明显偏大，应优先缩小图片宽度；数据图、响应图若在接近全宽时图中文字仍偏小，应回到成图脚本调整原图文字大小，不得仅靠 PDF 拉伸补救。
6. 讲义中的引入语、追问句、核心提醒若用 `>` 表示，则默认会在 PDF 中被渲染为浅底色提示块；写作时应保持句子简洁，不要把整段正文都塞进提示块。
7. 若图表在正文中被用于解释概念、规律或比较结论，则正文必须同步出现对应的解析支撑，至少满足以下之一：
   - 图对应明确系统模型或传递函数；
   - 响应曲线对应显式时域表达式、模态展开或性能指标表；
   - 频域曲线对应幅频/相频表达式、转折频率、带宽或近似计算说明；
   - 对比图对应明确的比较维度与数值结论。
8. 正文引用图、表、公式或文献时，必须使用规范交叉引用，不得写“上图 / 下图 / 下表 / 上式 / 图1 / 表2”这类硬编码位置词或序号词。
9. 当前 Markdown 讲义推荐采用以下标签约定：
   - 图：`{#fig:lesson-topic}`
   - 表：`{#tbl:lesson-topic}`
   - 公式：`\label{eq:lesson-topic}`
   - 文献：BibTeX / CSL 键，如 `[@zhou2024]`
10. 若需要对公式做正文交叉引用，允许对该公式使用原生 LaTeX `equation` / `align` 环境并配 `\label{}`；这是相对 `$$...$$` 的受控例外，目的是保证 PDF 中的可引用编号稳定。
11. 涉及计算的讲义，默认生成对应 `Octave` 验证脚本并保存到本课媒体原始目录或等价验证目录；该验证过程不直接暴露为讲义正文内容。
12. 默认优先调用 `Octave` / control 包原生高层函数完成出图和核验，例如 `step()`、`bode()`、`nyquist()`、`rlocus()`、`lsim()`、`margin()`；若原生函数不足以覆盖需求，必须先说明缺口，再补充必要的自定义计算。
13. 若需要学生复现，正文只给 `.m` 文件名提示，最基本 MATLAB/Octave 代码放附录，不加入复杂的版式或格式控制命令。
14. 讲义中给出的参考代码，默认统一采用 MATLAB/Octave 形式，不混入 Python、JavaScript 或其他语言示例。
15. 若图像在 PDF 中出现以下任一现象：全宽后仍裁切、右侧/顶部说明框被截断、图例/标注落在版心外、图中文字与正文字号明显失衡，则默认判定为**脚本外问题**，必须回到成图脚本或源 SVG/PDF 修复边界框、边距、字号和布局；不要继续依赖 PDF 导出链路强行缩放补救。
16. 需要单独控制大小的中间图片，必须直接在 Markdown 图片行上显式写出 `width=...`；讲义参考文件应记录这类经验，避免后续同类课次再次把所有图机械地按自然尺寸或整行宽度导出。

## Step 3 的双阶段讲义流程

Step 3 不再只包含学生版讲义，而是固定分成两段：

1. **学生版讲义阶段**
   - 先完成 `handout.md`
   - 同步补齐 `cover-comic-prompt.md`，并确认 `cover-comic.png` 与 `info.png` 的占位路径已固定
   - 经用户确认且所需图片已回写后，导出 `handout.pdf`
   - 抽样检查 PDF 版面
2. **教师版课堂讲义阶段**
   - 只有在学生版讲义与学生版 PDF 都通过确认后，才开始 `teacher-handout.md`
   - 教师版讲义经用户确认后，导出 `teacher-handout.pdf`
   - 再次抽样检查教师版 PDF 版面

两份 PDF 必须共用同一技能模板，不允许学生版和教师版各自演化成不同风格。

## 教师版课堂讲义要求

教师版课堂讲义固定文件名为 `teacher-handout.md`，用途是 90 分钟课堂教学，不替代学生版讲义。

教师版课堂讲义默认按**课堂流程**组织，而不是按学生自学正文组织。目标是给教师一份可直接跟着课堂推进的讲义骨架：保留主线、关键话术、必要公式推导、图示调用与板书顺序，不追求学生版那种完整展开。

### 教师版必须包含

- 按 90 分钟课堂顺序编排的分段结构
- 与上一课、本课、下一课的关键衔接语
- 本节唯一主线及课堂收束语
- 90 分钟课堂时间分配建议
- 必须保留的核心推导
- 建议板书内容
- 课堂需要调用、复用或补画的图形
- 教师提醒：哪里可略、哪里必须强调、哪里容易误判

### 教师版写法硬约束

- 讲义应按“开场桥接 -> 核心推进 -> 例题/对照 -> 收束铺垫”的课堂流程展开，每段只保留基本逻辑框架和关键文本，不展开成长篇学生讲解稿
- 图示、公式推导、板书和例题必须按课堂实际使用顺序插入，教师翻页时就能顺着讲，不需要自己再二次排布
- 教师版可以引用必要的正式媒体，但**不包含**面向学生版首页导入的封面漫画和讲义末尾信息图
- 教师版中的公式推导应只保留课堂上必须写、必须讲、必须提醒的版本；较长推导可压缩成“讲到哪一步为止 + 详细过程见学生版/附录”
- 教师版默认不是摘要目录，也不是全文复刻；它应当比学生版短得多，但仍能支撑教师完整完成一节课
- 教师版中的“关键文本”优先写成教师可直接使用的桥接语、追问句、收束句和误区提醒，而不是再重复一遍学生版解释段落

### 教师版不应变成

- 学生版讲义的全文复制
- 只有时间表和项目符号的授课提纲
- 脱离学生版真值来源的另一套内容体系
- 把封面漫画、讲义信息图等学生导入型资源照搬进教师版

### 教师版与学生版的关系

- 学生版负责“学生自学可读的完整知识链与能力链”
- 教师版负责“课堂组织、讲授优先级、板书和图形调度”
- 教师版只能压缩、抽取、重组学生版中的核心内容，不能改写事实口径或引入未核验的新数据

## Markdown 转 PDF 导出规范

学生版讲义与教师版课堂讲义完成后，都要导出同目录 PDF，作为正式交付的一部分。

### 默认工具链

- `pandoc`
- `xelatex`
- `rsvg-convert`（保证 Markdown 中的 SVG 图片可直接嵌入 PDF）

### 交叉引用写法规范

- PDF 成品中的图、表、公式、文献引用，默认都应从源 Markdown 中的标签生成，而不是在正文里手工写死编号。
- 推荐写法：

```markdown
![主导极点近似何时可靠的时域对照图](../media/processed/3-1-pp-03-dominant-pole-response-families.svg){#fig:dominant-step}

见图~\ref{fig:dominant-step}，可以把附加极点位置和阶跃响应形态逐一对应起来。
```

```markdown
\begin{equation}
M_p=e^{-\frac{\pi\zeta}{\sqrt{1-\zeta^2}}}\times 100\%
\label{eq:overshoot}
\end{equation}

由式~\ref{eq:overshoot} 可得标准二阶系统的超调量。
```

- 表格若需要在正文中被引用，也必须提供表标签；若当前 Markdown 表语法不便直接绑定标签，应使用能稳定附着 `#tbl:` 标识的 Pandoc 表格写法，或退回原生 LaTeX `table` 环境。
- 文献引用使用文献键，例如 `[@zhou2024]`，不要直接写“参考文献[1]”或“文献1”。
- 若当前导出链路暂未自动解析某类交叉引用，仍应优先保留标签与 `\ref{}` / `\cite{}` 兼容写法，不允许回退到“下图”“上式”等不稳定表述。

### 默认命令

```bash
python3 .codex/skills/lesson/scripts/export_handout_pdf.py \
  course-content/authoring/lessons/[单元编号]/design/handout.md \
  --refresh-style
```

若导出教师版课堂讲义，则把输入文件替换为：

```bash
python3 .codex/skills/lesson/scripts/export_handout_pdf.py \
  course-content/authoring/lessons/[单元编号]/design/teacher-handout.md \
  --refresh-style
```

### 样式模板

- 技能模板固定存放在 `.codex/skills/lesson/templates/handout-pdf-style.tex.tpl`
- 导出时脚本会在目标文档同目录生成对应样式文件，如 `handout-pdf-style.tex`、`teacher-handout-pdf-style.tex`
- 如需统一升级样式，优先改模板，不要逐课手写不同版本
- `handout.pdf` 与 `teacher-handout.pdf` 必须共用该模板，不允许教师版另配一套独立样式体系

### 导出前必须确认

- `cover-comic.png` 若仍未制作完成，学生版讲义只保留占位，不执行最终 PDF 导出
- `info.png` 若仍未制作完成，学生版讲义只保留占位，不执行最终 PDF 导出
- 若用户明确要求“先审 Markdown、后补图再导 PDF”，则必须按该顺序执行，不得把缺图状态误报为讲义完成态

### 导出后必须检查

学生版至少抽查以下页面：

1. 首页：看标题层级、页眉页脚、段落密度是否正常
2. 一页含图片/表格的正文页：看图题、图片清晰度、是否有裁切或遮挡
3. 一页公式较密集的正文页：看公式换行、编号、留白是否自然
4. 一页附录代码页：看代码块是否越界、字符是否缺失

教师版至少抽查以下页面：

1. 首页：看标题层级、页眉页脚、课堂定位是否清晰
2. 一页核心推导页：看公式与解释是否拥挤
3. 一页图文混排页：看图题、图片缩放和版面平衡
4. 一页板书/课堂组织页：看表格、列表和段落是否过密或越界

### 常见故障与处理

- 缺少 `rsvg-convert`：安装 `librsvg`
- PDF 导出报某个 LaTeX 键无效：先查样式模板是否使用了当前 `xelatex/fvextra/fancyvrb` 版本不支持的参数
- 行内代码出现希腊字母缺字：优先显式指定等宽字体，而不是改正文符号

## 推荐自检问题

- 全文是否始终围绕同一条单元主题逻辑链推进，而不是零散罗列知识点？
- 为了压缩字数而删掉的内容，是否恰好破坏了知识链或能力链的完整性？
- 哪些复杂推导适合放到附录，以保持正文顺畅？
- 学生只看讲义，能否知道“这节课究竟学什么、为什么学、怎么判断自己学会了”？
- 是否同时出现了知识解释与能力训练，而不是只剩定义堆叠？
- 图表是否真的帮助理解，而不只是插图占位？
- 所有关键数值、曲线、结论是否能被 `Octave` 脚本复现？
