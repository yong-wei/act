# Step 3：讲义文档生成规格

> 目标：基于Step 2确认的概念结构，生成完整、高质量的教学讲义。

## 生成前必做

1. 先读取范文：`course-content/authoring/lessons/legacy/L-2a/design/handout.md`
2. 只提炼文风感受，不继承具体内容：
   - 叙述节奏是否平稳
   - 工程引入是否自然
   - 概念解释是否通俗
   - 图表与正文如何配合
   - 小结与过渡如何收束
3. 读取后立刻回到当前单元真实内容，避免复制范文的结构、例题、措辞与论证顺序
4. 禁用词和句式：
   - 钉死，立住，不是……而是，不在于……而在于，以及任何类似的先否定再肯定句式。直接写出事实。
   - 作者态 / 教师态 / 编排态话语，例如“学生应该……”“教师应该……”“本节课的教学目的是……”“这一讲只负责……”“从课程结构看……”“入口课要先把一个动作……”“真正要被学生带走的是……”。
   - 默认不用“学生应该”“教师应该”这类外部指挥口吻；若确需表达规范动作，优先改写为“我们应……”“我们需要……”“应当……”等面向内容本身的书面表达。

## 成文主流程

Step 3 不是“读取约束后直接写讲义”。默认必须按以下三阶段推进：

### 阶段A｜抽取 clean brief

先把上游技能、模块设计、资源采用单和课程边界压缩成 **隐藏版 brief**，只保留：

- 必须讲什么
- 必须出现什么对象 / 模型 / 图表 / 案例 / 证据
- 不能扩张到什么范围
- 目标读者是谁
- 本文最需要完成哪些理解 / 判断 / 迁移动作

这一阶段把所有导出要求、done-when、脚本、验证口径、流程控制都视为 **hidden constraints**，不作为正文句型来源。

### 阶段B｜生成 prose 初稿

根据 clean brief 生成面向学生的 prose 初稿：

- 用自然、连续、书面化的解释组织正文
- 只围绕对象、证据、判断、意义展开
- 不把 clean brief 的清单口吻直接抄进正文
- 不把“本讲/上一讲/下一步/必须产出/交付物”当作段落推进器

### 阶段C｜去污染重写

初稿写完后，必须再做一次去污染重写，逐段检查：

- 这段是在解释对象，还是在解释文档自己
- 这句话是在传递知识，还是在提前自我保护
- 这段像人在讲问题，还是像代理在执行任务
- 是否高频出现“本讲/上一讲/下一步/不能直接/不是……而是……”
- 是否相邻段落围绕同一结论反复打转

若当前上下文里混入大量 harness、superpowers 或技能级流程提示，优先采用“当前代理先抽 clean brief，再由子代理只接收 brief 写 prose”的策略；子代理默认不得继承检查表、流程控制和工单式话语。

## 核心标准

- **独立可读**：讲义必须写成“学生不看课件、不听老师补充，也能基本学懂”的完整文本
- **双重任务**：既讲清知识，也训练能力；至少覆盖“理解、计算/判断、迁移应用”中的多个层次
- **单一逻辑主线**：围绕本次课程目标与当前知识对象组织一条稳定的逻辑链，例如“问题提出 → 关键概念 → 规律/公式 → 判断/计算 → 工程意义”，避免零散堆点
- **证据密度优先**：每个核心知识点都必须落成“知识点 -> 证据 -> 判断 -> 练习”的最小闭环；没有对象、参数、曲线、图块、表格、例题中的至少一种证据，就不算完成讲解
- **篇幅服从完整性**：不对正文做机械字数压缩；为了讲清完整知识链和能力链，可以适当放开篇幅
- **附录分流复杂内容**：过于复杂、但又值得保留的长推导、补充证明、拓展案例、学生复现代码等，可放入附录，不打断正文主线
- **可读性**：逻辑顺、术语稳、通俗但不失严谨，避免堆砌定义
- **多表征**：正文中主动安排配图、表格、对照表、结构图或示意图；图题由导出模板自动生成，表格则在 Markdown 源稿中保留“表序号 + 标题”，导出 PDF 时每个表格都必须转为居中的正式表题与连续编号
- **图题不手写序号**：Markdown 中图片标题只写标题内容本身，不写“图1”等硬编码序号；表格标题则单独保留“表1. 标题”这一行，便于 Markdown 源稿直接阅读，最终 PDF 再转为居中的正式表题，不能缺失序号
- **图示解释不能停留在口头**：凡是用图像解释概念、机理、规律、性能或近似时，正文必须同时给出能与图逐项对照的解析对象，例如系统模型、传递函数、模态展开、时域解析式、幅频特性表达式、性能指标表等；禁止只写“从图上可以看出……”
- **正文引用必须可追溯**：正文中凡引用图、表、公式或文献，必须使用标签 + 交叉引用，不得写死“图1”“表2”“上图”“下图”“上式”“下式”等依赖排版顺序的表述
- **图像形式合规**：图像只能使用代码直出图或 AI 生成图，禁止 ASCII 字符图形
- **可验证**：凡涉及控制系统计算、曲线、性能指标、稳定性判断，必须用 `Octave` 脚本验证
- **优先原生函数**：时域响应、Bode 图、Nyquist 图、根轨迹、频率裕度等，默认优先使用 `step()`、`bode()`、`nyquist()`、`rlocus()`、`lsim()`、`margin()` 等 `Octave` / control 包原生函数，不手写同类底层计算
- **数值图样式统一**：数值类图像的最终排版必须回到 `references/step7-multimedia-codegen.md` 执行，采用“`Octave` 导出数据 + `Python/matplotlib` 最终排版”的统一策略；讲义阶段只定义图像的教学任务，不另起独立出图风格
- **公式统一**：行内公式使用 `$...$`，行间公式使用 `$$...$$`
- **术语统一**：
  - 幅值恰好为 `1`（即 `0 dB`）时对应的频率，统一称为**截止频率**，统一记为 $\omega_c$
  - 相角恰好为 $-180^\circ$ 时对应的频率，统一称为**穿越频率**，统一记为 $\omega_g$
  - 学生版讲义不再把 $\omega_c$ 写成“交叉频率”；若资源原文使用该叫法，成稿时必须统一改写为“截止频率”
  - 相角裕度统一写成“在截止频率 $\omega_c$ 处读取”；幅值裕度统一写成“在穿越频率 $\omega_g$ 处读取”
- **成品化表达**：正式讲义中不得保留“图示建议”“待制作”“占位说明”“脚本验证”等创作过程文本

## 讲义文风与叙述规则

以下规则直接吸收自 `refine` 技能，作为 Step 3 生成学生版讲义时的前置硬约束，而不是留到润色阶段再修补。

### 1. 只写学生真正需要的信息

- 删除或改写作者在解释“这门课怎样设计、这一讲如何编排、教师为什么这样安排”的句子。
- 正文只保留帮助学生理解知识、判断条件、掌握方法、建立迁移的内容。
- 禁止把课程组织语言直接写进学生讲义，例如：
  - “本节课的教学目的是……”
  - “这一讲真正要做的是……”
  - “真正要被学生带走的是……”
  - “教师要追问……”
  - “从课程结构看……”

### 2. 统一使用书面化的“我们”视角

- 学生版讲义默认使用“我们”作为主导视角，必要时可少量使用“你”做提醒。
- 禁止使用“您”。
- 禁止使用“学生应该……”“教师应该……”“老师带着大家……”等作者态 / 教师态 / 指挥态表达。
- 若需要表达方法要求、判断要求或规范动作，优先写成：
  - “我们应先确认……”
  - “我们需要比较……”
  - “此处应当区分……”
  而不要写成：
  - “学生应该先确认……”
  - “教师应该在这里强调……”

### 3. 直接陈述事实，不写绕行对比句

- 除非确有必要做概念辨析，否则不要高密度使用“不是……而是……”“不在于……而在于……”“先不……而是……”。
- 优先把结论直接写成正面陈述句。
- 若一句话可以直接写成“本课的产出是……”“这里的关键是……”“这个量表示……”，就不要再绕成否定后转折。

### 4. 口头动作词一律收紧为书面表达

- 禁止高频使用这类口头动作词：`立住`、`钉住`、`钉死`、`压住`、`压成`、`压实`、`回收`、`接走`、`写浅一层`。
- 优先替换为更直接的书面词：
  - `明确`
  - `写清`
  - `概括为`
  - `整理为`
  - `归纳为`
  - `作为后续输入`

### 5. 每段只完成一个功能

- 每段优先只承担一个明确任务：给出结论、解释原因、呈现证据、比较对象、提醒误区。
- 不要在同一段里同时做“讲知识 + 讲教学安排 + 预告后文 + 防御误解”四件事。
- 长段优先改写成“结论句 + 解释句 + 证据句”的短段结构。

### 6. 结论前置，标题承担信息

- 段落顺序优先采用“先结论，后原因，再例子或证据”。
- 标题已经表达主旨时，正文第一段直接解释内容，不再用近义句重复同一主旨。
- 不要把真正有用的信息埋在段末、转折句后半截或多层铺垫之后。

### 7. 少用防御性修辞和课堂推进口吻

- 普通正文中慎用“不要急着……”“先别……”“不能直接……”“这并不意味着……”。
- 这些句式只适合放在明确的误区辨析处，不应成为整篇讲义的默认腔调。
- 讲义是学生自读文本，不是课堂口播稿；少用“接下来我们先……”“到这里……”“这一讲先……”“我们还要再把一个边界……”等课堂推进语。

### 8. 避免围绕同一结论反复打转

- 同一结论在相邻段落中只完整表达一次；后文若需再提，只做推进论证所需的简短回指。
- 不依靠重复口号制造推进感。
- 检查相邻段落是否在重复同一主张，例如“同图异读”“任务排序会改变”“先守底线，再争收益”等；若重复，则压缩为一次完整表达。

### 9. 快速自检

生成学生版讲义后，至少复核以下问题：

- 是否仍出现作者态 / 教师态 / 编排态话语？
- 是否仍出现“学生应该……”“教师应该……”这类外部指挥句？
- “我们”是否成为主导视角？
- 是否仍有高密度“不是……而是……”结构？
- 是否仍保留“立住 / 钉死 / 压实 / 回收”等口头动作词？
- 每节开头是否能直接看出本节重点？
- 相邻段落是否围绕同一结论反复绕写？
- 引入和正文主体段落是否滥用课次编号，而没有优先使用概念名、任务名或对象名？

### 10. 前后课程关系只做弱提示

- 学生版讲义可以交代前置知识、当前位置与后续去向，但这类信息默认只放在“课次信息节”或“本节小结”中。
- 正文主线必须由“问题、对象、方法、案例、练习”驱动，不得由“上一讲 / 下一讲 / 本单元在课程中的位置”驱动。
- 允许在确有必要消除歧义时补充一次课次编号，但优先采用“上一轮建立的频域判断”“后续的首次验证”“下一步的参数比较”这类概念化表述。
- 若前后课程关系在正文中出现超过一次，默认视为结构失衡，应回退重写引入与总结。

### 11. hidden constraints 不进入正文

- PDF 导出、媒体占位、脚本验证、资源采用单、技能切换、运行时同步等要求，只作为 hidden constraints 存在。
- 除非文档本身正在说明使用方法，否则这些要求不得在学生版 prose 中直接出现。
- 教师版也只保留课堂组织真正需要的说明，不把“完成态检查”“导出前确认”“后续流程安排”写成正文。

## 讲义标准结构

根据知识类型 `[C/X/D]` 调整各章节权重，但学生版讲义默认都要围绕“问题、证据、判断、练习”闭环展开。

在正式正文前，默认包含以下前置信息区：

1. 标题
2. 课次信息节（课型、学时、知识类型、前置/后续位置等）
3. **封面图片占位**
4. **信息图占位（附录前）**

其中，**课次信息节**默认遵守以下硬约束：

- 学时固定写为 `90分钟`
- “前置”优先写当前主线课程中的前置知识，不写 `legacy` 课程编号或来源说明
- “讲义定位”只写这份讲义帮助学生解决什么问题、获得什么能力，不写课程设计职责说明
- “后续”只作弱提示，最多 1 行，不得把后续课次写成正文主线

推荐写法示例：

```markdown
- 学时：90分钟
- 前置：已掌握二阶系统的标准形式、典型性能指标与基本结构图含义
- 讲义定位：这份讲义将带你判断频率响应如何映射到图形对象，并完成首次粗粒度读图。
```

封面图片占位必须放在“讲义信息节”之后、“问题引入”之前，默认使用如下引用形式：

```markdown
![封面漫画：单元导入](../media/processed/[单元编号]-cover-comic.png)
```

后续媒体制作完成后，直接按该占位文件名回写，即可在 Markdown 与 PDF 中正常显示；不要在讲义完成后再临时改结构腾位置。

封面漫画在 Step 3 默认**只产出提示词文件** `media/raw/[单元编号]-cover-comic-prompt.md`，不要求在讲义起草阶段立即生成 `[单元编号]-cover-comic.png`。讲义正文保留图片占位，待图片制作完成后再回写并导出正式 PDF。若交付的是中文定稿提示词，其首句必须固定为“以哆啦A梦中的人物为原型”，且后续整段设计都要保持该系列漫画画风。

若讲义正文已经成文、需要先导出一版 PDF 供 NotebookLM 或后续封面/信息图制作使用，而 `[单元编号]-cover-comic.png` 尚未回写，则必须使用：

```bash
python3 .codex/skills/lesson/scripts/export_handout_pdf.py \
  --draft-mode \
  course-content/authoring/lessons/[单元编号]/design/handout.md
```

该命令只会在临时目录生成导出占位图，并输出 `handout-draft.pdf`；不得为了让第一次导出跑通而在 `media/processed/` 下手工生成或脚本渲染假的 `cover-comic.png`。

封面漫画默认按 **4 格或 6 格多格漫画** 编写提示词，不得写成单张大图式海报描述。正文必须逐格展开，至少写出 `第1格 / 第2格 / 第3格 / 第4格`，每格单独说明场景、角色动作/表情、关键道具和一句简短中文台词。详细硬约束与逐格样例统一见 `references/step7-multimedia-ai.md`。

---

在正文结束、附录开始之前，固定预留信息图占位：

```markdown
![本讲信息图总结](../media/processed/[单元编号]-info.png)
```

`[单元编号]-info.png` 默认不要求在 Step 3 同步生成提示词；讲义先保留占位，待后续多媒体制作或人工制作完成后再回写并导出最终 PDF。若首次只需导出草稿 PDF，同样使用 `--draft-mode`，不得在 `media/processed/` 中写入假的 `info.png`。

### 学生版正文固定骨架

学生版讲义默认按以下顺序组织；课次边界与编号约束继续作为内部依据静默执行，不进入面向学生的显式文本：

1. **问题 / 任务引入**
2. **本次课程目标**
3. **原理主线讲解**
4. **锚点案例精讲**
5. **最小例题**
6. **分层练习**
7. **特殊情况 / 边缘情况**
8. **总结与扩展思考**

若缺少“锚点案例、最小例题、分层练习”中的任意一项，默认判定为结构不完整，不进入导出阶段。

### 3.1 问题 / 任务引入

- 必须从一个典型、明确的问题或任务开篇，而不是先大段回顾上一课
- 引入中要指出：前置知识能够解决什么、仍有哪一块没有覆盖到
- 开头优先使用对象名、任务名、现象名，不用课次编号组织段落
- 篇幅以把问题讲清为准；至少需要 1 个情境问题
- 优先配置 1 张引入图或 1 个场景表，使学生先进入问题情境，而不是直接进入定义罗列

### 3.2 本次课程目标

- 只显式列出本次课程目标，不额外解释单元边界、课次定位或课程接口
- 目标必须写成 3-5 条布鲁姆动词能力项，推荐使用“识别 / 解释 / 计算 / 判断 / 比较 / 设计 / 迁移 / 评估”等可观察动词
- 每条能力项都要落在本次课程已经提供的对象、证据和方法上，不能写成空泛口号
- 表述统一采用“完成本次课程后，学习者能够……”的句式或与之等价的单列表达
- 若需提示后续，只允许用 1 句说明“这些能力将支持后续哪类分析、判断或设计任务”，不得展开课程编排说明

### 3.3 原理主线讲解

每个核心知识点都必须落成“知识点 -> 证据 -> 判断 -> 练习前导”的四联体。

#### [C] 计算型内容要求

- 给出严格的数学定义和推导过程
- 标明计算步骤（Step 1→2→3→...）
- 提供典型数值示例，验证计算过程
- 指出常见错误和边界情况
- 对所有计算结论，用 `Octave` 补做数值或曲线验证
- 若图像承担解释任务，必须把“图像现象”和“解析表达”显式对照

#### [X] 跨域型内容要求

- 明确指出两个领域之间的映射关系（A域→B域）
- 给出直觉性解释和定量关系
- 至少有 1 处图表或对照表，把“概念对应关系”可视化
- 提供一个可直接复述的小例子或小判断题，防止停留在抽象映射口号

#### [D] 设计型内容要求

- 以工程任务为驱动（给定目标和约束）
- 展示至少两个候选方案及其比较依据
- 必须给出一个“首轮起步”或“最小计算切片”，不能只给结构口号
- 对方案对比结果，优先使用表格呈现评价维度、优点、风险与适用场景
- 边界、代价和“不选另一个方案的原因”必须说清

### 3.4 锚点案例精讲

- 每讲至少 1 个锚点案例，且必须在正文中被重复调用，不得只出现在引入
- 锚点案例至少包含下面一项具体证据：模型、参数、曲线、图块、表格
- 案例讲解要回答：
  - 当前对象的现状证据是什么
  - 前置知识在哪一步不够用
  - 本课方法怎样补上这一步
  - 判断结论是什么

### 3.5 最小例题

- 每讲至少 1 道最小例题，优先 1 道即可把闭环走完整，再决定是否加第 2 道
- 例题结构固定为：题目陈述 → 解题思路 → 详细求解 → 结论与工程意义
- [D] 型例题允许以“最小设计切片”形式出现，例如只判断首选结构、参数方向和预期代价，不强求展开完整整定
- 若例题适合学生自行复现，可在正文中点名 MATLAB/Octave 文件名，并把最基本 MATLAB/Octave 代码放入附录；不要在正文单列“脚本验证”小节

### 3.6 分层练习

- 每讲至少 3 道练习，分别覆盖：
  - 复述型：能否复述本课结论
  - 判断型：能否根据新证据做出判断
  - 迁移型：能否把判断链迁移到新对象
- 练习必须与正文锚点案例或最小例题有直接对应关系
- 不允许只给泛泛而谈的思考题

### 3.7 特殊情况 / 边缘情况

- 若本课存在特殊情况、反例、失败情形或近似失效边界，应单列讨论
- 讨论必须结合具体案例、图表、习题或参数变化，不做空泛提醒
- 若本课确实没有值得单列的边缘情况，可省略本节，但要确认不是因为正文把边界全删掉了

### 3.8 总结与扩展思考

- 用 3-5 条核心要点总结本课
- 总结优先回收“问题是怎么被解决的、能力是怎么获得的”
- 若需提示后续用途，只保留一句对象层面的应用指向，不写单元边界或课程接口
- 若需设置扩展思考，应与本课案例或判断链直接相关，而不是重复写课程过渡说明

### 3.9 AI 练习位置

- 学生版正文不再强制插入 `[AI融入点]`
- 如需保留 AI 练习，默认放在章末“自学建议 / 练习”区，或放入教师版课堂讲义
- AI 练习仍需遵守“学生先独立判断 -> 再让 AI 质疑或验证 -> 最后回到证据复核”的顺序

### 3.10 附录（按需生成）

- 适用内容：复杂推导、补充证明、拓展案例、长表、MATLAB/Octave 复现代码、额外练习
- 原则：附录服务正文，不喧宾夺主；正文仍需独立可读
- 若正文中省略了部分长推导，必须明确标注“详见附录 X”

## 图片、表格与验证脚本要求

1. 至少安排以下其一：
   - 1 张结构/关系示意图 + 1 张响应/规律图
   - 1 张示意图 + 2 张表格
   - 3 张以上图表混排
2. 图表不能只是“装饰”，必须承担解释任务：
   - 图：帮助学生看出结构、趋势、机制或现象
   - 表：帮助学生做对比、归类、记忆或判断
3. 每幅图、每张表都要有正式编号与题名，不得用“图示建议”“待制作”等过程性说明替代；图题编号由导出模板自动生成，表格则在 Markdown 源稿中单独写“表1. 标题”这一行，导出 PDF 时必须转成**居中的正式表题与连续编号**。
4. 封面图与课末信息图固定按正文版心全宽导出；其余图片默认必须根据图中文字与正文的视觉字号关系单独设置 `width=...`，不要把所有图都机械地扩展至整行宽度。
5. 线框图、方框图、结构图若图中文字明显偏大，应优先缩小图片宽度；数据图、响应图若在接近全宽时图中文字仍偏小，应回到成图脚本调整原图文字大小，不得仅靠 PDF 拉伸补救。
6. 讲义中的引入语、追问句、核心提醒若用 `>` 表示，则默认会在 PDF 中被渲染为浅底色提示块；写作时应保持句子简洁，不要把整段正文都放入提示块。
7. 若图表在正文中被用于解释概念、规律或比较结论，则正文必须同步出现对应的解析支撑，至少满足以下之一：
   - 图对应明确系统模型或传递函数；
   - 响应曲线对应显式时域表达式、模态展开或性能指标表；
   - 频域曲线对应幅频/相频表达式、转折频率、带宽或近似计算说明；
   - 对比图对应明确的比较维度与数值结论。
8. 正文引用图、表、公式或文献时，必须使用规范交叉引用，不得写“上图 / 下图 / 下表 / 上式 / 图1 / 表2”这类硬编码位置词或序号词。
9. 当前 Markdown 讲义推荐采用以下标签约定：
   - 图：`{#fig:lesson-topic}`
   - 表：`{#tbl:lesson-topic}`
   - 公式：`\label{eq:lesson-topic}`
   - 文献：BibTeX / CSL 键，如 `[@zhou2024]`
10. 若需要对公式做正文交叉引用，允许对该公式使用原生 LaTeX `equation` / `align` 环境并配 `\label{}`；这是相对 `$$...$$` 的受控例外，目的是保证 PDF 中的可引用编号稳定。
11. 涉及计算的讲义，默认生成对应 `Octave` 验证脚本并保存到本课媒体原始目录或等价验证目录；该验证过程不直接暴露为讲义正文内容。
12. 默认优先调用 `Octave` / control 包原生高层函数完成出图和核验，例如 `step()`、`bode()`、`nyquist()`、`rlocus()`、`lsim()`、`margin()`；若原生函数不足以覆盖需求，必须先说明缺口，再补充必要的自定义计算。
13. 若该图属于响应曲线、根轨迹、Bode/Nyquist、参数扫描、稳定域或其他数值类图像，其最终排版必须回到 `references/step7-multimedia-codegen.md` 的数值图像约束，不得在讲义阶段另起一套与多媒体规范不一致的出图样式。凡根轨迹转入 `Python/matplotlib` 复绘，必须先经过 `.codex/skills/lesson/scripts/root_locus_branch_match.py` 处理。
14. 若讲义中使用跨域 `2×2` 图，默认子图顺序为“时域响应、根轨迹、幅频图、相频/裕度图”，且子图标题只写基本标题，不写“左上/右上/左下/右下”等方位提示。
15. 若根轨迹存在全范围与关键区域两个明显尺度，讲义可采用异尺度多联版式；但必须在正文中同步解释每个子图在原图中的位置、各自承担的判断任务，以及为何不能互换阅读顺序。
16. 若正文借助根轨迹解释设计判断，至少要同步交代开环极点/零点分布、关键闭环极点迁移趋势，以及它与时域性能或频域指标之间的对应关系；禁止只写“从根轨迹可以看出……”
17. 若需要学生复现，正文只给 `.m` 文件名提示，最基本 MATLAB/Octave 代码放附录，不加入复杂的版式或格式控制命令。
18. 讲义中给出的参考代码，默认统一采用 MATLAB/Octave 形式，不混入 Python、JavaScript 或其他语言示例。
19. 若图像在 PDF 中出现以下任一现象：全宽后仍裁切、右侧/顶部说明框被截断、图例/标注落在版心外、图中文字与正文字号明显失衡，则默认判定为**脚本外问题**，必须回到成图脚本或源 SVG/PDF 修复边界框、边距、字号和布局；不要继续依赖 PDF 导出链路强行缩放补救。
20. 需要单独控制大小的中间图片，必须直接在 Markdown 图片行上显式写出 `width=...`；讲义参考文件应记录这类经验，避免后续同类课次再次把所有图机械地按自然尺寸或整行宽度导出。
21. 表格必须有表头；不允许用“无表头纯数据块”代替正式表格。即使只有两列，也应写出列名。
22. PDF 导出后的表格列宽应主动调整并尽量充分利用页心宽度，优先让长文本列获得更多宽度；若出现第一列过宽、后续列被挤窄导致过度折行，或整张表未能铺开页心而显得局促，应优先调整导出模板或预处理脚本中的列宽分配，而不是在 Markdown 里插入生硬换行。

## Step 3 的双阶段讲义流程

Step 3 不再只包含学生版讲义，而是固定分成两段：

1. **学生版讲义阶段**
   - 先完成 `handout.md`
   - 同步补齐 `cover-comic-prompt.md`，并确认 `cover-comic.png` 与 `info.png` 的占位路径已固定
   - 经用户确认且所需图片已回写后，导出 `handout.pdf`
   - 抽样检查 PDF 版面
2. **教师版课堂讲义阶段**
   - 只有在学生版讲义与学生版 PDF 都通过确认后，才开始 `teacher-handout.md`
   - 教师版讲义经用户确认后，导出 `teacher-handout.pdf`
   - 再次抽样检查教师版 PDF 版面

两份 PDF 必须共用同一技能模板，不允许学生版和教师版各自演化成不同风格。

## 教师版课堂讲义要求

教师版课堂讲义固定文件名为 `teacher-handout.md`，用途是 90 分钟课堂教学，不替代学生版讲义。

教师版课堂讲义默认按**课堂流程**组织，而不是按学生自学正文组织。目标是给教师一份可直接用于课堂推进的讲义骨架：保留主线、关键话术、必要公式推导、图示调用与板书顺序，不追求学生版那种完整展开。

### 教师版必须包含

- 按 90 分钟课堂顺序编排的分段结构
- 与上一课、本课、下一课的关键衔接语
- 本节唯一主线及课堂收束语
- 90 分钟课堂时间分配建议
- 必须保留的核心推导
- 建议板书内容
- 课堂需要调用、复用或补画的图形
- 教师提醒：哪里可略、哪里必须强调、哪里容易误判

### 教师版写法硬约束

- 讲义应按“开场桥接 -> 核心推进 -> 例题/对照 -> 收束铺垫”的课堂流程展开，每段只保留基本逻辑框架和关键文本，不展开成长篇学生讲解稿
- 图示、公式推导、板书和例题必须按课堂实际使用顺序插入，教师在翻页过程中应能直接按顺序讲解，不需要再次排布
- 教师版可以引用必要的正式媒体，但**不包含**面向学生版首页导入的封面漫画和讲义末尾信息图
- 教师版中的公式推导应只保留课堂上必须写、必须讲、必须提醒的版本；较长推导可压缩成“讲到哪一步为止 + 详细过程见学生版/附录”
- 教师版默认不是摘要目录，也不是全文复刻；它应当比学生版短得多，但仍能支撑教师完整完成一节课
- 教师版中的“关键文本”优先写成教师可直接使用的桥接语、追问句、收束句和误区提醒，而不是再重复一遍学生版解释段落

### 教师版不应变成

- 学生版讲义的全文复制
- 只有时间表和项目符号的授课提纲
- 脱离学生版真值来源的另一套内容体系
- 把封面漫画、讲义信息图等学生导入型资源照搬进教师版

### 教师版与学生版的关系

- 学生版负责“学生自学可读的完整知识链与能力链”
- 教师版负责“课堂组织、讲授优先级、板书和图形调度”
- 教师版只能压缩、抽取、重组学生版中的核心内容，不能改写事实口径或引入未核验的新数据

## Markdown 转 PDF 导出规范

学生版讲义与教师版课堂讲义完成后，都要导出同目录 PDF，作为正式交付的一部分。

### 默认工具链

- `pandoc`
- `xelatex`
- `rsvg-convert`（保证 Markdown 中的 SVG 图片可直接嵌入 PDF）

### 交叉引用写法规范

- PDF 成品中的图、表、公式、文献引用，默认都应从源 Markdown 中的标签生成，而不是在正文里手工写死编号。
- Markdown 源稿中的表格默认可写成“表1. 标题”后接 pipe table；若该表需要在正文中稳定交叉引用，推荐写成 `表1. 标题 {#tbl:lesson-topic}`，导出脚本会将其转为 PDF 中**居中的正式表题**与 `\label{}`。
- 推荐写法：

```markdown
![主导极点近似何时可靠的时域对照图](../media/processed/3-1-pp-03-dominant-pole-response-families.svg){#fig:dominant-step}

见图~\ref{fig:dominant-step}，可以把附加极点位置和阶跃响应形态逐一对应起来。
```

```markdown
\begin{equation}
M_p=e^{-\frac{\pi\zeta}{\sqrt{1-\zeta^2}}}\times 100\%
\label{eq:overshoot}
\end{equation}

由式~\ref{eq:overshoot} 可得标准二阶系统的超调量。
```

- 表格若需要在正文中被引用，也必须提供表标签；若当前 Markdown 表语法不便直接绑定标签，应使用能稳定附着 `#tbl:` 标识的 Pandoc 表格写法，或退回原生 LaTeX `table` 环境。
- 文献引用使用文献键，例如 `[@zhou2024]`，不要直接写“参考文献[1]”或“文献1”。
- 若当前导出链路暂未自动解析某类交叉引用，仍应优先保留标签与 `\ref{}` / `\cite{}` 兼容写法，不允许回退到“下图”“上式”等不稳定表述。

### 常见故障与处理

- 缺少 `rsvg-convert`：安装 `librsvg`
- `pdftoppm` 不支持 `-png/-jpeg`：不要继续手工试错，直接改用 `render_pdf_review_pages.py`
- PDF 导出报某个 LaTeX 键无效：先查样式模板是否使用了当前 `xelatex/fvextra/fancyvrb` 版本不支持的参数
- 行内代码出现希腊字母缺字：优先显式指定等宽字体，而不是改正文符号

- 学生只看讲义，能否知道“这节课究竟学什么、为什么学、怎么判断自己学会了”？
- 是否同时出现了知识解释与能力训练，而不是只剩定义堆叠？
- 图表是否真的帮助理解，而不只是插图占位？
- 所有关键数值、曲线、结论是否能被 `Octave` 脚本复现？
