# Step 7：多模态资源设计总入口

> 目标：扫描讲义和互动课设计文档，识别所有需要媒体支撑的位置，按资源类型和用途输出制作规格，并在完成后将引用路径回写到对应文档中。

**总约束**：所有正式图像都必须是代码直出图或 AI 生成图；ASCII 字符图、字符框图、字符波形只能作为临时草稿，不能进入最终交付文档。

**数值图像统一约束**：响应曲线、Bode/Nyquist、根轨迹、稳定域、参数扫描等数值图像统一采用“Octave 导出数据 + Python/matplotlib 最终排版”两段式流程；`3-6` 单元的数值图风格是默认基线，后续单元不得各自发明新风格。

**媒体链接文档约束**：每个单元在多媒体阶段都必须于 `course-content/authoring/lessons/<unit>/media/processed/` 下确保存在 `<unit>-media.md`。该文档只做初始化模板，不做内容整理。若文件不存在，创建 5 个固定节：`<unit>-intro-video.mp4`、`<unit>-slides.pdf`、`<unit>-course.mp4`、`<unit>-audio.m4a`、`handout.md`；除 `intro-video.mp4` 节写 1 句导入视频简介外，其余节一律留空，不填写标题、摘要、占位说明或 URL。若文件已存在且已有任何人工内容，则不得覆盖、追加、改写、重排或规范化；即使导入视频节已有内容，也不得再追加主题句。

## 本文件负责什么

- 统一说明多媒体阶段的总工作流
- 统一说明资源分类、文件命名和回写规则
- 指引后续应读取哪一份“代码直出媒体”或“AI 生成式媒体”参考

## 继续读取哪些参考文件

- 若资源属于响应曲线、Bode/Nyquist、根轨迹、参数扫描、结构图、电路图、机械结构图或互动前端绘制：
  - 读取 `references/step7-multimedia-codegen.md`
- 若资源属于封面漫画、工程场景位图、讲义信息图、导入视频、课程视频、课程音频、即梦提示词：
  - 读取 `references/step7-multimedia-ai.md`
- 若资源属于代码直出图、TikZ 线框图无法充分表达的生成式图像，例如场景导入、具体对象、实物/设备意象、类比解释、框图中的具象对象嵌入：
  - 同时读取 `imagen` 技能，使用 GPT Image 2 生成图片，并保存同名提示词文件

同一单元通常会同时用到两份参考文件，不要只读其一就结束。

## 默认新增媒体（理论课优先考虑）

除常规图表、结构图、代码直出图外，理论课默认还应规划：

- 讲义封面漫画提示词：`[单元编号]-cover-comic-prompt.md`
- 15 秒导入视频提示词：用于后续生成 `[单元编号]-intro-video.mp4`
- 讲义信息图成品占位：`[单元编号]-info.png`
- 课程级后续审查占位：
  - `[单元编号]-slides.pdf`
  - `[单元编号]-course.mp4`
  - `[单元编号]-audio.m4a`
- 媒体链接文档：
  - `[单元编号]-media.md`

媒体制作阶段的硬交付边界如下：

- 必做：代码直出图、TikZ 线框图、互动前端绘制需求、`cover-comic-prompt.md`、导入视频提示词。
- 必做：在 `media/processed/` 下确保存在 `[单元编号]-media.md`；仅在文件不存在时初始化 5 节模板，除导入视频节写 1 句简介外，其余节保持空白。已有内容的文件一概不改。
- 仅登记待审查占位：`cover-comic.png`、`intro-video.mp4`、`info.png`、`slides.pdf`、`audio.m4a`。
- 上述待审查占位由用户后续完成成品后，在审查阶段确认可用性。
- `cover-comic.png` 与 `info.png` 属于**保留资产文件名**：代码直出脚本、数值图渲染脚本和批量复绘脚本不得把它们作为输出目标。若需要在图片未回写前先导出讲义，只允许通过 `export_handout_pdf.py --draft-mode` 在临时目录生成占位图，不得向 `media/processed/` 回写伪造图片。

## 资源分类体系

### 维度一：用途

| 前缀 | 用途 | 引用目标文档 |
|------|------|-------------|
| `h`  | 讲义专用 | `design/{unit}-handout.md` |
| `ic` | 互动课专用 | `design/{unit}-interactive-page.md` |
| `sh` | 讲义与互动课共用 | 两处均引用 |
| `cd` | 卡片专用 | `authoring/knowledge/cards/nodes/<node_id>.md` |

> **跨媒介复用原则**：讲义、互动课、知识卡片可复用同一媒体文件。`sh` 前缀表示讲义+互动课共用；若卡片也复用讲义图像，不新建文件，只在 `card-media-plan.md` 的"可复用自"列注明。

### 维度二：生成方式

| 类型 | 判断标准 | 输出内容 |
|------|----------|----------|
| **代码直出图** | 响应曲线、根轨迹、Bode图、各类参数曲线、稳定域、参数扫描图等可计算生成的图形 | 图片内容描述 + `Octave` 数据导出脚本 + `Python/matplotlib` 排版脚本 |
| **TikZ 线框图** | 方框图、信号流图、电路图、机械结构图等结构类线框图 | 图片内容描述 + `tikz-control-draw` 生成要求 |
| **位图（AI生成）** | 原理示意图、工程场景图、实物/设备图、类比解释图、具象对象嵌入图等无法代码直出的图像 | 中文场景描述 + 中文定稿提示词；适宜时调用 `imagen` 直接生成成品图并保存同名提示词 |
| **互动前端绘制** | 互动课中需要随参数变化实时更新的图表（有交互价值） | 前端绘制需求描述（不产生媒体文件） |
| **视频** | 课堂开场或互动课首页使用的动态导入/演示内容 | 中文内容描述 + 中文定稿提示词 |

> **互动课静态图判断规则**：若某图在互动课中无需随参数动态变化，按"代码直出图"、"TikZ 线框图"或"位图"处理，不另起前端绘制需求。

> **本技能补充规则**：讲义封面漫画归入“位图（AI生成）”，15 秒导入视频归入“视频”。两者都属于优先级较高的单元导入媒体，而不是普通装饰素材。

## 文件命名规则

```
{单元编号}-{用途前缀}-{两位序号}-{简短描述}.{ext}

示例：
  2-1-h-01-step-response-family.m          ← 讲义用，代码直出，Octave 源文件（→ raw/）
  2-1-h-01-step-response-family.svg        ← 对应产出图（→ processed/）
  2-1-h-02-ship-bridge-scene.png           ← 讲义用位图（原始 → raw/，处理后 → processed/）
  2-1-ic-03-bode-plot-static.m             ← 互动课用静态图，代码直出
  2-1-sh-04-second-order-block-diagram.png ← 讲义与互动课共用方框图（由 tikz-control-draw 生成）
```

存储路径：`course-content/authoring/lessons/<unit>/media/`
- `raw/`：`Octave` 源文件、AI 生成原始图、录屏母版等
- `processed/`：产出的 .svg/.png，裁剪/压缩后可上线的版本

**命名硬约束：**
- 所有最终媒体文件都必须统一带单元前缀，即都以 `<unit>-` 开头。
- `h` / `ic` / `sh` / `cd` 这类用途前缀仍保留，但位于单元前缀之后，作为第二层命名信息。
- 媒体阶段登记的待审查成品占位也必须遵守同一规则，例如：
  - `<unit>-cover-comic.png`
  - `<unit>-info.png`
  - `<unit>-slides.pdf`
  - `<unit>-intro-video.mp4`
  - `<unit>-course.mp4`
  - `<unit>-audio.m4a`

互动前端绘制需求**不产生媒体文件**，只在 `design/{unit}-interactive-page.md` 对应步骤中描述。

若讲义中的证据单元属于可调参数曲线图，则默认视为“互动前端绘制需求”，并额外满足以下镜像约束：
- 互动图必须是讲义静态图的“可调镜像”，而不是另起一张新图。
- 默认参数、默认结构组合、默认曲线数量与讲义静态图完全一致。
- 静态图若为 `2×2` 图组，互动图默认仍为 `2×2` 图组，仅允许为窄屏做响应式重排。
- 控件栏默认位于图组下方并折叠显示，不得挤占主证据区。

## 工作流

### 1. 扫描阶段

**同时**读取以下三类内容，识别所有媒体插入点：
- `design/{unit}-handout.md`（讲义）
- `design/{unit}-interactive-page.md`（互动课设计）
- `course-content/authoring/knowledge/cards/lessons/<unit>/sequence.json` 与其引用的 `course-content/authoring/knowledge/cards/nodes/<node_id>.md`（若已进入互动设计或 Step 4 已登记 `card-media-plan.md`，直接读取；若 sequence 尚未定稿，只扫描已存在的卡片草案，不把卡片顺序当作媒体引用真源）

扫描结果输出为统一资源总表，与用户确认优先级。**同一图像在多处引用时只列一行，"引用于"列注明所有引用位置**：

```
| 编号 | 用途前缀 | 简短描述 | 生成方式 | 引用于 | 优先级 |
|------|----------|----------|----------|--------|--------|
| 01   | sh       | ...      | 代码直出 | handout §2.1 / 卡片：复平面可行域首页 | P1 |
| 02   | h        | ...      | 代码直出 | handout §4例题1 | P1 |
| 03   | cd       | ...      | TikZ 线框图 | 卡片：设计可行域首页（无讲义复用） | P2 |
| ...  |          |          |          |        |        |
```

扫描时，优先检查以下两个提示词位是否已经被规划：

- `h-cover`：学生版讲义封面漫画提示词（对应后续成品 `cover-comic.png`）
- `ic-intro-video` 或 `sh-intro-video`：15 秒导入视频提示词（对应后续成品 `intro-video.mp4`）

### 2. 逐项生成阶段

用户确认优先级后，按序逐项输出完整制作规格（见下方格式）。

对 AI 位图执行以下判断：
- 若只是规划封面漫画、导入视频或课末信息图占位，按 `step7-multimedia-ai.md` 交付提示词或占位要求即可。
- 若讲义正文已经需要一张具体图片支撑阅读，且该图片不适合由 Octave/Python/TikZ 制作，调用 `imagen` 生成成品图。
- `imagen` 输出应先落在其默认或用户指定目录，再按本课媒体命名规则复制或登记到 `media/raw/` 与 `media/processed/`，同时保留 `.prompt.md`。
- 生成式图片不得替代可验证的数值图。凡涉及响应、裕度、稳定性、参数扫描等结论，仍必须由 Octave/Python 完成数据和曲线。

### 3. 回写阶段

所有资源规格输出完毕后，将引用路径插入对应文档的对应位置：
- 格式：`![图注](../media/processed/{文件名})`（Markdown 图片引用）
- 互动前端绘制需求：在 interactive-page.md 对应步骤的「资源」栏补充 `[前端绘制]` 标注

同时在 `media/processed/{unit}-media.md` 中确保存在以下 5 个标准节名：

1. `{unit}-intro-video.mp4`
2. `{unit}-slides.pdf`
3. `{unit}-course.mp4`
4. `{unit}-audio.m4a`
5. `handout.md`

回写该文档时遵守以下边界：
- 只在 `<unit>-media.md` 不存在时执行初始化；文件已经存在且已有任何正文、链接、备注或人工标题时，不得修改。
- 初始化模板只包含 5 个标准节名和导入视频节 1 句中文简介；不得为 `slides.pdf`、`course.mp4`、`audio.m4a`、`handout.md` 填写任何说明文字、摘要、占位句或 URL。
- 导入视频简介必须压缩自导入视频提示词的主线情节，直接描述视频中的对象、动作、冲突或对比结果。
- 禁止写“用导入情境引出……”“围绕……展开”这类抽象句式。
- 禁止为已有文件补主题句、补讲义摘要、规范标题顺序、移动链接位置或清理旧内容。

## 工具选用指南

| 资源类型 | 推荐工具 | 说明 |
|----------|----------|------|
| 响应曲线、Bode图、根轨迹、参数曲线 | `Octave` + `Python/matplotlib` | `Octave` 负责数据导出，`Python/matplotlib` 负责最终排版；字体、线型、网格、颜色、留白和摘要框风格都以 `3-6` 单元为统一基线 |
| 框图、信号流图、电路图、机械结构图 | `tikz-control-draw` | 专用线框图流程 |
| 工程场景图、设备实物图、类比解释图、具象对象嵌入图 | `imagen` | GPT Image 2 位图；用于代码直出和 TikZ 难以表达但能提升理解体验的视觉资产，必须保存图片和同名提示词 |
| 封面漫画 | 即梦 / Midjourney / DALL-E / `imagen` | 位图，媒体阶段默认先交提示词；若用户要求直接生成，可调用 `imagen` |
| 动态演示视频 | `seedance` | lesson 技能中的课程视频与导入视频默认统一走 `seedance` Agent 模式 |
| 实时交互图表 | Recharts / Canvas / D3 | 前端绘制，无媒体文件 |
