# Step 7：多模态资源设计总入口

> 目标：扫描讲义和互动课设计文档，识别所有需要媒体支撑的位置，按资源类型和用途输出制作规格，并在完成后将引用路径回写到对应文档中。

**总约束**：所有正式图像都必须是代码直出图或 AI 生成图；ASCII 字符图、字符框图、字符波形只能作为临时草稿，不能进入最终交付文档。

## 本文件负责什么

- 统一说明多媒体阶段的总工作流
- 统一说明资源分类、文件命名和回写规则
- 指引后续应读取哪一份“代码直出媒体”或“AI 生成式媒体”参考

## 继续读取哪些参考文件

- 若资源属于响应曲线、Bode/Nyquist、根轨迹、参数扫描、结构图、电路图、机械结构图或互动前端绘制：
  - 读取 `references/step7-multimedia-codegen.md`
- 若资源属于封面漫画、工程场景位图、讲义信息图、导入视频、课程视频、课程音频、即梦提示词：
  - 读取 `references/step7-multimedia-ai.md`

同一单元通常会同时用到两份参考文件，不要只读其一就结束。

## 默认新增媒体（理论课优先考虑）

除常规图表、结构图、代码直出图外，理论课默认还应规划：

- 讲义封面漫画：`[单元编号]-cover-comic-prompt.md` / `[单元编号]-cover-comic.png`
- 15 秒导入视频：`[单元编号]-intro-video.mp4`
- 讲义信息图：`[单元编号]-info.png`
- 课程级默认成套媒体：
  - `[单元编号]-slides.pdf`
  - `[单元编号]-course.mp4`
  - `[单元编号]-audio.m4a`

若某项不适合当前单元，需在 `multimedia.md` 中明确写出不采用原因，而不是默认省略。

## 资源分类体系

### 维度一：用途

| 前缀 | 用途 | 引用目标文档 |
|------|------|-------------|
| `h`  | 讲义专用 | `design/handout.md` |
| `ic` | 互动课专用 | `design/interactive-page.md` |
| `sh` | 讲义与互动课共用 | 两处均引用 |
| `cd` | 卡片专用 | `authoring/knowledge/cards/nodes/<node_id>.md` |

> **跨媒介复用原则**：讲义、互动课、知识卡片可复用同一媒体文件。`sh` 前缀表示讲义+互动课共用；若卡片也复用讲义图像，不新建文件，只在 `card-media-plan.md` 的"可复用自"列注明。

### 维度二：生成方式

| 类型 | 判断标准 | 输出内容 |
|------|----------|----------|
| **代码直出图** | 响应曲线、根轨迹、Bode图、各类参数曲线、稳定域、参数扫描图等可计算生成的图形 | 图片内容描述 + `Octave` 原生函数验证脚本 |
| **TikZ 线框图** | 方框图、信号流图、电路图、机械结构图等结构类线框图 | 图片内容描述 + `tikz-control-draw` 生成要求 |
| **位图（AI生成）** | 原理示意图、工程场景图、实物/设备图等无法代码直出的图像 | 中文场景描述 + 中文定稿提示词 |
| **互动前端绘制** | 互动课中需要随参数变化实时更新的图表（有交互价值） | 前端绘制需求描述（不产生媒体文件） |
| **视频** | 课堂开场或互动课首页使用的动态导入/演示内容 | 中文内容描述 + 中文定稿提示词 |

> **互动课静态图判断规则**：若某图在互动课中无需随参数动态变化，按"代码直出图"、"TikZ 线框图"或"位图"处理，不另起前端绘制需求。

> **本技能补充规则**：讲义封面漫画归入“位图（AI生成）”，15 秒导入视频归入“视频”。两者都属于优先级较高的单元导入媒体，而不是普通装饰素材。

## 文件命名规则

```
{单元编号}-{用途前缀}-{两位序号}-{简短描述}.{ext}

示例：
  2-1-h-01-step-response-family.m          ← 讲义用，代码直出，Octave 源文件（→ raw/）
  2-1-h-01-step-response-family.svg        ← 对应产出图（→ processed/）
  2-1-h-02-ship-bridge-scene.png           ← 讲义用位图（原始 → raw/，处理后 → processed/）
  2-1-ic-03-bode-plot-static.m             ← 互动课用静态图，代码直出
  2-1-sh-04-second-order-block-diagram.png ← 讲义与互动课共用方框图（由 tikz-control-draw 生成）
```

存储路径：`course-content/authoring/lessons/<unit>/media/`
- `raw/`：`Octave` 源文件、AI 生成原始图、录屏母版等
- `processed/`：产出的 .svg/.png，裁剪/压缩后可上线的版本

**命名硬约束：**
- 所有最终媒体文件都必须统一带单元前缀，即都以 `<unit>-` 开头。
- `h` / `ic` / `sh` / `cd` 这类用途前缀仍保留，但位于单元前缀之后，作为第二层命名信息。
- 默认新增媒体也必须遵守同一规则，例如：
  - `<unit>-cover-comic.png`
  - `<unit>-info.png`
  - `<unit>-slides.pdf`
  - `<unit>-intro-video.mp4`
  - `<unit>-course.mp4`
  - `<unit>-audio.m4a`

互动前端绘制需求**不产生媒体文件**，只在 `design/interactive-page.md` 对应步骤中描述。

## 工作流

### 1. 扫描阶段

**同时**读取以下三类内容，识别所有媒体插入点：
- `design/handout.md`（讲义）
- `design/interactive-page.md`（互动课设计）
- `course-content/authoring/knowledge/cards/lessons/<unit>/sequence.json` 与其引用的 `course-content/authoring/knowledge/cards/nodes/<node_id>.md`（若 Step 4 已登记 `card-media-plan.md`，直接读取）

扫描结果输出为统一资源总表，与用户确认优先级。**同一图像在多处引用时只列一行，"引用于"列注明所有引用位置**：

```
| 编号 | 用途前缀 | 简短描述 | 生成方式 | 引用于 | 优先级 |
|------|----------|----------|----------|--------|--------|
| 01   | sh       | ...      | 代码直出 | handout §2.1 / 卡片：复平面可行域首页 | P1 |
| 02   | h        | ...      | 代码直出 | handout §4例题1 | P1 |
| 03   | cd       | ...      | TikZ 线框图 | 卡片：设计可行域首页（无讲义复用） | P2 |
| ...  |          |          |          |        |        |
```

扫描时，优先检查以下两个默认媒体位是否已经被规划：

- `h-cover`：学生版讲义封面漫画（引用于 `design/handout.md` 信息节后）
- `ic-intro-video` 或 `sh-intro-video`：15 秒导入视频（引用于课堂开场或互动课首页）

### 2. 逐项生成阶段

用户确认优先级后，按序逐项输出完整制作规格（见下方格式）。

### 3. 回写阶段

所有资源规格输出完毕后，将引用路径插入对应文档的对应位置：
- 格式：`![图注](../media/processed/{文件名})`（Markdown 图片引用）
- 互动前端绘制需求：在 interactive-page.md 对应步骤的「资源」栏补充 `[前端绘制]` 标注

## 工具选用指南

| 资源类型 | 推荐工具 | 说明 |
|----------|----------|------|
| 响应曲线、Bode图、根轨迹、参数曲线 | `Octave` | 优先使用 `step()`、`bode()`、`nyquist()`、`rlocus()`、`lsim()`、`margin()` 等原生函数完成建模、核验与出图 |
| 框图、信号流图、电路图、机械结构图 | `tikz-control-draw` | 专用线框图流程 |
| 工程场景图、设备实物图、封面漫画 | 即梦 / Midjourney / DALL-E | 位图，需提示词 |
| 动态演示视频 | `seedance` / Sora | 即梦导入视频提示词默认走 `seedance` 技能；Sora 可作备选 |
| 实时交互图表 | Recharts / Canvas / D3 | 前端绘制，无媒体文件 |
