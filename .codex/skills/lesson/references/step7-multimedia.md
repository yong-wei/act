# Step 7：多模态资源设计规格

> 目标：扫描讲义和互动课设计文档，识别所有需要媒体支撑的位置，按资源类型和用途输出制作规格，并在完成后将引用路径回写到对应文档中。

**总约束**：所有产出物中的正式图像都必须是代码直出图或 AI 生成图；ASCII 字符图、字符框图、字符波形只能作为临时思路草稿，不能进入最终交付文档。

## 默认新增媒体（理论课优先考虑）

除常规图表、结构图、代码直出图外，理论课默认应额外规划以下几类媒体：

1. **讲义封面漫画**
   - 用于学生版讲义首页信息节之后、正文之前的注意力引入
   - 以多格漫画形式，用简洁对话提炼本单元的核心概念或问题意识
   - 多媒体阶段默认先交付 `[单元编号]-cover-comic-prompt.md`；若后续实际成图，再命名为 `[单元编号]-cover-comic.png` 放入 `media/processed/`
   - 封面漫画的中文定稿提示词必须以“以哆啦A梦中的人物为原型”开头，后续整段设计需持续符合该系列漫画的人物原型与画风，不得中途切换为其他视觉体系
2. **15 秒导入视频**
   - 用于课堂开场或互动课首页的情绪启动
   - 生成导入视频提示词时，默认显式调用 `seedance` 技能
   - 设计阶段可以考虑电影级、2D 动漫、3D 动画、木偶、黏土动画等方向；若用户未指定具体风格，可随机选择其中一个最适合本课主线的单一风格，但最终提示词必须只保留这**一个明确风格**，不能把多个风格并列为“任选”
   - 目标不是复述讲义，而是快速建立问题情境、唤起兴趣、形成“为什么要学这一节”的感受
   - 若用户指定即梦平台，默认使用**中文提示词**，并按“主体 -> 关键动作 -> 场景 -> 镜头/构图 -> 风格 -> 光线色彩 -> 画质 -> 负面约束”的顺序组织
   - 默认少写公式、板书和推导过程；尤其在电影感方案中，除非用户明确要求，否则不要让公式成为画面主体
   - 默认成品文件命名为 `[单元编号]-intro-video.mp4`
3. **讲义信息图**
   - 用于学生版讲义正文结束、附录开始前的整页总结
   - 作用是把本单元的概念关系、关键结论、典型图形或辨识线索压缩成一张可复习的信息图
   - 默认成品文件命名为 `[单元编号]-info.png`，放入 `media/processed/`

此外，课程级默认成套媒体也必须在资源规划中显式保留：
- `[单元编号]-slides.pdf`
- `[单元编号]-course.mp4`
- `[单元编号]-audio.m4a`

若单元确实不适合使用其中某类媒体，需在 `multimedia.md` 中明确写出不采用原因，而不是默认省略。

## 提示词结构硬约束

若本课媒体需要交付 AI 提示词，默认按以下结构组织，不得只写零散关键词：

### 封面漫画 / 位图（中文提示词优先）

0. **固定开头**：封面漫画的中文定稿提示词首句必须是“以哆啦A梦中的人物为原型”。
1. **主体对象**：先写谁在画面里、在做什么。
2. **核心情境**：本课问题意识是什么，冲突或悬念是什么。
3. **构图与镜头**：横版/竖版、几格漫画、视角、阅读顺序。
4. **风格与材质**：在固定开头之后，明确保持哆啦A梦原型漫画风格的线条、配色、人物比例和叙事气质，不得再改写成写实或其他画风。
5. **关键细节**：必须出现的设备、公式、曲线、板书、船舶等。
6. **文字要求**：是否全中文、是否允许气泡、字数限制。
7. **负面约束**：不要英文、不要背景过满、不要错字、不要错误连线。

### 即梦视频（中文提示词）

参考 `seedance` 技能与即梦中文创作社区常用稳定写法，视频提示词默认拆成 8 个槽位：

1. **主体**：谁或什么系统是主角。
2. **动作链**：必须按时间顺序写清 3 到 5 个关键动作，不得只写主题名词。
3. **场景**：课堂、实验室、桥楼、控制面板、海面等空间背景。
4. **镜头与构图**：远景/中景/近景，推进、平移、拉远、定格等镜头安排。
5. **风格**：只能选一种主风格，例如 2.5D 工程动态信息图、电影级写实、二维动画。
6. **光线与色彩**：主色、辅助色、冷暖关系、是否高对比。
7. **画质与稳定性**：高清、线条清晰、文字稳定、公式可读、运动平滑。
8. **负面约束**：明确不要的内容，例如跳切、闪烁、乱码、畸形人物、杂乱 UI。

**禁止写法**：

- 只堆风格词，不写动作链
- 同时并列多个主风格
- 只写“科技感、大片感、电影感”而没有主体和镜头
- 不写负面约束，导致文字漂移、公式错形、结构图误连

## 资源分类体系

### 维度一：用途

| 前缀 | 用途 | 引用目标文档 |
|------|------|-------------|
| `h`  | 讲义专用 | `design/handout.md` |
| `ic` | 互动课专用 | `design/interactive-page.md` |
| `sh` | 讲义与互动课共用 | 两处均引用 |
| `cd` | 卡片专用 | `authoring/knowledge/cards/nodes/<node_id>.md` |

> **跨媒介复用原则**：讲义、互动课、知识卡片可复用同一媒体文件。`sh` 前缀表示讲义+互动课共用；若卡片也复用讲义图像，不新建文件，只在 `card-media-plan.md` 的"可复用自"列注明。

### 维度二：生成方式

| 类型 | 判断标准 | 输出内容 |
|------|----------|----------|
| **代码直出图** | 响应曲线、根轨迹、Bode图、各类参数曲线、稳定域、参数扫描图等可计算生成的图形 | 图片内容描述 + `Octave`/`control` 内置函数验证脚本 |
| **TikZ 线框图** | 方框图、信号流图、电路图、机械结构图等结构类线框图 | 图片内容描述 + `tikz-control-draw` 生成要求 |
| **位图（AI生成）** | 原理示意图、工程场景图、实物/设备图等无法代码直出的图像 | 中文场景描述 + 英文生图提示词 |
| **互动前端绘制** | 互动课中需要随参数变化实时更新的图表（有交互价值） | 前端绘制需求描述（不产生媒体文件） |
| **视频** | 课堂开场或互动课首页使用的动态导入/演示内容 | 中文内容描述 + 提示词（可按工具选择中文或英文）|

> **互动课静态图判断规则**：若某图在互动课中无需随参数动态变化，按"代码直出图"、"TikZ 线框图"或"位图"处理，不另起前端绘制需求。

> **本技能补充规则**：讲义封面漫画归入“位图（AI生成）”，15 秒导入视频归入“视频”。两者都属于优先级较高的单元导入媒体，而不是普通装饰素材。

## 文件命名规则

```
{单元编号}-{用途前缀}-{两位序号}-{简短描述}.{ext}

示例：
  2-1-h-01-step-response-family.m          ← 讲义用，代码直出，Octave 源文件（→ raw/）
  2-1-h-01-step-response-family.svg        ← 对应产出图（→ processed/）
  2-1-h-02-ship-bridge-scene.png           ← 讲义用位图（原始 → raw/，处理后 → processed/）
  2-1-ic-03-bode-plot-static.m             ← 互动课用静态图，代码直出
  2-1-sh-04-second-order-block-diagram.png ← 讲义与互动课共用方框图（由 tikz-control-draw 生成）
```

存储路径：`course-content/authoring/lessons/<unit>/media/`
- `raw/`：Octave 源文件、AI 生成原始图、录屏母版等
- `processed/`：产出的 .svg/.png，裁剪/压缩后可上线的版本

**命名硬约束：**
- 所有最终媒体文件都必须统一带单元前缀，即都以 `<unit>-` 开头。
- `h` / `ic` / `sh` / `cd` 这类用途前缀仍保留，但位于单元前缀之后，作为第二层命名信息。
- 默认新增媒体也必须遵守同一规则，例如：
  - `<unit>-cover-comic.png`
  - `<unit>-info.png`
  - `<unit>-slides.pdf`
  - `<unit>-intro-video.mp4`
  - `<unit>-course.mp4`
  - `<unit>-audio.m4a`

互动前端绘制需求**不产生媒体文件**，只在 `design/interactive-page.md` 对应步骤中描述。

## 工作流

### 1. 扫描阶段

**同时**读取以下三类内容，识别所有媒体插入点：
- `design/handout.md`（讲义）
- `design/interactive-page.md`（互动课设计）
- `course-content/authoring/knowledge/cards/lessons/<unit>/sequence.json` 与其引用的 `course-content/authoring/knowledge/cards/nodes/<node_id>.md`（若 Step 4 已登记 `card-media-plan.md`，直接读取）

扫描结果输出为统一资源总表，与用户确认优先级。**同一图像在多处引用时只列一行，"引用于"列注明所有引用位置**：

```
| 编号 | 用途前缀 | 简短描述 | 生成方式 | 引用于 | 优先级 |
|------|----------|----------|----------|--------|--------|
| 01   | sh       | ...      | 代码直出 | handout §2.1 / 卡片：复平面可行域首页 | P1 |
| 02   | h        | ...      | 代码直出 | handout §4例题1 | P1 |
| 03   | cd       | ...      | TikZ 线框图 | 卡片：设计可行域首页（无讲义复用） | P2 |
| ...  |          |          |          |        |        |
```

扫描时，优先检查以下两个默认媒体位是否已经被规划：

- `h-cover`：学生版讲义封面漫画（引用于 `design/handout.md` 信息节后）
- `ic-intro-video` 或 `sh-intro-video`：15 秒导入视频（引用于课堂开场或互动课首页）

### 2. 逐项生成阶段

用户确认优先级后，按序逐项输出完整制作规格（见下方格式）。

### 3. 回写阶段

所有资源规格输出完毕后，将引用路径插入对应文档的对应位置：
- 格式：`![图注](../media/processed/{文件名})`（Markdown 图片引用）
- 互动前端绘制需求：在 interactive-page.md 对应步骤的「资源」栏补充 `[前端绘制]` 标注
