# OpenSpec 提案覆盖说明（2026-06-26）

本文的核心方向将由 `structured-associative-retrieval` 提案系列覆盖。系列采用 ACT 内部 SAR（Structured Associative Retrieval）定位，而不是照搬外部 SAG 工程，也不是替代 Source Pack/RAG、K/A/Q 图谱、ResourceNode、LearningFact、Citation Verifier 或路径规划。

本批提案包含七个按顺序执行的变更：

- `define-structured-associative-retrieval-contract`：定义 SAR event/entity/relation/trace/result 合同、安全摘要、稳定 ID、权限与引用边界。
- `project-platform-sources-to-sar-events`：将 K/A/Q 图谱、LearningGoal、ResourceNode、LearningEvidenceCorpusChunk、LearningFact 摘要、诊断/评分/仿真/Arena/路径摘要投影为 SAR events/entities。
- `implement-sar-association-expansion-provider`：实现 seed refs 到 0/1/2-hop 关联扩展 provider，输出候选事件、实体和 trace；不重复实现 Source Pack 的 hybrid ranking 或 citation hydration。
- `wire-sar-to-konling-grounding`：将 SAR 作为控灵 grounding 的多跳关联上下文和工具来源，正式引用仍走 Source Pack/CitationChip。
- `wire-sar-to-graph-center-resource-gaps`：让图谱中心显示 associated evidence 和资源缺口候选建议，建议绑定只进入 draft/suggested 状态。
- `extend-path-planner-with-sar-candidates`：将 SAR 作为路径规划 Tier 4 候选补充和解释依据，不绕过 LearningGoal、K/A/Q 子图、ResourceNode/PlanningUnit 审计和终端验证要求。
- `add-sar-diagnostics-evaluation-report`：提供 SAR 管理员诊断、检索 trace、评估指标和竞赛演示 fixture。

本批提案已根据探索结果修正原计划：Change 3 不再承担完整 hybrid/RAG 检索、排序、多样性和 citation verification，这些属于 `unified-source-pack-retrieval` 系列；SAR 只负责结构化关联扩展、候选来源与 trace。未纳入本批的是生产级 SAR 落库、异步索引调度、大规模向量服务、外部 SAG 项目依赖和自动写回 K/A/Q 图谱的绑定治理。

# 面向 Codex 的 SAG 实施路线：图谱驱动智慧教学平台的结构化关联检索层

## 0. 判断

SAG 可以成为 ACT 平台下一阶段的重要检索能力，但它不应替代当前 K/A/Q 目标体系、知识/能力/素质图谱、ResourceNode、LearningFact、Citation Verifier 或路径规划算法。更合理的定位是：

```text
SAG-style Structured Associative Retrieval
= 图谱语义锚点 + 事项/事件索引 + 实体关联 + SQL 动态扩展 + 引用校验 + 检索轨迹
```

它应作为平台的“结构化关联检索层”，服务控灵回答、学情诊断、资源缺口发现、作业批改解释、教师备课增强包，以及路径规划中的动态候选资源补充。

SAG 论文的核心思想是将 chunk 转为语义完整的 event 和 indexing entities，查询时通过 SQL join 将共享实体的 events 动态连接为局部 hyperedges，而不是预先构建全局静态图；论文报告其在 HotpotQA、2WikiMultiHopQA、MuSiQue 三个多跳检索 benchmark 上取得 9 个 Recall@K 指标中的 8 个最佳，并在 MuSiQue Recall@5 达到 80.0%。([arXiv][1])

ACT 平台不应照搬外部 SAG 工程，而应吸收其架构思想，因为当前平台已经有自己的课程 runtime、ResourceNode、LearningFact、RAG corpus、K/A/Q 图谱和控灵运行时。项目说明中已经明确：互动提交、仿真操作、AI 交互和 Arena 评测会被记录为学习事件，并经数据治理链路物化为学习事实、能力画像、风险提示、班级洞察和个性化建议。 这正好为 SAG-style event/entity layer 提供了稳定事件源。

## 2. SAG 在 ACT 中的架构定位

### 2.1 不采用的路线

不应采用以下路线：

```text
1. 用 SAG 替代 K/A/Q 图谱
2. 用 SAG 替代 ResourceNode
3. 用 SAG 替代 LearningFact
4. 用 SAG 替代 Citation Verifier
5. 用 SAG 直接决定学习路径顺序
6. 直接把外部 SAG 项目作为核心依赖引入 ACT
```

原因是，ACT 的稳定教学结构已经由 K/A/Q 目标和三类图谱承担；ResourceNode 和 PlanningUnit 已经承担资源规划语义；LearningFact 承担受治理学习证据；Citation Verifier 承担内容可信和权限校验。SAG 只能补“动态关联检索”，不能替代这些确定性结构。

### 2.2 采用的路线

采用 SAG-inspired 的“结构化关联检索层”：

```text
Structured Associative Retrieval Layer
```

简称可以命名为：

```text
SAR
```

如果希望与 SAG 术语保持关联，可以在文档中说明：

```text
SAR is an ACT-specific SAG-inspired structured associative retrieval layer.
```

它的角色是：

```text
稳定教学语义：K/A/Q 图谱
稳定资源语义：ResourceNode / PlanningUnit
稳定证据语义：LearningFact / Diagnosis / Grading / Arena / Simulation
可信引用语义：RAG Corpus / CitationTarget / CitationVerifier
动态关联检索：SAR event/entity/query-time expansion
```

## 3. 核心设计原则

### 3.1 平台稳定 ID 优先

SAG 通常需要从文本中抽实体。但 ACT 已经有大量稳定 ID：

```text
K/A/Q graph node id
K/A/Q objective id
PortraitV2 dimension id
ResourceNode id
PlanningUnit id
LearningGoal id
PathNode id
LearningFact id
Rubric criterion id
Arena task id
Arena submission id
Simulation run id
Citation target id
Student id / Class id
```

因此，实体抽取应优先使用平台稳定 ID，而不是让 LLM 自由抽取。

### 3.2 Event 是语义完整事项，不是固定 chunk

ACT 中的 event 不应是“500 字文本块”，而应是教学语义完整单元：

```text
知识卡
教材节段
讲义小节
视频片段
音频片段
互动步骤
控制工作台任务
仿真运行摘要
Arena 官方提交摘要
作业 Rubric criterion 评阅
学习路径节点执行
诊断报告片段
教师报告片段
控灵干预摘要
```

### 3.3 查询时动态扩展，不污染主图谱

SAR 可以在查询时通过 entity join 动态找到关联事件，但不得把动态关联自动写回 K/A/Q 图谱。若发现高质量关联，只能生成“建议绑定”或“资源候选”，由资源治理流程审核。

### 3.4 Citation Verifier 仍是最终可信门槛

SAR 召回的 event/chunk 只是候选。用于控灵回答、诊断说明、教师报告、学生反馈时，仍必须经过 citation verification。XH-202620 明确要求知识权威可信和内容可追溯，生成内容涉及权威信息时要准确标注出处并可核查。

### 3.5 路径规划只能把 SAR 作为候选补充

路径规划的主约束仍是：

```text
LearningGoal v2
K/A/Q 子图
Learner overlay
ResourceNode audit
PlanningUnit
Teacher policy
Terminal validation
```

SAR 只能补充“相关候选资源”和“解释证据链”，不得绕过先修、权限、教师策略、资源审计和终端验证。

## 4. 目标架构

### 4.1 总体链路

```text
Course Runtime / ResourceNode / LearningFact / RAG Corpus / K/A/Q Graph
        ↓
SAR Projection
        ↓
RetrievalEvent / RetrievalEntity / RetrievalEventEntity
        ↓

        ↓

        ↓

        ↓

        ↓
```

### 4.2 SAR 与既有模块关系

```text

  → 提供稳定教学实体

  → 提供资源实体、路径可用性、证据能力

  → 提供学生行为和评价事件

  → 使用 SAR 检索多跳证据

  → 使用 SAR 补充资源候选和解释链

Graph Center
  → 显示关联事件、资源缺口和检索 trace

Teacher Report / Prep Pack
  → 使用 SAR 聚合班级薄弱节点周围证据
```

## 设计要求

1. 所有 SAR event 必须有 sourceRef 和 sourceOwner。
2. 所有 SAR entity 必须优先使用平台稳定 ID。
3. LLM 抽取 entity 可以存在，但必须标记 `source = 'llm-extraction'`，且默认低于 deterministic-id。
4. SAR event 不得携带 raw restricted content。
5. SAR event 可以携带 summary，但 summary 必须是 privacy-safe。
6. CitationTarget 不由 SAR 自行判断可信，仍交给 citation verifier。

## 验收标准

1. 类型文件编译通过。
2. 单元测试验证：

   * event 缺 sourceRef 时报错。
   * entity 缺 canonicalRef 时报错。
   * event/entity 关系 confidence 必须在 0–1。
   * restricted source 不得包含 raw content 字段。
3. OpenSpec 校验：

```bash
rtk openspec validate define-structured-associative-retrieval-contract --strict
```

```text
entities:
  - resource-node
  - knowledge-node refs
  - capability refs from abilityImpact
  - evidence instrumentation
  - source refs
```

PR #608 的 resource coverage 已经根据 ResourceNode 和 evidence corpus 计算资源覆盖，SAR projection 应复用其匹配逻辑，不另起一套资源识别规则。

### RAG corpus 投影

每个 `LearningEvidenceCorpusChunk` 生成一个 event：

```text
eventType = chunk.sourceType mapped
entities:
  - knowledgeNodeRefs
  - capabilityTargetRefs
  - retrieval.tags
  - retrieval.goals
  - citation target
```

不得复制 raw text。使用 redacted summary 或 chunk display capsule。

### LearningFact 投影

仅投影治理后的摘要：

```text
eventType = 'learning-fact'
entities:
  - student
  - class
  - kaq graph refs if mapped
  - resourceNode refs if source links exist
  - evidence type
```

## 验收标准

1. 对 K/A/Q 图谱目录可以生成 SAR events。
2. 对 ResourceNodeRegistry 可以生成 SAR events。
3. 对 RAG corpus chunks 可以生成 SAR events。
4. 每个 event 至少绑定一个 entity。
5. 每个 graph node event 至少绑定：

   * kaq-graph-node entity
   * kaq-objective entity
   * portrait-dimension entity
6. 每个 ResourceNode event 至少绑定：

   * resource-node entity
   * source ref entity
7. 私有学生证据只能输出 redacted summary。
8. 单元测试覆盖 graph/resource/rag/learningFact 四类投影。

# Change 3: implement-sar-association-expansion-provider

## 目标

实现查询时结构化关联扩展 provider，支持 seed entity、0/1/2-hop SQL-style expansion、权限过滤、候选事件选择和 trace 输出。它不接管 Source Pack 的 hybrid/RAG ranking、diversification、excerpt budget、citation hydration 或 citation verification。

## 新增文件

```text
src/lib/data-governance/sar-association-expansion.ts
src/lib/data-governance/sar-trace.ts
src/lib/data-governance/__tests__/sar-association-expansion.test.ts
```

## 输入接口

```ts
export interface SarRetrieveInput {
  query: string;
  useCase: 'konling' | 'diagnosis' | 'path-planning' | 'grading' | 'prep-pack' | 'graph-center';
  seedRefs?: {
    objectiveIds?: string[];
    graphNodeIds?: string[];
    portraitDimensionIds?: string[];
    knowledgeNodeIds?: string[];
    capabilityNodeIds?: string[];

    learningGoalIds?: string[];
    resourceNodeIds?: string[];
    pathNodeIds?: string[];
    citationTargetIds?: string[];
    studentId?: string;
    classId?: string;
  };
  role: 'student' | 'teacher' | 'admin' | 'service';
  studentId?: string | null;
  classId?: string | null;
  maxHops?: 0 | 1 | 2;
  limit?: number;
  outputBudget?: number;
}
```

## 输出接口

```ts
export interface SarRetrieveResult {
  events: SarRetrievalEvent[];
  entities: SarRetrievalEntity[];

    eventIds: string[];
    entityIds: string[];

  trace: SarRetrievalTrace;

```

## 检索流程

```text
1. Normalize query
2. Resolve seed entities
3. Direct event lookup
4. First-hop expansion:
   seed entities → events → connected entities
5. Second-hop expansion:
   connected entities → additional events
6. Produce candidate refs for Source Pack / downstream consumers
7. Role/class/student privacy filter
8. Authority/freshness sorting
9. Return trace
```

## 排序规则

建议第一版使用确定性加权：

```text
score =
  0.30 seed entity match
+ 0.20 graph objective match
+ 0.15 role-safe authority
+ 0.15 hop-distance and trace quality
+ 0.10 freshness
+ 0.10 resource/path relevance
- privacy/limitation penalty
```

不引入复杂 LLM rerank，避免不可控。

## 验收标准

1. 0-hop 查询能返回 seed entity 直接相关 event。
2. 1-hop 查询能返回共享 entity 的 event。
3. 2-hop 查询能发现 query 中未出现但由中间 event 引出的新 entity。
4. teacher 角色不能看到 audit-only raw evidence。
5. student 角色只能看到自己的 student-visible 或 public evidence。
6. SAR 输出 candidate refs 而不是 hydrated CitationChip 或 verified citation payload。
7. trace 必须包含：

   * seedEntities
   * expandedEntities
   * joinedEventIds
   * selectedEventIds
   * rejectedRefs
   * downstreamCandidateRefs
8. 单元测试必须包含一个多跳 fixture：

```text
Bode 裕度 → 控制器校正 → 仿真验证 → Arena 官方评价
```

9. OpenSpec 校验通过。

# Change 4: wire-sar-to-konling-grounding

## 目标

将 SAR 接入控灵，使控灵能够围绕 K/A/Q 图谱、学习目标、路径节点、资源证据和学生状态进行多跳可追溯回答。

新增工具：


工具权限：


6. SAR trace 不向学生暴露隐私诊断细节，只显示简化 trace。
7. 单元测试覆盖：

   * path-advisor with SAR
   * missing citation fallback
   * student privacy redaction

# Change 6: extend-path-planner-with-sar-candidates

## 目标

将 SAR 接入路径规划，但只作为候选资源补充和解释证据，不替代图谱约束与 ResourceNode 审计。

## 当前基础

当前路径规划目标仍由 `AdaptiveLearningPathGoal` 承载，包含 `knowledgeTargets`、`competencyTargets` 和 `capabilityTargets`。 当前注册目标主要包括 `control-correction` 和 `frequency-response-foundations`。

## 新增 Planner 输入

```ts
interface AdaptiveLearningPathPlannerInput {
  ...
  associativeCandidates?: {
    enabled: boolean;
    candidateResourceNodeIds: string[];
    traceId: string;
    limitations: string[];
  };
}
```

## 候选池分层

```text
Tier 1: graph-mandated resources
Tier 2: teacher-assigned resources
Tier 3: ResourceNode eligible resources
Tier 4: SAR-associated resources
```

Tier 4 只能补充，不得覆盖前 3 层规则。

## 约束

SAR candidate 必须满足：

```text
ResourceNode exists
pathEligible = true
privacy allowed
teacherPolicy allowed
evidenceInstrumentation present
not reference-only external resource
terminal validation node must be explicitly capable
```

## 路径解释新增字段

```ts
associatedRetrievalBasis: {
  traceId: string;
  seedEntities: string[];
  candidateResourceNodeIds: string[];
  selectedCandidateNodeIds: string[];
  rejectedCandidateNodeIds: Array<{ nodeId: string; reason: string }>;
}
```

## 验收标准

1. SAR 候选能进入候选池，但不能绕过硬先修。
2. SAR 候选若不 pathEligible，必须被拒绝并记录 reason。
3. SAR 候选若无 verified citation，只能作为参考资源，不得作为解释核心证据。
4. 高阶目标需要 terminal validation 时，SAR 候选不能替代无终端验证能力的资源。
5. 路径解释中必须显示 SAR 候选是否被采纳。
6. 路径结果必须仍能在 SAR disabled 时稳定运行。
7. 单元测试覆盖：

   * SAR candidate accepted
   * SAR candidate rejected by privacy
   * SAR candidate rejected by missing path eligibility
   * SAR disabled fallback

## 6. 数据模型策略

### 6.1 第一阶段建议不直接 Prisma 落库

第一阶段以 TypeScript projection + in-memory/indexed fixtures + service tests 为主。原因：

1. 当前 SAR 仍在结构验证阶段。
2. 直接建表会增加迁移成本。
3. 先让控灵、图谱中心、路径规划消费统一 contract 更重要。

### 6.2 第二阶段再落库

当 contract 稳定后，新增 Prisma 表：

```prisma
model SarRetrievalEvent {
  id             String   @id
  eventType      String
  title          String
  summary        String
  sourceType     String
  sourceRef      String
  sourceOwner    String
  contentHash    String?
  citationTargetId String?
  authorityLevel String
  privacyScope   String
  freshness      String
  createdAt      DateTime
  payload        Json?
}

model SarRetrievalEntity {
  id           String @id
  entityType   String
  canonicalRef String
  label        String
  aliases      Json
  privacyScope String
}

model SarRetrievalEventEntity {
  id         String @id @default(cuid())
  eventId    String
  entityId   String
  role       String
  confidence Float
  source     String

  @@index([eventId])
  @@index([entityId])
  @@index([role])
}

model SarRetrievalTrace {
  id          String   @id @default(cuid())
  useCase     String
  role        String
  studentId   String?
  classId     String?
  queryHash   String
  payload     Json
  createdAt   DateTime @default(now())
}
```

### 6.3 隐私原则

1. student-visible 查询不得返回其他学生事件。
2. teacher-scoped 查询只能返回本班聚合或授权学生。
3. audit-only event 不能进入普通控灵回答。
4. raw answer body、private memory、hidden Arena internals 不得投影为公开 event summary。
5. SAR trace 给学生显示时必须降维脱敏。

## 9. 全局验收标准
