## 结论

1. **三条路线是风格倾向，不是互斥过滤器。** 仿真路线可以出现原理，原理路线可以出现仿真。要调生成参数找平衡，不要把某一风格收成单一资源类型。
2. **用户选的目标是远期/终极目标。** 无画像时完整知识路径必然很长，但不能整段放进一次路径。应从路径的默认头部开始，在优先知识点骨架上生成，总长度有限。学习事实必须沉淀为用户对特定知识点的掌握程度；掌握越高，该点越不容易进入骨架。首要目标是学新知识。画像更新后，同一目标再次生成时，已掌握的起点可以不再作为起始节点。
3. **课程绑定过宽是事实，不是规划器要抹掉的噪音。** 课程出现在路径中时，通常作为收官，前期不要轻易出现。课程覆盖知识点多，前置也多：前置不满足时评价必须降低，从而压低课程进入早期路径的概率。
4. **冷启动补基础是正确行为，不是系统缺陷。** 远祖先出现在无基础路径里是预期。测试必须用已有充分基础的账号；没有就现场 seed。在第 1–3 条落地后，再看有前置基础的用户会不会把长先修忽略掉。
5. **步骤标题若是内部名称，必须全量审计并配上可读标题。** 可用大量子代理并行处理。
6. **空着的预置目标要按现行教学投影做知识点映射，** 不要继续空宇宙。
7. **测试必须覆盖以上要求，** 不能只断言「不出闭包 / 空目标为空」。

## 明确否决

- 不要把仿真冲刺收成「只挂仿真、缺类型就跳过」。
- 不要从目标端截后缀，让一次路径以终极目标收束；应从默认头部截有限长度。
- 不要把无画像时的长先修链当成 bug 去砍。
- 不要为了「课程绑定过宽」禁止课程入选；只降低它出现在早期的分数。
- 不要用无基础的 `demo` 去验收「先修是否被忽略」。
- 不要只测搜索空间，不测风格倾向、头部截取、掌握度剔除、课程收官和标题可读。

## 后续影响

- 组装：`clipKnowledgeSkeleton` 改为从拓扑头部取优先骨架；填充分数继续用风格加权，不用类型硬门。
- 掌握度：学习事实 → 知识点掌握程度 → 高掌握节点不进或难进骨架。没有进度数据时走冷启动头部。
- 课程：作为收官候选；前置未满足则降分。
- 内容：内部标题全量补中文标题；两个空目标按活投影补 `GOAL_CANONICAL_KNOWLEDGE`。
- 验收：seed 有基础账号，再测同一目标第二次生成是否前移起点。
