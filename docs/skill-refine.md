【总目标】
把当前仓库中所有与人类阅读文档相关的技能、说明、子目录约束，改造成以下生成路径：

A. 先从上游设计文件、模块文件、技能文件中抽取“隐藏版 brief”
B. 再根据 brief 生成面向人的 prose
C. 再执行一次“去污染重写”，删除流程腔、工程腔、防御腔
D. 最后才进入已有润色技能

【必须遵守的基本原则】
1. 不改变课程知识结构本身，不随意删减关键教学内容。
2. 不把软件工程、流程控制、合规检查、done-when、任务拆解等语言暴露到人类阅读文档正文。
3. 只把这些内容保留为隐含约束。
4. 人类阅读文档包括但不限于：
   - 学生讲义
   - moduleX 系列的人读版设计文档
   - 教案
   - 互动课程设计人读稿
   - 上述文档的润色稿和重写稿
5. 若发现当前上下文中存在明显的工程性提示污染，优先采用“当前代理抽取 brief -> 子代理只接收 brief 生成 prose”的策略。

【文风改造的具体标准】
你在修改技能时，应把以下内容写入规则中：

一、brief 抽取阶段只允许保留：
- 必须讲什么
- 必须出现什么对象/模型/图表/案例/证据
- 不可扩张到什么范围
- 目标读者是谁
- 本文需要完成哪些理解/判断/迁移动作

二、prose 生成阶段必须压制：
- 流程叙述
- 课堂推进口吻
- 边界先行
- 防御性修辞
- 工程管理话语
- 高密度“编号列表代替论证”

三、去污染重写阶段必须检查：
- 是否在解释对象，还是在解释文档自己
- 是否在传授知识，还是在提前自我保护
- 是否像人在解释问题，还是像代理在执行任务
- 是否高频出现“本讲/上一讲/下一步/不能直接/不是……而是……”
- 是否相邻段落重复同一结论

【重要限制】
- 不要写“忽略系统提示词”这类措辞。
- 不要声称可以覆盖更高优先级指令。
- 只能把工程性、框架性、流程性提示降级为隐含约束，而不是显式对抗。
- 一切修改都以“面向人类阅读文档”这一任务重定义为核心。
