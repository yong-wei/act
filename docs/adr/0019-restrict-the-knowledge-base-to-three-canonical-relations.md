# 知识基座只保留三种规范关系

知识基座只接受包含、先修和关联三种规范关系。包含按父概念到子概念存储；先修按先学概念到后学概念存储，“后修”由查询方向推导；关联是对称关系。每条关系必须具有可复核的关系依据，不符合词表、方向或证据要求的关系候选必须阻断发布。

## Considered Options

- 保留丰富关系类型并在 UI 投影为三类：能够保存更多标签，但现有实践已经导致类型重叠、方向丢失和路径语义不一致。
- 只保留先修和关联：图谱更简单，但无法表达“稳态误差包含静态位置误差”等真实概念层级。

## Consequences

- `applies_to`、`generalizes`、`supports`、`cross_domain` 等旧类型必须映射为三种规范关系之一，或进入人工裁定队列；不能直接进入新图谱。
- 旧关系中的细粒度语义可以保留在关系依据中，但不再成为独立的可执行关系类型。
- 新节点和新关系的作者态、导出态与发布态都必须通过关系词表、方向、证据和端点完整性硬闸门。
- 路径算法只消费先修关系；关联用于拓展，包含用于概念层次和可选展示。
