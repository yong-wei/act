# 核心知识基座上线闸门不可豁免

最终上线必须同时满足规范名称与同义词唯一、近义候选全部裁定、语义档案完整、领域归属合法、三类关系及依据合法、包含和先修无环且直接、先修要求组和路径覆盖完整、无未裁定孤立节点、规范 Markdown 卡全覆盖、视觉化适用性已裁定、原子教学资源绑定完整、旧身份和历史证据迁移完整、作者真源与数据库投影一致，以及分块、跨块和收尾审核清场。核心条件不提供生产白名单、`allow-missing` 或警告降级。

## Considered Options

- 允许维护者为失败项增加临时白名单：有利于赶进度，但会使临时例外永久积累并削弱知识基座可信度。
- 所有检查只报告不阻断：保留人工裁量，却无法保证最后一项变更真正承担合法性闸门。

## Consequences

- 开发过程中可以运行部分检查并输出未完成报告，但正式上线命令必须执行完整硬闸门。
- 已明确不设配额的视觉卡数量、关联边数量等仅作为非阻塞统计，不能伪装成核心合法性条件。
- 人工或代理裁定必须转化为结构化已决工件；口头同意不能绕过机器可验证的未决项检查。
- 最终门禁脚本不得包含面向生产的跳过参数，测试夹具中的故障注入不构成运行豁免。
