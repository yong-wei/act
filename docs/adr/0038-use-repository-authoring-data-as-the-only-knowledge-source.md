# 仓库 authoring 数据是唯一知识真源

规范概念、领域归属、课程编排、三类关系、知识卡索引、资源知识绑定和身份迁移在仓库结构化 authoring 数据中维护。runtime 文件和数据库记录都由同一生成器确定性投影，禁止独立人工编辑或相互覆盖；数据库只承担运行查询和学习事实关联，不拥有另一套节点语义。

## Considered Options

- 数据库作为唯一真源：适合平台化在线编辑，但与当前仓库内离线治理和代码审查流程不一致。
- 仓库与数据库均可编辑：短期灵活，却会延续当前节点、关系和来源标记漂移。

## Consequences

- 最终硬闸门必须从干净 authoring 数据重新生成全部投影，并验证节点、领域、关系、卡片、资源绑定和修订摘要一致。
- runtime 和数据库迁移脚本只接受作者真源输入，不能把生产数据中的未审核节点反向合入。
- 生产数据库中的知识结构数据可以重建；学习事实和历史修订仍作为持久业务数据维护，并通过规范 ID 关联。
- 应用运行只能选择一个明确的知识读模型，不再保留文件与数据库各自可能过期的隐式真相。
