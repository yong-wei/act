# 初次知识基座重建采用离线软件变更系列

当前知识图谱重建属于仓库内离线软件工程，不建设面向教师个人的节点创建、草稿晋升或发布状态机。分块结果、跨块关系、规范知识卡、资源绑定和迁移脚本作为变更系列工件逐步完成，系列最后一项统一执行全量硬闸门和收尾审核，只有完整合法的候选知识基座才能上线。

## Considered Options

- 建设草稿、已发布、已归档的平台化编辑流程：适合教师自助建图，但超出当前离线治理目标并增加无必要状态管理。
- 允许不完整中间结果进入正式图谱：能够更早展示进度，但违反全部完成后一次上线的决定。

## Consequences

- 初次重建的中间状态由 Git 分支、变更工件、审查块和验证报告承载，不新增平台业务状态。
- 变更系列最后一项必须执行名称、领域、关系、路径、卡片、资源绑定、迁移和历史事实的全量硬闸门。
- 分块审核可以并行，但中间结果不面向正式业务，也不需要平台级引用隔离机制。
- 上线后的少量维护继续采用命名变化必审、命名不变免代理审核但保留确定性闸门和知识真相修订的规则。
