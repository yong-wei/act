# 正式应用只读取数据库知识投影

正式应用统一读取由仓库知识作者真源生成的数据库知识投影。部署时整体导入规范节点、领域归属、课程编排、三类关系、资源绑定、身份迁移和修订摘要；runtime JSON 只作为可审计构建工件、测试夹具和数据库导入输入，不再作为 `/knowledge` 或其他正式功能的独立实时读源。

## Considered Options

- runtime 文件作为唯一运行读模型：适合静态图谱，但资源反查、课程编排和学习事实需要与数据库进行跨投影拼接。
- 保留文件优先和数据库回退：短期兼容现有实现，却无法保证两条读取路径始终具有同一知识真相。

## Consequences

- `/knowledge`、路径规划、教师资源页面和知识点反查资源必须读取同一数据库投影。
- 知识投影导入必须在事务中整体完成，不能让部分节点和部分关系先行可见。
- 最终硬闸门验证 runtime 构建工件与待导入数据库投影完全一致；生产导入后还需验证投影摘要。
- 当前文件优先、数据库缺省回退的加载分支需要移除，数据库不可用时应显式失败而不是读取可能不同步的文件。
