# Issue #1330：学生端完整微辅导流程

## 目标

把已交付的错答归因、微辅导编排和微干预记录能力接入学生自适应练习页面，使学生能够在一次持久化错题后主动完成“任务生成—资源学习—验证—建议”的闭环。

## 已确认决策

- 入口仅出现在学生提交后得到的持久化错题反馈中；答对、演示数据和没有持久化答案的反馈不显示入口。
- 学生必须显式点击“开始微辅导”；提交答案、打开错题解析或页面加载均不得自动创建编排任务或干预实例。
- 浏览器只提交 `answerId`；服务端根据当前认证学生重新生成或读取其错答归因，再调用既有编排能力。内部 attribution ID 不成为浏览器状态或 URL 参数。
- 流程保持在自适应练习页面的内嵌面板中，避免为一次 5–10 分钟辅导创建平行学生工作区。
- 资源启动只使用后端投影给出的平台内 action path。点击资源时记录一次 `RESOURCE_USED` 事件；提示、完成和验证均由用户的显式操作触发。
- 验证题只能在干预已经开始且当前任务仍通过服务器授权/漂移校验时读取。浏览器只获得题面与可选项，不获得答案、解析、原题、归因、知识节点或教师私有数据。
- 验证通过或失败后的建议按既有后端投影呈现；前端不得据此更新掌握度、学习事实、正式路径或自动跳转。
- 网络、授权、归因不足、资源/题目不可用、版本漂移和幂等冲突都必须显示可理解的状态；对安全未知状态保持失败关闭。

## 非目标

- 不修改 #1158/#1159 的编排算法、持久化结构、幂等键模型或数据库迁移。
- 不自动开始干预，不生成正式验证题，不新增教师查看或班级聚合功能。
- 不把微辅导结果混入自适应掌握度或正式学习路径。

## 验收证据

- 组件测试覆盖入口门槛、可用/不可用、开始、资源使用、提示、完成、验证和建议状态。
- 路由测试覆盖 answerId 归属、学生身份、验证题脱敏与失效状态。
- 浏览器验收覆盖错题进入、重复操作与窄屏可用性。
