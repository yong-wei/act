# 候选学习路径调整

本上下文约定学生从候选路径比较界面发起“调整”时使用的领域语言。调整产生新的候选事实，不能直接改写正在执行的路径，也不能被记录为一次路径选择。

## Language

**候选路径调整**：
学生以一条已保存候选路径为基线，修改时间、节奏、资源、检查点或自然语言意图后，请求系统生成新的候选结果。
_Avoid_: 修改当前路径、重新选择路径

**调整基线候选**：
学生明确选择用于调整的已持久化候选路径；它由来源批次和来源候选的稳定身份共同确定。
_Avoid_: 当前页面第一条方案、`path-option-1`

**派生候选批次**：
一次有效调整产生的新的不可变候选集合，保留来源批次、来源候选、调整请求和生成时活动进度版本。
_Avoid_: 覆盖原候选、临时候选卡片

**调整差异**：
服务端依据调整基线候选与派生候选事实计算的结构化变化，包括节点、顺序、预计时长、资源构成、检查点和限制变化。
_Avoid_: 前端推测变化、宣传性改进描述

**无实质变化**：
调整后没有形成节点身份、节点顺序或受支持路径指标上的实际变化。系统明确返回该状态，不创建伪装成新方案的成功批次。
_Avoid_: 调整成功但内容相同

**失效调整结果**：
来源批次、来源候选、活动进度版本或请求身份已不再匹配当前服务端事实的结果；页面不得把它作为当前有效调整结果展示。
_Avoid_: 可继续应用的旧结果

**明确路径选择**：
学生在查看调整结果后主动选择某条候选路径的独立动作。只有该动作可以通过现有路径选择流程改变活动路径。
_Avoid_: 生成即应用、调整即切换

## Flagged Ambiguities

- “调整”描述的是从候选事实派生新候选的过程，不是对 `LearningPath` 执行状态的原地修改。
- “当前路径”指学生已选择或正在执行的路径；它可以与调整基线候选不同。
- “成功调整”要求产生可核验的实质差异；只有文字或评分变化不构成新的候选路径。
- 调整请求和路径选择都是可审计动作，但调整记录不得伪装成 `switch` 或其他选择证据。

## Example Dialogue

开发者：学生点击某条候选路径的“调整”后，是否可以直接替换正在学习的路径？

领域专家：不可以。系统先生成新的派生候选批次，活动路径、当前节点和完成进度保持不变；学生明确选择新候选后才能切换。

开发者：页面上仍显示 `path-option-1`，可以只把它作为调整来源吗？

领域专家：不可以。调整基线必须由服务端持久化的来源批次和来源候选身份确定，页面顺序只能用于展示。

开发者：调整结果与原候选完全相同，是否仍显示为新的成功方案？

领域专家：不显示。服务端应返回“无实质变化”，保留原候选并提示学生修改调整条件。

开发者：调整期间学生完成了一个节点，旧请求回来后怎么处理？

领域专家：旧结果失效，不得覆盖当前页面或路径状态；学生需要基于最新进度重新调整。
