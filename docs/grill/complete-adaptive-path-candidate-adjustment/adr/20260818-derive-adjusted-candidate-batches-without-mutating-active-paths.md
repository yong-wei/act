# 候选路径调整生成派生批次，不直接修改活动路径

候选路径调整必须以一个已持久化候选为明确基线，并生成新的不可变候选批次。派生批次记录来源批次、来源候选、调整请求快照、生成时活动进度版本和服务端差异摘要。来源身份使用稳定的批次与候选标识，不使用页面顺序或 `path-option-N`。若没有实质路径差异，系统返回 `no_material_difference`，不创建形式上的新成功批次。

调整期间，当前活动路径、当前节点、完成进度、执行证据和偏离记录保持不变。只有学生随后明确选择某条派生候选时，现有路径选择流程才可以应用候选。调整工具保留自身审计记录，但不得写入 `action: switch` 或其他路径选择证据。

本次优先复用 `AdaptivePathCandidateBatch.metadata` 保存派生关系和请求快照，不新增数据库迁移。该选择接受 metadata 需要统一服务端解码的代价，以避免在调整契约尚未稳定时扩大持久化结构。直接覆盖原批次、原地修改 `LearningPath`、由前端计算调整结果或把调整等同于路径选择均被拒绝，因为这些方案会破坏候选审计、活动进度连续性或服务端事实权威。
