# Issue #1399 控灵 system 消息修复

本上下文统一控灵会话持久化记录与模型消息投影之间的领域语言，服务于修复 system 消息重复导致的供应商 400。

## 语言

**控灵页面上下文记录**：
控灵会话跨页面继续时，服务端在用户消息之前追加的一条受控记录，写明该轮所在的课程、页面、资源、路径或候选图谱范围；它作为 system 角色持久化，客户端展示时隐藏。
_避免：页面上下文提示词、用户消息、可见聊天记录_

**控灵助手绑定记录**：
控灵会话进入诊断解释、资源辅导、备课共创等助手模式时追加的 system 角色记录，用于在会话历史中保留模式与受控提示；它不直接面向用户展示。
_避免：模式选择框、客户端绑定状态、普通聊天消息_

**模型消息投影**：
把持久化会话转换为发给模型的消息数组的过程。该数组只允许以一条服务端构造的 system prompt 开头，内部上下文记录和绑定记录不得作为额外 system 消息进入数组。
_避免：原样回放持久化消息、第二条 system 消息、把记录改写成用户消息_

**会话可见消息**：
客户端恢复会话时展示的用户与助手消息；system 上下文记录和绑定记录只保留在服务端，不进入可见消息。
_避免：把上下文记录显示为聊天气泡、由客户端判断消息是否内部_

**供应商消息契约**：
SiliconFlow 等严格供应商要求 OpenAI 兼容消息中 system 消息只能有一条且位于开头；`streamText` 的 `system` 参数满足该契约，持久化上下文记录不得作为额外 system 消息投影。
_避免：第二条 system 消息、system 出现在中间、用供应商错误码驱动产品语义_

**生产模型归属**：
SiliconFlow 当前主力模型为 `Qwen/Qwen3.6-35B-A3B`，`deepseek-ai/DeepSeek-V4-Flash` 仅作为可选模型保留；生产运行模型由 `PlatformSetting.ai_provider_settings` 决定，代码回退默认不得替代生产配置核对。
_避免：把代码默认值当作生产已切换证据、把 DeepSeek 当作当前主力模型_
