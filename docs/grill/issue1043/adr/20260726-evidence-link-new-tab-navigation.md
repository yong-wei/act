# 证据链接使用新标签页 + URL 参数回退导航

- **状态**：Accepted
- **日期**：2026-07-26
- **决策者**：团队 @issue1043

## 上下文

知识图谱资源面板中点击"查看关联课次证据"或"进入证据浏览器"链接后，证据页在当前标签页中直接覆盖加载。用户点击浏览器返回按钮时，跳过知识点详情页直接退回知识图谱主画布，丢失了浏览上下文。用户需要在密集的图谱中重新定位该知识节点。

该行为影响所有通过 `/profile/evidence` 查看学习记录的入口，但知识图谱场景中的上下文丢失最为敏感。

## 触发场景

1. 用户打开知识图谱主页
2. 点击某知识节点，打开右侧资源面板（知识点详情）
3. 在资源面板底部的学习动作区域点击"查看关联课次证据"
4. 当前标签页跳转到 `/profile/evidence?lessonId=xx`
5. 用户查看完证据后点击浏览器返回按钮
6. 由于浏览器历史栈中上一步是知识图谱主页（而非资源面板打开状态），页面直接回到图谱主画布

## 备选方案

### 方案 A：前端路由栈保留（否决）
使用 `window.history.pushState` 在打开证据前后插入知识点详情页记录。
- **优点**：保留在同一标签页
- **缺点**：与 Next.js App Router 的客户端导航栈冲突；需要侵入性改造；浏览器返回按钮行为不可预测（取决于用户点击图谱节点后的历史记录深度）

### 方案 B：弹窗 / Drawer 嵌入证据（否决）
在资源面板中以弹窗或抽屉形式内联渲染证据浏览器。
- **优点**：完全不离开当前页面
- **缺点**：证据浏览器依赖完整的路由 shell 和滚动视口；嵌入后 UI 裁切严重；移动端不友好；改造成本高（需要将 `/profile/evidence` 重构为可内嵌组件）

### 方案 C：新标签页 + URL 参数回退导航（选定）
证据链接使用 `target="_blank"` 在新标签页打开，同时将当前知识节点 ID 以 `node` 参数传递。证据页读取后将其设为 `backHref`。
- **优点**：保留原始标签页的完整上下文；与现有路由体系正交；`EvidenceTimelineBrowser` 的 `backHref` prop 不需改动；改动量仅 4 行源文件 + 测试更新
- **缺点**：依赖浏览器标签页机制；用户需手动关闭新标签页或切换回原标签页

## 决策

采用方案 C。

具体约束：

1. 在 `resource-panel.tsx` 中，`evidenceHref` 追加 `node=${encodeURIComponent(displayNode.id)}`
2. 证据 `<a>` 标签增加 `target="_blank"` 和 `rel="noopener noreferrer"`
3. `profile/evidence/page.tsx` 读取 `searchParams.node`，当存在时覆盖 `backHref` 为 `/knowledge?node=<node>`
4. 测试断言同步更新，验证 `target` 属性与 href 中的 `node=` 参数

## 后果

### 正面
- 知识点详情页在原始标签页中保持完整状态——图谱相机位置、缩放级别、面板展开/折叠状态均不受影响
- 不修改 `EvidenceTimelineBrowser` 组件内部逻辑，回归风险低
- `backHref` 的条件行为自然——当用户从知识图谱跳转来时显示"返回知识图谱"，从其他入口（如成长中心）跳转来时仍显示"返回成长中心"
- 安全性：`rel="noopener noreferrer"` 防止新标签页通过 `window.opener` 访问原页面

### 负面
- 从知识图谱外路径（如 `/profile/growth`）手动在 URL 中构造 `node` 参数不会产生副作用——`backHref` 仅返回按钮文案变化，不影响证据数据
- 其他入口（如自适应练习、教师端）打开 `/profile/evidence` 时不带 `node` 参数，行为保持不变
- 该模式仅保护了资源面板处的证据入口；图谱中其他证据交互点（如边证据色块、知识卡片内的证据链接）需另行处理

### 测试承诺
- client 组件测试验证 `<a>` 元素的 `target` 属性和 href 中的 `node=` 参数
- 静态源码测试更新模式匹配
- 不新增 E2E 测试（手动验收已足够）
