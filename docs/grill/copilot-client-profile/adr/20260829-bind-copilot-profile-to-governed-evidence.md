# Copilot 画像必须绑定服务端受治理证据

## Context

`usePageAIContext` 为认证用户构造了固定的学习风格、认知水平和能力向量，并将其作为 `userProfile` 发送到通用 `/api/ai/chat`。服务端在存在 `pageContext` 和 `userProfile` 时直接把这组字段交给系统提示词构建器。这样，浏览器默认值或被篡改的画像就可能成为学习陪伴回答的依据。

## Decision

通用 Copilot 的个性化画像由服务端按认证用户和受治理学习状态派生。客户端只提交当前页面的有界定位信息，不能提交或覆盖学习画像字段。服务端没有足够证据时返回明确的冷启动或不可用状态，并继续提供不依赖个人画像的课程解释。

- 服务端以认证会话确定 `UserProfile.id`，忽略或拒绝客户端画像身份与能力字段。
- 画像投影保留可用性、置信度和限制语义，缺失不转换为默认能力向量。
- 普通 Copilot 的课程主题、页面类型和会话历史行为保持兼容。
- 本变更不重写 Portrait v2 计算、不新增画像维度，不自动写入 LearningFact、成绩、排行榜或学习记录。

## Alternatives considered

- **继续信任客户端画像**：实现改动最少，但浏览器可伪造学生事实，不能作为学习陪伴依据。
- **删除全部画像上下文**：能避免伪造，但会损失已有受治理个性化能力，且不符合平台智能助教定位。
- **服务端重算并显式降级**：保留真实个性化能力，同时使无证据场景诚实可用，采用此方案。

## Consequences

服务端请求链需要明确区分页面定位和学生画像来源；客户端测试必须证明伪造画像不影响系统上下文。无画像学生需要看到通用辅导或证据采集入口，而不是默认的个人能力结论。
