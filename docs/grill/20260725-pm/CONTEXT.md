# 智能备课与控灵交互

该上下文统一智能备课主流程与全平台控灵会话界面的产品语言。

## 智能备课

**智能备课主流程**：
教师按照课程依据、课题与目标、班级学情、教案生成与审核、课件生成的顺序完成一节课的设计；控灵在整个流程中提供辅助，但不取代结构化确认。
_避免：任务卡片看板、对话即任务、逐页向导_

**智能备课一级视图**：
智能备课工作台分为备课任务和课程依据两个一级视图。课程依据的创建、上传、版本、停用和删除集中在课程依据视图；任务中的课程依据阶段只负责选择、预览和进入管理，两个视图共享即时状态。
_避免：课程依据从属于单个任务、上下堆叠两套工作区、管理后必须刷新_

**备课任务导航**：
智能备课工作台左侧显示教师的单次课备课任务列表，包含课题、更新时间、当前阶段和状态，并提供新建、搜索和已归档筛选；右侧只呈现当前任务的备课阶段手风琴。
_避免：多个任务卡片同时展开、仅以下拉菜单切换、任务管理与编辑完全分离_

**备课阶段手风琴**：
智能备课主流程的总览界面，各阶段及其内部内容均可折叠，使教师能够同时观察整体进度和局部内容。普通阶段在必填内容有效并保存后自动显示完成标记，需要教师确认的阶段在确认后显示；后续修改使内容失效时完成标记自动撤销。
_避免：只能前后切换的步骤页、全部内容平铺、原始状态列表_

**备课任务删除**：
尚未进入正式教学运行的单次课备课任务可以连同生成记录、教案草稿和批准版本永久删除；课件一旦发布或被课堂引用，任务只能归档。不能删除时，界面必须明确说明正式教学引用关系，并提供归档操作。
_避免：生成后即禁止删除、删除正式课堂历史、无原因禁用按钮_

**课程依据删除**：
没有被备课任务引用的课程依据或教学文档可以永久删除；已经被引用的只能停用并继续支持历史查看。删除受阻时，界面必须列出阻断删除的引用原因，并提供进入相关任务、删除尚可删除的生成内容或改为停用等处理方法。
_避免：无原因禁用删除、停用后无法查看、破坏历史来源引用_

**课程依据文档视图**：
课程依据文档以连续完整的原文结构呈现，正确渲染 Markdown 标题、列表、表格、公式和代码；检索使用的内部提取分段不向教师展示，文档状态、版本和提取信息作为简洁元数据呈现。
_避免：原始 Markdown 文本、提取分段列表、工程索引详情_

**课程依据文档冻结**：
教师提交的课程依据文档在首次被正式引用前保持可编辑，不设置编辑后的重复确认。任务中勾选文档不构成正式引用；备课资源包首次实际采用该文档内容支撑知识点、教学目标或生成上下文时，系统自动确认并冻结当前内容。冻结后继续编辑必须创建新版本，既有引用继续指向原版本。
_避免：提交即冻结、未引用文档反复确认、原地修改已引用文档_

**课程依据文档状态**：
教师界面只使用上传中、正在提取、可编辑、已冻结、已停用和处理失败六种中文状态；首次实际引用前为可编辑，冻结后继续使用稳定版本，不显示提取或确认流程的内部枚举。
_避免：EXTRACTED、CONFIRMED、只显示可用或不可用_

**备课文档选择**：
新建单次课任务时，课程依据下全部启用且可用的教学文档默认被选中，教师可以取消不相关文档；首次实际引用前的可编辑文档和既有已冻结文档都可以进入选择，停用版本只用于历史引用，不进入新任务。
_避免：默认空选、停用文档进入新任务、系统替教师锁定文档_

**备课资源包**：
系统从当前任务已选教学文档中检索、整理并验证的内容集合，用于支撑备课知识点、教学目标和教案生成；它是内部 `Source Pack` 在教师界面的统一中文名称。
_避免：Source Pack、原始全文、最终参考文献列表_

**备课来源展示**：
知识点、教学目标和生成内容默认显示已关联依据、需要确认来源或无可靠来源等简洁中文状态；展开后显示文档名称、章节位置和引用片段，并允许教师更换或移除。教师编辑使内容语义发生变化时，原引用进入需要确认状态并由系统重新匹配；仅格式、空白或标点变化继续保留原引用。
_避免：始终展开全部引用、只显示内部来源枚举、无法核查的来源标记_

**备课检索范围**：
单次课任务用于形成备课资源包的资料边界，包括教师选择的平台预置教材章节和当前课程依据中选定的教师上传资料；上传资料进入检索召回，平台教材复用教材 RAG 系列提供的结构化章节与检索能力。系统根据课程和课题推荐教材及章节，只有教师确认的范围进入检索；教师可以选择整本、章或节并修改推荐范围。
_避免：重新建设备课专用 RAG、只能使用上传资料、把整本教材无差别送入模型_

**备课 RAG 依赖边界**：
智能备课只消费教材 RAG 系列提供的正式章节、检索、重排、引用和阅读合同；备课侧负责资料范围选择、备课资源包和生成接入，不复制向量、索引、重排或阅读器实现。
_避免：备课专用临时 RAG、两套来源语义、只做界面而不接入真实检索_

**默认备课班级**：
智能备课的班级学情阶段自动选择教师的默认班级，并显示该班级当前累计画像摘要；教师可以改选其他班级或明确不使用班级学情。默认班级暂时没有可用画像时显示原因，但不阻止继续备课。
_避免：强制使用班级学情、默认空选、无画像即阻断生成_

**备课实时班级学情**：
备课生成使用所选班级当前可用的累计画像，不为备课任务冻结独立画像版本，也不因制作期间画像变化增加提醒或版本管理。教案产生内容后更换班级或改为不使用学情时，已有生成内容保留供对照并标记为需要更新；教师确认后从提纲阶段重新生成。
_避免：备课画像快照、学情变化检测、边缘场景版本工作流_

**备课来源建议**：
系统为教师手工填写的备课知识点和教学目标自动匹配课程依据中的可靠来源，并把匹配结果交给教师确认或更换；只有没有可靠匹配或存在歧义的条目需要教师处理。确无来源时保留明确的来源覆盖缺口；教师填写简短说明并显式确认后，所在阶段才可完成，但该内容继续显示为无可靠来源，不能被表示为已验证。
_避免：无入口的来源待补、要求教师逐项从头检索、把教师创建视为已验证来源_

**控灵备课建议**：
控灵在自然语言备课会话中提出的结构化修改，以包含变更内容及应用、忽略操作的建议卡片显示在对应对话消息中。教师应用后，系统更新并短暂高亮相应备课阶段。
_避免：独立建议收件箱、无反馈的查看按钮、未经确认自动改写任务_

**教案 AI 审核建议**：
教师主动发起的教案质量建议显示在统一编辑器右侧，并定位到具体内容单元；教师逐条采纳或忽略，采纳后更新对应内容并保留修改记录。建议不自动批准教案。
_避免：无法定位的完整报告、自动改写整份教案、AI 审核即批准_

**备课生成修复**：
生成结果不符合结构要求时，系统先执行确定性解析和规范化，仍不合格时自动进行一次模型纠正；再次失败才暂停，并保留已完成内容供教师从当前阶段重试。
_避免：首次格式偏差即中断、无限自动重试、整份重新生成_

**备课生成状态**：
生成期间以“教学阶段 + 当前动作”两层结构持续显示进度：教学阶段包括提纲、导入、学习目标、前测、参与式学习、后测和总结，当前动作使用等待开始、正在准备依据、正在生成、正在校验、正在自动修正、等待教师确认、可重试、已完成和已取消等统一中文状态。动态图标只辅助表达正在执行。单个阶段通过结构、来源和时长校验后一次显示完整渲染内容；已完成阶段立即可见，不等待整份教案结束。
_避免：静态 RUNNING、只显示加载动画、供应商错误名称_

**统一备课编辑器**：
提纲、教案和后续课件内容通过同一个全屏所见即所得文档编辑工作区进行编辑和保存；顶部提供文档名称、保存状态、显式保存和退出，停止输入后自动保存，并持续显示正在保存、已保存或保存失败。未成功保存的修改不能无提示退出。左侧提供文档结构导航，退出后回到原手风琴位置。BOPPPS 六个阶段固定存在，教师可以增删、调整和排序阶段内部步骤；阶段内容不完整时显示为未完成。Markdown 和结构化数据只作为内部存储与转换格式，不向教师暴露。课程依据文档首次实际引用前通过同一编辑器修改当前可编辑版本；冻结后再次编辑必须创建新版本，既有任务继续引用原版本。
_避免：浏览器输入框、Markdown 源码编辑、原始 JSON 编辑、多套独立编辑器、原地修改已确认来源_

## 控灵会话

**控灵侧边状态**：
控灵默认使用的页面侧边会话形态，使用户在保留当前业务页面上下文的同时进行交流。
_避免：缩小版、临时聊天框_

**控灵最大化状态**：
控灵从侧边状态通过过渡动画进入的全屏会话形态，提供完整对话空间和持久会话导航，并可恢复为侧边状态。
_避免：独立控灵页面、新建会话模式_

**控灵会话历史**：
用户持久保存的控灵对话集合；首轮完整问答结束后，系统依据首个问题和回答自动生成简短名称，失败时使用首个问题的简短文本。用户手动改名后系统不再覆盖。会话允许置顶、按名称搜索和永久删除；置顶会话优先显示，其余按最近活动时间排序。会话在用户主动删除前持续保留，不设置产品级自动过期；统一的数据治理政策仍可覆盖保留期限。删除当前会话后进入新的空会话，删除聊天记录不删除由该会话产生的备课任务等结构化业务成果。
_避免：浏览器临时记录、页面内消息缓存_

**控灵页面上下文转换**：
控灵会话归属于用户并可跨页面继续。会话开始时记录起始页面上下文；用户在其他页面继续提问时，不改写既有消息和上下文结构，而是在新用户消息之前追加一条当前页面上下文记录。
_避免：会话绑定单一页面、覆盖起始上下文、把页面转换伪装成用户消息_

**控灵最大化布局**：
控灵最大化后左侧显示会话历史，右侧显示当前会话；窄屏时会话历史改为可关闭的抽屉。最大化和恢复不新建会话，不丢失输入草稿、消息、流式响应、滚动位置和焦点。
_避免：最大化后重新加载会话、移动端并排挤压、独立聊天页面_

**控灵结构化操作**：
控灵的工具调用和结构化建议必须与对应的助手消息及工具运行记录一起持久化，重新打开会话后恢复原有状态，不自动再次执行。智能备课建议在消息内以操作卡片呈现，应用时通过当前任务修订执行，忽略、冲突和失败均在原卡片内反馈。
_避免：工具结果只存在前端内存、刷新后操作卡消失、重复执行已完成工具_

**控灵工具调用规范化**：
供应商原生工具调用、结构化内容块和可识别的 DSML 工具语法在进入消息展示前统一转换为平台工具事件，工具语法不得作为正文显示。确定性解析无法安全处理时可以执行一次受限纠正；仍失败则显示可处理的错误，不泄露原始工具标记。
_避免：DSML 泄露、把工具参数当回答、无限纠正_

**控灵响应优化**：
首轮回答直接流式输出；需要后台纠正时，在同一条回答上显示“正在后台优化响应”，纠正成功后刷新同一条回答，不生成第二条回复。后台等待上限使用真实实验的 p95；超时后停止等待并保留明确的降级结果或错误。
_避免：等待纠正后才首屏输出、生成两条互相冲突的回答、无限后台等待_

**控灵页面工具边界**：
全平台继续使用现有页面上下文注入；不同页面和助手模式只暴露当前任务所需的聚焦工具集。跨页继续会话时只影响新一轮的上下文和工具权限，不重写旧轮次。
_避免：所有页面暴露完整工具集、为了图谱个案新增特定意图路径、跨页篡改历史工具语义_

**控灵界面层级**：
平台壳层统一管理控灵、个人中心、浮动操作区和遮罩的层级；个人中心及其他页头控件不得遮挡控灵标题栏、消息、输入区或操作卡。最大化状态必须支持焦点约束、退出后焦点恢复和安全区。
_避免：页面自行叠加 z-index、控件可见但不可点击、最大化后焦点逃逸_

**既有数据迁移**：
既有可读的智能备课任务继续显示在新手风琴中，合法结构化结果按文档渲染，失败任务从可恢复阶段继续；既有可读控灵会话保留消息、工具记录和时间并自动命名。过期、空会话和仅初始化失败的会话不迁移。
_避免：新界面只支持新建数据、迁移后显示原始 JSON、把无有效内容的会话写入历史_

**验收基线**：
使用真实教师账号、平台教材章节、教师上传文档和真实累计班级画像，完成课程依据和单课任务创建、真实供应商完整 BOPPPS 生成、失败恢复、编辑保存、AI 建议、重新打开以及未发布任务删除；同时验证控灵跨页会话、最大化历史和结构化操作卡。智能备课完整流程以桌面端为主并检查窄屏可用性，控灵同时验证桌面和移动端，至少保留一条真实模型完整成功证据。
_避免：只用确定性夹具验收、只验证接口不验证教师流程、以单张截图代替恢复和迁移证据_

**变更系列边界**：
智能备课拆为工作台与任务体验、统一编辑器、课程依据文档体验与生命周期、生成可靠性、RAG 与来源治理五项变更；控灵拆为会话历史、最大化工作区、结构化操作可靠性三项变更。工作台、编辑器、生成可靠性和控灵会话历史可以并行开始；课程依据依赖编辑器，控灵最大化依赖会话历史，结构化操作依赖会话历史并消费 `integrate-konling-textbook-rag` 已定义的共享消息修订合同，RAG 与来源治理最后接入并依赖正式教材 RAG 合同和课程依据首次引用冻结接口。跨系列依赖只复用已经在建的消息修订能力，不扩大结构化操作的产品范围。
_避免：一个无法独立审核的超大变更、把两个产品边界混为一个主体、重复建设 RAG 或会话基础设施_
