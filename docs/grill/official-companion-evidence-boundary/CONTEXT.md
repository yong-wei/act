# 控制工作台正式评测陪伴边界

该上下文定义控制工作台中控灵调参陪伴可使用的尝试证据，确保陪伴建议与正式 Arena 评测保持同一权威来源。

## 领域语言

**正式陪伴尝试**：
由当前认证学生在当前任务中产生并持久化的正式 `ArenaSubmission`，包含服务端评测的控制器参数、指标、有效性和硬约束结果。
_避免：客户端手填尝试、预览运行、普通仿真记录_

**客户端自报尝试**：
学生在浏览器中自行填写参数、指标和成功状态后形成的未验证描述。它可以作为临时草稿，但不能触发或持久化受治理干预。
_避免：正式评测事实、官方提交、可验证尝试_

**正式陪伴轮次**：
以一份正式陪伴尝试触发建议，并由下一份同学生、同任务正式提交完成验证的受治理闭环。
_避免：按时间聚合的手填尝试、跨任务比较_

**双通道陪伴**：
正式评测结果陪伴与客户端自报干预同时存在、并都能创建受治理干预记录的状态。该状态会产生互相冲突的证据和冷却身份，必须消除。
_避免：预览与正式评测的正常界面分层_

## 已确认边界

- 控制工作台受治理陪伴只能从当前学生、当前任务的正式 `ArenaSubmission` 建立尝试和验证轮次。
- 客户端填写的参数、指标和成功状态不得决定干预、冷却、证据、Memory 或验证结果。
- 旧手填面板不得与正式结果陪伴并存；预览和自由探索可以保留，但必须明确不产生受治理干预。
- 整改不改变正式评分、硬约束、排行榜、LearningFact、学习画像或学生对控制参数的最终决定权。
