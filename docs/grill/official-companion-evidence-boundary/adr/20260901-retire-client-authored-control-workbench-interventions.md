# 控制工作台只允许正式评测触发受治理陪伴

控制工作台已经具备基于持久化 `ArenaSubmission` 的正式结果陪伴，但页面仍挂载旧 `AICompanionPanel`，允许学生手填参数、指标和成功状态，并通过 `/api/ai/intervention/generate` 创建受治理干预、证据和 Memory。这形成两个相互冲突的陪伴真源。控制工作台应移除或停用客户端自报干预通道，并让正式提交、建议生成和下一次正式提交验证成为唯一受治理闭环；预览或手工记录若保留，只能是明确的非正式本地辅助，不得进入干预持久化、冷却或学习证据。该决定复用现有正式陪伴实现，并避免再维护一套无法审计的尝试历史。
