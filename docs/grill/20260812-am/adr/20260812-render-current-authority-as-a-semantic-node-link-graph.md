# 当前 Authority 采用语义节点—关系图并隐藏系统身份

## 背景

当前 `ActiveAuthorityGraph` 将全部权威对象渲染为卡片网格，并把全部关系另行渲染为卡片列表。页面同时直接显示 ReleaseSet、Release、Snapshot、Activation、节点 ID、相邻节点 ID和未映射枚举；对象缺少说明或关系端点缺少名称时，还会以内部 ID 作为回退。用户看到的是数据清单和实现身份，而不是可理解的知识结构。

ActKG 已经发布异质对象、精确工程谓词和关系方向。现有权威数据足以形成节点—关系图，不需要也不允许由 ACT 补造关系。规范知识卡仍是对象内容真源，但知识卡的卡片形态不应取代图谱结构。

## 决策

当前 Authority 的产品主视图改为语义节点—关系画布：

1. 每个可展示权威对象以紧凑节点表达，使用语义名称作为唯一可见身份，并按对象类型配置稳定的形状、颜色或图标。
2. 每条可展示权威关系以连接真实端点的边表达；线型、箭头和中文关系词共同呈现谓词与方向。关联可显示为无向边，其他有向关系必须显示方向。
3. 默认画布采用渐进式关系呈现。选中节点后突出其一跳邻域，并允许继续沿真实关系展开；不默认同时绘制全部 4,891 个对象和 2,409 条关系，也不随机抽边或生成聚合事实边。
4. 定义、公式、可读来源、关系摘要和受治理教学内容进入节点详情面板。对象卡片与关系条目只能作为详情阅读辅助，不能继续充当主图谱。
5. 所有当前 Authority 产品角色均隐藏系统身份。Release/ReleaseSet、版本哈希、Snapshot、Activation、Projection、对象 ID、关系 ID、原始枚举、内部来源定位符和实现状态不得出现在可见文本、辅助技术名称、复制内容或回退文案中。
6. 内部 ID 继续作为客户端数据关联、边端点解析和受控请求参数；本决定不把展示要求扩展为取消运行时身份。需要查看内部身份的审计和运维能力必须放在独立、受控的诊断界面，不混入当前 Authority 产品视图。
7. 对象类型、谓词、方向、治理状态和来源都必须经过用户可读词表或引用投影。缺少适配时失败关闭为“暂不支持展示”或“信息暂不可用”，禁止回退原始字符串。
8. 只显示当前 Authority 已发布的真实关系。孤立对象如实呈现为暂无已发布关系，工程关系不得推断为尚未发布的教学关系。

## 考虑过的方案

- 保留卡片网格，只增加关系数量和筛选：实现简单，但仍无法表达拓扑、方向和局部邻域，用户不能沿关系理解知识结构。
- 在卡片之间绘制装饰连线：视觉上接近图谱，却会混淆布局连接与权威关系，并在大量卡片下失去可读性。
- 默认绘制全部对象和关系：数据最完整，但 4,891 个对象会形成不可读画布；完整性应由可达性和筛选保证，而不是首屏同时出现。
- 为改善连通性推断额外关系：能够减少孤立节点，但会把前端推断伪装成权威事实，违反单一权威边界。
- 只对学生隐藏系统身份：保留教师和管理员调试便利，但会把运维诊断混入产品语义，并使相同图谱随角色产生不同身份表达。

## 后果

- 前端需要复用或扩展现有图谱画布能力，为 Authority 对象和关系建立独立的显示适配层、渐进布局与选择状态。
- 现有卡片网格、关系卡片列表和页头内部身份必须移除；详情中的节点 ID、相邻节点 ID、原始来源定位和治理枚举也必须替换为用户可读投影。
- API 可以继续返回内部关联键，但前端测试必须证明这些值不会出现在可见文本、可访问名称和缺省回退中。
- 新对象类型或谓词在获得用户可读适配前可能暂时不可展示；这是比泄漏原始枚举更可信的失败方式。
- 验收需要覆盖真实节点—边拓扑、方向表达、类型区分、局部展开、孤立节点、全角色字符串隐藏和窄屏详情交互。
