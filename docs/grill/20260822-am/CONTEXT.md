# 新版图谱迁移到旧版图谱引擎

本上下文记录新版图谱画布、教学关系、跨领域导航与节点关联内容的访谈事实。当前阶段只确认产品和领域边界，不修改产品代码或 OpenSpec。

## 已确认语言

**旧版图谱引擎**：
现有旧版知识图谱的完整运行底座，而不只是视觉样式。它包含 `react-force-graph-2d`、`react-force-graph-3d` 及 ACT 包装层中的全工作区画布、力导向布局、相机与坐标状态、关系动效、筛选图例、悬停预览、详情检查器和焦点管理。
_避免：仅复刻旧版配色、在新版 SVG 上重新实现一套相似交互_

**新版图谱数据适配**：
把当前激活 Authority 的领域分片、异质节点、教学关系、工程关系和详情内容转换为旧版图谱引擎可消费的独立视图模型。适配不得混入旧版 API、Legacy 节点、Legacy 关系、选择状态或缓存。
_避免：把新版数据降格为旧版三类关系、把 Legacy DTO 当作新版真源_

**领域圆形入口**：
新版根视图中的领域导航投影。它由领域目录生成，不是 Canonical Object，也不应被移动到知识节点详情中；综合入口同样只是展示投影。
_避免：把领域入口解释为知识节点、为根入口补造关系_

**跨领域节点入口**：
领域关系或节点邻域中指向其他领域真实 Canonical Object 的导航动作。当前入口只在相关关系分片或邻域分片加载并具有边界引用时出现；它与根视图的领域圆形入口不是同一对象。
_避免：跨领域专题入口、领域目录入口、没有真实关系端点的推荐入口_

**教学关系骨架**：
进入领域后默认可见的已发布教学关系层。它与工程关系层并存；工程关系不得被改写或推断为教学关系。
_避免：用结构、推导、表示或应用关系临时冒充包含、先修或关联_

**工程关系族筛选**：
控制结构、推导与表示、应用与分析、关联等工程关系可见性的可逆开关。开启或关闭只改变对应关系边和必要分片请求，不重置领域、节点位置、选择、检查器、平移或缩放。
_避免：只能累加不能取消的启用按钮、通过返回领域清空筛选_

**节点悬停快速预览**：
指针停留在节点时出现的轻量即时说明，用于快速确认名称、类型和简短语义；点击节点后才打开完整检查器。
_避免：用悬停替代可聚焦的节点详情、把完整属性堆入画布节点_

**跨领域节点装饰**：
用于提示某个真实节点具有可沿当前 Authority 下已发布且用户可访问的关系进入其他领域能力的画布内持续视觉标识。用户提出以动态光环表达；光环不随当前关系边筛选消失，装饰不能成为关系事实，也不能代替可访问名称和详情说明。
_避免：为没有跨域关系的节点加光环、把光环解释为节点重要度_

**知识卡节点标识**：
用于提示所选节点具有当前 Authority、Runtime Release v2 与绑定修订身份下正式发布且当前用户可读取的知识卡。用户提出在节点内部使用星形标识；开发态、未绑定、失败或无权访问的卡片不得触发普通图谱星标。
_避免：仅因旧版资源路径存在就显示星标、知识卡不可用时仍显示可点击状态_

**显示名称不可用节点**：
当前发布对象中缺少合格用户可读名称、因而只能显示“暂不可用”的真实 Canonical Object。该类节点默认不进入普通浏览画布，但必须能通过明确的审核过滤器单独或连同正常节点显示；过滤只改变展示，不改变对象身份和发布状态。
_避免：把内部 ID 当作名称、从运行数据中删除节点、普通用户默认看到大量“暂不可用”_

**节点资源类型标识组**：
节点内部用于说明该节点当前具有哪些受治理系统资源的紧凑标识集合。知识卡、视频、教材及其他批准类型使用不同图形；一个节点同时具有多种资源时全部显示，不以单个汇总图标覆盖。
_避免：只显示优先级最高的一种资源、把资源数量误作节点重要度、在节点外堆放分散徽标_

**资源感知动态节点尺寸**：
节点形状根据内部资源类型标识组和必要语义状态在受控范围内动态调整尺寸，并把最终尺寸纳入力导向碰撞、标签定位、命中区和 2D/3D 布局。节点尺寸不按资源总数量无限增长。
_避免：标识溢出固定节点、只放大视觉而不更新碰撞半径、按重复资源条目持续放大_

**正式发布资源分母**：
由既有内容寻址 Runtime Release v2 manifest/receipt 的扩展合同明确枚举的全部教学资源集合。回执必须绑定候选资源清单、正式纳入清单、排除处置清单、Canonical 绑定集、Authority 身份、runtime/tree hash 和捕获 Git 修订；本地 `course-content/runtime` 目录不能同时充当开发态与正式发布态身份。
_避免：扫描当前目录临时计算、用 `published` 布尔值推断正式包、把开发态资源误计为正式发布资源_

**原子资源锚点**：
可稳定定位和复核资源具体位置的最小身份。视频、音频及其他文本资源均以语义段落作为最小绑定单位，保存绑定资源版本的稳定 `segmentId`、ordinal、位置和内容摘要；习题使用稳定题目 ID。
_避免：只保存临时段落序号、只保存时间秒数、媒体或文本修订后静默沿用旧锚点_

**绑定修订身份**：
把正式发布包、资源版本、原子资源锚点、Canonical Authority/对象修订、教学角色、审核决定和证据摘要冻结为可追溯版本。旧的学习事件和审核证据继续引用当时的绑定修订，不随新资源或新 Authority 静默改写。
_避免：只记录节点 ID 与资源路径、把外部签名 URL 当媒体身份、修改绑定后重解释历史事件_

## 已确认根因

- 新版 `ActiveAuthorityGraph` 没有建立在旧版图谱引擎上，而是独立实现了固定高度、固定 `viewBox` 的 SVG 画布。
- 新版的缩放依赖加减按钮，关系布局是静态坐标；旧版由 force-graph 提供滚轮缩放、拖拽平移、节点拖拽和力导向仿真，并由 ACT 包装层补充视口、动效和持久状态。
- 新版缺少旧版的 2D/3D 模式、力导向自动布局、动态关系流、悬停快速预览、紧凑悬浮图例、节点固定与重排等能力。
- 当前关系族按钮只调用追加式 `enableFamily`，没有 disable 或 toggle 路径，因此开启后只能通过返回领域重置，不能直接取消。
- 新版知识卡只消费与当前 Authority/Teaching Projection 身份严格一致的 `learningContent`；旧版节点资源中的卡片不会自动进入新版。当前仓库内分片的 Teaching envelope 为 unavailable，因此卡片与信息图失败关闭。
- 模式切换、旧版返回动作、新版内部标题与外层 `AppShell` 标题分别拥有独立布局和绝对定位，没有共享右上角控制槽，因而发生覆盖和重复标题。

## 用户已明确的产品边界

- 新版必须迁移到旧版图谱引擎，不继续扩展当前独立 SVG 引擎。
- 旧版主要操作习惯和 UI 能力全部保留，包括滚轮缩放、力导向自动布局、动态连线、小型图例、悬停快速预览和稳定悬浮检查器。
- 新版新增属性统一进入节点悬浮抽屉，不扩张画布节点本体。
- 节点类型与关系类型筛选迁移为旧版形态，并支持直接开启和取消。
- 真实跨领域节点入口进入节点检查器，并在画布节点上使用可辨识装饰；根视图领域入口保持导航投影。
- 具备可用知识卡的节点在节点内部显示明显的星形标识。
- 显示名称为“暂不可用”的节点默认隐藏，并提供明确过滤器供审核显示。
- 系统资源绑定必须纳入本次协调交付；绑定节点按卡片、视频、教材等资源类型在节点内部显示不同标识，多种类型同时存在时全部显示。
- 节点大小根据内部标识组动态调整，并在 2D/3D 两种模式中保持一致的碰撞、命中和标签行为。
- 新版/旧版切换与返回上一层合并为同一右上角控制区，不能与标题重叠。
- 教学关系覆盖属于本项目需要完成的交付责任，不能把缺口作为独立图谱项目的后续工作留置。

## 当前教学关系证据

- 当前仓库内 active Authority domain shard 的可消费教学关系为 0：包含 0、先修 0、关联 0。其当前指针没有绑定 Teaching Projection，所有领域处于 `unavailable`，不是已经审核的空关系集。
- 仓库另有一套通用 runtime Teaching Projection，包含 4 条节点—节点先修关系和 567 条资源—节点绑定；它没有与当前 domain shard 组成同一身份包，因此新版领域图不能消费。资源绑定也不能计作知识—知识教学关系。
- 当前工程 Authority 含 4,891 个对象和 2,409 条工程关系；这些对象总数不是课程教学关系覆盖分母，工程关系也不得重标为教学关系。
- 当前领域目录展示 10 个唯一 Canonical Object，分布在 8 个领域；这些领域当前均没有可用教学关系层。
- 现有仓库证据不能计算“完整课程还需覆盖多少节点”。最小缺失输入是与当前 Authority 同身份的课程选择集、逐节点 CourseCoverage 审核处置，以及已激活的 domain-teaching composed manifest/fragment。
- 已接受 ADR 曾规定由 ActKG Teaching Projection 最终接管知识—知识教学关系；现行 `act-teaching-projection` spec 又把 Teaching Projection 定义为 ACT authoring 生成的 ACT-owned versioned artifact。用户当前要求 ACT 对教学关系建立负责，因此需要在新变更中明确裁决并修订这项冲突。

## 当前名称与系统资源证据

- 当前仓库 active Authority 分片共有 408 个详情节点，408/408 的显示名称均为“名称暂不可用”；552 条唯一关系的端点涉及其中 405 个节点。按占位名称默认隐藏后，普通画布将没有节点或关系。
- 现有显示名称占位来自本地化 resolver 的失败关闭或物化阶段缺少安全可读标签，不是节点身份缺失。当前分片没有保存足以反推具体失败原因的 label provenance。
- 当前通用 Teaching Projection 已有 567 条资源绑定，覆盖 525 个资源和 48 个 Canonical Object；与当前 408 个 active 节点相交 20 个，与当前领域目录 10 个节点相交 6 个。
- 绑定角色为 `PRACTICES` 524、`COVERS` 31、`EXPLAINS` 12、`ASSESSES` 0；资源类型为 step 520、lesson 35、textbook-section 12。当前没有 video 资源类型，也没有作为 resource row 的 card。
- 当前 active domain shard 没有 Teaching Projection identity，节点详情 API 因此把全部系统资源失败关闭为 unavailable；这解释了抽查中没有任何系统资源。
- 即使补齐 Teaching identity，现有 567 条绑定中有 555 条缺少当前详情投影要求的安全标题，会被投影器跳过。资源缺失同时包含激活身份缺口和显示元数据缺口，不能只修改前端。
- 旧 canonical-resource-binding shadow 链没有当前 HEAD capture，crosswalk 和 binding decision 均为 0；若目标扩展到正式 canonical binding 治理，需要独立补齐 inventory、审核、裁决与 activation 证据。
- 当前资源节点注册表虽已有 `video`、`audio`、`quiz`、`knowledge_card` 等 20 类运行态资源，但 Teaching Projection 合同只接受 `lesson`、`handout`、`step`、`textbook`、`textbook-chapter`、`textbook-section` 和 `card`；媒体、音频与习题尚无可发布绑定类型合同。
- 当前 runtime 治理投影包括 487 个 lesson step、1,487 个 lesson module、788 个 lesson media segment、39 个 handout、838 个 knowledge-card 记录、161 个 infograph、1,007 个 textbook section 等；这些数字是现有盘点记录，不等于同一正式发布包的完整分母。
- 现有 `ResourceMediaSourceManifest` 类型具有可选的 `startSeconds`、`endSeconds` 和 `transcriptRef`，但运行态没有找到实际脚本、语义分段、时间码或已持久化生产 manifest；验证器也允许只给 transcript 而不给时间码，不能满足本次语义段落起始时间合同。
- 当前媒体工件至少含 89 条 external-http 和 27 条 missing-local 记录；外部签名 URL、文件名或标题不能作为正式媒体身份。正式绑定还需要最终媒体 hash、脚本/段落 hash、来源修订与审核决定。
- 当前 canonical-resource-binding 是 SHADOW 链，正式消费者仍走 Legacy 或显式 pin；其按规范化 label/alias 自动匹配的旧规则不能直接充当正式绑定裁决。
- 当前学习事件和 LearningFact 没有一等保存发布包、绑定 decision/revision、原子资源片段及内容版本。资源播放或阅读只能作为访问上下文，不能因存在 Canonical 绑定就自动产生掌握证据。

## 规格核对约束

- 进行中的 `admit-complete-authority-locales-and-add-language-switching` 已拥有完整中文 locale 接收、无回退与精确版本激活边界。协调系列应依赖并消费其 qualification receipt，不得另建平行语言门禁；最终验收仍等待其绑定目标 Authority 的不可变中文发布。
- 资源绑定变更必须显式收窄现行 `canonical-knowledge-resource-binding` 中 normalized label/alias 可直接产生 `BOUND` 的规则。名称或 alias 匹配最多只能生成候选，不能直接进入正式 Runtime Release v2 回执。
- 当前 408 个节点只是仓库快照与测试基线。正式门禁必须从目标 composed manifest 动态计算 active-domain 分母，并验证其中每个节点具有 parent 或 root 处置，不能把 408 写成长期固定常量。
- 最新决定明确审核只在开发过程中由课程所有者本人完成，不进入拉起的项目服务。因此协调系列不得新增审核角色、用户级 entitlement、在线审核 API 或服务内审核模式。

## 当前审核授权证据

- 数据库与 session 当前只有 `STUDENT`、`TEACHER`、`ADMIN` 三类角色；`User`、JWT 和 session 均没有 entitlement、capability 或用户级治理授权关联。
- `requireCourseBasisActor` 与 ResourceNode 维护路径把所有教师视为课程或自有资源维护者，不能表达“被显式授予图谱治理权限的维护者”。知识节点写 API 同样只使用 `TEACHER | ADMIN` 粗粒度角色。
- active Authority shard、节点详情与资源绑定响应已有服务端 session/role 校验；完整 active graph diagnostics 与 candidate graph 已有 ADMIN-only 路径，但本次不将其扩展为运行态审核产品。
- Legacy `/api/knowledge/graph`、部分 Legacy node GET 和通用 `/api/resources` 读取路径没有等价服务端授权，或允许调用者自行请求 teacher-only 内容。迁移只能复用旧版渲染引擎和 UI 组件，不能把这些 Legacy 数据 API 当作 Authority 审核接口。
- 由于审核不进入项目服务，现有 entitlement 缺口不在本次范围内；未来若扩大到其他教师，必须另开授权变更，不能沿用本次单人开发流程推断权限。

## 最终规格核对

- 开发期单人仓库审核与“不新增角色、entitlement、在线审核”一致；本次只复用旧版渲染引擎，不复用授权不足的 Legacy 数据 API。
- 正式运行态只消费 `PARTIAL` Teaching Projection 中已经通过的关系，未裁决候选只留在仓库审核包中，不会成为正式边。
- 占位节点静态审核工件不进入应用路由、部署包或 Runtime Release，并复用正式 Authority 适配器与旧版引擎，不形成第二数据解释。
- 详情抽屉复用 source-owned launcher/renderer；无法消费原子锚点的资源失败关闭，不得进入正式 Runtime Release v2。
- 独立规格复核未发现阻断创建协调 OpenSpec 系列的未决产品或治理问题。

## 已确认决策

**新版双模式画布**：
新版完整保留旧版的 2D/3D 双模式，默认进入 2D。两种模式消费同一份 Active Authority 视图模型，并共同支持筛选、跨领域装饰、知识卡标识、悬停预览、选择和详情检查器；模式切换不得混入旧版数据或丢失新版语义状态。
_避免：新版只实现 2D、3D 继续使用 Legacy 数据、两种模式形成不同关系真相_

**ACT 教学关系长期权威**：
Canonical Object 之间的包含、先修和关联等教学关系由 ACT 永久负责。ACT 维护作者数据、证据、方向与强度、审核和冲突裁决，生成并激活绑定明确 ActKG Authority 身份的不可变 Teaching Projection；ActKG 继续负责 Canonical 身份、工程对象、工程关系和来源证据。
_避免：等待独立图谱项目补齐教学关系、把工程关系重标为教学关系、长期保留两个教学关系真源_

该决定取代既有“ActKG Teaching Projection 最终接管知识—知识教学关系”的权威边界。后续变更需要新增 ADR，明确旧 ADR 的 supersession 关系，并同步修订冲突的执行计划和规范措辞。

**课程 active domain 教学覆盖分母**：
教学关系治理以目标 Authority 发布中正式纳入课程 active domain 分片的全部真实 Canonical Object 为分母，不以资源绑定存在为条件，也不扩大到未进入本课程图谱的完整工程 Authority。领域圆形导航入口不是 Canonical Object，不计入分母。当前仓库快照的待处置分母为 408 个节点。
_避免：只治理有资源节点、把 10 个领域目录入口当作完整节点集、要求 ACT 覆盖全部 4,891 个工程对象_

**教学关系逐族 100% 处置**：
每个课程 active domain 节点都必须分别取得包含、先修和关联三类教学关系处置。包含处置为已有审核父节点或明确课程根节点；先修和关联处置为已有审核关系或明确审核后无需关系。只有真实、具备证据的关系才生成边，不为满足数量制造虚假关系。当前快照需要完成 408 个节点、逻辑上 1,224 个关系族处置位；实际新增边数必须由处置结果计算。
完整闭合 1,224 个处置位是长期治理目标，但根据后续决定，不再作为首个 `PARTIAL` Teaching Projection 通过最终产品验收的必要条件。
_避免：把 1,224 个处置位误作必须新增 1,224 条边、以稠密度代替教学正确性、把长期目标误写成首发硬门禁_

**教学关系自动优先与异常人工裁决**：
包含、先修和关联关系及其显式无关系处置先由自动管道生成。通过专用冻结评测门禁且没有低置信度、证据不足、方向冲突、非法环路或其他一致性问题的结果可以直接激活，不要求逐关系人工审核；异常结果不得生成正式边，也不得自动改写为“无需关系”，而是进入人类审核包等待裁决。管道与审核包共同保存模型或算法版本、配置、Authority 与课程输入 hash、候选证据、置信度、方向、强度、冲突及处置理由。
_避免：让单个异常阻断全部合格关系、把不确定性伪装成无关系、把资源 ASR 评测结果当作教学关系准确性证明、只保存最终边而没有生成证据_

**部分 Teaching Projection 可最终验收**：
合格关系可以进入版本化且明确标记 `PARTIAL` 的正式 Teaching Projection；存在未裁决审核包时仍允许协调系列通过最终产品验收。发布包必须绑定真实覆盖分母、已闭合处置数、各关系族正式边数、待裁决数和审核包 hash，不能把部分覆盖表述为完整覆盖；首发最低有效覆盖由包含关系骨架门禁确定。
_避免：隐藏审核积压、把 `PARTIAL` 标作 `COMPLETE`、因部分激活而把后续裁决责任转交给独立图谱项目_

**首发包含关系骨架门禁**：
`PARTIAL` Teaching Projection 通过最终产品验收前，课程 active domain 节点的包含关系必须达到 100% 处置：每个节点具有通过门禁的父节点关系，或被明确判定为课程根节点。先修和关联允许部分完成，但必须随发布包公布真实覆盖率、正式边数、待裁决数及审核包身份。当前 0 条可消费教学关系的状态不能通过该门禁。
_避免：零关系或近零关系被视为可交付部分版本、包含骨架断裂仍依靠力导向假装结构完整、隐藏先修和关联审核积压_

**ACT 仓库工件承载异常裁决**：
异常教学关系由 ACT 生成仓库内审核包，维护者在受治理工件中批准、拒绝、修改或暂缓候选，再运行校验与投影生成管道。图谱页面可以展示待裁决状态和证据摘要，但本次不要求实现页面内写入或审核操作；裁决责任和工件合同仍属于 ACT，不导出给独立图谱项目作为权威。
_避免：另建图谱内写操作和权限系统、把 Markdown 邮件或外部项目返回值当作无版本权威、审核决定无法重建 Teaching Projection_

**机器可读教学关系裁决真源**：
仓库内使用版本化 JSON 或 JSONL 保存候选 ID、Authority 与课程输入身份、证据 hash、原始自动结果、批准/拒绝/修改/暂缓决定、审核者和时间，并由管道生成 Markdown 阅读报告。Markdown 不得反向成为裁决权威，TypeScript 代码常量也不得承载内容决策。
_避免：解析自由文本恢复关键决定、人工报告与机器投影漂移、修改业务代码才能完成一次教学审核_

**自动管道平衡评测取向**：
资源 ASR、语义分段、Canonical 绑定与教学关系管道的版本准入以精确率和召回率的平衡指标为主，不采用单纯精确率优先或召回率优先。管道整体通过评测不改变单项失败关闭：低于单项阈值、证据不足、身份漂移、方向冲突或结构非法的具体结果仍不得进入正式绑定或正式关系。
_避免：以整体 F1 合格掩盖单项明显错误、为提高召回率放行非法关系、把被排除结果计作正式覆盖_

**代表性 gold/holdout 后定阈值**：
ACT 为资源 ASR、语义分段、时间对齐、Canonical 绑定和三类教学关系维护分别适用的版本化 gold/holdout 工件。先覆盖代表性资源类型、课程领域、中文术语和关系族并形成确认标注，再测量基线、确定并冻结指标阈值；模型、提示词、配置、分段或映射算法变化时形成新管道版本并重新通过 holdout，不能沿用旧版本资格。
_避免：没有基准数据就宣布任意固定阈值、在评测集上反复调参后仍把它当独立 holdout、模型漂移后只比较格式成功率_

**开发期单人审核，无运行态审核角色**：
占位名称、开发态资源、失败绑定和教学关系异常通过仓库工件与开发工具由课程所有者本人审核。拉起的项目服务不提供审核入口，不新增系统角色、用户级 entitlement 或在线裁决 API；当前范围只服务这一门自有课程。允许尚未裁决的教学关系继续留在仓库审核包中，但它们不得进入运行态关系投影。未来扩展到其他教师必须另开权限与多租户治理变更。
_避免：为单人开发审核提前建设角色系统、把仓库工件暴露到运行态、从当前单课程边界推断所有教师均可治理_

**教学覆盖治理状态仅存在于开发工件**：
`PARTIAL` Teaching Projection 的覆盖率、待裁决数量、审核包内容和失败原因保留在仓库治理工件和生成报告中，不通过拉起的项目服务展示。运行态只显示已经正式发布的有效教学关系，同时不得声称教学关系已经完整覆盖。
_避免：把内部审核包打包进运行态、隐藏覆盖状态后宣称完整、因局部缺口显示“教学关系全部不可用”_

**占位名称节点三态开发审核过滤**：
正式运行态固定排除显示名称不可用节点。开发期独立静态审核工件复用旧版图谱引擎与 Authority 数据适配器，提供“仅正常节点”“正常与占位节点”“仅占位节点”三态过滤，以便课程所有者集中审核。该工件不依赖 Next.js 项目服务，不进入应用路由、部署包或正式 Runtime Release。
_避免：把占位节点审核入口部署给运行态用户、只能混入全部节点而无法集中审核、普通用户获得占位节点入口_

**独立静态图谱审核工件**：
开发脚本从冻结 Authority 候选与审核工件生成可在本地直接打开的静态交互页面，复用正式 Authority 适配器、旧版 2D/3D 引擎和三态占位节点过滤。生成与打开该工件不需要登录或角色系统，因此它不得包含签名 URL、令牌、私有原文载荷或个人数据，也不得进入运行态构建和发布清单。
_避免：为开发审核启动生产应用、另造与正式适配器不同的数据解释、把无鉴权静态工件部署到公共路径_

**节点内部标识统一进入详情抽屉**：
知识卡星标及视频、音频、教材、讲义、习题等内部资源类型标识只表达当前节点具备哪些正式可访问资源，不建立独立点击区域。点击节点统一打开详情抽屉，抽屉按视觉类型族和精确 runtime 子类型列出全部资源，并提供播放、阅读或受治理跳转入口；2D 与 3D 使用相同交互语义。
_避免：为 force-graph 节点内部每个小图标重造命中系统、同类多资源点击结果不确定、2D 与 3D 形成不同操作习惯_

知识卡视觉类型族直接使用已经确认的内部星形标识，不额外叠加第二个通用卡片图标。

**绑定资源复用现有运行态渲染器**：
详情抽屉只承载资源摘要、精确子类型、绑定角色、语义锚点和启动入口，不内嵌或重造完整播放器、阅读器或题目运行态。视频和音频入口把语义段落 `startSeconds` 交给现有播放器；教材、卡片和讲义入口定位稳定段落；习题入口定位稳定题目。现有渲染器缺少锚点消费能力时，在其原有合同上进行兼容升级。无法生成安全启动目标或无法消费原子锚点的资源不得进入正式 Runtime Release v2。
_避免：图谱抽屉形成第二套资源运行时、只打开文件首页而丢失绑定位置、存在正式标识但点击后无法访问对应资源片段_

**关系筛选默认状态**：
进入领域图谱时，包含、先修和关联三类教学关系默认开启；结构、推导与表示、应用与分析及其他工程关系族默认关闭。旧版小型图例为全部关系类型提供可逆多选开关，用户可以直接开启或取消任一类型；筛选变化不重置视口、布局、选择或详情抽屉。
_避免：工程边默认淹没教学骨架、只能累加不能取消、切换关系类型后重新初始化画布_

**节点类型筛选默认状态**：
进入领域图谱时，所有显示名称合格且当前用户可访问的 DomainConcept、KnowledgeStatement、Formula、SystemModel 及后续受支持节点类型默认可见。旧版小型图例提供可逆节点类型多选；关闭某类节点同步隐藏其关联边，但不重置力布局、视口、选择、关系筛选或详情抽屉。占位名称状态继续由独立三态审核过滤控制。
_避免：默认只显示概念节点导致结构失真、把占位名称与节点类型混成同一过滤维度、筛选后重新计算随机初始布局_

**旧版与 Authority 数据模式状态隔离**：
旧版数据模式和新版 Authority 数据模式共用同一旧版图谱引擎与操作 UI，但分别保存力布局位置、视口、节点与关系筛选、选中节点和详情抽屉状态。切回某模式时恢复该模式自己的现场，不重置，也不尝试按名称或类型把 Legacy 节点状态映射到 Canonical Object。
_避免：两个数据真源共享选择或缓存、切换后丢失用户现场、用模糊名称把 Legacy 节点错误映射到 Authority 节点_

**协调变更系列**：
本次工作采用多个有依赖关系的 OpenSpec 变更并执行一次整体验收。画布引擎迁移与 ACT 教学关系治理保持独立实现和审查边界；页面最终交付不得以教学关系继续不可用为完成状态。
_避免：把 UI 与教学权威揉成一个不可审查的大变更、只完成画布后保留教学缺口_

**Authority 中文名称接收门禁**：
Authority 对象、关系和说明的中文作者权继续属于 ActKG。ActKG 必须提供与目标 Authority 身份绑定、覆盖完整且通过安全校验的中文发布；ACT 负责重新计算覆盖分母、执行 100% 完整性接收门禁，并在普通模式隐藏占位名称节点、在审核过滤器中允许查看。完整中文发布未到位时，本次协调系列不得通过最终产品验收。
_避免：ACT 本地补写 Authority 名称、以英文或内部 ID 回退、普通模式空图仍声明交付完成_

**完整系统资源绑定治理**：
系统资源绑定作为协调系列的第三个独立依赖变更。它覆盖所有准备进入正式运行态发布的教学资源，而不是只接通当前 567 条既有绑定。资源必须以受治理教学角色绑定一个或多个 CourseCoverage 范围内的 Canonical Object；不要求每个 Canonical Object 都具有资源。
_避免：以节点全覆盖代替资源全覆盖、只修复现有投影显示、由资源标题猜测正式绑定_

**正式运行态资源绑定闸门**：
所有进入正式发布版本运行态的教学资源必须具有通过身份、语义、角色、片段和来源校验的 Canonical 绑定。没有合格绑定的资源可以保留在开发版本运行态，但不得进入正式发布版本。非教学资产只有在显式分类和审核后才可豁免。
_避免：未绑定资源警告放行、以文件存在代表可发布、把开发运行态资格误作正式发布资格_

**媒体语义段落绑定真源**：
视频和音频先形成可审查脚本，再按完整语义划分段落，并以语义段落作为最小绑定片段；不要求每句台词分别建立 Canonical 绑定。段落必须能够定位到具体播放位置，脚本身份、媒体身份与内容修订共同进入绑定证据。
_避免：整段媒体只绑定一个宽泛节点、强迫每句台词制造独立语义关系、无时间位置的转写文本、仅凭标题或简介建立绑定_

**intro-video 绑定来源**：
`intro-video` 由独立项目制作，绑定分析优先请求其台词本和设计真源，并核对到最终媒体身份；不以重新转写结果覆盖已有制作真源。
_避免：只读取成片标题、忽略设计真源、把独立项目工作目录当作 ACT 运行真源_

**课程视频与播客脚本**：
course 视频系列和播客系列音频通过音频识别形成脚本，并按语义段落建立稳定锚点；脚本及段落位置在进入正式绑定前完成内容与媒体身份校验。
_避免：没有语义分段和时间定位的整篇转写、未经校验的识别输出直接发布_

**文本段落绑定**：
教材、知识卡、讲义及其他文本资源同样以稳定语义段落为最小绑定单位。绑定保存资源版本、段落身份、内容摘要和 Canonical 端点；文本修订不得静默保留已经失配的绑定。
_避免：整份文档宽泛绑定、按临时检索窗口绑定、只保存段落序号而不绑定内容版本_

**原子级 100% 审核处置**：
正式发布资源中的每个语义段落或独立习题都必须具有稳定锚点，并取得“已绑定 Canonical Object”或“经审核的非教学片段”处置。所有教学语义段落和正式习题必须绑定；片头、过场、版权声明等没有教学语义的片段可经审核豁免。每份进入正式发布的教学资源至少包含一个已绑定片段。
_避免：整份资源有一条绑定便放行其余未审核内容、给过场或版权声明制造虚假关系、未处置片段进入正式发布_

**媒体段落时间定位**：
每个视频或音频语义段落必须保存经过校验的 `startSeconds`。段落结束位置由下一语义段落的起始时间推导，最后一段由媒体总时长推导；绑定证据同时保存推导规则版本和媒体身份，使相同输入能够重建相同定位结果。
_避免：要求逐句时间码、人工重复维护相邻段落的结束和开始时间、媒体修订后沿用旧时间位置_

**媒体脚本全自动准入**：
course 视频和播客的 ASR、语义分段、时间对齐以及 intro-video 制作真源与最终媒体的自动核对，都不以人工确认作为正式绑定前置条件；自动结果可以直接进入正式绑定流程。自动校验的最低阈值和证据合同仍需单独确定。
_避免：把人工签字设为所有媒体发布的必经步骤、把“无需人工”误解为无需机器可验证证据_

**资源级发布失败关闭**：
任一资源未通过脚本、语义分段、时间定位、来源身份、Canonical 映射或绑定完整性校验时，该资源不得进入正式 manifest，只能保留在开发运行态。正式 manifest 排除失败资源后重新冻结；其他全部合格资源可以继续发布。排除项及原因必须留在候选资源处置记录中，不能通过漏报资源缩小分母。
_避免：一项失败阻断所有无关合格资源、失败资源警告放行、静默删除失败项后伪造全量通过率_

**自动管道冻结评测集准入**：
ASR、语义分段、时间对齐和 Canonical 映射的每个管道版本必须先通过冻结且版本化的确认基准集，才能生成正式绑定产物。每项正式产物保存模型或算法版本、配置、输入资源 hash、输出置信度和候选证据；通过管道级准入后不再要求逐资源人工审核。
_避免：只信模型自报置信度、模型或提示词变化后沿用旧准入结论、只保存最终节点 ID 而无法复核生成过程_

**扩展既有 Runtime Release v2 身份**：
系统沿用现有内容寻址 Runtime Release v2 manifest、receipt 和生产指针，不建立第二套独立资源发布权威。扩展回执同时绑定候选资源清单 hash、正式纳入清单 hash、排除处置清单 hash、Canonical 绑定集 hash 与 Authority 身份；生产指针只接受这些身份一致且闸门通过的完整回执。
_避免：绑定包与资源包独立漂移、发布时临时扫描目录、生产指针只绑定媒体文件而不绑定语义关系_

**资源类型感知的绑定失效**：
媒体文件 hash 改变时，整份媒体的脚本、语义分段、时间定位和 Canonical 绑定全部失效并重新生成。文本资源重新分段后，只保留稳定 ID 与内容 hash 均未变化的语义段落绑定；新增、删除或内容变化的段落重新处置。习题的题干、选项、答案或解析任一变化时，该题绑定失效并重新生成。
_避免：媒体换版后沿用旧时间码、文本局部修改导致整本教材无差别重算、只凭稳定 ID 忽略内容变化_

**资源类型与教学角色正交**：
Canonical 绑定继续使用 `COVERS`、`EXPLAINS`、`PRACTICES`、`ASSESSES` 四类教学角色；视频、音频、播客、知识卡、习题及其他正式运行态资源通过扩展 `resourceType` 表达媒介与运行形态。同一资源片段可以针对不同 Canonical Object 使用不同教学角色。
_避免：用 `WATCHES`、`LISTENS`、`READS` 混淆媒介和教学语义、为每种媒介复制一套关系角色、因新增资源类型改变既有角色含义_

**节点资源视觉类型族**：
绑定、发布和抽屉数据保留每项资源的精确 runtime 子类型；画布节点内部将其聚合为卡片、视频、音频/播客、教材、讲义/幻灯、习题、仿真、项目等可辨识视觉类型族。同一节点具有多个类型族时全部显示，每个类型族只占一个内部标识；抽屉列出该族下全部精确子类型和资源。
_避免：为二十余种 runtime 子类型堆放难以辨认的小图标、只显示优先级最高的一类资源、在投影数据中丢失精确子类型_

**正式资源标识资格**：
运行态图谱只根据与当前 Authority、Runtime Release v2、Canonical 绑定修订一致且当前用户有权访问的正式资源生成节点内部标识和知识卡星标。开发态、未绑定或失败资源及其处置状态仅出现在仓库审核工件或开发工具中，不写入运行态节点投影。
_避免：运行态泄露无权访问资源、用开发候选装饰正式节点、因历史绑定存在而显示当前不可用标识_

**跨领域光环持续显示**：
节点只要具有当前 Authority 下已发布且当前用户可访问的跨领域关系，就持续显示动态光环；关系族筛选只控制边线，不改变节点的跨领域入口资格。节点抽屉始终列出可访问的跨领域目标和关系依据。
_避免：关闭某类边后入口能力无提示、把隐藏边误作关系不存在、用光环泄露无权查看的领域目标_
