# Issue 1141 Context

## 目标

学习路径页面必须准确表达路径数据的可用状态，避免把尚未完成的数据加载误判为学生没有活动路径。

## 领域术语

### 路径上下文加载态

系统正在获取学生的活动路径、路径节点和进度信息，尚不能判断学生是否存在活动路径。此时页面保留稳定框架，所有依赖真实路径的业务内容统一显示为不可操作的加载状态。

### 确认无活动路径

学习状态和路径数据均已成功加载，且系统确认学生当前没有活动路径。只有完整满足这些条件，页面才能展示入门路径、入门诊断和生成路径入口等冷启动内容；不得根据超时或部分数据推断该状态。

### 路径上下文不可用

路径数据未能成功加载，系统无法判断学生是否存在活动路径。页面保留稳定框架，明确提示学习路径暂时无法加载，并提供重新加载操作；该状态不得被表达为确认无活动路径。

## 已确认边界

- 路径上下文加载期间，页面保留路径区域的稳定尺寸，使用与真实内容结构对应的骨架占位，并显示简短、明确的加载状态。
- 路径建议、节点、进度和生成入口依赖真实路径数据；加载期间统一替换为不可操作的加载状态。
- 加载期间不得展示任何暗示学生没有活动路径的业务结论或操作入口。
- 加载状态只约束依赖路径数据的区域，不阻断页面内其他独立功能。
- 路径上下文不可用时展示明确的失败反馈和重新加载操作，不展示冷启动内容。
- 冷启动内容仅在学习状态与路径上下文均已就绪，并明确确认没有活动路径时出现。
- 不以等待时长或部分数据作为没有活动路径的判断依据。
- 本问题不改变学习路径规划算法、路径生成策略、数据库模型或真实无路径学生的冷启动内容。

## 待确认

无。

## 验收边界

- 路径上下文加载期间，不出现入门路径、入门诊断或生成路径入口等冷启动内容。
- 存在活动路径时，加载完成后显示真实路径、节点和进度。
- 学习状态与路径上下文均已就绪且确认没有活动路径时，原有冷启动内容正常出现。
- 路径上下文不可用时，显示错误反馈和重新加载操作，不伪装为没有活动路径。
- 桌面端与 320px 移动端均不得出现文本重叠、操作遮挡或不可接受的布局跳动。
