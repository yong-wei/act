# ADR：使用持久化异步任务编排诊断生成

## 状态

已接受

## 背景

Issue #1178 要求教师点击触发诊断生成，同时处理重复点击、失败重试、模型超时、幂等与审计。现有公开写接口在一个请求内直接接受并持久化报告正文，无法满足服务端生成信任边界，也没有可恢复的任务状态。

## 决策

诊断生成采用持久化异步任务：创建请求返回任务标识，服务端异步执行 Konling `teacher-diagnosis` 流程，前端查询任务状态并在成功后读取已持久化报告。

任务至少表达等待、执行、成功、失败或超时状态，并保存最终报告引用及生成尝试的审计信息。具体幂等键和重试语义由后续决策确定。

同一请求键复用同一任务，同一班级或学生范围同时最多有一个活动任务。成功后再次明确发起生成会创建新任务，以新的证据截止时间形成新报告快照。

数据库记录是任务状态与审计的权威来源，BullMQ/Redis 负责投递和 worker 执行。队列投递失败不得删除数据库任务，任务必须保留为可见、可重试状态。

可恢复错误最多自动重试 3 次；确定性校验错误不自动重试。自动重试耗尽后，教师可以显式重试原逻辑任务。所有执行尝试归属于同一任务，且一个逻辑任务最多关联一份成功报告。

持久化结构由生成任务、执行尝试和诊断报告组成。任务记录请求与生成边界；尝试记录每次 Konling 会话、工具摘要和错误分类；报告通过唯一关系追溯到任务。数据库约束负责阻止同一任务产生多个成功报告。

任务创建时冻结证据截止时间。自动重试和人工重试都不得改变该截止时间；需要使用更新后的证据时必须创建新任务和新快照。

Konling 必须返回符合报告 schema 的结构化输出。服务端在同一持久化边界内复核证据引用、截止时间、诊断范围、发现项白名单和工具来源；全部通过后才创建报告并完成任务。治理校验失败是确定性失败，不保存报告且不自动重试。

## 影响

- HTTP 请求不需要等待模型调用完成。
- 重复点击、进程中断和超时恢复由持久化状态管理。
- UI 可以稳定呈现进行中、失败和完成状态。
- 需要新增任务持久化结构、领取执行机制和状态查询接口。
- 可以复用仓库现有生成任务的 BullMQ 组织方式，但诊断任务保持独立队列与业务状态。
