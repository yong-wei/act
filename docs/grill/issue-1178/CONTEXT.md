# Issue #1178：教师学情诊断生成编排

## 目标

教师在既有班级或学生工作区主动发起诊断生成。服务端调用 Konling `teacher-diagnosis` 模式，验证结构化输出与受治理证据后持久化报告；浏览器不能提交报告事实正文。

## 已确认术语与约束

- **生成任务**：一次持久化的异步诊断生成请求，具有可查询的状态、尝试记录和最终报告引用。
- **报告范围**：由服务端依据路由、当前教师身份、班级归属及学生成员关系确定，不信任客户端声明的权限信息。
- **报告正文**：只能来自服务端执行的 Konling 生成链路，并在持久化前通过结构、证据、截止时间和范围校验。
- **前端职责**：提交生成意图、显示进行中/失败/完成状态并刷新历史记录；不生成或提交事实性报告内容。

## 已确认决策

### 持久化异步执行

生成请求立即返回任务标识，页面通过状态查询观察执行结果。任务状态必须覆盖等待、执行、成功、失败或超时；失败和超时能够恢复，并保留可审计的尝试信息。该模型承担重复点击合并、幂等处理和报告关联，不依赖单次 HTTP 请求持续存活。

### 请求键去重与范围级互斥

- 同一请求键始终返回同一生成任务和结果。
- 同一教师可访问的班级或学生诊断范围，在等待或执行期间最多存在一个活动任务；不同请求键的重复点击也复用该活动任务。
- 成功任务不会永久阻止刷新。教师后续明确点击时使用新的请求键，并以新的证据截止时间生成新的报告快照。
- 失败或超时任务保留审计记录；重试方式仍需与执行载体一并确定。

### 数据库任务真源与 BullMQ 执行

- 数据库任务记录是状态、幂等和审计的权威来源。
- BullMQ/Redis 只负责可靠投递与 worker 执行，不作为业务状态真源。
- 创建数据库任务后若投递失败，任务仍然可见，并能由显式重试重新投递。
- 不依赖已经失效的 `worker:scheduler` 脚本入口；沿用仓库现有生成任务的队列与 worker 组织方式。

### 有限自动重试与显式人工重试

- 网络、模型服务暂时不可用等可恢复错误，在同一任务内由队列自动重试，最多 3 次；每次执行都形成尝试记录。
- 结构化输出不合法、权限失效、范围不匹配或证据越界等确定性错误不自动重试。
- 自动重试耗尽后，任务进入失败或超时终态。教师可显式重试原逻辑任务，使其重新入队并继续累计尝试记录。
- 成功报告只在完整验证通过后写入；重试不得为同一逻辑任务产生多个成功报告。

### 规范化审计关系

- 生成任务保存教师、班级、可选学生、请求键、生成器版本、证据截止时间、状态和最终报告引用。
- 每次 worker 执行形成独立尝试记录，保存 Konling 会话标识、开始与结束时间、结果状态、错误分类和受治理工具调用摘要。
- 最终报告与生成任务建立唯一关系，使报告能够追溯到生成请求及其尝试链；一个逻辑任务最多产生一份成功报告。
- 不把关键状态与唯一性约束仅封装在不可查询的 JSON 中。

### 固定证据快照

- 生成任务创建时确定 `evidenceCutoff`，并在整个任务生命周期保持不变。
- 自动重试与教师显式重试只能读取该截止时间之前的受治理证据，保证所有尝试共享同一事实输入边界。
- 需要纳入新证据时，教师重新发起生成并创建新任务，而不是改变既有任务的输入。

### 严格结构化输出与服务端治理校验

- Konling `teacher-diagnosis` 必须产生符合 `DiagnosisReportBody` schema 的结构化输出，不通过自由文本解析形成报告。
- 持久化前由服务端再次校验证据引用、固定截止时间、班级或学生范围、发现项白名单及允许的工具来源。
- 只有全部校验通过，才能在事务中创建唯一报告、关联生成任务并将任务标记为成功。
- 任一治理校验失败都不得保存部分报告，尝试记录为确定性验证失败且不自动重试。

## 实施边界

- 用生成意图接口替代公开报告正文写入能力。
- 在既有班级与学生报告历史区域加入生成入口和任务状态，不创建独立助手门户。
- 后端实现任务创建、状态查询、显式重试、BullMQ 投递与 worker、Konling 生成、治理校验和事务持久化。
- 覆盖权限、范围、幂等、并发、重试、超时、验证失败、类型检查与关键 UI 流程。
