# Evidence Copilot 使用服务端授权证据上下文

## Context

当前 Evidence Copilot 页面根据 URL 的 `source` 生成证据摘要，并将客户端上下文提交到 AI Chat。这样页面看似进入了“证据复盘”，但服务端没有证明该来源属于当前学生，也没有从受治理学习证据中建立回答上下文。学生可能因此把导航参数或自填文字误认为个人学习证据。

该问题直接影响学习过程陪伴的可信度：陪伴回答必须建立在真实学习事实、评测结果或场景指标上，并能说明证据缺失和可用范围。

## Decision

Evidence Copilot 采用服务端授权证据作为唯一事实来源。服务端依据当前认证身份读取并投影学生可见的受治理证据；客户端传入的 `source`、`assignment`、`intent` 等字段只能帮助定位入口或表达学习目标，不得作为证据内容或权威上下文。

当证据为空、部分可用、过期或服务不可用时，系统必须保留对应状态和限制说明，不以零值或模型推测补齐个人事实；页面应提供与状态匹配的真实学习行动。Evidence Copilot 的回答保持辅助性质，不写入官方成绩、排行榜、LearningFact 或学习画像。

## Consequences

- 学生看到的证据摘要和建议能够追溯到当前身份可访问的学习事实。
- 客户端伪造来源或任务描述不能扩大 AI 的事实范围。
- 需要为证据投影、授权失败、空数据、部分数据和不可用状态建立统一测试与页面验收。
- 通用 Copilot 在没有 Evidence Copilot 上下文时保持原有行为。
