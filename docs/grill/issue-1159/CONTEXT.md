# Issue #1159 范围上下文：微干预结果记录与后续推荐

## 目标

在 #1158 产生的、受治理的可用微辅导任务之上，记录一次学习者实际干预的开始、资源使用、提示、完成、耗时与验证作答结果；据此给出可追溯但不改变正式学习状态的下一步建议。

## 已确认的边界

- 干预实例由服务端在开始时创建并分配 `interventionId`；后续完成、提示与验证提交均绑定该实例。
- 同一事件键的重试幂等；新的开始请求保留为独立历史，而非覆盖已有实例。
- 通过验证但没有受治理的高阶迁移练习时，保留通过结果并返回“当前无可用迁移练习”的受控建议；不得捏造推荐或改变正式路径。
- 验证失败时，优先推荐当前受治理的前置知识点拆分；没有可用前置节点时，建议调整辅导策略和人工练习入口。
- 原始归因、任务资源、验证题版本与学习者会话必须可审计绑定；会话由归因记录在服务端确定，学习者请求不得自报或替换它。学习者响应不得暴露答案键、解析、原题标识、误解标签或教师私有数据。

## 非目标

- 不自动更新掌握度、能力估计、学习事实或正式学习路径。
- 不产生新题、不聚合跨会话历史、不提供教师或班级效果统计。
- 不以自由文本、标题相似度或生成式推断补全迁移练习或前置关系。

## 术语

- **微干预实例**：学习者针对一个可用微辅导任务发起的一次独立、服务端编号的执行记录。
- **事件键**：客户端为可重试写入提供的稳定标识；同一实例内重复提交不得产生第二个事件。
- **受控不可用建议**：保留已经证实的结果，同时明确说明当前缺少可安全展示的下一步资源，而不伪造替代内容。
- **建议依据摘要**：面向学习者的、经白名单投影后的理由，说明建议来自本次干预的验证结果与当前有效治理关系。
