# 协调切换执行时最新 Authority、完整教学投影和活动 OSS 资源绑定

ACT 当前生产 Authority 与活动 OSS Runtime Release 分属独立选择边界，既有资源变更只治理目标候选，教学关系变更又允许先修与关联未闭合时发布 `PARTIAL`。这不能满足“切换到最新图谱后，现有正式教学资源仍完整可见且教学投影已经完成”的产品目标。

## 决策

1. 执行开始时刷新本机 ActKG 项目的正式远端标签，选择当时最新且组件闭合的复合发布，冻结 commit、tags、组件身份和 hashes。当前已知 v0.37 组合只是参考，不写成长期版本常量；捕获后出现的新版本由后继增量升级处理。
2. 新发布若继续满足 ACT 已支持的公开 Schema、合同和适配器门禁，则直接生成新的不可变接入、投影和选择器候选，不建立版本专用适配 spec。Schema 或消费合同发生不兼容变化时，必须先建立独立适配变更。
3. 正式资源后继 Release 的分母由捕获时活动 OSS Runtime Release 的全部逻辑资源，加上本次明确准备发布的新增或修改资源组成。OSS 历史 Release、候选前缀、孤立对象和工作区扫描结果不进入分母。
4. 资源绑定按原子和依赖身份增量计算。只有资源内容、原子内容、Canonical 身份或修订、教学角色、课程范围、管道版本或启动合同发生变化时，才使受影响结果失效；图谱或资源任一变化都不得触发无差别全库重绑。
5. 当前生产教学资源受连续性门禁保护：它们必须完成原子绑定后继续纳入，只有课程所有者明确批准退役时才能排除。脚本、识别、分段、时间、锚点、映射或启动能力的技术失败会阻断生产切换。新增资源失败时可以保留在开发态，不得进入后继正式 Release，也不阻断既有资源连续性。
6. 完整 Teaching Projection 以目标课程 sealed active-domain 为分母。每个 Canonical Object 的包含、先修和教学关联三类关系都必须取得最终处置；处置可以是已准入关系或有证据的 `NO_RELATION`。生产激活前 `pending=0`，不得以 `PARTIAL` 投影、上线后审核或人为补边满足门禁。
7. 最新 Authority、完整 Teaching Projection、资源绑定后继 Runtime Release 和全部选择器先离线生成并验证，再在同一停服批次协调提交。任何失败都必须在恢复服务前还原原有 Authority 与 Runtime Release 组合，用户不得看到跨版本中间态。
8. 同 Schema Authority 可以自动生成候选工件，但候选不等于生产。每次生产激活仍需显式授权并使用协调切换事务。
9. 不可变身份图必须单向构造：先分配协调运行身份并生成内层工件，再由外层候选收据绑定其精确哈希；激活时先在日志中分配事务身份，内层变更收据只绑定事务与候选，最终活动收据随后绑定全部内层收据和选择器。禁止内层收据反向引用尚未生成的外层收据哈希。

## 后果

- 既有“包含完整即可发布 `PARTIAL`”口径被本次生产切换门禁取代；审核包可以保留已裁决历史，但不能保留未裁决项。
- 既有资源级排除策略仍适用于新增候选，但不再允许技术失败静默移除当前生产教学资源。
- OpenSpec 应描述版本无关的捕获、增量派生、完整性和协调切换能力，不为当前 v0.37 或未来每个同 Schema 数据版本复制一套适配变更。
- 旧 Authority、旧 Runtime Release 和既有历史事实保持不可变，并作为协调回退组合保留；本决定不建立新旧 Canonical 身份映射。

## 未采用方案

- 先切图谱、后补资源，或先切资源、后切图谱：都会产生用户可见的跨版本组合。
- 持续追逐 ActKG 最新版本直到切换：会反复使审核、绑定和收据失效，无法形成可重放发布。
- 对当前生产资源沿用“失败即排除”：会把技术缺陷转化为正式资源丢失。
- 强制每个节点具备三类关系边：会为满足数量制造没有教学依据的事实。
