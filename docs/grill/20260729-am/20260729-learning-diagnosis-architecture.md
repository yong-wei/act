# 助教场景学情精准诊断：架构决策与实施要点

> 本文记录 2026-07-29 访谈形成的架构结论。实施范围以
> `openspec/changes/teaching-assistant-learning-diagnosis/` 为准。

## 背景

教师需要基于受治理的作业、测验、知识进度和能力快照识别班级与学生的薄弱点。当前变更先建立可执行、可鉴权、可审计的后端基础；教师仪表盘入口和报告展示由后续前端变更承接。

## 架构决策

### D1：诊断证据

- 知识进度是薄弱知识点判断的基础证据。
- 能力快照用于班级维度聚合和跨域不平衡判断。
- 任何诊断结论都必须携带证据引用、证据截止时间、覆盖率、置信度和局限说明。
- 缺失证据不能以零值替代。

### D2：诊断触发

诊断由教师主动请求。后台定时任务只维护确定性风险标记，不生成诊断报告，也不触发教学行动。

### D3：风险标记

当前诊断仅使用三类确定性风险：

- `constraint`
- `stagnation`
- `cross_domain`

`participation` 和 `ai_misuse` 只保留为历史审计记录，不进入当前风险输出。扫描器依据受治理证据创建、更新、解除或保持风险状态。单纯经过一段日历时间不能取代证据状态迁移。

### D4：诊断范围

- 班级级报告：班级能力覆盖、均值、薄弱点和当前风险分布。
- 学生级报告：该生知识进度、能力证据和当前风险摘要。
- 学生级查询必须验证学生仍属于教师当前班级。

### D5：Konling 诊断模式

`teacher-diagnosis` 是仅供教师使用的 Konling 模式，提供三个只读工具：

- `get_student_risk_flags`
- `get_class_competency_summary`
- `get_student_knowledge_progress`

工具在服务端重新验证教师、活动班级和学生成员关系。工具只返回允许的摘要字段，不返回原始答案、事件载荷、私密对话或原始证据 JSON。

### D6：报告持久化

诊断报告保存为结构化 JSON，并单独记录：

- 班级、创建教师和可选目标学生；
- 证据引用和证据截止时间；
- 来源覆盖率、置信度和局限；
- 生成器版本。

报告写入和读取共用同一套班级所有权与成员关系校验。报告内容递归拒绝已知的原始或私密证据字段。

### D7：诊断到备课

包含知识节点的报告发现项可以携带备课导航链接。该链接只负责导航，不自动创建备课包、练习或干预记录，教学决定仍由教师完成。

## 实施边界

本次变更包括：

- 风险扫描规则、分页执行、调度和队列消费者；
- Konling 教师诊断模式与三个受控工具；
- `DiagnosisReport` 数据模型、迁移、读写服务和 API；
- 知识节点到备课入口的导航链接；
- 授权、脱敏、状态迁移和持久化测试。

本次变更不包括：

- 教师仪表盘的诊断按钮；
- 班级或学生报告展示页面；
- 学生侧诊断界面；
- 自动教学干预。
