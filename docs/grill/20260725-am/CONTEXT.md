# 教材检索、引用与阅读

该上下文统一教材运行资源在检索、引用和自由阅读中的领域语言。

## 语言

**教材结构单元**：
依照教材原有标题、编号和语义边界形成的最小完整阅读与引用单位；同一版本中的教材结构单元互不重叠，只保存自身直属正文，并保留其祖先层级。父级只承载自身引言和导航，不复制后代正文；引用优先定位到能够完整支撑结论的最深层单元，跨越多个子项的结论才引用父级或多个子项。
_避免：任意字符块、检索窗口、整章引用_

**教材检索窗口**：
围绕一个教材结构单元组合必要上级说明或相邻内容形成的检索上下文；它可以与其他窗口共享内容，并以全文参与候选召回，但不能成为用户引用的定位目标。窗口内每段内容必须保留所属教材结构单元的稳定标识。
_避免：教材结构单元、独立引用块_

**教材 RAG**：
以用户问题和服务器持有的通用页面上下文查询教材检索窗口，通过词面和语义召回取得正文候选，并把经过教材证据裁决的结构单元交给模型回答和引用。它作为共享工具加入需要课程知识支撑的页面工具合同，由模型结合当前问题与既有页面上下文自主决定是否调用；导航、状态查询等不需要教材证据的回答不自动执行外部检索。RAG 负责“哪段教材正文能够支撑当前回答”。
_避免：每条控灵消息无条件检索教材、只按旧图谱绑定取内容、把召回窗口直接当引用、用关系扩展代替正文检索_

**教材向量召回**：
使用同一嵌入模型把教材检索窗口和查询转换为向量，按向量相似度取得语义候选；向量可以存放在文件型索引、专用向量库或 PostgreSQL `pgvector` 中，是否使用向量与选择哪种存储方式是两个独立问题。
_避免：把 pgvector 等同于向量模型、只生成教材向量而不生成查询向量、用向量相似度直接判定引用充分性_

**文件型教材混合索引**：
随教材运行态发布的只读中文词面索引、连续向量矩阵、窗口元数据和正文文件偏移，覆盖当前六部教材及一个参考集合。每个应用进程的常驻索引预算不超过 150 MiB，教材正文只在窗口命中后按偏移读取；初期使用精确向量检索，只有实际并发基准不达标时才引入近似近邻索引。
_避免：每次请求重新读取全部教材、JavaScript `number[]` 向量、全部正文常驻内存、未经基准直接引入复杂近邻服务_

**教材嵌入服务**：
教材检索窗口的离线向量和运行时查询向量统一通过硅基流动 API 生成，使用同一个经过教材检索基准验证并固定版本的向量模型；索引清单记录模型标识、维度和内容哈希。离线向量、词面索引和元数据在本地教材导出时生成、验收并随运行态一起部署，生产服务器只负责加载和查询，不在启动或首次请求时构建索引。本地导出按嵌入模型、维度和规范化内容哈希复用未变化窗口的可再生缓存，只为新增或变化窗口调用服务；最终运行态索引仍完整重建，缓存不部署且不作为真源。运行时嵌入服务暂时不可用时只执行中文词面召回，并在开发诊断中明确显示降级原因。
_避免：导出和查询使用不同模型、生产部署时临时生成索引、每次导出重复嵌入全部未变化内容、把本地缓存当作教材真源、运行时静默返回零向量、把聊天模型当作嵌入模型、本地容器重复部署嵌入模型_

**教材插图视觉检索**：
以 `Qwen/Qwen3-VL-Embedding-8B` 为候选建立独立、非阻塞的插图检索实验，分层评估框图、响应曲线、根轨迹、频域图和一般示意图。正文混合检索、引用和阅读器达到验收门槛即可上线；只有视觉通道相对“标题、图片描述和所属正文”的文本检索产生明确增益时，才在后续为全部插图生成独立视觉索引。正文继续使用文本嵌入模型，插图引用定位到其教材片段锚点。
_避免：用视觉模型统一替代正文模型、让视觉实验阻塞正文 RAG 上线、未经专项基准索引全部插图、把图像召回等同于回答模型已理解图像_

**教材候选重排**：
词面、文本向量和可选视觉向量召回约 20—30 个窗口后，通过硅基流动重排服务结合完整查询与候选正文进行精排，再交给教材证据裁决。重排服务失败时退回本地融合排序；重排分数不能绕过直接支撑门槛、教材来源优先级或引用定位规则。
_避免：对全量教材调用重排、把最高重排分数直接视为可信引用、重排失败即无法回答_

**`pgvector`**：
PostgreSQL 的向量字段与相似度索引扩展，负责共享存储、过滤和检索向量，不负责生成向量，也不是实现语义召回的必要条件。静态且规模有限的教材语料可以使用随运行态发布的文件型向量索引。
_避免：嵌入模型、RAG 本身、教材结构索引_

**教材检索交接**：
查询阶段只把召回并裁决后的少量教材窗口、所属结构单元标识和引用编号交给控灵；全量教材和全量索引只存在于检索层，不进入模型上下文。
_避免：把整本教材放入提示词、只交引用标题不交正文、让模型自行遍历全部教材_

**回答引用编号**：
服务端在生成回答前为教材内容和学习证据分配统一的 `[1]`、`[2]` 序列，模型只能使用已分配编号。教材编号打开统一教材阅读视图，学习证据编号在同一来源列表中标明证据类型和可用定位；服务端通过兜底解析器规范化模型返回的非标准引用格式。
_避免：`[content: ...]`、原始 citation ID、内容与证据两套编号、由模型自行创造编号_

**引用修复重试**：
兜底解析器只执行确定性规范化；首轮仍存在未知或歧义引用时，将原始用户问题、首轮使用的完整服务端上下文、已分配引用表、首轮回答和全部未解析项组成冻结的裁决上下文，只调用模型一次并要求返回引用映射，不重新生成回答正文。重试后仍无法确认的引用保持未解析；生产正文移除其原始 ID、异常语法和无效链接，只保留已核验引用。部分失败时在引用区显示“部分引用未能核验”；全部教材引用失败时仍保留回答正文，并显示“引用未能核验”。具体原因只进入开发诊断。
_避免：模糊猜测来源、重跑完整回答、遗漏首轮上下文、多次循环修复、第二轮引入新的引用、因全部引用失败隐藏正文、向用户暴露内部引用标记_

**流式回答纠正**：
首轮回答不因引用兜底而延迟，直接完整流式显示；需要引用修复重试时，服务端根据映射生成同一消息的新修订版本，并原位替换正文、引用和对应最终状态，不创建第二条回答。
_避免：等待全部校验后才显示首字、追加一条“纠正回答”、让首轮和修订版同时留在对话中_

**控灵上下文能力**：
全平台控灵体系具备查询个性化状态和学习路径上下文的能力，但单个页面只暴露与其场景相关的最小工具集，以节省上下文并使模型行为聚焦；模型在当页可用工具中自主决定本轮是否调用。页面当前状态通过项目既有的通用上下文链路随聊天请求进入服务端，并注入系统提示词和需要它的检索过程；不同页面使用各自已有的页面状态，不把知识图谱的选中节点固化为全平台合同，也不另建“这个概念”等指代问题的专用补全路径。新版教材 RAG 保持现有上下文注入机制，只修改检索、证据交接和引用链路所必需的部分。工具可用但未调用属于正常决策，只有工具不可用、调用失败，或回答已作出个性化或路径结论却缺少相应上下文时才标记降级。
_避免：把知识图谱页面症状收缩为页面专用修复、概念解释专用例外、重复实现页面指代补全、强制每轮调用全部状态工具、每页暴露全平台工具、把自主未调用记为缺失_

**页面工具合同**：
由服务端按照页面类型、控灵模式和用户角色声明当页允许的最小工具集；同一轮开始后工具集保持不变，不根据查询关键词或模型中间输出再次动态路由。
_避免：客户端决定工具权限、每轮预调用模型选择工具、生成过程中临时增加工具、所有页面共享完整工具表_

**控灵诊断可见性**：
开发环境继续显示上下文、工具、检索、引用和降级诊断，生产环境不显示这些内部状态；环境差异只影响诊断展示，不改变实际检索、工具能力和回答结果。
_避免：生产环境暴露内部诊断、通过隐藏诊断掩盖运行差异、开发与生产执行不同回答逻辑_

**结构化关联检索（SAR）**：
从服务器已经掌握的稳定实体和受治理关系出发，关联知识节点、能力、资源、路径、学习事实及引用候选；它为 RAG 提供查询扩展和候选引用信号，但不负责在教材全文中寻找语义相近正文，也不直接证明教材内容能够支撑结论。
_避免：SAG、向量检索、教材全文搜索、绑定即证据_

**教材证据裁决**：
检索窗口召回后，系统按窗口内的教材结构单元拆解候选、去重并重排，将少量候选正文及服务端引用编号交给回答模型，由回答模型只选择直接、完整支撑当前结论的最小单元或片段锚点。服务端校验引用编号和覆盖情况；首版不增加独立裁决模型，只有端到端引用准确率未达验收门槛时才引入。
_避免：把检索窗口直接显示为引用、固定引用窗口中心单元、以相邻命中冒充直接证据_

**现有图谱绑定信号**：
当前知识节点的名称、别名、描述及“节点—教材内容”绑定只用于扩展教材候选，不构成直接证据，也不能绕过教材证据裁决和教材来源优先级。
_避免：绑定即引用、旧绑定强制入选、用图谱相关性代替文本直接支撑_

**教材作者态真源**：
Mathpix 高质量转换后按现有章节文件保存的教材 Markdown；它保留原始内容与校订边界，不为适配检索、引用或网页路由而物理拆分。
_避免：运行态目录、检索分块、网页页面文件_

**教材运行态结构投影**：
导出器从教材作者态真源解析并生成的分层目录、稳定标识、索引和内容文件；它服务于检索、引用定位和统一教材阅读视图，可以重新生成，不反向改写作者态真源。
_避免：新的教材真源、手工维护的副本、作者态物理拆分_

**教材运行态格式切换**：
本次重新导出最终以教材结构单元、教材检索窗口和统一阅读索引替换现有 `sections/chunks/search-documents/citation-map`；系列开发期间允许生成一套未接入生产的新版运行态测试产物，供解析、结构审计、索引和检索独立验证。最终切换时所有运行态消费者原子迁移，并删除旧格式和过渡测试产物；不生成旧格式兼容投影，也不保留旧 section/chunk 到新版结构单元的映射或重定向。
_避免：测试产物提前接入生产、双格式长期并存、旧格式回退路径、两套生产解析结果、历史教材链接兼容层_

**教材运行态停服切换**：
新版教材运行态与匹配的新版应用必须先在本地完成验证，再采用短暂停服方式整体上线：先停止生产应用，再部署并校验新版运行态，随后启动新版应用并执行冒烟验证。上线过程失败时保持停服，修复并重新验证新版后继续上线，不恢复旧应用或旧运行态；也不为无停机发布保留双版本目录、兼容层或运行时切换指针。
_避免：未经本地验证直接上线、新旧应用与运行态交叉运行、失败后恢复旧格式、双版本长期保留、为教材导出引入额外灰度机制_

**教材运行态一致性更新**：
教材发生较大变更或重新导出时，由导出流程同步更新结构单元、检索索引、引用定位和相关派生数据，并在上线前完成本地验证。应用启动时不比较教材内容哈希，也不因细微文本改动拒绝启动；教材版本变化较少，不为此增加严格的运行时校验。
_避免：用启动门禁约束空格等无语义改动、应用每次启动重新验证教材内容、引用和索引脱离导出流程单独更新_

**教材运行态分级验证**：
日常小范围教材修改只重新导出并验证受影响教材及其索引、引用和派生数据；本次不兼容的运行态格式整体替换必须对六部教材和一个参考文献集合执行全量导出、结构检查与检索—引用—阅读定位端到端验收。
_避免：任何细微修改都触发七套来源全量验收、格式整体迁移只抽查局部来源_

**教材 RAG 交付系列**：
主体工程划分为五个有依赖关系的子变更：一是教材结构校订、确定性解析器和新版临时运行态导出；二是语义基准、嵌入缓存、文件型混合索引和外部重排；三是统一教材阅读器、稳定层级路由和访问控制；四是控灵教材检索工具、统一引用编号、修复重试、后台优化刷新及最终运行态切换；五是非阻塞的插图视觉检索实验。第四项依赖前三项并负责删除旧格式和全部过渡产物，第五项不阻塞发布。
_避免：把全部工程压入一个无法独立验证的变更、让前置变更提前切换生产、让视觉实验阻塞正文 RAG、最终保留过渡产物_

**教材检索语义基准集**：
由 GPT 子代理读取教材结构单元及其语义，为真实控灵问题标注能够直接支撑回答的最小结构单元，覆盖概念、公式、图表、中英文术语和跨教材表达。同一问题存在多个可靠来源时，记录所有直接、完整支撑问题的合格单元，并依据来源优先级单独标记首选引用；检索命中任一合格单元即算召回成功，最终引用优先选择首选来源。基准集按问题类型和教材来源分层，约 80% 用于调整召回、重排和参数，20% 固定用于独立验收。它是项目级轻量开发与回归工具，以达到基本可用为目标，不追求研究级规模或统计显著性。正式执行使用项目允许的 `gpt-5.6-sol` 命名子代理。
_避免：仅根据标题自动生成自证式问题、只保留一个答案而误判其他正确召回、把检索模型自身的结果当作标准答案、调试与验收使用完全相同的问题、为项目开发建设研究级评测工程_

**教材检索基本可用门槛**：
独立验收集中，至少 80% 的问题必须在前 10 个候选中召回一个由语义基准集标注的合格结构单元；最终显示的引用编号与跳转必须全部有效；“单位阶跃响应”等已知失败案例必须召回能够直接支撑回答的来源。
_避免：只证明优于旧检索而没有绝对可用下限、以无效引用换取召回率、遗漏已知真实失败案例_

**教材外部检索软超时**：
向量查询与外部重排合计等待约 2 秒后仍未完成时，以现有词面召回或本地融合结果开始流式回答；生产环境只显示简短的进行中状态“正在后台优化响应”，不暴露模型名、超时值、错误码或内部诊断原因。外部调用在后台继续等待，后台上限根据真实实验延迟的 P95 设置。后台结果返回后，以结构单元稳定标识确定性比较降级回答实际使用的证据集合与最终证据集合：首选来源或已用引用集合发生变化时，重新生成并替换同一条回答；结果等价时只结束进行中状态，不重复生成，也不另行调用模型判断是否刷新。
_避免：为外部服务无限阻塞首字输出、超时后立即取消仍可能及时返回的高质量检索、在生产环境暴露内部诊断、任何后台返回都触发重生成、用额外模型调用裁决刷新、把刷新结果显示为第二条回答_

**教材结构解析**：
正式导出以确定性规则为主：通用编号规则结合每本教材的声明式解析配置生成层级，无法确定的结构必须显式失败。模型只对分散样本和异常结果进行审核，不参与正式导出结果的生成。
_避免：模型每次重新推断层级、静默接受歧义、只验证导出命令成功_

**教材结构异常**：
导出后表现为结构单元过大、过小、空缺、编号跳跃、层级突变、正文挂接错误或自然编号未被识别的结果。确认由 Mathpix 作者态结构缺损引起时，修复作者态真源后重新导出；确认属于解析规则缺口时，修改确定性解析配置。
_避免：只在运行态手工修补、用检索窗口掩盖结构错误、未经原文核对自动改写_

**教材结构校订闭环**：
先以确定性解析器生成候选运行态，再运行结构异常检测，并对每章的最深层单元、边界、编号序列以及最大和最小单元进行分散采样审核。审核确认作者态有缺损时修复作者态，确认规则有缺口时修复解析器，然后重新导出和复核。
_避免：导出前无证据地通读改写全部教材、只修运行态产物、异常未归因即调整规则_

**教材定位**：
指向特定教材版本中一个教材结构单元的稳定层级地址；结构单元标识由教材版本和确定性结构路径生成，优先使用原文自然编号，无编号单元使用父级内的确定性序号，不维护独立的永久映射登记表。正文或标题文字修改不改变已有编号单元的标识。引用通过教材定位打开对应内容，并保留其在全书中的上下文。
_避免：模型生成链接、内容哈希直接充当路径、仅指向整章、检索窗口 ID、长期维护独立标识映射_

**教材片段锚点**：
教材结构单元内部公式、插图或表格的稳定定位标识；这些内容仍归属最近的结构单元，不建立独立目录。引用命中片段锚点时，阅读器打开所属结构单元并聚焦该公式、图或表，同时保留周围语境。
_避免：公式目录、插图页面、脱离所属语义单元的表格引用_

**教材来源优先级**：
控灵先排除不能直接、完整支撑当前结论的教材内容，再在合格来源中依次优先采用胡寿松《自动控制原理》第八版、刘胜版和英文教材；中文来源只有间接提及时，由直接可靠的英文来源替代。胡寿松第七版只补充第八版没有覆盖的独有内容，习题解析只用于习题、解法和例题分析，控制百科只作补充参考；这些资源不能挤占能够直接支撑结论的第八版、刘胜版或英文教材引用。
_避免：用弱相关中文内容占位、固定只用一本教材、英文来源与中文来源无差别排序、让补充资源按分数覆盖权威教材_

**统一教材阅读视图**：
平台用于展示全部运行态教材的共同双栏阅读界面：左侧为可展开的全书章节导航，右侧为当前教材结构单元正文。它既可从引用直接定位内容，也可沿全书层级导航并自由浏览任意单元；在平台页面内以可关闭弹窗呈现。定位链接可以复制和分享，但教材正文仅向已登录且具有相应课程访问权限的用户开放。
_避免：只显示引用片段、每本教材独立阅读器、没有全书导航的 Markdown 页面、公开暴露教材正文_

**引用定位视图**：
统一教材阅读视图从引用进入时的状态，通过 `/textbooks/{bookId}/{edition}/{...unitPath}` 稳定路径打开被引用的教材结构单元，通过片段锚点进一步定位公式、插图或表格；平台内点击引用时以拦截式弹窗打开并更新 URL，关闭后恢复原页面和原 URL，直接访问、刷新或分享同一 URL 时则渲染独立全页双栏阅读器。
_避免：脱离全书的孤立文本片段、只显示检索窗口_
