# Keep Candidate Comparison Explicit, Read-Only, and Versioned

候选比较页采用显式选择、只读解释和版本化结果身份：进入比较入口时先展示批次事实摘要，不隐式选择比较对；用户选择两个不同候选后才加载两两差异。比较结果由候选批次、路径版本和规范化的无方向候选对共同标识，批次、版本或比较对变化会使旧响应失效。比较流程不得创建、覆盖或推进学习路径，也不得从事实差异推导新的系统推荐；这样可以避免过期结果覆盖当前选择，并保留路径执行状态的单一写入边界。

## Considered Options

- 自动比较候选列表中的前两条：被否决，因为它隐藏了比较对象，三候选时也无法表达用户真正想看的方案对。
- 把比较关系作为有方向的 `left/right`：被否决，因为交换左右会造成重复请求、缓存分裂和不一致的事实来源。
- 在比较摘要中自动评分并给出最佳路径：被否决，因为候选比较没有新增的推荐依据，事实展示不能替代正式推荐流程。
