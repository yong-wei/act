# 将权威迁移拆分为十二个聚焦变更

## 状态

已接受

## 背景

权威图谱迁移同时涉及发布合同、数据库、查询投影、前端图谱、控灵、课程覆盖、资源绑定、检索、教学关系、路径、学习事实和生产切换。将这些内容压缩为少数大型变更，会使数据合同与运行消费者相互遮蔽，也无法为局部能力建立清晰验收边界。

## 决策

迁移按以下顺序形成十二个变更：

1. Release 接入合同：ReleaseSet 锁定、Schema 校验、数据库模型、原始载荷与哈希、事务导入及往返验证。
2. Repository 与投影：候选与活动权威隔离、统一查询边界及三项首轮投影。
3. 候选图谱：V2 API、画布、详情、类型与谓词、核心与扩展关系，以及迁移期新旧切换。
4. 候选控灵：新版页面上下文、Canonical 搜索和邻居工具，以及只读诊断边界。
5. CourseCoverage Overlay：Git 作者态、三类课程角色、确定性导入和运行查询。
6. 资源 Canonical 绑定：Crosswalk、增量候选、独立审核和有效资源门禁。
7. RAG 迁移：Canonical 实体对齐、关系扩展及 EvidenceSegment 到正文引用链。
8. KAQ 与教学关系：Canonical 绑定及未来 Teaching Projection 接管接口。
9. SAR 迁移：跨 Repository、KAQ、资源和学习状态的查询时组合。
10. 学习路径迁移：停止旧路径、保留目标并重新规划 Canonical 路径。
11. 新学习事实边界：Canonical ID、Release、修订引用及候选写入禁令。
12. Legacy Archive 与生产切换：只读归档、最新生产数据本地演练、停服迁移和一次性权威切换。

每个变更必须以其真实上游已发布合同为依赖，并具有独立验收产物。KAQ 迁移先于 SAR，确保 SAR 能够沿显式 Canonical 绑定组合 KAQ Overlay。前十一个变更的完成均不单独改变生产知识权威；正式权威切换只发生在第十二项。

## 结果

- 数据接入、用户体验和业务消费者可以分别验证。
- RAG、SAR、KAQ、路径和事实写入不会被一个综合变更相互阻塞。
- 最终生产切换仍保持单次、完整和可演练。
