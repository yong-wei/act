# 使用关系化信封与 JSONB 载荷混合保存权威 Release

## 状态

已接受

## 背景

ACT 需要对 Canonical ID、关系端点、谓词、Release、核心与扩展等级、来源和证据执行稳定查询、唯一性约束和索引；同时，ActKG 将继续增加对象类型及类型专属字段。如果为每种对象类型建立固定表结构，新 Schema 会频繁触发 ACT 核心数据库迁移。若全部保存为无结构 JSONB，则身份、端点和版本约束难以可靠执行。

## 决策

1. Release、Canonical Object、关系、来源、证据建立稳定的关系化信封。
2. Canonical ID、对象类型、关系端点、谓词、ReleaseSet、治理等级、来源身份和版本等常用字段使用关系化列、外键、唯一约束和索引。
3. 每个对象和关系的完整类型专属字段保存在经对应锁定 ActKG Schema 校验的 JSONB 载荷中。
4. 原始 Engineering Release 及其哈希一并保存，用于导入后往返核验。
5. 新增 Schema 合法类型可以先以通用只读方式无损保存；消费者只有在显式声明语义支持后才能使用该类型参与业务计算。

## 结果

- 高频查询和结构门禁具有数据库约束。
- ActKG 增加类型时不必立即扩展 ACT 核心表。
- 原始 Release、完整 JSONB 和规范化关系化信封可以共同验证无损性。
