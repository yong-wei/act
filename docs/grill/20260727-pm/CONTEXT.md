# 权威知识图谱迁移

该上下文统一 ACT 从旧课程知识图谱迁移到 ActKG 权威发布版期间的产品与治理语言。

## 语言

**权威基座渐进建设**：
在不改变当前生产知识权威的前提下，逐步建立 ActKG Release Repository、完整类型模型、消费投影、活跃消费者重新绑定和影子验证能力。基座具备运行能力不表示对应 ActKG 数据已经接管生产知识身份。
_避免：局部权威切换、完成接口即完成迁移_

**十二项迁移变更系列**：
权威迁移按 Release 接入合同、Repository 与投影、候选图谱、候选控灵、CourseCoverage Overlay、资源 Canonical 绑定、RAG、KAQ 与教学关系、SAR、学习路径、新学习事实边界、Legacy Archive 与生产切换依次实施。每项变更只交付一个可独立验证的运行边界，后续项依赖已完成的稳定合同，不因局部完成而提前改变生产知识权威。KAQ 必须先于 SAR 提供 Canonical 绑定，避免 SAR 跨权威组合缺少可遍历边界。
_避免：一个主体变更覆盖全部消费者、把数据底座与生产切换合并验收、为减少变更数量牺牲边界_

**生产权威一次切换**：
ActKG 全课程发布版、活跃引用迁移和正式门禁全部完成后，将生产知识身份从旧图谱一次性切换到 ActKG；切换前 RAG、SAR、学习路径、资源绑定和学习事实等正式业务仍使用统一的旧生产权威。
_避免：按知识域混合权威、查询为空时跨权威回退_

**双版本图谱预览**：
迁移完成前，知识图谱前端允许用户在旧版图谱和 ActKG 新版候选图谱之间切换查看，并默认显示新版候选图谱。该切换只改变图谱前端的展示数据，不改变生产知识权威或其他业务消费者的数据来源。
_避免：双权威运行、以默认显示版本决定业务知识身份_

**权威工程语义**：
ActKG Release 中异质知识对象的规范类型、类型专属字段、工程关系谓词、方向、证据、来源和治理状态。ACT 必须无损保存并能够往返验证这些语义，不能把公式、系统模型和知识陈述统一压成普通理论节点，也不能把有方向的工程关系压成无序关联。
_避免：统一 THEORY 节点、三类关系替代工程关系、从画布 DTO 反推权威数据_

**教学语义投影**：
面向教学组织、资源编排和学习路径使用的包含、先修、关联等教学关系层。该层与权威工程语义并存但不覆盖工程关系；当前可以由 ACT 独立维护，后续在 ActKG 正式发布教学语义后迁移到相应权威发布内容。
_避免：把工程关系自动解释为先修、把教学关系写回工程关系、以现有三类关系限制 ActKG 本体_

**上游知识权威**：
由独立 ActKG 项目通过不可变 Release 发布的规范知识对象、工程关系、来源证据和治理结论。ACT 只能校验、固定版本、导入和消费这些内容；任何规范知识修订必须回到 ActKG 形成新的正式 Release。
_避免：ACT 导入后直接修改规范对象、双向同步两个可编辑真源_

**ACT 教学 Overlay 真源**：
ACT 仓库独立维护的课程编排、KAQ、资源绑定以及 ActKG 尚未正式发布的教学语义。Overlay 必须引用固定的 ActKG Canonical ID 和 Release，不得复制或改写上游知识权威。
_避免：第二套规范知识本体、以教学绑定覆盖工程语义_

**权威知识数据库读模型**：
ACT 对固定版本的 ActKG Release 完成校验后，以事务方式导入能够无损表达 Release 的数据库结构；运行时所有图谱和知识消费者统一经 AuthoritativeKnowledgeRepository 查询数据库，不直接读取 Release 文件或 ActKG 项目。数据库可以同时保存新版候选 ReleaseSet 和旧生产投影，但二者具有明确状态和用途。
_避免：文件优先数据库回退、运行时读取上游项目、用旧 KnowledgeNode 表压缩新 Release_

**混合权威持久化**：
Release、Canonical Object、关系、来源、证据的稳定身份、端点、版本、治理等级和常用查询字段使用关系化列与约束；各 `canonical_type` 的完整类型专属字段保存在经锁定 Schema 校验的 JSONB 载荷中，并同时保留原始 Release。新增合法对象类型可以先无损接入，不要求立即修改核心表结构。
_避免：每种类型一套易漂移表结构、只有 JSONB 而缺少身份约束、关系化摘要代替完整权威载荷_

**候选 ReleaseSet**：
已经导入并通过接入校验、可供新版图谱前端预览和影子验证，但尚未成为生产知识权威的一组 ActKG Release。候选状态不能被 RAG、SAR、学习路径、资源绑定或学习事实写入误作活动权威。
_避免：默认显示即正式生效、候选数据参与生产事实_

**首个公开候选 ReleaseSet**：
`root-locus-engineering-v0.1` 在 Release 接入、Repository、候选图谱和候选控灵四项变更完成并通过验证后，立即向所有现有图谱用户开放，作为默认新版候选视图。界面必须明确说明它是根轨迹局部发布版、实际覆盖范围以及教学关系尚未发布；所有正式业务消费者继续使用旧生产权威。
_避免：把局部发布版表述为全课程图谱、因默认显示而激活正式消费者、等待全课程完成才验证候选底座_

**Release 级无损**：
ACT 保存 ActKG Engineering Release 的原始载荷与哈希，并完整导入其中正式发布的对象、关系、类型专属字段、证据、来源引用和版本信息，使导入结果能够与 Release 往返核验。无损承诺不要求 ACT 复制 ActKG 的抽取运行、候选对象或审核草稿。
_避免：投影级无损冒充 Release 级无损、复制完整知识生产过程_

**Release 成员资格**：
上游 `release_status=RELEASED` 与 Release 实体清单共同决定正式成员。规范对象中冻结保留的 `publication_status=unpublished` 描述进入 Release 前的实体状态，不能用于过滤已经列入 `canonical_nodes`、正式关系或来源映射的内容。
_避免：按对象旧状态裁剪 Release、只导入标记 published 的对象、ACT 重新解释上游发布范围_

**数据集血缘引用**：
ACT 通过 CTKGDataset 哈希、发布标识和可解析位置追溯 Release 的完整知识生产血缘；抽取和审核过程仍由 ActKG 保存和治理，不进入 ACT 运行数据库。
_避免：ACT 内维护第二份抽取历史、无法追溯 Release 来源_

**历史知识事实冻结**：
历史 LearningFact、事件、画像、诊断、风险、成长、推荐、班级聚合和已完成路径继续由其原知识修订或不可变 legacy snapshot 解释。迁移不建立历史 Canonical sidecar，不将旧事实按新图谱重新聚合，也不改写历史引用。
_避免：用当前语义解释历史事实、历史事实全库回填、历史掌握度迁移_

**新事实权威引用**：
生产权威一次切换后产生的新学习事实必须写入明确的 ActKG Canonical ID、Release 和知识修订标识；切换前不得向候选 ReleaseSet 写入正式学习事实。
_避免：新事实继续写 legacy ID、候选预览产生正式事实、双写新旧知识身份_

**ActKG 规范身份**：
ActKG Canonical ID 是迁移后规范知识对象的唯一身份。ACT 旧节点 ID 只存在于归档旧图和旧知识修订中，不建立长期或临时的旧 ID 到 Canonical ID 映射合同。
_避免：优先复用 ACT 旧 ID、双规范身份、全局 LegacyCanonicalMapping_

**教学语义空缺**：
候选 ActKG Release 尚未正式发布包含、先修或关联等教学关系时，新版候选图谱只显示已经发布的工程对象与工程关系，并明确相应教学能力尚未可用。ACT 不把旧图谱教学关系复制到新版候选图谱，也不从工程关系自动推断教学关系。
_避免：以旧关系补齐新版、工程关系自动转先修、候选图谱伪装教学完整_

**教学语义接入点**：
为 ActKG 后续正式发布的教学关系预留的 Teaching Projection 接口。教学 Release 到达后通过同一权威接入、校验和投影机制进入 ACT，不需要改造权威工程对象或重建临时旧关系 Overlay。
_避免：提前固化旧教学关系、为每次教学发布重构底座_

**KAQ 规范知识绑定**：
ACT 的 KAQ 知识节点通过带有绑定角色、ActKG Release 和审核状态的显式关系指向一个或多个 ActKG Canonical Object。KAQ 节点表达教学和能力治理中的知识角色，不与工程对象合并，也不继续绑定退役的 ACT runtime ID。
_避免：删除 KAQ 教学身份、KAQ 长期绑定 legacy ID、把能力关系写入工程本体_

**组合式学习路径语义**：
学习路径继续使用 ACT 管理的 KAQ 能力、素养和教学关系，并通过 KAQ 规范知识绑定解析到 ActKG 知识身份；ActKG 正式发布教学语义后，再将 Teaching Projection 作为经审核的路径输入加入或替换相应 ACT 关系。
_避免：用工程关系直接生成路径、ActKG 教学语义未发布时强制切换路径_

**Legacy 整体归档**：
正式权威切换时，将旧图谱节点、关系、旧知识修订及其运行解释能力作为完整 legacy snapshot 归档，不要求每个旧节点对应一个 ActKG 对象，也不逐项建立处置映射。
_避免：为旧节点强行寻找新身份、删除历史解释所需旧图、把归档理解为新图谱组成部分_

**Legacy Archive**：
生产权威切换后独立保留的旧图只读归档入口，固定展示切换时封存的旧节点、关系、知识修订和旧节点笔记。归档延续切换前各角色对旧图内容的可见范围，个人旧节点笔记仅所有者可见，管理员可以执行归档审计。它不再属于主知识图谱，不提供编辑、控灵问答、资源推荐、学习路径、新事实写入或任何运行时回退能力。
_避免：在主图谱长期保留旧版切换、归档扩大内容或笔记权限、把归档入口继续当作业务 API、归档数据参与新计算_

**活跃消费者重新绑定**：
当前课程、资源、KAQ、学习进度、笔记和未完成路径等仍需继续运行的消费者，在各自迁移阶段依据新权威语义重新绑定 ActKG Canonical ID。重新绑定以消费者内容和用途为依据，不从旧节点名称或 ID 继承。
_避免：全局映射批量改写、旧绑定自动成为新绑定、重新解释历史事实_

**权威来源证据对齐**：
由 ActKG 管理的 Canonical Object 到 Source Object 和 EvidenceSegment 的受审核对应关系，用于说明规范知识的来源依据。ACT 通过稳定来源身份、片段身份、版本和内容哈希解析该证据，但不复制或改写其权威结论。
_避免：教学资源绑定代替来源证据、ACT 重新裁定 ActKG 证据_

**ACT 内容检索与引用链**：
ACT 管理教材正文、教材结构单元、RetrievalChunk、CitationTarget、访问权限和渲染，并通过 Crosswalk 将命中的内容定位到 ActKG EvidenceSegment。检索窗口和正文内容不进入 ActKG Release。
_避免：把全文装入知识图谱、EvidenceSegment 直接承担运行时正文_

**ACT 教学资源角色绑定**：
ACT 的课堂活动、作业、仿真、讲义等运行资源以讲解、练习、评价或引用等教学角色绑定 ActKG Canonical Object。该绑定描述资源如何用于教学，不等同于 ActKG 对权威来源证据的语义对齐。
_避免：证据对齐与教学用途混为一条关系、把 ACT 运行权限移入 ActKG_

**节点主导资源绑定**：
首次建立绑定以及新增或修订 Canonical Object 时，以节点语义档案为稳定上下文，查询已经建立的资源片段索引，并批量裁决召回的候选资源及教学角色。完整资源库不逐节点重复读入模型上下文。
_避免：逐节点装入全部资源正文、从旧 knowledgeNodeIds 继承绑定_

**变化端触发绑定**：
资源绑定采用双向增量触发：节点变化时只处理变化节点，资源变化时只处理变化资源；未变化的节点—资源片段对不重新裁决。两个方向使用同一候选对合同和绑定真源。
_避免：纯节点流程遗漏新资源、纯资源流程重复扫描旧资源、定期全量重绑_

**绑定裁决身份**：
一次节点—资源片段裁决由 Canonical Object ID 与修订、资源片段 ID 与内容哈希、绑定提示词版本共同确定。身份未变化时复用既有结论，任一组成发生变化时只使受影响候选对失效。
_避免：按运行批次重复调用模型、无边界清空全部绑定缓存_

**确定性资源绑定**：
资源片段能够唯一解析到 ActKG EvidenceSegment，并且 ACT 原子资源类型合同能够唯一确定讲解、练习、评价或引用角色时，绑定可以直接进入正式真源。
_避免：只有来源命中就推定教学角色、只有资源类型就猜测知识对象_

**语义资源绑定候选**：
词面、向量或 GPT 识别出的节点—资源片段关系，只要缺少唯一 EvidenceSegment 对齐或确定性教学角色，就只能形成带证据的候选，完成独立语义审核后才能发布。
_避免：高相似度自动生效、GPT 置信度代替审核、旧绑定直接继承_

**独立绑定审核**：
语义资源绑定候选由与候选生成相互隔离的 GPT 审核上下文读取 Canonical 语义档案、原子资源片段和拟议教学角色，给出接受、拒绝或争议结论。生成模型不能批准自己的候选。
_避免：同一上下文生成并批准、只输出无依据置信分_

**绑定争议队列**：
独立审核标记为争议、高影响或与候选生成结论冲突的项目进入人工裁定；其余经接受的候选仍须通过端点、角色、版本和唯一性确定性闸门后才能发布。
_避免：全部候选人工审核、争议项警告放行、GPT 接受结果绕过结构门禁_

**Canonical 辅助 RAG**：
RAG 使用 ActKG Canonical Object、别名、精确工程关系和 EvidenceSegment 引用执行实体对齐、查询扩展和候选正文定位；图谱信号只改变候选集合与排序，不直接证明回答结论。
_避免：图谱邻居直接成为引用、关系存在即正文充分_

**正文引用边界**：
控灵和其他回答的最终 `[序号]` 引用必须解析到 ACT 教材结构单元或片段锚点，并通过现有正文召回、重排和证据裁决。ActKG 发布包中的节点摘要、关系或 EvidenceSegment 存根不能代替用户可读教材证据。
_避免：Canonical Object 直接充当教材引用、只给存根不提供正文定位_

**SAR 查询组合**：
SAR 在请求期间分别查询 ActKG Repository 与 ACT 的 KAQ、资源、路径和学习状态 Overlay，再沿显式类型化绑定执行有限跳扩展。每个结果节点和边保留 namespace、权威来源、Release 或 Overlay 版本。
_避免：把所有数据复制为一张权威图、跨边界关联丢失来源_

**SAR 候选投影**：
SAR 组合结果是面向当前查询的可重建候选集合，只用于检索扩展和上下文组织，不回写为 ActKG 工程关系、ACT 教学关系或新的统一图谱真源。
_避免：查询结果晋升为正式关系、缓存候选成为第二真源_

**权威教学关系接管**：
ActKG 正式发布 Teaching Projection 后，知识对象之间的包含、先修、关联等教学关系以 ActKG 为权威。ACT 的 KAQ 继续拥有知识—能力—素养关系及具体教学运行语义。
_避免：KAQ 永久维护第二套知识—知识关系、ActKG 教学关系只作参考_

**教学关系冲突迁移**：
ActKG Teaching Projection 与既有 KAQ 知识—知识关系不一致时进入一次性审核；确认 ActKG 关系有效后，退役对应 KAQ 旧关系，不允许两个冲突版本同时供路径规划使用。
_避免：运行时长期裁决双关系、简单并集制造循环、未经审核直接覆盖_

**有效教学资源绑定门禁**：
正式权威切换前，所有当前已发布、可被推荐、可进入路径或能够产生学习证据的原子教学资源必须完成 ActKG Canonical 绑定并通过角色门禁。草稿、停用、归档资源和非教学资产不阻断切换。
_避免：为历史库存全量重绑、有效资源带未决知识身份上线、非教学资产制造虚假绑定_

**完整权威导入范围**：
ACT 对 ReleaseSet 锁定清单中的正式 ActKG Release 执行 Release 级完整导入和新版图谱展示，不因当前课程尚未使用某些对象而裁剪发布内容。
_避免：按课程范围删减 Release、只导入已有资源节点、课程扩展时重新拼接权威包_

**课程知识覆盖 Overlay**：
ACT 对具体课程声明哪些 ActKG Canonical Object 可以进入资源推荐、KAQ、学习路径、评价和新学习事实。未进入当前课程覆盖的正式对象仍可在权威图谱浏览，但不自动参与教学运行。
_避免：完整导入等于全部教学激活、在 ActKG 对象上写 ACT 课程状态_

**课程覆盖依据**：
Canonical Object 只有具备 `formal_objective`、`necessary_prerequisite` 或 `explicit_extension` 之一的显式课程角色，才能进入 CourseCoverage Overlay。资源绑定、教材出现和模型建议只可形成范围候选。
_避免：有资源即自动入课、同一 Release 全量教学激活、模型建议直接改变课程范围_

**课程 Overlay 作者真源**：
首轮 CourseCoverage Overlay 继续在 ACT 仓库的结构化 authoring 数据中维护，通过 Git 变更、确定性校验和审核治理，并在部署时事务性导入数据库运行投影。本次不建设教师在线编辑或数据库人工维护入口。
_避免：教师自助覆盖状态机、数据库成为第二真源、运行投影回写 authoring_

**全消费者切换门禁**：
生产权威一次切换前，图谱 API、控灵知识搜索、RAG 图谱扩展、SAR、KAQ、有效资源绑定、CourseCoverage、学习路径和新学习事实写入必须全部完成 Canonical 迁移与验证。切换后旧图只承担归档阅读和历史解释。
_避免：按消费者分批正式切换、长期双权威查询、旧图继续产生新事实_

**本地切换演练**：
正式部署前，导出切换前最新生产数据库并在本地受控环境恢复，使用与生产一致的应用修订、数据库结构、ReleaseSet 锁定清单、Overlay 和迁移命令完成整套权威切换，并验证新版图谱、全部知识消费者、Legacy Archive 及 Canonical 新事实写入。合成夹具可以用于自动化回归，但不能替代正式切换演练。
_避免：生产首次执行迁移、只验证前端预览、用简化夹具或过期数据库替代最新生产数据_

**停服权威切换**：
本地演练通过后停止生产应用、worker 和 scheduler，备份数据库，执行同一份已验证迁移，在事务内切换活动知识版本和 Canonical 写入边界；全部冒烟验证通过后才恢复服务。
_避免：在线双版本切换、迁移期间继续写事实、未经冒烟即开放服务_

**权威切换回滚窗口**：
生产切换只能在服务和 Canonical 事实写入恢复前回滚旧数据库与旧应用。一旦开放服务并产生新 Canonical 事实，旧图谱不再成为可回滚活动权威；后续问题通过再次停服的前向修复处理。
_避免：为回滚双写新旧事实、将新事实反向映射 legacy ID、开放后静默切回旧图_

**纯新版候选视图**：
迁移期图谱前端的新版模式只展示已经导入的 ActKG 正式 Release 内容，不混入 legacy 节点，也不在对象或关系缺失时自动回退旧图。界面同时说明当前 Release、覆盖范围和尚未发布的教学语义。
_避免：新版画布混合 legacy gap、查询为空隐式回退、把局部覆盖表示为全课程完整_

**显式旧版切换**：
用户需要查看尚未被 ActKG Release 覆盖的旧课程图谱时，主动切换到旧版模式。旧版和新版具有独立清晰的数据来源，切换不改变任何正式业务消费者或生产知识权威。
_避免：按单个节点自动跨图查询、组合画布、视图选择改变生产状态_

**全角色新版预览**：
所有原本有权访问知识图谱的教师和学生都可以查看新版候选视图并切换旧版，首次进入默认显示新版。新版规范内容只读，并明确显示 Release、当前覆盖范围和尚未发布的教学语义。
_避免：把候选预览限制为内部管理页、向学生隐藏已正式发布内容、以覆盖不全冒充完整课程图谱_

**ACT 权威内容只读**：
ACT 不允许直接修改 Canonical Object 或工程关系，也暂不提供问题反馈、跨项目提交或自动修订入口。画布布局、收藏、课程编排、KAQ 和教学资源绑定仍按各自 ACT 权限维护。
_避免：ACT PATCH 权威对象、从 ACT 发起 ActKG 修订、在 ACT 复制治理工作流_

**Release 修订提案**：
由 ActKG 发布与治理过程产生、与规范对象和关系内容分离的上游修订建议。提案进入独立版本化登记表并持续记录状态；Release 使用者定期审阅并决定是否纳入后续版本修订流程。ACT 暂不接收或上送用户反馈。
_避免：ACT 用户编辑即生成新 Release、ACT 反馈入口、提案自动改变当前权威内容_

**修订提案登记表**：
独立于不可变 Engineering Release 的版本化治理工件，记录提案身份、关联 Canonical ID、状态和处置进度。Release 包保存登记表快照或版本引用；状态变化产生新的登记表版本，不修改既有 Release 内容和哈希。
_避免：原地修改已发布 Release、只在下一版知识 Release 才显示进度_

**ACT 提案登记引用**：
ACT 只保存当前 Engineering Release 所引用的 RevisionProposalRegistry 版本和哈希，用于审计发布关联；不导入提案明细，也不在教师、学生或管理员运行界面中展示提案进度。
_避免：ACT 提案管理页、节点详情暴露未决治理问题、复制上游提案数据库_

**ReleaseSet 锁定清单**：
ACT 仓库中显式列出候选知识基座所接受的 ActKG Release 标识、版本、受控路径和哈希的可审查清单。只有锁定清单发生变更且全部接入校验通过后，发布包才被事务性导入候选数据库。
_避免：扫描目录自动接收、运行时追随最新版本、实验包隐式进入候选图谱_

**可复现候选知识版本**：
由锁定清单内容、各 Release 哈希、导入合同版本和投影版本共同确定的候选 ReleaseSet。相同 Git 修订和锁定清单必须生成相同数据库内容及投影摘要。
_避免：部署时动态选择 Release、候选版本无法复建_

**ReleaseSet 对象唯一性**：
同一个候选 ReleaseSet 中，每个 Canonical Object 和权威关系只能具有一个有效语义版本。多个并列 Release 重复携带同一身份时，其规范化内容必须一致；真实变更必须通过显式对象修订或 Release 取代关系进入。
_避免：按加载顺序覆盖、按领域保留多个真相、时间戳自动胜出_

**Release 冲突关闭**：
多个 Release 对同一 Canonical ID 或关系提供不一致内容且没有声明修订或取代关系时，整个候选 ReleaseSet 导入失败，不生成部分合并结果。
_避免：选择任一版本继续导入、记录警告后放行、同一图谱显示冲突副本_

**首轮消费投影集**：
权威基座首轮只实现 `act.canvas.v2`、`act.node-detail.v2` 和 `act.migration-review.v1` 三个可运行投影，分别服务新版画布、权威详情以及 Release 接入、Legacy 归档和活跃消费者重新绑定审计。每个投影声明所含字段、隐藏内容及源 ReleaseSet，不承担其他消费者的万能 DTO。
_避免：一次实现全部未使用投影、一个投影承载所有业务_

**后续消费者扩展合同**：
RAG、SAR、控灵、KAQ 和学习路径在首轮只获得稳定的 Repository 查询边界、Canonical ID、ReleaseSet 版本和相应类型合同，不提前生成专用投影；对应消费者进入迁移阶段后再实现和验证其 Profile。
_避免：空壳物化投影、教学语义未发布时伪造路径 Profile、消费者直接读取数据库表_

**双版本图谱 API**：
旧版图谱继续使用现有端点和 `UnifiedKnowledgeGraphPayload`；新版图谱使用独立版本化的 `act.canvas.v2` 与 `act.node-detail.v2` 合同。前端切换只选择对应 API，不在客户端拼接、补全或转换两套图谱。
_避免：用可选字段扩展万能 DTO、客户端混合新旧节点、旧 API 反推新版权威语义_

**旧图 API 退役边界**：
现有图谱业务 API 只为迁移期显式旧版视图保留；生产权威一次切换后，主图谱移除旧版切换，旧 DTO、业务查询和运行读取路径一并退役。Legacy Archive 只通过独立的固定快照只读合同提供历史阅读，不成为旧业务 API 的兼容层。
_避免：正式切换后继续双业务 API、归档接口承担运行查询、无限期保留 legacy fallback_

**角色分层权威详情**：
新版节点详情按角色投影同一权威对象。学生查看名称、类型、定义或公式、关系及可读来源证据；教师额外查看 Release、Gold/Silver、审核状态和来源覆盖；管理员迁移审计再查看哈希、隐藏内容、导入诊断和活跃消费者重新绑定状态。
_避免：学生详情显示工程审计字段、教师无法核查权威状态、为不同角色复制知识真相_

**核心关系标签**：
ActKG Gold 关系在教师和学生图谱界面中显示为“核心”，原始 Gold 治理值只在管理员审计和内部合同中保留。
_避免：向普通用户显示 Gold、用核心标签改写原始治理状态_

**扩展关系标签**：
ActKG Silver 关系在教师和学生图谱界面中显示为“扩展”，原始 Silver 治理值只在管理员审计和内部合同中保留。前端提供核心与扩展显示切换，并默认进入扩展状态。
_避免：向普通用户显示 Silver、将扩展关系升级为核心关系_

**核心关系视图**：
只显示 ActKG Gold 关系的图谱筛选状态，用于观察已经形成核心工程网络的关系。
_避免：核心视图混入 Silver、把核心理解为节点重要度_

**扩展关系视图**：
在核心关系视图基础上同时显示 ActKG Gold 和 Silver 关系的图谱筛选状态，是新版图谱的默认状态。扩展关系以区别于核心关系的视觉样式呈现，但不脱离核心网络单独显示。
_避免：扩展视图只显示 Silver、扩展关系与核心关系同样式_

**异质权威节点**：
Engineering Release 中正式发布的 DomainConcept、Formula、SystemModel、KnowledgeStatement、ModelRepresentation、Method 等对象都作为新版画布的一等节点显示，使用类型化视觉和详情模板，并支持按对象类型筛选。
_避免：只显示 DomainConcept、把公式和模型降为概念附属文本、所有对象统一 THEORY_

**完整对象默认视图**：
新版画布默认显示当前 ReleaseSet 内全部正式对象类型；类型筛选只改变展示，不改变对象身份、关系端点或权威数据。
_避免：按角色删除对象类型、筛选结果被保存为知识真相_

**精确谓词图例**：
新版画布直接按 ActKG Canonical Relation Type 提供中文图例、筛选和方向表达，不额外建立语义族筛选层，也不映射为旧版三类关系。当前根轨迹 Release 的六种谓词分别为 `association`、`represented_by`、`applies_to`、`derived_from`、`used_to_analyze` 和 `is_a`。
_避免：视觉语义族遮蔽真实谓词、三类关系压缩、向用户直接暴露英文工程枚举_

**谓词显示登记**：
每个已支持谓词具有稳定中文名称、方向、线型和说明；关系数量增加但仍可清晰辨识时继续使用精确谓词，只有未来实际复杂度证明图例不可用时才另行引入分组。
_避免：为未来数量预建分组、按当前关系数量过度抽象_

**Schema 驱动无损接入**：
Repository 依据受支持的 ActKG Schema 校验并保存 Release 中全部合法对象类型、类型专属字段和谓词，不以当前 ACT 代码白名单裁剪权威数据。未知字符串不能绕过 Schema 进入数据库。
_避免：只存当前六种谓词、任意字符串导入、ACT 枚举反向限制 ActKG_

**首包 Schema 兼容边界**：
首轮接入只实现并验证 `root-locus-engineering-v0.1` 当前发布包及其固定 Schema/`contract_hash`，不预建多版本 Schema 登记、自动兼容或迁移框架。第二个正式发布包如改变 Schema，依据其真实差异另行扩展接入合同并补充兼容性测试，未经适配不能加入 ReleaseSet。
_避免：对尚未稳定的未来 Schema 过度抽象、发布包自带 Schema 即自动接收、声称当前实现已经兼容未知版本_

**首包血缘兼容**：
当前发布包只携带来源运行和来源实现提交，没有 CTKGDataset 哈希、发布标识、可解析位置或 RevisionProposalRegistry 引用。首轮导入收据如实保存已有字段，并将缺失引用明确标记为未提供；不得虚构血缘，也不得仅因这些未来字段缺失而拒绝当前锁定发布包。后续发布包增加真实字段时再扩展接入合同。
_避免：把 Release 哈希冒充 CTKGDataset 哈希、用说明文字推断 Registry、要求 ActKG 为首轮迁移重发发布包_

**知识类型扩展点**：
对象存储、画布节点渲染、详情模板和谓词显示采用可扩展登记机制。新 Schema 引入合法对象类型或谓词时，底座可以先无损保存并以通用只读样式呈现；随后通过新增类型适配器补充专属视觉、字段解释和消费者能力，不需要修改既有对象或迁移核心表结构。
_避免：新类型必须重构统一节点表、通用兜底被误作完整语义支持_

**消费者语义支持状态**：
某个对象类型或谓词能够被 Repository 保存和画布预览，不表示 RAG、SAR、KAQ、学习路径或学习事实已经理解其语义。各消费者必须显式声明支持范围，未支持语义不得自动参与业务计算。
_避免：可存储等于可计算、未知关系自动进入路径或画像_

**候选感知控灵上下文**：
用户位于新版候选图谱页面时，控灵使用当前 ReleaseSet、选中 Canonical Object、候选图谱搜索和邻居查询作为本轮页面知识上下文。首轮复用 `act.node-detail.v2` 与 Repository 查询，不新增独立控灵投影。
_避免：页面显示新版但控灵查询旧节点、从名称猜测对应 legacy 节点_

**候选控灵只读边界**：
新版图谱中的控灵可以解释和查询候选 Release 内容，但不能据此产生学习事实、执行候选学习路径或改变其他页面使用的生产知识权威。候选来源必须随回答上下文保留并可诊断。
_避免：预览问答提前激活候选业务语义、候选图谱影响画像或推荐_

**顶级对象类型导航**：
在 ActKG Release 尚未提供稳定领域字段和对象—领域归属前，新版图谱一级导航按 `canonical_type` 分类。当前入口对应 DomainConcept、Formula、KnowledgeStatement 和 SystemModel；课程章节、课次、教材目录、Release 版本和宽泛 `scope` 均不作为本体顶级导航。
_避免：从 Release 名称推断领域、chapter-node 作为本体节点、把 concept_kind 当领域_

**对象类型显示词表**：
前端通过可扩展词表把 `canonical_type` 映射为中文导航名称和说明；新增类型只需增加词表项。词表尚未登记的合法类型直接显示上游原文，并使用通用只读样式。
_避免：组件内硬编码所有类型、未知类型被隐藏、根据类型名称猜测中文_

**类型中心视图**：
用户进入某个 `canonical_type` 导航后，以该类型对象作为中心集合，同时保留与中心对象直接相连的一跳异质对象和权威关系。关联对象使用较弱视觉表现，仍可进入类型化详情。
_避免：严格类型过滤切断跨类型关系、不同类型入口始终显示同一完整图_

**旧图界面状态重置**：
正式权威切换时，绑定 legacy 节点的收藏、画布布局和最近访问记录不迁移到新版图谱，并按旧版退役范围重置。它们不构成需要保留的知识或学习事实。
_避免：为界面偏好建立语义映射、旧布局约束新版异质图谱_

**旧节点笔记只读归档**：
用户在旧节点上撰写的笔记随 legacy snapshot 保留，并可通过旧版归档入口只读访问；笔记不自动复制或重新绑定到 ActKG Canonical Object。
_避免：删除用户创作内容、以名称猜测笔记归属、归档笔记参与新事实_

**旧路径执行归档**：
正式权威切换时仍未完成的 legacy 学习路径停止继续执行，原步骤、执行记录和偏差记录保持只读归档，不逐项映射到 ActKG Canonical Object。
_避免：正式切换后继续运行旧路径引擎、按节点名称改写路径步骤_

**目标驱动路径再规划**：
系统保留旧路径已声明的学习目标或用户意图，并在 ActKG 教学语义可用后，结合当前累计画像生成一条具有独立身份的新 Canonical 路径。新路径不继承旧节点序列，旧执行历史仅作为历史记录。
_避免：把旧路径改名为新路径、没有教学语义时生成工程关系路径_
