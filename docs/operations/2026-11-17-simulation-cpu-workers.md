# 仿真保存计算线程与多核验证

## 当前进度

2026-11-17完成本地实现和验证，候选版本0.7.53。生产部署与持续负载结果在验收后补入本文。

## 实现与测量范围

复用七船已有首步原生输入，输入包合并SHA-256为`c812d7cad7c6d3648a9bf9b90b49742d1ae9a952d41413f12d2e088f66e37bd7`。函数采样使用每船前三个5秒检查点，七船预热后运行五轮。基线从已部署0.7.52提交`ba2e1dafc78ed3ff2e3a8a3719e83d7cb4b1b5f2`提取保存服务、采样提交和CAS实现，复用同一数值内核与课程参数。

本机为Apple M5 Max，18个可用CPU，128GiB内存，Node 26.0.0。采样记录主线程函数自身时间，进程CPU统计合计主线程、计算线程和异步压缩线程。主线程采样时间按实际经过时间折算，基线数值核验约占37.6%，数据合同校验12.3%，规范序文本生成6.2%。

采样分块的JSON解析、合同校验和编码合为一次计算任务。检查点的不可变分块读取、顺序校验、状态核验、指标及恢复点编码合为另一次任务。跨线程返回提交摘要和数据库行数据。原有数据库事务继续在应用线程中核对本人归属、报告状态和采样前缀，并原子提交。

工作线程按需建立并复用，每线程最多两个异步在途任务。全部等待与在途任务上限128，入队起60秒超时。线程异常、超时或队列满返回503，调用方可以重试。`SIMULATION_CPU_WORKERS`支持0至8，默认1，0使用进程内计算。部署脚本将该参数传入应用容器。

核当量为进程CPU时间除以实际经过时间。RSS取各轮结束时整个进程的观测值，运行顺序共享同一主进程。表中4与8表示本机工作线程配置。4或8vCPU云主机的整站容量仍需对应硬件上的持续HTTP测试。

复现命令如下。工具仅接受本地数据库，临时实验记录及私有文件在结束时清理。

```bash
rtk npx tsx scripts/simulations/benchmark-evidence-workers.mts .tmp/load-fixtures .logs/evidence-worker-benchmark.json
```

输入沿用`scripts/simulations/generate-load-fixtures.mts`的七船代表包。脱敏汇总保存在本文同名JSON中。
