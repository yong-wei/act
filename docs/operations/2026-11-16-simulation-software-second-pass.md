# 仿真保存链路第二轮优化

0.7.52已部署阿里云。新账号常速10路5分钟对照中，检查点提交p95由11.38降至3.53秒，请求超时由3次降至0。常速10路30分钟阶段达到运行节奏和状态一致性判据，产生10次请求错误；1.5秒延迟目标仍未全部达到。120名学生同时持续操作的目标尚未验证通过。

## 改动与兼容性

本轮针对0.7.51保存链路继续优化。基线为`5c3ecaaf5a6be34f4b987b24737ffc881e3a3237`，沿用七船已有的一组代表首步输入。页面布局、教学模型、步骤、实验空间账号及控灵鉴权沿用现有实现。

- 规范序列化在单次调用内复用字段名文本，减少每个样本的中间数组。正文、整数键字典序、数值文本、内容哈希及旧记录保持一致。
- 检查点事务批量写入已校验分块，最后更新一次累计进度。八份分块对应的采样创建及运行更新调用由17次降至2次，首样本回执等固定操作另计。原归属、前缀和恢复点并发检测继续执行，唯一键冲突使整批回滚。
- 私有分块存储及私有恢复响应改用gzip三级压缩。旧gzip继续可读，SHA256仍针对解压后的规范序正文计算。客户端上传方式及公开模型资源保持原策略。

## 本机同输入比较

文件存储测量每轮使用七船代表分块各十份，共70份，以十份并发写入、读取，精确核对正文和内容引用。排除预热后，五轮交替执行基线与新版。

| 指标 | 基线 | 新版 |
| --- | --- | --- |
| 完整存取耗时中位数 | 1127.16 ms | 938.39 ms |
| CPU时间中位数 | 2218.20 ms | 1618.74 ms |
| 事件循环p95中位数 | 12.43 ms | 24.25 ms |
| 70份压缩正文 | 11,933,160字节 | 13,467,978字节 |

完整存取耗时约下降16.7%，CPU约下降27.0%，压缩体积约增加12.9%。本轮事件循环p95上升，仍有主线程解析和序列化开销。上述数值是本机测量，生产容量由独立负载验证。

真实PostgreSQL检查点比较复用同一055四十秒输入及八份待提交分块，预热后五轮交替执行。耗时中位数由115.32降至99.51ms，CPU中位数由130.83降至121.71ms。原始分块、检查点、累计数量及重复请求回执逐项一致。

压缩级别6、3、1在七船同输入70次压缩中的CPU中位数分别为859.58、377.30、272.72ms，压缩字节分别为11,934,400、13,469,150、14,524,800。采用级别3，记录存储体积与CPU之间的实际取舍。

## 阿里云发布与实测

0.7.52已部署到阿里云，发布修订为`ba2e1dafc78ed3ff2e3a8a3719e83d7cb4b1b5f2`。镜像为`localhost/act-obe-platform:0.7.52-ba2e1da`，归档831,160,320字节，SHA256为`8520debae793920e77204df2e249a65fefaf5a75c0bb81a785072cb16704819f`。应用与worker修订一致，数据库、Redis容器及课程Runtime身份未变。

生产055原页面通过正常学生登录，在6.383333秒保存，独立浏览器恢复同一原始检查点字符串并继续到7.966667秒。页面、教学步骤和实验空间身份逻辑未改动。

压力发生器通过公网使用130个专用PLATFORM学生测试账号；每船复用一份真实首步轨迹。每5秒保存原始证据和检查点，每15秒写草稿，每30秒恢复，每60秒刷新，结束时提交首步并保存报告草稿。未完成的20步报告按预期被400拒绝，该请求计为正确响应。正式实验空间和AI上游压力调用均为0。
