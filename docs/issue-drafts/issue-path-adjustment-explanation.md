# Issue：候选路径“调整”操作缺少调整说明

## 背景

自适应学习路径中心为每条候选路径提供“调整”入口。当前用户点击“调整”后，界面不能明确说明调整的是哪条候选路径、将依据哪些参数调整，以及生成结果具体发生了什么变化。

这会让用户误以为按钮没有生效，也无法判断调整结果是否符合自己的意图。该问题与候选路径生成、比较和已保存路径执行状态有关，需要在不改变原路径的前提下补齐可见反馈。

## 问题

点击候选路径的“调整”按钮时，系统存在以下缺口：

- 未明确显示当前调整对象；
- 未说明时间、节奏、资源和检查点等调整条件；
- 用户无法区分“进入调整设置”和“已经生成新的候选路径”；
- 生成结果未展示相对原候选的实际变化；
- 缺少明确保证：调整不会覆盖已保存路径。

## 目标

让用户能够理解并验证一次候选路径调整：

1. 点击“调整”后立即进入可见的调整状态；
2. 显示被调整的候选路径及调整依据；
3. 用户修改参数后，显式点击按钮生成新的候选批次；
4. 生成后展示服务端返回的实际变化字段；
5. 调整过程不修改已保存路径、当前执行路径或执行进度。

## 预期行为

### 点击“调整”

页面显示：

- “正在调整：<候选路径名称>”；
- 调整条件包括可用时间、难度节奏、资源偏好、检查点密度和站外资源开关；
- “生成调整后的候选路径”按钮；
- “取消调整”按钮；
- 明确提示原路径不会被覆盖。

### 生成调整方案

用户修改参数并点击“生成调整后的候选路径”后：

- 服务端生成新的候选批次；
- 页面切换到新的候选批次；
- 页面显示本次调整使用的条件；
- 每个候选显示相对来源方案的实际变化，例如学习步骤、预计用时、资源组合、检查点、解锁条件或终点验证；
- 没有变化时显示“与原候选在当前维度没有变化”，不能伪造差异。

### 取消调整

点击“取消调整”只退出调整状态，不提交生成请求，不改变当前候选批次和已保存路径。

## 约束

- 服务端候选批次 metadata 是调整条件和差异事实的唯一来源；
- 前端不得根据候选顺序或展示文本自行推断差异；
- 调整结果必须保持为候选状态，只有用户显式选择后才能进入执行或覆盖路径；
- 不新增系统排名、最佳路径或推荐结论；
- 不改变已有的候选比较、路径继续和路径执行流程。

## 验收标准

- [ ] 点击任意可调整候选后，页面显示明确的调整对象。
- [ ] 调整面板展示时间、节奏、资源、检查点等可编辑条件。
- [ ] 未点击“生成调整后的候选路径”前，不发起调整生成请求。
- [ ] 生成后页面显示新的候选批次和实际变化说明。
- [ ] 差异字段来自服务端 metadata；无差异和数据不足状态有明确文案。
- [ ] 取消调整不会改变候选批次、已保存路径或执行状态。
- [ ] 原有候选比较、继续原路径和选择候选流程保持可用。
- [ ] 相关单元测试覆盖调整入口、调整状态和结果说明。
- [ ] `npm run typecheck` 通过。

## 非目标

- 不修改候选路径生成算法；
- 不修改已保存学习路径的数据模型；
- 不改变候选比较的事实维度和比较关系；
- 不引入系统排名或“最佳路径”判断；
- 不自动采用调整后的候选路径。
