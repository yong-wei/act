# Issue：调整候选方案比较模块在学习路径中心的页面位置

## 背景

当前自适应学习路径中心中，“比较候选方案”模块位于学习记录内容之后。用户完成路径生成后，需要向下浏览较长内容才能看到候选方案比较入口，生成路径、比较候选和查看活动路径之间的操作顺序不够清晰。

## 需求

将“比较候选方案”模块移动到以下位置：

1. 路径生成模块之后；
2. `Active route`（活动路径）模块之前。

目标页面顺序应体现：先配置并生成路径 → 查看和比较候选方案 → 再查看当前活动路径和执行状态。

## 预期行为

- 路径生成模块完成后，用户可以直接看到候选方案摘要和比较入口；
- 候选方案比较模块不再被学习记录模块隔开；
- `Active route` 仍保留在页面中，并位于候选方案比较模块之后；
- 移动模块只改变页面展示顺序，不改变候选生成、比较请求、路径选择、路径执行和学习记录数据；
- 刷新页面、通过 URL 恢复批次、继续原路径和新建路径时，模块顺序保持一致；
- 桌面端与窄屏布局都遵循同一内容顺序，不因响应式布局隐藏或重复比较模块。

## 约束

- 不复制候选比较状态或生成状态；
- 不改变候选批次、比较对、比较结果和已保存路径；
- 不改变学习记录的内容和数据来源；
- 保留现有无候选、加载中、数据不足和错误状态；
- 页面仅调整布局层级和渲染顺序，避免引入新的业务状态。

## 验收标准

- [ ] 路径生成模块之后紧接候选方案摘要/比较模块。
- [ ] 候选方案比较模块位于 `Active route` 之前。
- [ ] 学习记录内容不再插入路径生成与候选比较之间。
- [ ] 候选选择、比较结果展示和调整入口仍然可用。
- [ ] 原路径继续、候选路径执行和刷新恢复行为不变。
- [ ] 桌面端和窄屏端均验证模块顺序正确。
- [ ] 相关 UI 回归测试覆盖模块顺序和关键交互。
- [ ] `npm run typecheck` 通过。

## 非目标

- 不修改候选方案生成逻辑；
- 不修改比较结果的计算和服务端事实来源；
- 不修改学习记录数据模型或记录内容；
- 不新增路径推荐、排序或自动选择规则。
