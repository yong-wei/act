# 知识图谱现状调查与综合判断

> 调查日期：2026-07-18
> 调查范围：当前 `/knowledge` 运行时图谱、知识节点与关系模型、本地导入的生产数据库快照、知识卡片与资源治理投影
> 调查性质：只读现状审计；本文不代表整改方案已经批准

## 1. 调查目标

本次调查关注以下问题：

1. 知识点是否存在重复、同义异名和身份分裂。
2. 知识领域是否具有一致、可解释的分类语义。
3. 图谱关系是否适合表达学习顺序和知识关联。
4. 知识卡片、信息图和教学资源是否形成完整覆盖。
5. runtime 文件、数据库与资源治理投影是否保持一致。

## 2. 数据口径与运行路径

当前 `/knowledge` 页面优先读取以下 canonical runtime 文件：

- `course-content/runtime/knowledge/graph/nodes.json`
- `course-content/runtime/knowledge/graph/relations.jsonl`

只有上述文件不存在时，`loadKnowledgeGraphData()` 才回退数据库。因此，“当前页面可见图谱”和“数据库中的全部活动记录”是两个不同口径，不能混合统计。

本次数据库统计来自本地导入的生产数据库快照，反映同步时点的远端数据，不等同于调查结束时的实时生产库。

| 指标 | 当前页面 runtime | 本地生产数据库快照 |
|---|---:|---:|
| 活动知识节点 | 838 | 944 |
| 原始关系 | 16,571 | 16,591 |
| 逻辑领域 | 15 | 124 个节点缺少领域元数据 |
| 孤立节点 | 8 | 10 |

runtime 与数据库的节点交集为 820 个；数据库独有 124 个历史节点，runtime 独有 18 个新节点。数据库当前不是 runtime 的完整镜像。

关键实现位置：

- `src/lib/knowledge-graph-source.ts`
- `src/features/knowledge/graph/relation-contract.ts`
- `src/features/knowledge/graph/selected-corridor.ts`
- `src/features/knowledge/resource-panel/resource-panel.tsx`
- `prisma/schema.prisma`

## 3. 知识点重复与身份分裂

### 3.1 统计结果

当前 runtime 中存在：

- 59 组同名知识点；
- 141 个节点卷入同名重复，即相对每组保留一个身份后有 82 个多余身份；
- 56 组、135 个节点跨领域重复；
- 同名节点形成 119 个节点对，但相互之间没有有效的 canonical alias、等价或身份合并关系。

代表性重复包括：

| 名称 | 节点数量 |
|---|---:|
| 传递函数 | 7 |
| 稳定性 | 5 |
| 稳态误差 | 4 |
| 开环增益 | 3 |
| 极点 | 3 |
| 闭环特征方程 | 3 |
| 单位阶跃响应 | 3 |
| 主导极点 | 3 |

精确同名统计尚未包含“拉氏变换/拉普拉斯变换”等同义异名，实际语义重复规模高于 59 组。

### 3.2 结构原因

`KnowledgeNode.name` 没有唯一约束，模型也没有一等的 canonical identity、alias、merge、supersedes 或多领域引用结构。现有导出链路主要按节点 ID 合并，不按名称或概念语义合并。

当前 canonical 注册表约有 220 个条目，但只有 3 个 ID alias，没有消除主要同名组。相同概念为了出现在不同章节或教学路径中，被复制为多个节点，而不是由多个领域引用同一 canonical 概念。

### 3.3 直接影响

- 学习证据会分散到多个 nodeId。
- 一个重复节点有卡片，另一个重复节点可能没有卡片。
- 同一概念可能获得不同领域、不同关系和不同学习顺序。
- 推荐、画像和路径规划可能把同一概念视为多个不同目标。
- 如果直接给所有缺卡副本补卡，会进一步扩大重复内容。

例如 `传递函数_2_2c5e2589` 没有直接卡片，但其他“传递函数”节点已有卡片。该问题应先通过身份合并或 alias 解决，而不是继续新建同名卡片。

## 4. 知识领域分类混乱

### 4.1 领域不是一等模型

当前领域不是 Prisma 实体，而是节点 `metadata.chapterName` 的单值展示字段。该结构无法准确表达：

- 一个知识点同时属于多个领域；
- canonical 概念和章节引用之间的区别；
- 课程章节、知识本体、教学组织层和学习路径之间的区别。

### 4.2 分类维度混用

前端传统显示顺序定义了 9 个课程领域：

- 基本概念
- 系统模型
- 时域分析
- 根轨迹分析
- 频域分析
- 系统校正
- 离散系统
- 非线性系统
- 状态空间

runtime 实际还包含：

- 课程全景
- 建模专题速通
- 结构机理层
- 约束设计层
- 知识边界与方法迁移层
- 前沿拓展

这些名称并不属于同一分类维度。“频域分析”是知识领域，“课程全景”是导航入口，“知识边界与方法迁移层”更接近教学组织层。将它们作为平级领域展示，会造成首页语义混乱。

### 4.3 章节编号冲突

- 第 3 章同时出现“时域分析”和“结构机理层”。
- 第 4 章同时出现“根轨迹分析”和“约束设计层”。
- 第 5 章同时出现“频域分析”“知识边界与方法迁移层”“前沿拓展”。
- 第 9、10 章都被显示映射为“状态空间”。

因此，`chapter` 已不能唯一决定领域，`chapterName` 也不能承担完整知识本体分类职责。

## 5. 关系体系现状

### 5.1 数据规模与分布

runtime 有 16,571 条原始关系、32 种原始关系类型，主要分布如下：

| 关系类型 | 数量 |
|---|---:|
| related | 7,444 |
| applies_to | 5,383 |
| contains | 1,547 |
| leads_to | 1,132 |
| prerequisite | 754 |
| opposite | 179 |
| cross_domain | 66 |

`related` 与 `applies_to` 合计约占全部关系的 77.4%。图谱主体由宽泛关联构成，明确的学习先后关系并不占主导。

### 5.2 数据库约束不足

`KnowledgeLink.relation` 是无约束字符串。数据库只有关系 ID 主键和端点外键，没有：

- canonical 关系类型约束；
- `(sourceId, targetId, relation)` 唯一约束；
- 自环政策；
- 方向约束；
- 对称关系约束；
- 合法关系组合约束。

关系完整性主要依赖应用层合同和导入检查。

### 5.3 三类视觉投影

当前 UI 将关系映射为三族：

| 视觉关系族 | 原始关系 | 方向 |
|---|---|---|
| 子级 | `contains` | 父级到子级 |
| 后置 | `prerequisite`、`provides_foundation`、`follows`、`leads_to` | 先学到后学 |
| 关联 | 其余关系 | 统一按无序关系处理 |

这种投影简化了图例，但把多种本质上有方向的关系改成了无向关联，包括：

- `applies_to`
- `cross_domain`
- `generalizes`
- `instance_of`
- `supports`
- `derives`
- `causes`
- `produces`
- `precedes`
- `refines` / `refined_by`

画布会按无序端点合并这些边，而详情栏仍保留原始方向和语义，造成画布表达与详情语义不一致。

### 5.4 结构合法不等于教学合理

当前严格关系检查能够通过，16,571 条原始关系投影为 16,533 条视觉边，未发现重复 ID、自环或缺失端点。但这只能证明关系可解析，不能证明教学语义合理。

现状还包括：

- 16 组同类型互反关系；
- 82 个节点对同时存在多种关系；
- 8 个 runtime 孤立节点；
- 大量 `related` 与更具体关系并存的冗余候选。

典型组合需要分别判断：

- `prerequisite + related`：通常是冗余弱关系；
- `cross_domain + related`：通常是语义降级重复；
- `applies_to + prerequisite`：需要审核方向和教学含义；
- `contains + leads_to`：可能同时表达层级和学习顺序，也可能是分类混用。

## 6. 知识卡片与资源覆盖

### 6.1 总体覆盖

| 资源状态 | 节点数 | 占 838 个节点 |
|---|---:|---:|
| 绑定 runtime 知识卡 | 297 | 35.4% |
| 卡片首页和详情均可正确识别 | 288 | 34.4% |
| 无卡但有 handout 与 citation | 18 | 2.1% |
| 无卡、无信息图、无 handout/citation | 523 | 62.4% |
| 直接卡片投影可进入治理学习路径 | 2 | 0.2% |

297 张 runtime 卡片文件均存在，且与 authoring 文件内容一致。161 张已接受信息图也均能找到对应文件，但全部绑定在已有卡片的节点上，没有独立补足无卡节点。

### 6.2 覆盖分布不均

- 第 1–5 章直接卡片覆盖约为 40%–67%。
- 第 6 章只有 3/44。
- 第 7 章为 0/70。
- 第 8 章有 3 个绑定，但详情结构不兼容。
- 第 9 章为 0/79。
- 第 10 章只有 2/52。

如果第 7、9、10 章继续对学生开放，应优先覆盖 z 变换、脉冲传递函数、离散稳定性、状态空间表达、可控性、可观测性、状态反馈、观测器、李雅普诺夫稳定性和最优控制等核心概念。

### 6.3 卡片运行兼容问题

9 张卡片使用 `## 详情页`，但运行组件只识别精确标题 `## 详情`。这些卡片首页可以打开，详情切换不可用。

课程审查脚本当前采用子串检查，会把 `## 详情页` 误判为满足 `## 详情`，因此既有 knowledge-card-check 全绿不能证明运行组件兼容。

### 6.4 资源绑定断层

数据库没有独立的 `KnowledgeCard` 表；知识卡是 `KnowledgeNode.resources` 中的 Markdown 资源，再投影为 `ResourceNode`。

数据库当前有：

- 112 个 `TeachingResource`；
- 105 个带 `registryId`；
- 86 个不同 registry 身份；
- 19 组重复 registry 身份；
- `TeachingResource—KnowledgeNode` 多对多绑定为 0。

运行逻辑只能在数据库绑定为空时依赖 registry metadata 的 `knowledgeNodeIds`。另有 82 个 registry 资源没有对应的数据库 TeachingResource 实体。

因此以下三个状态必须分开统计：

1. 图谱检查器能够打开知识卡；
2. 资源已注册并可被课程使用；
3. 资源满足路径治理要求，可进入学习路径。

目前只有 2 个直接卡片投影满足第三种状态，其余 295 个主要缺少 path profile、能力目标或正式路径目标。

## 7. 数据一致性与回退风险

数据库中的 runtime-owned 节点只有 820 个，落后当前 runtime 18 个节点。数据库还保留旧关系别名和 50 条 runtime 已不存在的 `follows` 关系。

更严重的是，数据库关系缺少 loader 要求的 `metadata.runtimeSource` 标记。当前 runtime 文件存在时不会触发问题；一旦文件缺失，数据库回退关系查询可能返回 0 条，形成“代码声明支持回退、数据实际不能回退”的失效路径。

## 8. 综合判断

当前知识图谱可以作为浏览界面使用，但还不能视为稳定的课程知识本体，也不能直接作为可靠的学习路径规划真源。

主要根因不是某一批内容质量不足，而是四个基础模型没有统一：

1. canonical 概念身份与章节引用没有分离；
2. 课程章节、知识领域和教学组织层混在同一字段；
3. 原始关系语义、学习路径资格和视觉表达混在同一关系族合同；
4. 卡片可查看、资源可注册和资源可进入学习路径使用不同门禁，但缺少统一覆盖矩阵。

如果不先解决身份问题，直接补卡或补关系会继续制造同名节点、重复卡片和冲突边。合理的治理顺序应当是先统一身份，再调整领域引用和关系，最后补齐内容资源。

## 9. 建议的后续治理顺序

1. 建立 canonical 概念、alias 和合并清单，优先处理 59 组同名节点。
2. 将概念身份与领域引用分离，使一个概念可以被多个章节和领域引用。
3. 将课程章节、知识领域、教学组织层拆成不同维度。
4. 审核 82 个多关系节点对，优先处理 `related + 更具体关系` 等明确冗余。
5. 将关系的学习路径资格、原始方向、画布样式和合并策略拆开。
6. 在身份合并后补知识卡，优先处理核心概念和第 6、7、9、10 章。
7. 修复 9 张卡片的详情标题及审查脚本的精确匹配。
8. 同步 runtime 与数据库，并修复不可用的数据库回退。
9. 建立 `KnowledgeNode × card × infograph × handout × citation × TeachingResource × path eligibility` 全局覆盖矩阵。

## 10. 调查边界

- 本次没有修改 runtime 文件、数据库、图谱关系或资源绑定。
- 本次没有对 82 个多关系节点对逐条作课程语义裁定。
- “跨章节关系”不能直接等同于真正的跨领域关系，严格统计需要先建立领域本体。
- 当前 adaptive learning 路径规划还使用其他治理输入，不能把知识图谱的 canonical corridor 与全部自适应路径规划能力视为同一数据流。
