你现在的混乱不在于功能太多，而在于几个维度被混在了一起：对象来源、控制方法、评价指标、教学入口、数据埋点、虚拟仿真接口，全部纠缠在“竞技场”这个概念里。更合理的设计是：**竞技场不是某一种校正工具，而是统一评测与排行榜层；学生工作台是统一设计与实验层；对象库是统一资源层；多表征联动引擎只是其中一个适合串联校正的工作台模式。**

我建议按下面的结构重构思路。

---

# 一、先确立总原则：竞技场不要绑定“串联校正”

你的平台里未来会有这些对象：

1. 典型传递函数对象；
2. 作业中的校正对象；
3. 控制奥德赛中的 level 对象；
4. 虚拟仿真中的后台对象；
5. 未来用于 MPC、优化校正、数据驱动控制、黑箱辨识的前沿对象。

这些对象来源不同，但它们都可以被抽象为同一类东西：**被控对象挑战任务**。

所以平台的核心不应该是：

> 给一个传递函数，让学生设计串联校正装置，然后比超调量、调节时间、稳态误差。

而应该是：

> 给定一个对象、一个任务目标、一组允许的控制器形式、一套评测协议，学生提交一个控制方案，平台根据统一规则评测并排名。

也就是说，竞技场的基本单元不是“对象”，而是：

> **对象 + 任务 + 允许方法 + 评测协议 + 榜单规则**

同一个对象可以对应多个挑战任务。例如同一个二阶系统可以有：

* 串联校正挑战；
* PID 调参挑战；
* 复合校正挑战；
* 鲁棒性挑战；
* 最低控制能量挑战；
* 黑箱辨识后控制挑战；
* MPC 约束控制挑战。

这样后续扩展不会卡死在现有多表征联动引擎上。

---

# 二、平台应拆成五个核心层

建议你把系统拆成五层，而不是把所有功能塞进竞技场。

## 1. 对象库层：统一管理所有被控对象

对象库负责管理所有“可被挑战的对象”，但不直接决定怎么排名。

每个对象至少包含：

* 对象 ID；
* 对象名称；
* 来源类型：典型对象、作业对象、控制奥德赛对象、虚拟仿真对象、前沿挑战对象；
* 模型公开程度：白箱、灰箱、黑箱；
* 可用接口：传递函数、状态空间、仿真接口、实验数据接口、虚拟仿真后台接口；
* 版本号；
* 标签：一阶、二阶、高阶、含积分环节、非最小相位、纯滞后、非线性、强耦合、受约束、黑箱等；
* 教学关联：章节、知识点、课程任务、作业题、实验项目、奥德赛关卡。

这里要特别注意：**对象不是任务。**

例如一个虚拟水箱系统是对象，但它可以对应多个任务：

* 液位跟踪；
* 抗扰控制；
* 能耗最小控制；
* 黑箱辨识；
* 受限执行器控制；
* MPC 控制。

对象库只负责“这个东西是什么”，不负责“怎么比赛”。

---

## 2. 任务层：定义挑战目标

挑战任务负责定义学生要解决什么问题。

一个任务应包含：

* 目标信号：阶跃、斜坡、轨迹跟踪、自定义参考输入；
* 扰动设置：输入扰动、输出扰动、参数扰动、噪声；
* 初始条件；
* 约束条件：控制量限幅、输出安全区间、超调上限、最大调节时间、稳定性要求；
* 允许方法：串联校正、复合校正、PID、状态反馈、MPC、优化校正、黑箱控制等；
* 评价指标；
* 榜单类型；
* 是否用于作业评分；
* 是否开放隐藏测试集；
* 是否允许查看其他学生提交结果。

这一步很关键。你不应该让“对象”直接进入排行榜，而应该让“任务”进入排行榜。

例如：

> 对象 A：二阶欠阻尼系统
> 任务 A1：串联超前校正，要求相位裕度提升
> 任务 A2：复合校正，要求抗扰性能优先
> 任务 A3：优化校正，目标是 ITAE 最小
> 任务 A4：低阶控制器挑战，控制器阶次不得超过 2

这些是四个不同榜单，而不是一个榜单。

---

## 3. 工作台层：让学生设计、辨识、仿真和提交

你提到“或许增加一个学生工作台”，我认为这不是可选项，而是必要项。

因为一旦引入虚拟仿真黑箱对象、复合校正、优化校正、MPC，就不能再依赖原有串联校正的多表征联动界面。原有界面适合讲清楚根轨迹、Bode 图、校正环节与时域响应之间的关系，但它不适合承载全部控制方法。

学生工作台应该成为统一入口，内部再根据任务类型切换不同模式。

建议工作台包括以下几个区域：

1. **对象信息区**
   显示对象说明、公开模型、黑箱接口、任务目标、允许控制器类型、评价规则。

2. **实验与辨识区**
   特别用于虚拟仿真对象和黑箱对象。学生可以设计输入信号，采集输出数据，进行模型辨识，保存辨识结果。

3. **模型区**
   支持学生导入或生成模型，例如传递函数、状态空间模型、离散模型、辨识模型。

4. **控制器设计区**
   支持不同控制器形式：

   * 串联校正器；
   * PID；
   * 前置滤波器；
   * 反馈校正器；
   * 前馈控制器；
   * 复合校正结构；
   * 状态反馈；
   * 观测器；
   * MPC 参数化控制器；
   * 优化得到的控制器参数。

5. **仿真比较区**
   显示不同设计方案的响应曲线、指标对比、控制量曲线、约束违反情况、鲁棒性测试结果。

6. **提交区**
   学生将最终控制器方案提交到竞技场，平台调用官方评测协议生成成绩。

这样设计之后，原有多表征联动引擎仍然有价值，但它变成“串联校正工作台模式”，而不是整个竞技场的底座。

---

## 4. 评测层：统一计算性能指标

评测层负责根据任务协议运行仿真或虚拟实验，并输出指标。

它应该与工作台分离。学生在工作台里做的是探索，竞技场评测做的是官方裁判。

评测结果可以包括：

对经典线性系统：

* 闭环稳定性；
* 稳态误差；
* 上升时间；
* 峰值时间；
* 超调量；
* 调节时间；
* ITAE；
* IAE；
* ISE；
* 控制能量；
* 最大控制量；
* 相位裕度；
* 幅值裕度；
* 带宽；
* 灵敏度峰值；
* 鲁棒性指标；
* 控制器阶次。

对复合校正：

* 跟踪性能；
* 抗扰性能；
* 噪声抑制性能；
* 控制能量；
* 执行器饱和情况；
* 多通道误差；
* 结构复杂度。

对虚拟仿真黑箱对象：

* 实际任务完成度；
* 轨迹跟踪误差；
* 安全约束违反次数；
* 最大偏差；
* 平均误差；
* 稳态误差；
* 控制能耗；
* 操作平滑度；
* 抗扰表现；
* 多初值、多扰动、多场景下的平均表现与最差表现。

对 MPC 或优化控制：

* 目标函数值；
* 约束违反程度；
* 计算时间；
* 控制量变化率；
* 轨迹误差；
* 鲁棒性；
* 可重复性。

这里真正关键的是：**评测层只关心闭环行为，不强制关心学生用了什么方法。**
方法只是榜单分类与任务限制的一部分。

---

## 5. 榜单层：不要用一个简单加权分数解决所有问题

你担心“同一对象校正后有不同性能指标，不知道如何排名”，这个担心是合理的。控制系统设计本来就是多目标权衡，单一加权分数很容易失真。

我的建议是采用“四类榜单并存”的方案。

---

# 三、排行榜设计：主榜、分榜、Pareto 榜、专题榜

## 1. 主榜：用于教学与竞赛的默认排名

每个挑战任务应该有一个主榜。主榜需要给学生一个清晰的排名，否则竞技感会很弱。

但主榜不应直接把所有指标粗暴加权，而应采用：

> 硬约束门槛 + 指标归一化 + 加权满意度 + 违规惩罚 + 同分决胜

具体做法如下。

第一步，设置硬约束。比如：

* 闭环必须稳定；
* 控制器必须因果、真有理；
* 输出不能超过安全范围；
* 控制量不能严重超限；
* 不能出现 NaN、发散、仿真失败；
* 对黑箱对象不能调用未授权模型接口。

违反硬约束的提交不进入正式排名，或者进入“未达标榜”。

第二步，对各性能指标做归一化。
例如对于“越小越好”的指标，如调节时间、超调量、ITAE、能耗，可以设置两个值：

* 理想值；
* 不可接受值。

然后把实际指标转成 0 到 1 之间的满意度分数。

例如：

* 达到或优于理想值，得 1；
* 劣于不可接受值，得 0；
* 中间按比例或非线性函数衰减。

第三步，用几何平均而不是普通加权平均。
这是一个重要建议。

普通加权平均的问题是：某个指标很差，可以被其他指标“洗掉”。例如超调量极高，但调节时间很短，最后分数仍然可能很高。控制系统设计中这通常不合理。

更稳妥的是使用类似下面的形式：

> 总分 = 1000 × 各指标满意度的加权几何平均 − 违规惩罚

这样一个关键指标很差时，总分会明显下降。

第四步，设置同分决胜规则。
例如：

1. 隐藏测试集表现更好者优先；
2. 控制能量更小者优先；
3. 控制器阶次更低者优先；
4. 提交时间更早者优先。

这样主榜既清晰，又不至于被某一个单指标绑架。

---

## 2. 分方法榜：保证教学公平性

不要把串联校正、复合校正、MPC、优化控制全部混在一个榜里。那样很快会变成“高阶方法碾压基础方法”，对本科教学未必有价值。

建议每个任务可以有多个方法榜：

* 串联校正榜；
* PID 榜；
* 复合校正榜；
* 低阶控制器榜；
* 优化调参榜；
* MPC 榜；
* 黑箱辨识后控制榜；
* 开放方法榜。

其中“开放方法榜”可以允许更强方法，但课程考核最好使用限定方法榜。

例如“自动控制原理”课程中的任务，默认榜单可以是：

> 串联校正榜 + PID 榜 + 开放挑战榜

而研究生“最优控制”课程可以增加：

> MPC 榜 + 最优控制榜 + 约束控制榜

这样不同课程、不同阶段都能用同一个平台，但不会互相干扰。

---

## 3. Pareto 榜：反映多目标权衡

有些任务不适合强行压成一个分数。比如：

* 调节时间越短，控制能量可能越大；
* 超调量越小，响应速度可能变慢；
* 鲁棒性越强，带宽可能降低；
* 控制器阶次越低，性能可能受限。

这些任务应显示 Pareto 前沿。

可以给学生展示：

* 当前非支配解集合；
* 自己的方案是否在 Pareto 前沿；
* 自己被哪些方案支配；
* 自己在哪些指标上有优势，在哪些指标上有劣势。

Pareto 榜不一定取代主榜，但它非常适合培养学生理解“控制设计是权衡”这一事实。

主榜给竞技感，Pareto 榜给理解深度。

---

## 4. 专题榜：增强可玩性和教学导向

除了主榜，可以设置专题榜，例如：

* 最快响应榜；
* 最小超调榜；
* 最小稳态误差榜；
* 最小控制能量榜；
* 最强鲁棒性榜；
* 最低阶控制器榜；
* 最平滑控制榜；
* 最佳黑箱辨识榜；
* 最少实验次数榜；
* 最佳综合改进榜。

这些榜单的价值不是替代主榜，而是让学生看到不同设计目标之间的差异。

例如一个学生主榜排名不高，但在“最低控制能量榜”上排名靠前，这对教学反馈很有意义。

---

# 四、虚拟仿真对象应采用黑箱挑战模式

你判断“虚拟仿真中的后台模型并不是传递函数，因此不能暴露模型”是对的。

这里不能强行把虚拟仿真对象转成传递函数对象，也不能把真实后台模型开放给学生。更合理的模式是：

> 虚拟仿真对象作为黑箱对象，通过实验接口、数据接口和官方评测接口进入竞技场。

完整流程可以这样设计。

## 1. 虚拟仿真对象提供黑箱实验接口

学生可以在虚拟仿真中进行实验，例如：

* 输入阶跃信号；
* 输入脉冲信号；
* 输入 PRBS 信号；
* 输入自定义测试信号；
* 改变初始条件；
* 加入扰动；
* 记录输出数据。

平台只返回输入输出数据，不暴露后台模型。

## 2. 学生将实验数据导入工作台

学生在工作台里可以：

* 查看数据；
* 清洗数据；
* 拟合模型；
* 选择模型结构；
* 得到传递函数、状态空间模型或离散模型；
* 验证辨识模型；
* 保存“我的辨识模型”。

这个辨识模型不是官方对象，而是学生自己的工作成果。

## 3. 学生基于辨识模型设计控制器

学生可以使用：

* 串联校正；
* PID；
* 复合校正；
* 状态反馈；
* MPC；
* 优化方法。

在工作台里先基于自己辨识的模型做仿真。

## 4. 学生将控制器导入虚拟仿真对象

控制器需要以标准格式提交，例如：

* 连续传递函数控制器；
* 离散传递函数控制器；
* PID 参数；
* 状态反馈矩阵；
* 复合控制框图；
* MPC 参数配置；
* 受限代码控制器。

对于虚拟仿真，最好统一转成离散控制器执行，因为后台仿真通常有采样周期。

控制器导入时需要明确：

* 采样周期；
* 离散化方法；
* 输入输出通道；
* 控制量限幅；
* 初始状态；
* 是否包含抗积分饱和；
* 是否包含滤波环节。

## 5. 官方评测在真实虚拟仿真后台运行

学生工作台里使用的是自己的辨识模型，但正式排名必须在真实虚拟仿真对象上运行。

这样可以避免“辨识模型上表现很好，真实对象上崩掉”的问题，也能让学生理解模型误差与鲁棒性。

黑箱虚拟仿真的主榜可以按照实际表现排名，例如：

* 真实闭环误差；
* 安全约束违反；
* 控制能量；
* 抗扰能力；
* 多场景平均性能；
* 最坏场景性能。

---

# 五、现有多表征联动引擎的定位

你现有的多表征联动引擎对串联校正支持很好，这是资产，不应该推倒。

但它的定位要收窄：

> 它是“经典串联校正工作台”，不是“所有控制方法的统一表达引擎”。

对于串联校正，它可以继续提供：

* 根轨迹；
* Bode 图；
* Nyquist 图；
* 零极点分布；
* 时域响应；
* 校正前后对比；
* 稳态误差分析；
* 相位裕度与幅值裕度；
* 校正装置参数化编辑。

对于复合校正，不要强行套入原有串联校正界面，而应引入“框图式工作台”。

复合校正工作台可以支持：

* 前置滤波器；
* 串联控制器；
* 局部反馈；
* 前馈通道；
* 扰动补偿通道；
* 传感器滤波；
* 内环/外环结构；
* 多闭环结构。

如果结构仍然是 LTI 系统，可以计算闭环传递函数、灵敏度函数、互补灵敏度函数等。
如果结构更复杂，则以场景仿真和指标评测为主，不强求根轨迹或 Bode 图解释。

对于 MPC、优化控制、黑箱控制，也不要强行要求多表征联动。它们更适合：

* 指标面板；
* 约束违反图；
* 轨迹误差图；
* 控制量曲线；
* 预测轨迹；
* 目标函数变化；
* 鲁棒性测试结果。

这里要接受一个事实：**不同控制方法的“可解释表征”不同。平台应统一评测，不必统一可视化形式。**

---

# 六、控制器提交格式要标准化

这是后续扩展的基础。建议你尽早定义“控制器工件”。

不同方法都应转成可存储、可复现、可评测的控制器工件。

可以分几类。

## 1. 串联校正器工件

包括：

* 控制器传递函数；
* 零极点增益形式；
* 超前/滞后/滞后-超前结构；
* 参数；
* 设计说明；
* 是否连续时间；
* 若用于虚拟仿真，需包含离散化配置。

## 2. PID 工件

包括：

* Kp；
* Ki；
* Kd；
* 滤波系数；
* 抗积分饱和方式；
* 采样周期；
* 控制量限幅。

## 3. 复合校正工件

可以用框图 JSON 表示：

* 节点：控制器、滤波器、反馈通道、前馈通道、求和点；
* 边：信号连接；
* 输入输出定义；
* 各模块参数；
* 连续/离散属性；
* 通道名称；
* 约束配置。

## 4. MPC 工件

初期不建议直接允许学生上传任意代码。更可控的方式是提供参数化 MPC 模板。

MPC 工件可以包括：

* 内部预测模型；
* 预测时域；
* 控制时域；
* 状态权重；
* 控制权重；
* 终端权重；
* 约束条件；
* 求解器选项；
* 采样周期。

等平台成熟后，再考虑开放受限代码提交。

## 5. 代码型控制器工件

这个要谨慎。任意代码提交会带来安全、算力、作弊和维护问题。若未来开放，至少需要：

* 沙箱运行；
* 禁止网络访问；
* 限制运行时间；
* 限制内存；
* 固定输入输出接口；
* 固定随机种子；
* 记录依赖版本；
* 禁止访问真实模型内部参数；
* 对异常输出设置自动失败规则。

如果平台主要面向本科教学，第一阶段不建议开放任意代码控制器。

# 七、评价指标体系建议分为三层

为了兼顾教学清晰度和扩展能力，指标不要一次性全暴露给学生。可以分三层。

## 第一层：达标指标

用于判断方案是否有效。

例如：

* 是否稳定；
* 稳态误差是否满足要求；
* 超调量是否不超过上限；
* 调节时间是否不超过上限；
* 控制量是否不超限；
* 安全约束是否满足。

这是基础门槛。

## 第二层：排名指标

用于主榜计分。

例如：

* ITAE；
* 调节时间；
* 超调量；
* 控制能量；
* 鲁棒性平均分；
* 最坏场景表现。

排名指标不宜太多。一般 4 到 6 个较合适。太多会让学生不知道该优化什么。

## 第三层：诊断指标

用于反馈和教学分析，不一定参与排名。

例如：

* 相位裕度；
* 幅值裕度；
* 带宽；
* 灵敏度峰值；
* 噪声放大程度；
* 控制器阶次；
* 控制量变化率；
* 饱和持续时间；
* 误差积分曲线；
* 不同场景下的性能分解。

这些指标适合在结果页显示，帮助学生理解为什么方案表现好或差。

# 八、虚拟仿真与竞技场的数据流

建议你把虚拟仿真和竞技场之间设计成双向流动。

## 从虚拟仿真到工作台

学生在虚拟仿真中运行实验，平台记录：

* 输入信号；
* 输出信号；
* 初始条件；
* 扰动设置；
* 采样周期；
* 实验时间；
* 实验场景；
* 数据质量。

然后学生可以点击：

> 导出到控制工作台

工作台中生成一个“实验数据集”。

## 从工作台到虚拟仿真

学生在工作台完成控制器设计后，可以点击：

> 应用到虚拟仿真对象

平台将控制器工件传入虚拟仿真后台，执行闭环实验。

## 从虚拟仿真到竞技场

如果学生认为结果满意，可以提交到竞技场。竞技场不直接使用学生刚才那一次实验结果，而是重新执行官方评测。

原因很简单：排行榜必须可复现、可比较、可防作弊。

## 从竞技场到教学分析

竞技场评测结果进入教学数据系统，包括：

* 学生是否能稳定系统；
* 哪些指标长期不达标；
* 是否只会追求响应速度而忽略控制能量；
* 是否在黑箱对象上辨识质量差；
* 是否能从失败方案迭代到成功方案；
* 是否存在盲目调参行为。

这些数据对个性化学习路径规划很有价值。

# 九、埋点设计：记录“关键行为”，不要记录“所有动作”

你的顾虑是对的，数据埋点不能过重，否则服务器压力大，也会产生大量低价值数据。

建议采用分层埋点。

## L0：必须记录的核心事件

这些事件量少、价值高，必须记录：

* 打开挑战；
* 开始工作台；
* 运行仿真；
* 保存控制器；
* 保存辨识模型；
* 导入虚拟仿真；
* 提交竞技场；
* 官方评测完成；
* 查看成绩；
* 查看榜单；
* 查看反馈。

## L1：设计过程事件

这些用于分析学生学习行为，但要做压缩和节流：

* 修改控制器参数；
* 切换控制器结构；
* 改变仿真条件；
* 运行辨识实验；
* 选择辨识模型阶次；
* 比较两个方案；
* 使用提示或 AI 反馈。

不建议每次滑块移动都上传。可以在客户端聚合后上传，例如记录：

* 本轮修改了哪些参数；
* 修改次数；
* 参数变化范围；
* 是否导致性能改善；
* 是否从不稳定变为稳定。

## L2：高频轨迹数据

高频数据只在必要时记录，例如：

* 官方评测轨迹；
* 典型失败案例；
* 教师开启研究模式的班级；
* 学生主动提交的实验数据集。

一般探索过程中的每条响应曲线不需要全部上传，可以只上传摘要指标和数据哈希。详细曲线可以本地缓存，或者只保存最后若干次关键实验。

## L3：研究级详细日志

如果你未来要做学习分析或教育数据挖掘，可以单独开启研究模式，但不要默认开启。

研究模式可以记录：

* 完整参数迭代轨迹；
* 每次仿真曲线；
* 学生查看图表的行为；
* 学生使用 AI 建议前后的变化；
* 学生从辨识到控制设计的全过程。

这类数据价值高，但成本也高，应该按课程、班级、任务单独配置。

# 十、服务器负担控制策略

竞技场容易产生两个负担：仿真计算负担和日志存储负担。

建议采用以下策略。

## 1. 白箱传递函数对象尽量前端计算

典型线性系统、串联校正、PID 调参等，可以尽量在前端完成探索性仿真。

服务器只负责：

* 保存最终方案；
* 官方复算；
* 生成排行榜；
* 记录摘要数据。

## 2. 官方评测才走服务器

学生在工作台中反复试验，不一定每次都需要服务器评测。

正式提交时才由服务器执行统一评测。

## 3. 对黑箱虚拟仿真设置实验预算

黑箱虚拟仿真不能无限调用，否则服务器压力会很大，也会变成暴力搜索。

可以设置：

* 每个任务每日实验次数；
* 每次实验最长仿真时间；
* 每个学生最大并发数；
* 每个提交冷却时间；
* 同一控制器哈希不重复评测。

## 4. 使用控制器哈希缓存

如果两个提交的控制器工件完全相同，或者同一学生重复提交相同控制器，可以直接复用评测结果。

## 5. 隐藏测试集分级执行

可以先运行公开场景快速评测。
只有进入前若干名、或学生选择正式提交时，才运行完整隐藏测试集。

这样可以减少大量低质量方案占用计算资源。

## 6. 日志批量上传

客户端不要每个事件即时上传，而应批量上传、压缩上传、失败后重试。

日志结构应轻量化，优先存摘要，不存冗余曲线。

# 十一、各类对象如何进入竞技场

你现在列出的对象来源可以这样归类。

## 1. 典型对象

这是第一阶段最容易做的。

例如：

* 一阶惯性环节；
* 二阶欠阻尼系统；
* 高阶系统；
* 含积分环节系统；
* 非最小相位系统；
* 含纯滞后系统；
* 不稳定系统。

适合任务：

* 串联校正；
* PID；
* 复合校正；
* 性能指标优化；
* 鲁棒性挑战。

这部分可以直接依托现有多表征联动引擎。

## 2. 作业对象

作业对象要注意与公开榜单的关系。

建议有两种模式：

* 作业模式：截止前不公开完整榜单，只显示个人达标情况或匿名百分位；
* 赛后模式：截止后开放排行榜和优秀方案分析。

否则排行榜会变成抄作业入口。

## 3. 控制奥德赛对象

控制奥德赛适合做成“关卡挑战”。

每个 level 对应一个对象和一个任务，排行榜可以分为：

* 当前关卡榜；
* 章节榜；
* 总进度榜；
* 最少尝试次数榜；
* 最佳改进榜。

控制奥德赛更适合强调成长性，而不是只强调最终最优。

## 4. 虚拟仿真对象

虚拟仿真对象应作为黑箱挑战。

入口可以有两个：

* 从虚拟仿真实验进入：“将本实验对象导入工作台”；
* 从竞技场进入：“挑战该虚拟对象”。

评测按照实际闭环表现，而不是传递函数指标。

## 5. 前沿拓展对象

这部分可以独立为“高级挑战区”。

适合研究生、课程项目、拔高任务，例如：

* MPC 约束控制；
* 数据驱动控制；
* 强扰动对象；
* 多变量系统；
* 非线性对象；
* 鲁棒控制；
* 学习型控制器；
* 神经 ODE 建模后控制。

这里不要过早追求和本科串联校正完全统一。统一的是评测和工件接口，不是设计界面。

# 十二、入口设计：不要让学生先选技术，而应先选任务

一个常见错误是把入口设计成：

* 串联校正；
* 复合校正；
* MPC；
* 虚拟仿真；
* 作业；
* 奥德赛。

这会导致学生从技术入口进入，平台割裂感很强。

更好的入口是：

## 1. 竞技场大厅

展示挑战卡片，每张卡片包括：

* 对象名称；
* 来源；
* 难度；
* 任务目标；
* 允许方法；
* 当前参与人数；
* 是否计入作业；
* 是否有黑箱实验；
* 当前最高分；
* 自己最好成绩。

筛选条件包括：

* 课程章节；
* 对象类型；
* 方法类型；
* 难度；
* 是否白箱；
* 是否黑箱；
* 是否作业；
* 是否奥德赛；
* 是否虚拟仿真；
* 是否开放榜单。

## 2. 对象详情页

对象详情页展示：

* 对象说明；
* 可见模型或黑箱接口；
* 相关任务；
* 相关知识点；
* 我的历史方案；
* 其他学生的优秀结果；
* 可进入的工作台模式。

## 3. 工作台入口

从任一任务进入后，平台自动选择合适工作台：

* 串联校正任务 → 多表征联动工作台；
* 复合校正任务 → 框图工作台；
* 黑箱对象任务 → 辨识 + 控制工作台；
* MPC 任务 → 预测控制工作台；
* 虚拟仿真任务 → 黑箱实验 + 控制器导入工作台。

## 4. 个人中心

展示：

* 我的控制器；
* 我的辨识模型；
* 我的提交记录；
* 我的排行榜位置；
* 我的能力画像；
* 我在哪类对象上经常失败；
* 我在哪类指标上提升明显。

# 十五、推荐的评分结构

你可以采用如下统一评分框架。

## 1. 先判定有效性

提交先经过有效性检查：

* 控制器格式是否合法；
* 是否因果；
* 是否满足阶次限制；
* 是否满足采样周期要求；
* 是否闭环稳定；
* 是否违反安全约束；
* 是否仿真失败。

无效方案不进入主榜。

## 2. 再计算指标满意度

对每个指标转成 0 到 1 的满意度。

例如：

* 调节时间满意度；
* 超调量满意度；
* 稳态误差满意度；
* ITAE 满意度；
* 控制能量满意度；
* 鲁棒性满意度。

## 3. 用加权几何平均得到基础分

例如：

> 基础分 = 1000 × s₁^w₁ × s₂^w₂ × s₃^w₃ × ... × sₙ^wₙ

其中 s 是指标满意度，w 是指标权重。

## 4. 加入惩罚项

惩罚项包括：

* 轻微约束违反；
* 控制量过大；
* 控制器阶次过高；
* 计算时间过长；
* 采样时间不合适；
* 黑箱实验调用次数过多。

但要注意：控制器复杂度最好不要在所有任务中都惩罚。
有些高级任务允许复杂控制器，复杂度应放到“低阶榜”或作为同分决胜，而不是默认压制。

## 5. 保留分数解释

每次提交后，学生不只看到总分，还应看到：

* 哪些指标拉低了总分；
* 是否被硬约束卡住；
* 与榜首相比差在哪里；
* 与自己上一次相比改善了什么；
* 哪些指标存在权衡。

这比单纯给一个排名更有教学价值。

# 十七、作业、竞技和教学评价要分开

这一点很重要。

作业系统的目标是评价学生是否掌握知识。
竞技场的目标是激发探索和比较。
两者可以连通，但不能完全等同。

建议作业模式中采用：

* 达标分；
* 改进分；
* 反思报告分；
* 最终性能分；
* 过程参与分。

不要只按排行榜名次给作业成绩。否则学生会把目标从理解控制设计变成追求榜单投机。

更合理的是：

* 达到基本控制要求即可获得基础分；
* 性能更好获得附加分；
* 提交过程和改进轨迹计入过程评价；
* 榜单名次只作为奖励或荣誉，不作为主成绩依据。

# 十八、第一阶段不要一次性做全

如果你现在直接把串联校正、复合校正、虚拟仿真、MPC、黑箱辨识、作业、奥德赛全部一起做，系统复杂度会失控。

建议分阶段推进。

## 第一阶段：白箱对象竞技场

目标：先把统一任务、评分、榜单做出来。

包括：

* 典型传递函数对象；
* 作业对象；
* 控制奥德赛部分简单对象；
* 串联校正；
* PID；
* 主榜；
* 方法榜；
* 指标榜；
* 基础埋点。

这阶段继续充分利用现有多表征联动引擎。

## 第二阶段：复合校正工作台

目标：突破串联校正限制。

增加：

* 框图式控制器；
* 前馈；
* 局部反馈；
* 预滤波；
* 扰动补偿；
* 复合结构提交；
* 复合校正榜。

这一步可以显著扩展平台能力，但还不涉及黑箱虚拟仿真的高负载问题。

## 第三阶段：黑箱辨识 + 虚拟仿真接入

目标：把虚拟仿真对象纳入竞技场。

增加：

* 黑箱实验接口；
* 实验数据导出；
* 学生辨识模型管理；
* 控制器导入虚拟仿真；
* 官方黑箱评测；
* 黑箱对象排行榜；
* 实验调用次数限制。

这是平台从“经典控制教学工具”升级为“控制实验与建模平台”的关键阶段。

## 第四阶段：高级方法

目标：服务研究生课程、课程项目和拔高挑战。

增加：

* MPC 参数化模板；
* 优化调参；
* 鲁棒控制挑战；
* 多场景隐藏测试；
* 代码型控制器沙箱；
* 更复杂的学习分析。

这部分不要过早做，否则会吞掉大量工程资源。

# 十九、一个可落地的 MVP 方案

如果要尽快启动，我建议 MVP 这样做：

1. 建立对象库，先放 8 到 12 个典型传递函数对象；
2. 每个对象配置 2 到 3 个挑战任务；
3. 支持串联校正器和 PID 控制器提交；
4. 每个任务设置主榜、串联榜、PID 榜、专题榜；
5. 评分采用硬约束 + 指标满意度 + 加权几何平均；
6. 工作台沿用现有多表征联动引擎；
7. 结果页显示总分、分项指标、曲线、与个人历史最好结果对比；
8. 教师端支持发布作业挑战；
9. 埋点只记录打开任务、运行仿真、提交、得分、查看榜单等核心事件；
10. 预留 ControllerArtifact、ChallengeTask、PlantAdapter 这些抽象，避免后期推倒重来。

第一阶段不要急着做 MPC，也不要急着做代码型控制器。
先把“对象—任务—评测—榜单—提交—反馈”的闭环做扎实。

# 二十、最终建议的产品结构

可以把平台结构整理成下面这个形态：

> 对象库
> → 挑战任务
> → 学生工作台
> → 控制器工件 / 辨识模型工件
> → 官方评测
> → 榜单
> → 教学分析
> → 作业 / 奥德赛 / 虚拟仿真 / AI 辅助反馈

对应关系如下：

| 模块      | 作用                       |
| ------- | ------------------------ |
| 对象库     | 管理典型对象、作业对象、奥德赛对象、虚拟仿真对象 |
| 挑战任务    | 定义目标、限制、指标、榜单规则          |
| 学生工作台   | 设计、辨识、仿真、比较、保存方案         |
| 多表征联动引擎 | 作为串联校正专用工作台模式            |
| 框图工作台   | 支持复合校正                   |
| 黑箱实验工作台 | 支持虚拟仿真辨识与控制              |
| 控制器工件系统 | 标准化保存与提交控制器              |
| 官方评测引擎  | 统一计算指标和分数                |
| 排行榜系统   | 主榜、方法榜、专题榜、Pareto 榜      |
| 埋点系统    | 记录关键学习行为和提交过程            |
| 教师配置台   | 发布任务、设置评分、管理榜单           |
| 学习分析系统  | 生成能力画像、诊断问题、推荐练习         |

# 二十一、我对你当前方案的核心判断

你真正要做的不是“给平台增加一个竞技场应用”，而是要建立一个**控制系统设计任务的统一评测基础设施**。

竞技场只是它最外显、最有吸引力的表现形式。

如果只从“排行榜”入手，很容易变成一个附属小功能；
如果从“对象—任务—控制器工件—评测协议—榜单策略”入手，它就会成为你后续串联校正、复合校正、虚拟仿真、黑箱辨识、MPC、作业评价、控制奥德赛之间的数据与能力中枢。

最优先要定下来的不是界面，而是这几个抽象：

1. **ChallengeObject：对象是什么；**
2. **ChallengeTask：要完成什么控制任务；**
3. **ControllerArtifact：学生提交的控制器如何表示；**
4. **EvaluationProtocol：官方如何评测；**
5. **MetricProfile：指标如何归一化与计分；**
6. **LeaderboardPolicy：如何排名；**
7. **PlantAdapter：不同来源对象如何接入。**

这七个抽象定好之后，你现在列出的所有复杂来源和方法，基本都能被纳入同一体系。
