更合理的判断是：你说的“文学性”不是要把技术文档写得更华丽，而是要让模型具备更强的**中文语义辨析、搭配意识和语域控制**。GPT 的“硬”“稳”问题，本质不是词汇少，而是它把一个模糊的评价维度压缩成了一个口语化但不合语境的短词。真正要修的是“词语选择是否准确承载了判断”。

我查到的公开讨论和研究可以归纳为几个结论。

第一，所谓“AI味”确实有可观察的词汇指纹。英文研究更充分：Juzek 和 Ward 的研究指出，科学英文中类似 “delve”“intricate”“underscore” 这类词在近几年显著升频，并识别出 21 个可能与 LLM 使用有关的高频词；他们认为这种词汇过度代表现象不能简单归因于模型架构、算法或训练语料，RLHF 可能参与其中，但透明度不足仍限制了进一步确认。([arXiv][1]) 另一项对 2010—2024 年 1400 万篇 PubMed 摘要的研究发现，ChatGPT 出现后，某些风格性词汇频率突增，并据此估计 2024 年至少 10% 的摘要经过 LLM 处理。([arXiv][2]) 这说明“AI味”不是玄学，而是模型偏好的词汇、句式和语气在大规模文本中留下的痕迹。

第二，词汇贫化与搭配失真是两个不同问题。Reviriego 等人的研究比较了 ChatGPT 与人类文本的词汇多样性，发现 ChatGPT-3.5 的 distinct words 和 lexical diversity 低于人类，而 GPT-4 接近甚至部分超过人类；这意味着高阶模型未必“词少”，但仍可能在具体语境中反复调用某些安全、泛化、模板化的表达。([ScienceDirect][3]) 这正好对应你提到的现象：“硬”“稳”不是词汇量不足，而是语义维度没有被展开。它知道“robust/solid/stable”大概是什么意思，却没有把它翻译成中文学术语境中更合适的“论证强度更高、适用边界更清晰、结果更可复现、参数敏感性更低”。

第三，网上常见的“去AI味”提示词有一定价值，但方向经常跑偏。许多 prompt 建议“用简单直接的语言”“避免机器人式短语”“少用夸张营销词”，这些对公众号、邮件、博客有帮助。([Reddit][4]) 也有 Reddit 社区总结为“使用具体细节、避免陈词滥调、少做空泛乐观总结”。([Reddit][5]) 但这些方法移植到你的场景会出问题：自动控制原理讲义、教学创新报告、科研文档不能简单“口语化”，否则会损失概念密度、术语稳定性和论证层次。

第四，中文写作场景更适合采用“语言学约束型提示词”，而不是“人味化提示词”。PLOS ONE 上一篇关于日译中定语从句的研究表明，把语言学分析嵌入 prompt chain，可以显著改善复杂句式的翻译质量，平均得分提升超过 43%。([PLOS][6]) 这对你的问题很有启发：不要只告诉模型“写得自然”，而要告诉它如何判断中文搭配、语义维度、句法节奏和语体边界。

第五，从 Codex 工程实现看，这类约束不适合只塞进一次性 prompt，而应固化为写作 skill 或目录级 `AGENTS.override.md`。OpenAI 文档说明，Codex 会在工作前读取 `AGENTS.md`，并按全局、项目、子目录层级合并，越靠近当前目录的文件优先级越高。([OpenAI开发者][7]) OpenAI 的 Skills 文档也明确把 Skill 定义为可复用的指令与文件包，适合编码公司风格指南、多步骤流程和约定；如果要让行为更确定，应显式要求模型使用某个 skill。([OpenAI开发者][8])

下面给你一套我认为更适合你场景的设计。它的重点不是“去AI味”，而是把模型训练成一个懂中文技术文体的编辑。

## 一、核心策略：从“同义词替换”改为“语义维度展开”

你举的例子可以形成一个非常重要的规则：

| GPT常见表达   | 问题                                | 更合适的替代表达                                          |
| --------- | --------------------------------- | ------------------------------------------------- |
| 得到一个更硬的结论 | “硬”是英文 solid/hard 的粗糙映射，中文学术语境不自然 | 得到论证强度更高的结论；使结论建立在更充分的证据之上；扩大结论的适用范围；降低结论对特定假设的依赖 |
| 结果变得更稳    | “稳”没有说明稳定的维度                      | 提高结果的可复现性；降低随机初始化带来的波动；增强对参数扰动的鲁棒性；减少对样本划分的敏感性    |
| 方案更强      | “强”没有评价坐标                         | 方案在收敛速度、约束满足率或跨场景迁移能力上更具优势                        |
| 路径更清晰     | 可以接受，但仍偏泛                         | 学习路径的阶段划分更明确，前置知识、任务目标与评价证据之间的对应关系更容易追踪           |
| 机制更完整     | 泛化判断                              | 机制覆盖了诊断、推荐、反馈和再评价四个环节，因而能够支撑闭环改进                  |

这里真正关键的是：**形容词必须回答“在哪个维度上更好”，动词必须说明“对象发生了什么变化”。**

## 二、建议加入 Codex 的目录级 `AGENTS.override.md`

适合放在 `course-content/AGENTS.override.md` 或你专门写讲义、报告、申报书的目录中。

```markdown
# 中文专业文档写作约束

本目录中的任务主要涉及中文教学文档、课程讲义、教学创新报告、科研说明、项目申报与技术方案。写作目标不是“去AI味”，而是在保持专业性、准确性和论证密度的基础上，形成自然、成熟、有修辞判断力的中文表达。

## 总体文风

采用受过专业写作训练的中文作者风格：判断清楚，证据明确，语言有节奏，但不炫技；有修辞意识，但不文学化；有专业密度，但不堆砌术语。

避免默认使用模板化、宣传化、空泛化表达。不要把“正式”误解为“堆叠抽象名词”，不要把“自然”误解为“口语化”，不要把“高级”误解为“形容词密集”。

## 写作流程

处理任何中文文档写作或润色任务时，先在内部完成四步：

1. 抽取 brief：明确对象、事实、逻辑关系、判断、读者、语体和使用场景。
2. 选择语义维度：凡涉及“更好、更强、更稳、更深、更硬、更完整”等评价，必须展开为具体维度，例如论证强度、适用范围、可复现性、抗扰动性、可解释性、迁移能力、实施成本、学习负荷、评价证据等。
3. 起草正文：围绕对象、证据、机制、判断和意义展开，不围绕流程说明、自我解释和防御性声明展开。
4. 文风审校：检查动词是否具体、形容词是否有评价坐标、句式是否有节奏、段落是否存在模板化痕迹。

最终只输出成稿或必要说明，不展示内部 brief，除非用户要求。

## 词汇与搭配规则

优先使用能够精确表达关系的实义动词，例如：
揭示、刻画、约束、映射、分解、校准、筛选、验证、支撑、压缩、转化、追踪、聚合、对齐、嵌入、迁移、外推、收敛、扰动、退化、补偿、削弱、放大、固化、沉淀。

谨慎使用万能动词：
进行、实现、提升、加强、打造、赋能、推动、深化、聚焦、助力、构建、优化、完善。

不是禁止这些词，而是每次使用前必须判断是否可以换成更具体的动作。

## 形容词规则

禁止把以下词作为默认评价词：
硬、稳、强大、全面、深入、显著、有效、优质、丰富、完善、系统、创新、精准、高效、闭环。

如果确需表达相近含义，必须改写为具体判断：
- “更硬的结论”改为“论证强度更高”“适用边界更清晰”“对前提假设依赖更低”。
- “结果更稳”改为“可复现性更高”“参数敏感性更低”“随机波动更小”“跨样本表现更一致”。
- “全面提升”改为说明提升了哪些指标、环节或能力。
- “深度融合”改为说明谁嵌入谁、嵌入到哪个流程、改变了什么关系。

## 句式规则

避免连续使用同构句式。尤其避免：
- “不是……而是……”
- “既……又……”
- “从……到……”
- “一方面……另一方面……”
- “通过……实现……”
- “围绕……构建……体系”
- “以……为抓手，以……为路径，以……为目标”

这些结构不是绝对禁用，但不得作为默认组织方式。若使用，必须有真实辨析价值。

段落应有自然起伏：短句用于判断，长句用于展开机制；不要把所有句子写成同一长度、同一重心、同一节奏。

## 专业性规则

不得为了“自然”而牺牲术语准确性。控制理论、最优控制、教学评价、AI-OBE、知识图谱、学习路径规划等术语应保持稳定。

涉及方法、模型、指标、实验、平台、课程目标时，优先写清：
对象是什么；
变量是什么；
约束是什么；
证据是什么；
判断依据是什么；
对教学或科研问题有什么意义。

## 修辞规则

允许使用克制的比喻、转折和强调，但修辞必须服务于理解。不要使用宣传腔、口号腔和营销腔。

好的中文技术文档应让读者感觉：概念被讲清了，判断有依据，语言自然但不松散，表达有锋芒但不夸张。

## 输出前自检

提交正文前检查：
1. 是否存在“硬、稳、强、深、全面、显著”等未展开评价词？
2. 是否存在“进行、实现、打造、赋能、推动”等万能动词堆叠？
3. 是否存在只有连接词、没有真实逻辑关系的段落？
4. 是否存在英文思维直译成中文的搭配？
5. 是否可以用更准确的中文表达替换泛化表达？

发现问题时直接改写，不要解释。
```

## 三、如果做成 Skill，建议这样设计 `SKILL.md`

你之前已经在考虑 brief → prose 的隔离流程。这里应进一步加入“词汇校准”环节，而不是只做文风润色。

```markdown
---
name: chinese-professional-prose
description: 用于中文专业文档、教学文档、课程讲义、科研报告和申报材料的写作与润色。重点处理中文语义搭配、动词准确性、形容词评价维度、句式节奏和AI味消解。
---

# Chinese Professional Prose Skill

## 任务定位

你是中文专业文档编辑，不是“AI味消除器”。你的目标是在不牺牲事实、术语和逻辑密度的前提下，把文本改写为成熟、准确、自然、有修辞判断力的中文专业表达。

## 工作流程

### 1. Brief 抽取

在内部抽取以下信息：
- 文档类型：讲义、报告、申报书、论文、项目说明、课堂脚本、平台说明等。
- 目标读者：学生、专家、评委、同行、管理者、开发者等。
- 核心对象：课程、方法、平台、模型、实验、机制、问题或案例。
- 关键判断：文本最终要证明什么。
- 证据基础：数据、案例、机制、对比、理论依据或实践成果。
- 语体要求：学术、教学、申报、技术说明、课堂讲述等。

### 2. 语义维度校准

遇到泛化评价词时，必须追问它实际指向哪个维度：
- 强：论证强度、方法能力、指标优势、约束满足能力、迁移能力？
- 稳：可复现性、抗扰动性、跨样本一致性、参数敏感性、收敛稳定性？
- 深：理论深度、机制解释、数据颗粒度、任务嵌入程度、反思层次？
- 全面：覆盖范围、流程环节、评价维度、数据来源、应用场景？
- 有效：相对于什么基线、改善哪个指标、解决哪个问题？

不要保留未校准的评价词。

### 3. 动词替换

将万能动词替换为具体动作：
- 进行分析 → 分析、拆解、比较、刻画、验证
- 实现提升 → 提高、降低、缩短、扩大、增强、稳定、压缩
- 构建体系 → 建立结构、定义关系、串联流程、形成机制
- 深度融合 → 嵌入流程、对齐目标、连接数据、改写任务结构
- 赋能教学 → 支撑诊断、辅助反馈、驱动推荐、改进评价

### 4. 中文搭配审校

检查是否存在英文直译或不自然搭配：
- 更硬的结论 → 论证更充分 / 结论更有说服力 / 适用边界更清晰
- 更稳的结果 → 结果更可复现 / 波动更小 / 对扰动更不敏感
- 更深的融合 → 融入更具体的教学环节 / 与任务流程结合更紧
- 更强的能力 → 在某一指标或场景下表现出更高能力

### 5. 正文生成

正文应围绕对象、证据、逻辑、判断和意义展开。少用解释自己如何写作的句子。不要在正文中暴露流程。

## 禁止倾向

避免：
- 套话式总结；
- 宣传口号；
- 过度对称结构；
- 机械连接词；
- 空泛形容词；
- 过度列表化；
- 为“自然”而降低专业密度；
- 为“学术”而堆叠抽象名词。

## 输出要求

用户要求写作时，直接输出成稿。
用户要求润色时，输出润色稿；必要时附极简修改说明。
用户要求诊断时，指出词汇、句式、逻辑和语体问题，并给出替代表达。
```

## 六、我的最终建议

你不应该把目标设为“让 GPT 更有文学性”。这个说法容易诱导模型增加修饰、比喻和情绪，结果反而更像 AI。更稳妥的目标是：

**让模型在中文专业写作中具备语义维度意识、搭配判断能力和语体自律。**

也就是说，不是让它多用形容词和动词，而是让它知道：什么时候该用“更可复现”，什么时候该用“更具外推性”，什么时候该用“论证强度更高”，什么时候只能老老实实写“实验结果波动更小”。

这才是中文专业文档里真正的“文科生能力”：不是文采，而是词义的边界感。
