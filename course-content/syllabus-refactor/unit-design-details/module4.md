# 模块4单元设计细节

更新时间：2026-04-20

## 使用说明

- 本文件服务模块4的统一设计真值，优先约束学生版讲义，再派生教案、互动课程设计与媒体清单。
- 本轮已正式合并原 `4-3 / 4-4`，新的模块4固定为 `7` 个单元、`14` 学时。
- 本文件不再保留“防御性失败剧本”式写法。模块4的学生向主线必须首先服务直接设计逻辑，而不是服务教师诊断话语。

## 模块4总定位

- 模块4是课程的“约束设计层”。
- 它承接模块3已经建立的机理语言，把“结构机理”转成“设计动作”。
- 模块4的稳定主线固定为：
  - 任务表达；
  - 结构选型；
  - 初始方案落地；
  - 优化建模；
  - 带约束参数优化；
  - 结构编码与场景迁移；
  - 完整工程设计闭环。

## 四类产物的模块级约束

### 学生版讲义

- 讲义必须把模块4写成“设计动作链”，不再写成“控制器方法大全”。
- `4-3` 是本轮重构重点：
  - 正文必须按“对象分析 -> 结构组合 -> 参数方向 -> 首轮验证 -> 问题清单”展开；
  - 不允许再以“方案卡字段学”“失败分类学”“故意失败再归因”为主线。
- `4-4` 到 `4-7` 必须建立在 `4-3` 的证据之上，不另起抽象话语。

| 单元 | 讲义必须展开的内容 | 可降位处理的内容 | 禁止扩张的内容 |
|------|------------------|----------------|--------------|
| `4-1` | 指标角色、约束分类、任务书写法、`ITSE` 与控制量代价的最小评价语言 | 部分指标枝节数学细节 | 控制器选型与优化算法细节 |
| `4-2` | 控制结构任务适配逻辑、单结构起步、前馈入口 | 小众结构变体 | 完整方案形成与优化 |
| `4-3` | 对象分析、结构组合、参数方向、首轮验证、问题清单与参数优化入口 | 个别枝节参数经验 | 防御性失败剧本、优化算法原理细讲、最终最优解 |
| `4-4` | 目标函数构造、参数范围与归一化来源、权重偏好、无约束候选解解释、最小 Pareto 概念 | 某些指标组合的过细数学讨论、求解器细枝末节 | 输出侧硬约束、罚函数、完整优化算法专题 |
| `4-5` | 越界证据揭露、硬约束显化、罚函数法、带约束参数优化、证据复核与剩余风险 | 个别学生版本的参数细节 | 从零重选结构、黑箱自动调参 |
| `4-6` | 固定结构优化的边界、结构编码入口、迁移后的目标重排 | 个别案例延伸对比 | 前沿案例展示、完整算法比较课 |
| `4-7` | 完整设计闭环、结构/参数优化结果解释、有限换结构边界 | 个别对象变体 | 模块5内容前移 |

### 教师版教案

- 教案必须把模块4组织成“决策课”，不是“算法课”，也不是“平台演示课”。
- `4-3` 的教师追问应围绕：
  - 为什么这个对象先抓这组矛盾；
  - 为什么此刻仍用单结构，或必须补入第二机制；
  - 第一轮验证该看什么偏差。

| 单元 | 教师主讲重点 | 教师介入点 | 课堂收束句 |
|------|-------------|-----------|-----------|
| `4-1` | 先把任务写清，再谈方法 | 学生把所有指标视为同等目标时 | 先写任务，再选结构 |
| `4-2` | 选结构不是背名字，而是讲理由 | 学生只报结构名、不报作用点时 | 先说明为什么是它 |
| `4-3` | 方案落地比防御性解释更重要 | 学生想把设计写成预案堆积时 | 先做出第一版，再用证据说话 |
| `4-4` | 目标函数先于算法，先让候选解把偏好暴露出来 | 学生把候选解直接当成可用解时 | 先写清偏好与候选，再谈它为什么还不够 |
| `4-5` | 求解结果要能回到参数、约束和证据上解释 | 学生只报最优参数、不解释约束来源时 | 先解释哪条边界被突破，再接受数值结果 |
| `4-6` | 场景一变，固定结构优化可能先失效 | 学生把迁移看成只改几个参数时 | 先证明固定结构为什么不够，再引入结构编码 |
| `4-7` | 能完成从建模到解码解释的完整流程，才算完成设计闭环 | 学生只报最优解、不说明结构与参数含义时 | 会把优化结果翻译回工程语言，才算会设计 |

## 单元详细设计

### `4-1（理论） 设计起点：性能指标体系、工程约束与可行域表达`

**定位**

- 模块4入口课。
- 任务是把分析量改写成任务书，而不是重新罗列性能指标。

**建议课堂组织主线**

- 同图异读，先看主场景A与对照场景为什么任务排序不同。
- 再把时域、频域、积分误差类指标压成三种角色：
  - 硬约束；
  - 软目标；
  - 观察指标。
- 最后输出任务书与可行域分层。

**主资源**

- `pptx/6性能指标_控制效果评价`
- 船舶 `5.1 / 5.3`

**固定产出**

- 双场景同图异读对照表
- 任务表达卡
- 评价函数语言卡
- 初步可行域草图

### `4-2（理论） 控制器选型原理`

**定位**

- 模块4的单结构首轮起步课。
- 本课解决“为什么此刻先选它”，不解决“怎样把整套方案完全落地”。

**建议课堂组织主线**

- 回收 `4-1` 的任务书并锁定最紧矛盾。
- 用结构工具箱说明各结构先改哪段行为、先透支什么代价。
- 至少完成一轮 `PI/滞后` 与 `PD/超前` 的定量比较。
- 正式讲透前馈的两条路径：
  - 按输入补偿；
  - 按扰动补偿。

**主资源**

- `pptx/10.1`
- `pptx/20`
- `pptx/21`

**固定产出**

- 单结构起步卡
- 前馈适用边界表
- 结构选择理由表

### `4-3（实践） 初始方案落地实践：从对象分析到结构组合与首轮验证`

**定位**

- 本轮重构重点课次。
- 它是原 `4-3 / 4-4` 合并后的新实践课。
- 目标不是让学生先学一套失败诊断术语，而是让学生真正把方案做出来、跑起来、看见第一轮偏差。

**建议课堂组织主线**

- 第一步，回收任务书与 `4-2` 的单结构起步卡。
- 第二步，重新看对象：
  - 主矛盾是什么；
  - 只用单结构是否足够；
  - 是否需要补入前馈或第二条机制线。
- 第三步，把方案直接落地成最小可运行版本：
  - 结构骨架；
  - 参数方向；
  - 首轮关注的关键指标。
- 第四步，立即做首轮验证，不再把验证拆成下一课：
  - 看时域过程；
  - 看频域读回；
  - 看控制量与约束边界。
- 第五步，把偏差压成问题清单，只回答“下一轮先改什么”，不在本课展开完整优化课。

**知识清单**

- 对象分析如何直接进入设计。
- 单结构与复合结构的分流条件。
- 前馈与反馈共同进入方案时的骨架表达。
- 参数方向的最小写法：
  - 先改哪段行为；
  - 预期换来什么；
  - 最可能先透支什么。
- 首轮验证的最小读数逻辑：
  - 是否抓住主矛盾；
  - 是否触碰硬约束；
  - 下一轮该先问什么。

**能力清单**

- 能从对象分析直接写出第一版方案。
- 能解释为什么此刻仍用单结构，或必须进入组合结构。
- 能把参数方向写成设计语言，而不是“调大一些/调小一些”。
- 能在首轮验证后提炼问题清单。

**主资源**

- `pptx/22串联校正`
- `pptx/23滞后超前`
- 船舶 `6.1`
- 船舶 `6.2`

**固定产出**

- 对象分析记录单
- 初始方案表达卡
- 首轮验证记录表
- 问题清单移交表
- 参数优化入口卡

**成文边界**

- 讲义正文不再单列“失败三分类”。
- 讲义正文不再故意设计“先失败一次”来制造戏剧性。
- 若需保留偏差类型，只能放在教师教案或侧栏，不占正文主线。

### `4-4（理论） 多目标权衡与控制器优化设计`

**定位**

- 模块4后半链的理论中枢课。
- 建立在 `4-3` 已确定结构、已拿到首轮证据的基础上。
- 本课的重点不再是重复经典整定步骤，而是先把性能指标、控制代价和任务偏好写成无约束加权目标，并得到一版看似合理的候选解。

**建议课堂组织主线**

- 先回收 `4-3` 的固定结构、问题清单与参数起点。
- 再把调节时间、`ITAE / ITSE`、控制量代价等量改写为加权目标项，并说明归一化基准来自哪里。
- 明确局部优化问题的最小写法：参数向量、目标函数、参数范围、初值来源。
