# 单元 1-1 教师版课堂讲义

## 课堂定位

本课是整门课程的第一次课。核心任务只有一个：在 90 分钟内让学生**看见整门课的全貌**。不要求学生会推导任何公式，只需要他们下课时能说出三件事：反馈是什么、这门课有哪些核心主题、每个主题用一行什么代码。

学生可能带着两种心态走进教室：一种是"控制理论很难，全是数学"，另一种是"这就是调参数，没什么好学的"。本课要同时应对这两种心态——用一条船八个问题的闪电速通打破对数学的恐惧，用反馈和校正的直观必要性打破"调参数没什么好学的"的轻视。

## 90 分钟时间分配建议

| 时间段 | 环节 | 时长 | 核心动作 |
|------|------|:---:|------|
| 0-5min | 开场 | 5min | 模块1总览 + 封面图引入。一句话定位："今天你要用一条船，把整门课走一遍。" |
| 5-10min | 第一节 | 5min | 困惑型开场——读一遍"同样的问题，不同的面孔"段，让学生自己读出核心问题句 |
| 10-50min | 第二节 | 40min | **闪电速通核心段**。八个问题，平均每个 5min。节奏控制见下方 |
| 50-60min | 第三节 | 10min | 反馈改写行为逻辑 + 校正循环 + 开闭环对比表 |
| 60-65min | 第四、五节 | 5min | 课程地图表 + 学习习惯。这两节可以快速过，地图表让学生课后自己读 |
| 65-75min | 第六节 | 10min | 代码走通示例。如果教室有投影，逐段运行讲义第六节完整代码，让学生看到代码真的能跑 |
| 75-90min | 第七、八节 | 15min | 习题方向 + 后测提问 + 总结三句话。不展开复杂习题 |

## 第二节闪电速通节奏控制

八个问题以"一条船"贯穿。每个问题的讲解节奏：
1. **抛出问题**（1min）：用船的场景提问——"你拿到一条船的模型，第一件事做什么？"
2. **核心思想**（2min）：最简版本——一行公式、一个概念
3. **一行代码 + 一张图**（2min）：展示代码→展示运行结果图

**关键教学动作**：
- 问题一讲到代码时，停下来确认学生知道"MATLAB/Octave 是什么"——可能有学生从未接触过
- 问题三的模态叠加公式 $e^{\sigma t}\sin(\omega t)$ 不需要推导，只需要说"所有线性系统的响应都是这种形式的组合，其中 $\sigma$ 是极点实部"
- 问题五第一次出现"极点"——这是闪电速通中需要停留最久的一个概念。用"地图上的坐标"比喻，让学生建立"极点位置=系统行为"的直觉
- 前七个问题结束后，一定停下来问一句："到这里你手上有几件工具了？"——引导学生自己数：step/rlocus/bode/margin/isstable——五件
- 过渡到第三节时，用一个反问："工具都有了，但你只是在看——你什么时候能动手改？"

## 第三节教学要点

- 开环控制示意图和闭环控制示意图要并排放，让学生一眼看到差异
- 反馈的"双刃剑"比喻要在口头上强调——"反馈不保证变好，只保证有修正的机会"
- 校正循环口头走一遍：诊断→加控制器→重新诊断→比较→调整。"这条循环你会走几十遍，每次都会比上一次更清楚为什么这样调。"
- 开闭环五维对比表不需要逐行念，让学生课后自己看

## 第六节代码演示要点

- 如果教室能投影：现场打开 MATLAB/Octave，逐段运行讲义第六节的完整代码
- `step(G)` 出图时停顿 3 秒，让学生自己看曲线
- `rlocus(G)` 出图时指着会合点和分离趋势——"这里就是系统从平稳走向振荡的转折点"
- `margin(G)` 出图时指出相位裕度——"这个数字告诉你离失稳还有多远"
- 校正前后对比 `step(G, Phi2)` 是最有冲击力的一张图——一条曲线持续增长，另一条曲线收敛到有限值，反馈改写行为的效果一目了然
- 运行完全部代码后，回到开头那句"一节课学会自动控制"——"刚才的 20 行代码，你走通了建模→诊断→校正→验证的完整闭环。这就是控制工程师的标准动作序列。"

## 常见学生反应与应对

| 学生可能的反应 | 教师应对 |
|------|------|
| "代码太多，记不住" | "不需要记。后续每一章都会回到这些代码上。今天只需要知道它们存在。" |
| "极点到底是什么" | "把它想成系统指纹——每个系统有自己的极点，极点的位置决定了系统的性格。第 1-2 课专门讲这个。" |
| "根轨迹图怎么看" | "横轴是实部，纵轴是虚部。每条曲线是一个极点随增益增大走过的路径。第 3-3 课会教你画这张图。" |
| "这就完了？我没觉得学会了什么" | "这就对了。今天你看见的是整门课的地图。接下来的 31 次课，你会把这张地图上的每个标记都走一遍。" |
| 安静，没有反应 | 正常。第一次接触控制理论的学生很难在 90 分钟内形成可表达的问题。看他们下周回来时能不能说出"反馈"和"极点"两个词。 |

## 板书建议

- 黑板左侧保留：$e(t)=r(t)-y_m(t)$（整节课的核心公式）
- 黑板右侧保留：六个函数名纵列——`tf` `step` `rlocus` `bode` `margin` `feedback`（学生下课时带走的最小工具箱）
- 中间在讲八个问题时逐行擦写
- 下课时黑板上只剩左右两列——这是学生最可能记住的两件事

## 与后续课的衔接语

> "今天你看到了整张地图。下周我们回到地图上的第一个标记——模型与极点。你会知道那个 $G(s)$ 到底是怎么写出来的，以及为什么极点的位置几乎决定了系统的一切。"
