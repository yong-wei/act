# AGENTS.override.md

## 适用范围

本目录用于 lesson 主线下的人读文档，包括但不限于：

- `design/{unit}-handout.md`
- `design/{unit}-teacher-handout.md`
- `design/{unit}-boppps.md`
- `design/{unit}-interactive-page.md`

这些文件都继承上层 [course-content/AGENTS.override.md](/Users/YW/Documents/Site/act.just.edu.cn/course-content/AGENTS.override.md) 的总闸门；本文件只补本文类特化要求，不重复改写总则。

---

## 通用原则

- 根据读者与内容直接写作，校对实际问题；不机械执行多轮去污染重写。
- 资源采用单、PDF 导出、脚本验证、runtime 同步、实现契约、时长门槛等内容继续作为隐含约束存在，不直接进入解释性段落。
- 只有文档本身需要说明使用方式时，才允许显式写流程；否则默认压低工程和管理口吻。

---

## `handout.md`

- 目标是学生自读文本，主线应当是对象、证据、判断和意义。
- 强力压制“本讲 / 上一讲 / 下一步 / 本讲产出 / 本讲负责什么接口”。
- 不把课程编排、教师安排、导出检查和资源处理写成正文。

## `teacher-handout.md`

- 允许有限的课堂组织、板书提醒和节奏提示。
- 不得写成工单、项目汇报或逐项检查单。
- 教师提示应服务课堂判断与讲解，不服务流程自证。

## `boppps.md`

- 允许保留阶段顺序、时长和教师介入点。
- 解释性段落仍应围绕学习任务、证据和误判点展开。
- 不用项目管理文风描述课堂推进，不把“达成 / 移交 / 收口 / 交付”写成主干。

## `interactive-page.md`

- 允许使用页面、区域、模块、教师控制、学生默认状态等页面蓝图语言。
- 不得写成前端需求单、组件工单或教师口播脚本。
- 页面 prose 应解释“当前页在看什么对象、做什么判断、凭什么证据得出结论”。
