# 课程先后修作者决策

本清单覆盖已确认课程计划的模块 1—5，共 31 个单元。课程范围来自蓝图、单元设计和讲义知识节点，不由已有资源绑定反推。知识主题与先后修方向由本次执行代理逐项整理，脚本只校验和物化这些决策。

- `topics.jsonl`：主题、精确 Authority 对象、语义依据、课程出现位置；同一主题的不同来源对象保持各自身份。
- `units.jsonl`：每个单元涉及的主题及来源文件。
- `dependencies.jsonl`：逐条先后修、必要或推荐强度、教学理由及课程证据。
- `manifest.json`：课程与 Authority 来源、固定分母、既有事实来源、明确保留的 Authority 缺口。

2026-09-09 用户选择先交付现有 Authority 范围。MPC、数据驱动、强化学习等未匹配主题仍在清单中，`fullCourseCoverage` 始终为 false；它们的关系不会用相近对象代替，也不会被物化为虚假的已发布边。

143 个主题中，133 个映射到当前 r6 的 193 个 DomainConcept；10 个主题保留 Authority 缺口。应用型课程表单和同题比较通过其涉及的知识主题说明，不把表单标题冒充新的工程概念。31 个单元均有明确记录。

## 关系判断

必要前置仅用于定义或计算所必需的知识，例如相位裕度需要先区分增益穿越频率，峰值时间的计算需要识别阻尼振荡频率。推荐顺序用于课程安排和方法比较，不把讲授先后自动升级为知识上的必要依赖。

上升时间采用明确的定义约定；增益穿越、相位穿越和闭环带宽保持分离；根轨迹渐近线不与 Bode 渐近线合并。课程里的先后修不采用 Canonical ID 排序，也不通过任意连边满足弱连通。

组合时保留既有已发布课程先修及其原强度，排除旧领域层中没有证据的自动扩展边。适用的工程 prerequisite 复用现有采用器，保留快照和边级回执；与教学判断冲突或不在本课程范围内的工程关系保持原工程事实，不伪装为已采用的课程事实。

## 校验与物化

在仓库根目录运行 `rtk npx tsx scripts/knowledge/build-course-prerequisite-projection.ts --check`，检查课程来源、固定分母、语义摘要、端点、连通性及 REQUIRED 无环性。

提交作者决策并冻结应用修订后，运行同一命令并使用 `--write --authoring-revision <完整应用修订>`。该命令只更新本地候选教学投影；生产须与资源绑定、分片、双语资格和兼容性证明共同发布，不能单独拷贝或切换一个指针。
