## 一、M3 单元重排序分析

### 1.1 当前顺序的问题

当前 M3 顺序：
```
3-1 纯极点 → 3-2 劳斯 → 3-3 根轨迹 → 3-4 根轨迹读图
  → 3-5 零点动态改善 → 3-6 零点设计实验 → 3-7 稳态误差 → 3-8 频域判别 → 3-9 综合映射
```

用户反馈：**3-7 稳态误差出现得太迟**。从教学节奏看：
- 学生学完 3-2（劳斯判据）已经具备了"稳定 vs 不稳定"的判断能力
- 3-2 末尾引入了参数可行域，将视角拉到复平面上
- 此时学生自然会问："稳定之后，精度怎么办？"
- 但当前顺序下，学生需要先学完根轨迹（3-3/3-4）和零点（3-5/3-6），共 8 学时后才正式接触稳态误差

### 1.2 建议的新顺序

```
3-1 纯极点视角（理论）
  ↓
3-2 劳斯判据与参数可行域（实践）
  ↓
3-7 型别、积分与稳态改善（理论）  ← 前移
  ↓
3-3 根轨迹机制与完整法则（理论）
  ↓
3-4 根轨迹读图与广义参数（实践）
  ↓
3-5 零点引入与动态改善（理论）
  ↓
3-6 零点设计实验（实践）
  ↓
3-8 频域判别与跨域综合（理论）
  ↓
3-9 综合映射实验（实践）
```

### 1.3 前移的可行性验证

重读 3-7 讲义后确认：

**可调用的前置（已就绪）**：
- 负反馈结构表达 → 2-1 已建立
- 闭环传递函数 → 2-1 方框图工具 + 2-2 可以在课后练习中完成
- 终值定理 → 需要在 2-2 或 3-1 中增加最小引入（1页），这是前移的关键前提
- 极点语言和稳定判断 → 3-1/3-2 已建立

**需要调整的依赖**：
- 3-7 讲义中提及"根轨迹基本语言"和"超前/PD 动态改善"作为对照——前移后这些应改为**前向引用**：
  - "零点主导的动态改善线将在 3-5 中展开"
  - PI/滞后与 PD/超前的对比可以保留，但标注为"预告"而非"回顾"
- 3-7 的频域解读（PI/滞后在 Bode 图上的低频补偿效果）→ 不依赖 3-8，因为 M2-3/M2-4 已建立了 Bode 图的基本读法

**前移的收益**：
1. **逻辑链更自然**：稳定（3-1/3-2）→ 精度（3-7）→ 动态（3-3~3-6）→ 频域收束（3-8/3-9），形成"先保稳→再求准→再求快→统一翻译"的递进
2. **与指令跟踪的直觉一致**：学生天然会问"稳定了之后，能不能更准？"，而不是先问"极点怎么迁移"
3. **3-2 的参数可行域为 3-7 的型别概念做了铺垫**：参数可行域讲的是"k 在什么范围内稳定"，3-7 讲的是"系统结构（型别）决定了某类误差能否消除"
4. **M2 的频域对象不会被闲置太久**：3-7 的 PI/滞后频域解读调用了 M2-3/M2-4 的 Bode 图基础，保持频域语言热度

### 1.4 前移需要注意的问题

1. **终值定理的引入时机**：必须在 3-7 之前。建议在 2-2（时域响应基础）末尾增加一页"终值定理最小入口"——定义 + 一个一阶示例，3-7 直接调用。
2. **3-7 中 PI/滞后与 PD/超前的对照需要标注为前向引用**：将"我们已经知道 PD/超前改善动态"改为"后续 3-5 将建立零点动态改善线，那时你会看到 PD/超前与今天讲的 PI/滞后分别站在两条不同的补偿线上"
3. **3-2→3-7 的衔接句**："在 3-2 中你知道了参数在什么范围内系统是稳定的。今天我们来回答下一个问题：稳定了，就一定准吗？"

## 二、M3-M4 各单元的修正密度评估

### 2.1 3-8：从"🔴过载"修正为"🟡偏重"

**此前误判的原因**：将 3-8 视为"频域分析的完整建立课"，未考虑前置铺垫。

**实际情况**（重读讲义后确认）：
- 2-3/2-4 已建立 Bode/Nyquist 的对象层读图能力
- 3-4 的实践课已在频域图中做过主导极点近似验证
- 3-5/3-6 中零点作用的频域解读已多次出现
- 3-7 中 PI/滞后的低频补偿已涉及频域代价分析
- 因此 3-8 需要新讲的核心内容**只有两项**：
  1. 幅角原理 → Nyquist 判据（闭环稳定如何改写为开环曲线对待 (-1,0)）
  2. Bode 判稳与三频段理论的正式收束

讲义的实际组织也证明了这一点：2.1 节"频域是统一翻译器"直接回收了 3-1~3-7 的全部机制线，2.2 节"四类频域指纹"只是将已知内容重排到频域框架下，真正的新内容从 2.3 节（幅角原理→Nyquist 判据）才开始。

**修正后的密度**：🟡 偏重（而非 🔴 过载）。90 分钟内可完成——前提是 2.1/2.2 的"回收+翻译"控制在 25 分钟内，留 65 分钟给判据+案例。

### 2.2 4-1：内容偏空，需要充实

**用户判断**："真要说毛病的话，4-1感觉有些空倒是真的。"

**重读验证**：
- 4-1 的核心内容（同图异读、四格联读、任务排序）是有价值的——它解决的是"从分析走向设计"的认知转折
- 但"任务表达卡"的七字段格式和"三层区域"（可行域/满意域/最优域）确实有过度形式化的倾向
- 当前讲义中真正有血有肉的内容是 2.1 节的双场景跨域证据对比（客船 vs 稳定平台），其余部分偏向框架说明

**建议的充实方向**：
1. **将 ITSE/IAE/ITAE/ISE 等积分误差指标前移到 4-1**（当前只有 4-4 中出现），让学生在设计入口就建立"不同指标适合不同任务"的意识
2. **增加一个"失败的设计任务书"案例**——展示如果任务排序错误（例如在客船上优先追求速度），会出现什么后果。让"为什么任务排序重要"成为被证明的结论而非被宣称的原则
3. **或者将 4-2 的控制器结构总览表（表 2）轻量前移到 4-1 末尾**，作为"这是你接下来会用的工具箱"的预告，让 4-1 有一个更实在的落点

### 2.3 4-2：从"🔴过载"修正为"🟡偏重"

**用户判断**："PI与PD相关的内容也已经前置讲解过，本单元基本只是在此基础上给出复合结构（PID、滞后-超前）等，体量也并不离谱。"

**重读验证**：
- 表 2（8 种结构）确实信息量大，但 PI 和 PD 的核心机理已在 M3 讲透（3-5 PD/超前，3-7 PI/滞后），4-2 只需要**调用**而不需要**重新建立**
- 4-2 真正的新内容是：选型决策树（如何根据任务证据选择结构）、整定方法（ZN/频域/模型匹配）、客船案例的四候选比较
- 其中 ZN 整定在传统课程中是一个独立练习课，在此降为 4.1 节的 7 个步骤+一张表——这是合理的压缩

**修正后的密度**：🟡 偏重。主要压力来自"5 个例题"的课堂时间分配——建议精选 2 个主线例题（PI 整定 + 超前整定），其余作为课后延伸。

### 2.4 4-7：范围失控，需要收束

**用户判断**："作为收口单元，想表达的内容太多，没有把握住。"

**重读验证**：
- 讲义包含五大块：分段辨识（舵机+船体+扰动）→ 指标翻译（9项）→ 传统设计（四联图+PI+超前参数计算）→ 优化设计（结构编码+GA粗搜+精修+解码）→ 扰动/噪声边界（三级扰动+四类控制器+四类局限）
- 其中分段辨识（三组数据拟合）本身就是一次完整的系统辨识实践，放在一个"收口课"中过于奢侈
- 优化设计的结构编码+GA搜索重复了 4-6 的部分内容

**建议的收束**：
- **主线聚焦**：传统设计的完整流程（诊断→选结构→算参数→跨模型验证）。这是 4-7 最不可替代的价值——它是学生第一次在高保真模型上验证低阶设计。
- **降位处理**：分段辨识的方法细节降为"辨识方法卡"（半页速查），参数结果直接给出，不展开拟合过程
- **移除重复**：结构编码搜索已在 4-6 讲透，4-7 只引用结论，不再重新展开 GA/PSO
- **保留核心**：传统 vs 优化设计的双轨对比是 4-7 的精华，必须保留

## 三、M5 的内容充实分析

### 3.1 5-1：框架层过厚，工程内容不足

**用户判断**："AI味十足的空洞逻辑，看似步骤结构清晰，但是没有太大实践价值。"

**重读验证**：

讲义中**有价值的部分**（应保留和强化）：
- 五个默认条件表——线性主干的假设透明化，教学价值高
- 10 种非线性环节的数学定义和工程解读——具体、可验证
- 局部线性化的合理/不合理对比（tanh vs sgn）——用同一被控对象做控制变量，说服力强
- 四组仿真场景（饱和/死区/继电器/速率限制，均配图）——统一分析模板

讲义中**空洞的部分**（需要重写或删除）：
- "五步判断框架"（现象定位→假设回查→范围判断→风险说明→处理方向）——这五步没有给出任何工程上可操作的具体标准。什么算"假设回查"？怎么判断"范围"？框架本身没有回答这些问题
- "三类处理方向"（继续线性修正/进入边界工具/更换系统视角）——过于抽象，学生无法据此做出实际判断
- 整个第 5 章（五步框架+三类方向）约占据了讲义的 20%，但教学产出最低

**建议的重写方向**：

用**2-3 个真实的工程边界失效案例**替代抽象框架。每个案例回答四个问题：
1. 系统在什么工况下触碰了什么边界？
2. 线性预测与实际响应之间出现了什么具体的差异？
3. 这个差异在哪些图上（时域/频域/控制量）可以被看见？
4. 工程师实际做了什么来判断和处理？

例如：舵机饱和案例（完整的仿真对比）→ 摩擦死区案例 → 模式切换案例。通过这些案例，学生自己会归纳出"边界判断"的思维模式，而不是被灌输一个五步框架。

当前讲义中 4.1-4.6 的非线性环节描述质量不错，可以保留为"边界现象图鉴"，但讲义的主线应该从"框架→分类→定义"改为"**案例→现象→判断→工具选择**"。

### 3.2 5-4：数据驱动迁移的逻辑线需要澄清

**用户判断**："感觉讲的也不是很清晰。"

**重读验证**：

讲义中**清晰的部分**：
- 1.1-1.3 模型压力的三类来源（参数/约束/链路输入）——分析到位
- 2.1-2.3 MPC 的定位和局限——原理清楚，辨析例子有效
- 3.1 模型驱动与数据驱动的责任差异表——对比清晰

讲义中**不清晰的部分**：
- **3.2 数据驱动 MPC 的在线更新链路**：`r_{j+1}=a r_j+b δ_j+c → 参数估计 → 连续对象换算` 这一段的跳变太大。学生先看到"早段数据修正了名义模型"，然后突然跳到"离散模型参数估计"，中间缺少关键连接——**为什么要用离散模型？这个离散模型与原来的连续传递函数是什么关系？**
- **3.3 辨析例子的定位模糊**："数据补偿适合承担局部责任"是对的，但这一段的论证太依赖抽象推理，缺少一个配仿真图的对比（例如：全数据驱动 vs 局部数据补偿 在同一航向任务上的表现差异）

**建议的修改**：
- 在 3.2 之前增加半页"从连续模型到离散估计"的最小过渡——解释为什么需要用离散时间模型做在线参数估计（因为数据是离散采样点），以及离散参数 a, b, c 与连续参数 K, T 之间的数学关系
- 将 3.3 的辨析例子配上仿真对比图（与 1.3 的名义模型预测偏差图形成呼应）

### 3.3 5-5：原理层需要加强

**用户判断**："示例比较充分了，但是原理层面还是偏弱。"

**重读验证**：

讲义中**充分的部分**：
- 横向误差修正小仿真（2.2 节）——直观展示了"状态-动作-回报-策略"
- 航向控制 RL 的十步设计路线（4.1-4.10）——从结构选择到部署验证的完整工程链路
- 四种模式调度（预冷/正常/节能/保守恢复）——展示了 RL 作为"调度器"的务实工程入口
- 四类方法在复杂场景中的对比——评价结果表具体

讲义中**薄弱的部分**：
- **RL 的核心概念引入跳跃**：2.1 节直接从"序贯决策"跳到 `J(π)=E[Σγ^k r_k]`，然后跳到 Q-learning 更新式。中间缺少一个关键步骤——**值函数和策略之间的关系**。学生看完 2.1/2.2 后，知道"有状态、动作、回报"，但不知道为什么值函数会收敛、为什么策略会改善。
- **缺乏与经典控制的原理层桥接**：MPC 是"模型预测+滚动优化"→RL 是"样本驱动+值函数估计"。这个桥接在 5-4 和 5-5 之间是断裂的——学生看不到从 MPC 走到 RL 的**原理连续性**（两者都在解决"在不确定环境下序贯决策"的问题，只是信息和求解方式不同）。

**建议的加强**：
- 在 2.1 和 2.2 之间增加半页"值函数的最小解释"：不推导 Bellman 方程，但用一句话+一张图说清"当前动作的价值 = 当前回报 + 未来期望回报"这个核心思想
- 在 1.3 末尾增加一个"MPC→RL 的连续谱系"过渡段：MPC 需要模型来预测未来状态，RL 用样本和值函数估计来替代显式预测——两者在"序贯决策"上是连续的，分歧在于"信息从哪来"
