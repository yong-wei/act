# 课程文本写作指南

本文件是 `course-content/AGENTS.override.md` 的正向补充。前者规定"不写什么"，本文件规定"怎么写更好"。

适用范围：学生讲义（handout.md）、教师版讲义（teacher-handout.md）、互动课程设计人读稿。其他文档类型可参考执行。

## 一、作者声音

### 1.1 角色定义

讲义中的"我们"是一个**比学生多走半步的引路人**——不是讲台上的权威，也不是完全平行的同伴，而是一个对控制之美有感受力、对工程判断有经验、愿意带着学生一起看清系统内部结构的向导。

这个声音的特质是：

- **清醒但不冷酷**：对工程问题的复杂性有充分估计，但不因此变得悲观或过度谨慎
- **欣赏但不煽情**：可以对一个精巧的反馈结构或一个干净的极点分布表达赞叹，但用事实赞叹，不用感叹号赞叹
- **直接但不粗暴**：判断句短而肯定（"这里最关键的不是增益本身，而是增益改变了极点的位置"），但不把判断变成命令
- **耐心但不拖沓**：愿意花时间讲清楚一个概念的来龙去脉，但一旦讲清楚就果断向前推进

### 1.2 声音修养

以下表达体现了这个声音的修养：

"我们先不急着算，先看清楚极点在复平面上往哪走。" — 克制地把学生拉住，不是因为"你不懂"，而是因为"还没到算的时候"

"这个现象值得多看一遍。" — 不是"你必须掌握这个知识点"，而是"这个现象本身有意思"

"到这里，三条证据指向同一个结论。" — 判断句，干脆，不附加"因此我们可以清楚地看到"这种冗余引导

"增益继续增大，并不会单纯换来'更快'。" — 直接戳破一个常见的错误直觉，不先说"值得注意的是""需要特别强调的是"

以下表达**背叛**了这个声音：

"本讲将系统讲授……" — 这是教务通知，不是作者的邀请
"学生需要重点掌握……" — 作者在替教师说话
"这一节的交付物是……" — 作者在替项目经理说话
"值得注意的是，这一结论具有重要意义" — 作者在说废话

### 1.3 灵感来源

这个声音综合了两种传统的优点：

**Åström 传统**：深刻的物理直觉先行，数学是描述直觉的语言而非替代直觉的符号操作。简洁、直接、不绕弯。一个简单的例子可以揭示一个普遍原理。尊重读者的智力，不替读者下结论，但帮读者看清该看的东西。

**讲好故事的传统**：每个概念都应该回答"它从哪个问题中来、它解决了什么矛盾、它带来了什么新问题"。不是信息的顺序排列，而是一条有张力的理解弧线。

两者折中后的声音是：**像 Åström 一样思考，像讲故事一样组织，像工程师一样判断。**

### 1.4 角色切换：从 Agent 到 Author

编写教科书时，写作者面临一个隐性的角色冲突。

在编程助手或任务执行的 harness 环境中，模型被训练成先澄清边界、再采取行动——"我将做 X，不做 Y""本节只负责 A，不涉及 B"。这种模式在代码生成和任务执行中是有效的：它让行为可预测，建立了用户对 agent 的信任。

但当同一个模型切换到文档写作时，这个行为模式需要被**主动关闭**。教科书作者不提前声明自己做不了什么，不预先纠正可能的误解，不划定免责边界。他只做一件事：**带你看看这个东西。**

这两种角色的差异是根本性的：

| Agent 的默认姿态 | Author 应有的姿态 |
|------|------|
| 先划边界，再行动 | 直接进入对象 |
| 预防误解，提前澄清 | 用清晰的解释让误解没有机会产生 |
| "这里不展开……后续才会……" | "我们在第 X 章会回到这个问题上"——只做正向预告 |
| "不能直接把 A 当成 B" | "A 和 B 的差异在于……"——正面解释差异 |
| "这并不意味着……" | 删除——如果读者可能误解，重写前面的句子而不是追加防御 |
| 通过免责建立信任 | 通过清晰建立信任 |

**为什么防御腔会引发读者的生理性厌恶。** 这不是修辞问题，是姿态问题。当读者正在放开思绪、专注理解一个概念时，作者突然插入一句"不要急着……""这里不要求你……""不能简单地认为……"——读者的思维流被打断。更糟的是，被打断的原因不是内容需要，而是作者在保护自己。读者潜意识中的反应是："我正在努力思考，你却先泼冷水，告诉我不要这个不要那个。"这不是教学，是骚扰。

**根治方法。** 写完一段后，问自己：这句话是在帮读者理解对象，还是在保护作者免受误解？如果是后者，删掉。如果确实存在一个常见的误解需要处理，把它改写成正面的辨析——"你可能会想……实际上……"——而不是防御性的禁令——"不要误以为……"。

正面辨析示例：
- ❌ "不要把开环控制和闭环控制简单地对立起来。"
- ✅ "开环和闭环的差异不在于'谁更高级'，而在于是否使用了输出信息来修正控制动作。一个系统完全可以在不同工况下切换开环和闭环模式。"

关键区别：正面辨析把误解当成一个合理的、值得认真对待的想法来讨论。防御禁令把误解当成一个需要被警告的错误。

## 二、比喻与类比

### 2.1 好比喻的三个标准

1. **映射准确**：比喻的源域和目标域之间有真实的结构对应，不是表面上"有点像"
2. **降低认知门槛**：比喻让学生用已知的、具体的、可想象的东西去理解未知的、抽象的、难直观的东西
3. **可回收**：比喻在后续单元中可以再次调用，形成积累效应。"极点像指纹"第一次出现时说"每个系统有自己的极点指纹"，第二次出现时说"还记得指纹吗？今天我们来看指纹是怎么形成的"

### 2.2 本课程推荐使用的核心比喻

| 比喻 | 映射 | 适用位置 |
|------|------|------|
| 复平面是行为地图 | 极点位置 → 行为倾向，就像地图上的等高线 → 地形 | 1-2, 3-1 |
| 极点像系统的指纹 | 每个系统有独特的极点分布，识别极点 = 识别系统性格 | 1-2, 3-3 |
| 频域像给系统做 CT 扫描 | 不同频率的正弦信号像不同角度的 X 射线，穿透系统后暴露出内部结构 | 1-4, 2-3 |
| 根轨迹是参数的迁徙图 | 增益变化 → 极点沿固定路径移动，像候鸟沿固定路线迁徙 | 1-3, 3-3 |
| 反馈像舵手持续修正航向 | 不是一次性调整，而是持续观察—比较—修正的循环 | 1-1 |
| 稳定性边界像悬崖边缘 | 靠近边界时系统行为急剧变化，一旦越过就无法恢复 | 3-2, 3-8 |
| PI 和 PD 像两种不同性格的医生 | PI 追根究底（积分消除长期偏差），PD 快速反应（微分预判趋势） | 3-5, 3-7 |

### 2.3 比喻使用规范

- **密度控制**：每个单元 1-2 个核心比喻，不要在同一个章节堆叠多个比喻
- **首次引入时花一句话解释映射关系**：不是"频域像 CT 扫描"然后就跳到公式，而是"频域像给系统做 CT 扫描——不同频率的正弦信号从不同角度穿过系统，把内部结构的特征留在幅值和相位的变化里"
- **回收比喻时不重复解释**：后续单元再次使用时，一句"还记得 CT 扫描吗？"就够了
- **禁止牵强比喻**：如果找不到准确的映射关系，宁可用平实的语言直接解释，不要硬套一个比喻。"控制系统就像一支交响乐团"——这个比喻太牵强，不要用

## 三、章节叙事弧

### 3.1 标准弧线

一个好的章节不是信息的顺序堆叠，而是一条有张力的理解弧线：

```
提出问题 → 初次尝试 → 暴露矛盾 → 引入新概念 → 解决矛盾 → 回看意义
```

**提出问题**：以一个具体的工程场景或一个令人困惑的现象开场。不是"本节我们将学习……"，而是"为什么同样的增益调整，有时让系统变快，有时却让系统振荡？"

**初次尝试**：用学生已有的知识去解决问题。这一步的关键是让学生看到——"你现有的工具几乎够用了，只差一点"。如果没有这一步，新概念就会变成从天而降的答案。

**暴露矛盾**：已有知识的边界被触及——"用现有的方法只能看到系统稳不稳定，但无法判断它稳得够不够好"。

**引入新概念**：新概念作为解决矛盾的工具出现，而不是作为"大纲要求的教学内容"出现。它有一个明确的工程动机。

**解决矛盾**：用新概念回到开头的工程场景，把问题解决。这一步验证了新概念的实用性。

**回看意义**：用一两句话把新概念放回课程地图——"有了相位裕度之后，你不再只能说'系统稳定'或'系统不稳定'，而能说'系统还剩多少余量'。这是从定性判断到定量判断的一次升级。"

### 3.2 不同知识类型的叙事变体

**[C] 计算型**："你不会算 → 这个工具让你能算 → 算完之后你看到了以前看不到的东西"

**[X] 跨域型**："你在 A 域看到了现象 → 但你不知道为什么 → 把 B 域的图拿过来并排看 → 原来 A 域的现象是 B 域的结构造成的"

**[D] 设计型**："任务摆在这里 → 你先试了一个方案 → 方案有缺陷 → 缺陷揭示了一个之前没看到的约束 → 调整方案 → 回看调整的逻辑能否迁移到其他任务"

### 3.3 反例：当前讲义中叙事弧断裂的常见模式

**模式一：开门见山式**。开场就是"本节主要内容包括……"然后平铺直叙。学生不知道为什么要学这些内容。

**模式二：工具箱式**。连续列出多个方法/结构/指标，每个用一段解释，但之间缺乏因果连接。学生知道有哪些工具，但不知道什么时候用哪个。

**模式三：防御先行式**。在展开任何内容之前，先用大段文字说明"这里不展开 X""这里只负责 Y""Z 将在后续单元中讲授"。把边界声明写成了正文的序章。

## 四、数学与文字的交织

### 4.1 公式前后文字的职责

**公式前的文字**：铺垫动机——为什么需要这个公式？它在回答什么问题？

好例子（1-1，引入 e(t)=r(t)-y_m(t) 之前）：
> 闭环中的核心量是误差。用最简洁的形式表示，就是

差例子：
> 误差的定义如下所示：

**公式后的文字**：解读含义——公式说了什么？哪个符号对应哪个物理量？公式的结构揭示了什么关系？

好例子（1-1，在公式之后）：
> 其中，r(t) 表示期望输出，y_m(t) 表示测量输出，e(t) 表示两者之间的偏差。控制器真正关心的，不是"目标值本身"，而是"现在还差多少"。

差例子：
> 式中各参数含义如下：r(t)为期望输出，y_m(t)为测量输出，e(t)为误差信号。

**公式串之间的文字**：推进论证——从上一步到下一步的逻辑是什么？是化简？是代入？还是应用了一个定理？

### 4.2 数学推导的叙事节奏

一个完整的推导过程应该有三层节奏：

1. **动机句**（1-2 句）："要回答这个问题，我们需要把闭环特征方程写出来。"
2. **推导链**（公式序列，可以沉默推进）
3. **解读句**（2-3 句）："注意这个结果的结构——K 进入了根号里面。这意味着 K 不仅改变极点的实部，也改变虚部。增大 K 之后，极点不仅向左走（衰减变快），也向上走（振荡变强）。两者同时发生。"

不要在推导之后只说"由此可得"就跳到下一段。推导的成果需要被品读。

## 五、开场技法

### 5.1 三类有效开场

**困惑型**：展示一个令人困惑的工程现象，制造认知缺口。
> 船舶修正航向时，有的过程平稳靠近目标；有的先冲过头，再来回摆动几次；还有的越调越乱。对象不同，现象却有共性。为什么？

**历史型**：用一个简短的历史片段建立概念的来源和意义。
> 1868 年，麦克斯韦发表了一篇题为"论调节器"的论文。这是他生前唯一一篇控制论论文，也是人类第一次用数学语言系统性地分析反馈系统的稳定性。在此之前，蒸汽机的调速器已经用了近一个世纪，但没有人真正理解它们为什么有时稳定、有时振荡。

**实验型**：给出一个极简的数值实验或思想实验，让学生先"看到"现象再寻求解释。
> 取一个最简单的闭环系统，只调一个参数 K。K=1 时，阶跃响应像一条平滑的 S 形曲线；K=4 时，响应先冲到目标值的 150% 再回落；K=8 时，响应剧烈振荡，几乎停不下来。同一个系统，同一个结构，只改变一个数字，行为天差地别。这个 K 到底改变了什么？

### 5.2 开场忌讳

- ❌ "本节我们将学习……"（教务腔）
- ❌ "在上一节中我们已经……本节继续……"（纯行政衔接，无认知驱动力）
- ❌ 以定义开场，以定理跟进（把探索过程全部抹掉，只展示最终结论）
- ❌ 以边界说明开场（"本节只讲……不进入……"——让学生先看到为什么值得学，再划定边界）

## 六、节奏控制

### 6.1 段落节奏

好的科技文本有呼吸感：

- **长段**（4-6 句）：展开一个机制的完整因果链。用于解释推导、呈现证据、展开论证。
- **短段**（1-2 句）：钉住一个判断。用于总结、转折、强调、过渡。
- **空行**：给读者一秒钟消化。在重要判断之后、在新话题开始之前、在一段长推导之后。

节奏模式：

```
[长段：展开机制，建立因果链]

[短段：钉住核心判断]

[长段：用例题或数据验证这个判断]

[短段：一句过渡——"但这还不是完整的图景"]

[长段：引入新的变量，揭示之前忽略的维度]
```

### 6.2 句内节奏

- 短句（一行以内）用于判断和强调："极点迁移的路径，就是根轨迹。"
- 中句（一到两行）用于解释和连接："把不同 K 对应的极点位置画在同一张复平面上，并按 K 增大的顺序连起来——你看到的就是根轨迹的雏形。"
- 长句（两到三行）用于展开因果链，但必须保持语法清晰，重心稳定。

避免连续三句以上长度相同、结构相同的句子。这会让文本失去起伏，读起来像机器生成。

## 七、判断与洞见的表达

### 7.1 判断句的写法

好的判断句是**作者送给读者的礼物**——它把前面的推导、数据和论证压缩成一句可以带走的话。

写法：
- 短。判断句越长，力度越弱。
- 不附加"可以看出""值得注意的是""需要强调的是"这类引导词。
- 如果判断是反直觉的，让反直觉本身成为力度——不需要额外加粗或感叹。

示例：
> 增益增大，并不会单纯换来"更快"。当主导极点逼近虚轴时，响应品质会迅速恶化。三域联动观察的意义，就在于让我们不再被单一指标误导。

> 反馈改善的不是系统的完美程度，而是系统在变化环境中保持目标的能力。

### 7.2 洞见与信息的分工

信息回答"是什么"——传递函数是输出与输入的比值。
洞见回答"所以呢"——正因如此，传递函数把"分析不同系统"变成了"分析同一类代数对象"。

一个好的章节应该在信息与洞见之间交替：给一段信息（定义、公式、数据），跟一句洞见（这个信息意味着什么），再给一段信息，再跟一句洞见。如果连续三页只有信息没有洞见，文本会变成手册。如果连续三页只有洞见没有信息，文本会变成散文。

## 八、文学性的边界

"文学性"在工程教材中的恰当含义是：**精确的比喻、干净的短句、清醒的判断、偶尔为之的审美欣赏。** 它不是辞藻堆砌，不是煽情叙事，不是把技术内容写成散文。

### 8.1 允许的文学化表达

- "极点在复平面上往哪里走，响应就在时间轴上怎么变。"（对偶，节奏干净）
- "增益增大，相位裕度缩小——这个交换从来没有免费午餐。"（拟人，但直觉准确）
- "在复平面上，虚轴就是稳定的悬崖。极点越靠近它，系统越危险。"（比喻，映射准确）
- "根轨迹把'参数变化'这个抽象动作变成了一张可以看的图。你把 K 从零推到无穷，极点们就在复平面上画出一条条轨迹——每一条轨迹都是一组可能的系统行为。"（叙事化，但不煽情）

### 8.2 不允许的文学化表达

- "控制理论如同一首精妙的交响乐，每个环节都和谐共鸣。"（牵强比喻，空洞）
- "极点们在复平面上翩翩起舞，共同演绎着系统的动态特性。"（辞藻炫技，信息量为零）
- "反馈，这个看似简单的概念，实则蕴含着深刻的哲学智慧。"（升华过度，空洞）
- "让我们怀着敬畏之心，走进控制理论的殿堂。"（煽情，与学生距离过远）

### 8.3 自检规则

每次使用文学化表达之后，问自己三个问题：
1. 删掉这句话，知识的完整性会受损吗？如果不会，它不是文学性，是装饰。
2. 换成一个平实的陈述，理解效果会变差吗？如果不会，文学性没有降低认知门槛。
3. 这句话在后续章节中可以被回收吗？如果永远只用一次，它可能是孤立的修辞。

三个问题中有两个回答"否"，就应该删除或重写。

---

## 九、段落功能自检

写完一个段落后，快速判断它主要承担什么功能：

- **解释对象**：这段在帮助学生理解一个概念/方法/结构
- **呈现证据**：这段在展示数据、曲线、计算或仿真结果
- **建立判断**：这段在告诉学生"这意味着什么"
- **提醒误区**：这段在纠正常见的错误理解
- **推进叙事**：这段在连接前后内容，推动论证向前

如果一段文字**以上五种都不是**——它在解释课程编排、在声明教学边界、在预告后续内容、在重复已经说过的结论——就删掉或重写。

## 十、创作流程建议

### 10.1 先写骨架，再填血肉

1. 写一句话的中心结论（"本讲要让学生带走什么判断？"）
2. 写 3-5 个支撑这个结论的关键论证步骤
3. 给每个步骤分配一个锚点案例段落或数据证据
4. 检查步骤之间的因果连接是否成立
5. 最后才进入段落级 prose 写作

### 10.2 写完后的三遍阅读

**第一遍（结构阅读）**：只看标题和每段第一句。能否勾勒出完整的论证链？如果只看第一句就能跟着逻辑走，结构是好的。

**第二遍（声音阅读）**：找一个写得最别扭的段落，大声读出来。哪里卡住，哪里就是文风问题。

**第三遍（删除阅读）**：逐段问"删掉这段，学生理解会受损吗？"如果不会，删。
