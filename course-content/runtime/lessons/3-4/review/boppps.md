BOPPPS 课案 | 单元 3-4：根轨迹读图与对象化验证——把法则真正用到主图、参数窗口与工程后果上
课型：实践主线课 | 总学时：90分钟
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

B｜Bridge-in 场景导入（8min）
  形式：短视频导入 + 主图追问
  内容描述：先播放 `3-4-intro-video.mp4` 或展示封面漫画，追问“如果系统还稳定，是不是就可以直接说它是好方案？”随后投屏根轨迹主图，让学生直观看到 A、B、C 三个版本都还在稳定区内，但气质明显不同，把问题拉到“稳定之后如何继续判断”。
  教师操作：
  - 播放 `3-4-intro-video.mp4`，控制在 40-60 秒内；
  - 投屏 `3-4-root-locus-summary.png`；
  - 板书本节主问题：`关键节点 -> 参数窗口 -> 增益换算 -> 三域验证`
  - 明确边界：本节不重讲 `3-3` 的法则证明，不进入零点、PD 或模块4设计任务

O｜Objective 课堂目标（4min）
  呈现方式：板书 + 页面显示
  目标描述：
  - 学完本节，我能按固定顺序读取根轨迹主图中的关键节点，而不是凭感觉挑点。
  - 学完本节，我能区分“稳定窗口”和“可接受窗口”，并写出带证据的参数判断。
  - 学完本节，我能把根轨迹图上的增益 `k` 正确换算成实际控制器增益 `K`。
  - 学完本节，我能用时域与频域结果回查主图判断，形成对象化三域验证结论。
  与全局框架的连接：本节承接 `3-3` 的法则体系，把“为什么这样走”推进为“怎样按图做判断”；同时为 `3-5`“为什么只调增益很快不够”做铺垫。

P₁｜Pre-assessment 前测（6min）
  形式：举手投票 + 平台快答
  测试内容：
  - 如果一个参数版本还在稳定区内，你会不会直接把它判成“可用”？
  - 图上读到的增益，是否一定就是实际控制器增益？
  - 你更倾向于先看根轨迹、时域还是频域来判断版本差异？
  根据结果的教学调整策略：
  - 若多数学生把“稳定”直接等同于“可用”，则在 P₂ 第二段加重“窗口语言”训练。
  - 若多数学生混淆 `k` 与 `K`，则在 P₂ 第三段增加一次集体换算板书。
  - 若多数学生只盯时域图，则在 P₂ 第四段先用主图回收判断链，再放三域对照。

P₂｜Participatory Learning 主体教学（62min）

- 段 1（10min）：固定读图顺序
  - 教师讲授：用 `3-4-root-locus-summary.png` 说明为什么必须先看骨架、再找关键节点、最后再谈窗口和后果。
  - 组织形式：教师讲授 + 全班投票。
  - 学生典型反应：会想直接说“B 看起来最合适”，但说不出依据。
  - 教师处理：要求所有判断必须先回答“你是从哪一个关键节点开始读出来的？”

- 段 2（18min）：关键节点标注实践
  - 学生个体平台操作（12min）：
    - 在固定对象工作区中查看主图；
    - 用标注工具圈出分离点、虚轴交点、主导极点候选；
    - 填写 `关键节点读图记录`。
  - 快速汇总（6min）：
    - 教师端展示班级热力点位；
    - 对比“只找了一个点”和“形成完整读图链”的差别。
  - 组织形式：学生个体平台操作 + 教师巡回答疑。
  - 学生典型反应：会把“靠左”自动读成“更好”，会漏掉虚轴交点。
  - 教师处理：追问“你现在说的是骨架位置，还是已经说到窗口结论了？”

- 段 3（18min）：参数窗口判断与增益换算
  - 学生个体平台操作（10min）：
    - 根据主图和窗口卡片完成 `参数窗口判断表`；
    - 把图上的 `k` 换算为实际增益 `K`。
  - AI 对照验证（4min）：
    - 学生先独立完成换算；
    - 再打开 AI 对话，让 AI 只检查换算链是否完整；
    - 学生对照 AI 输出修正自己的表。
  - 教师纠偏（4min）：
    - 展示两份典型错误答案：`只写还稳定`、`把 k 直接当 K`。
  - 组织形式：学生个体平台操作 + AI 对照验证 + 教师板书归纳。
  - 学生典型反应：听懂窗口，但不会把窗口语言写成完整工程句子。
  - 教师处理：要求每组至少写出一句“它在稳定窗口中的位置 + 它在可接受窗口中的位置 + 代价”的完整表达。

- 段 4（16min）：对象化三域验证
  - 学生分组平台操作（10min）：
    - 查看 `3-4-step-compare.png` 与 `3-4-bode-compare.png`；
    - 在工作区中切换 A/B/C 三个版本，填写 `对象化验证记录`。
  - 教师对照点评（6min）：
    - 统一问三件事：哪一个域最早暴露 C 的风险？为什么 B 的主导极点近似可信？为什么 A 不能因为“更稳”就直接更优？
  - 组织形式：同伴讨论 + 学生个体平台操作 + 教师点评。
  - 学生典型反应：会只拿时域图支撑结论，忽略频域。
  - 教师处理：明确“本课的验证必须三域闭合，不允许只看一张图说结论”。

P₃｜Post-assessment 后测（6min）
  形式：平台即时题目 + 出口口头题
  测试内容：
  - 为什么“还稳定”不足以构成完整工程判断？
  - 若图上读得 `k=0.0104`，实际控制器增益 `K` 应是多少？
  - A/B/C 中谁更适合作为参考工作点？请说出至少两条证据。
  反馈方式：平台即时显示正确率；教师只对错得最多的题做追问，要求学生回答时必须说出“关键节点 / 窗口 / 换算 / 三域”中的至少两个关键词。

S｜Summary 总结（4min）
  方式：教师总结 + 知识地图回顾
  核心要点：
  - 3-4 的核心不是“继续讲法则”，而是把法则压成稳定读图动作；
  - 参数判断至少分两层：稳定窗口与可接受窗口；
  - 根轨迹图上的增益要先换算，才是工程控制器参数；
  - 三域验证不是重复展示，而是为主图判断补证据；
  - 下一课 `3-5` 将解释：为什么只调增益很快到边界，结构改变因此变得必要。

课前布置：复习 `3-3` 中“分离点、虚轴交点、主导分支”的意义，并准备一句“为什么知道轨迹怎样走还不够”的回答。
课后作业：以本课对象为例，分别完成 `关键节点读图记录`、`参数窗口判断表`、`对象化验证记录` 三张表；要求窗口判断中必须写出 `k -> K` 换算链。
