# 船舶航向控制对象 | Ship Heading Control Object

**一句话定义**：船舶航向控制对象把舵角、船体艏摇、航向角和罗经反馈放到同一条建模链中，用来说明真实工程对象怎样转化为可分析的控制对象。

**核心直觉**：船舶不是一个单独公式，而是一组环节和连接关系；只有先把对象写成传递函数和结构图，后续的时域、频域、根轨迹和设计判断才有共同对象。

**关键公式**：
$$
J\ddot{\theta}(t)+B\dot{\theta}(t)=Ku(t),\qquad
G_\theta(s)=\frac{K}{s(Js+B)}
$$

**关联**：前置 → 微分方程、拉氏变换工程动机 · 后续 → 零初值传递函数、典型环节对象库、结构图

## 详情

### 完整解释

`2-1` 第一次把船舶航向作为正式工程对象使用。它的价值不在于让学生提前学习船舶专业知识，而在于提供一个足够真实、又能被逐步简化的对象：舵机动作先改变船体偏航角速度，角速度再累积为航向角，罗经测量航向后回到比较点形成反馈。

从建模角度看，这个对象依次经过三次转写：

1. 物理方程写出舵角作用、阻尼和惯性之间的关系；
2. 拉氏变换把微分方程改写为代数形式；
3. 结构图把控制器、舵机、船体和测量反馈放入同一闭环。

这张卡片承担的是对象锚点作用。后续课程中，船舶航向还会出现在时域响应、频域指标、根轨迹、校正设计和高保真验证中；每次出现时，核心都不是“换了一个例子”，而是同一类对象在不同分析语言下被重新观察。

### 常见误区

1. **误区**：船舶航向只是一个情境包装。
   **纠正**：它提供了输入、输出、执行机构、对象和测量反馈的完整链条，是后续多域分析的共同对象。

2. **误区**：只要写出微分方程，就已经完成控制建模。
   **纠正**：微分方程说明物理来源，传递函数和结构图才让对象进入连接、比较和设计。
