## Context

经典四视图使用 `useMultiRepresentationLinkageModel` 持有对象极零点、增益、校正器、响应类型和分析范围；每次修改都会重新请求控制分析并驱动四类图表。工作台壳层仅持久化面板布局，尚无可恢复的设计状态或多方案分析结果。Arena 提交从当前实时控制器状态构建单一 artifact。

本变更仅覆盖经典四视图。黑箱辨识、复合控制和预测控制各自拥有不同的状态与提交模型，不在本次统一抽象。

## Goals / Non-Goals

**Goals:**

- 在当前浏览器会话中保存、管理并恢复经典四视图的完整设计快照。
- 使当前方案持续实时联动，而已保存快照的参数和分析结果不受后续编辑影响。
- 在时域、Bode、根轨迹与 Nyquist 图中同时比较当前方案和可见快照。
- 保持 Arena 提交的输入、评价和排行链路只使用当前编辑方案。

**Non-Goals:**

- 不跨浏览器会话、设备或账户持久化快照。
- 不为黑箱辨识、复合控制或预测控制预设增加快照。
- 不修改控制分析数值内核、Arena 评价器、数据库模型或提交 API。

## Decisions

### 会话级不可变快照

新增可 JSON 序列化的设计状态值对象，包含对象身份与可编辑模型、校正器、响应类型、时域与频域范围等会影响分析结果的字段。保存动作深拷贝该状态，并把快照列表写入与当前工作台上下文绑定的 `sessionStorage` 键。

`localStorage` 会在用户不再需要时保留试验数据，服务端持久化会引入账号数据和权限边界；两者均超出本次范围。只保存参数而在显示时重新使用当前模型会导致快照曲线漂移，因此快照必须保留独立状态和由该状态生成的分析结果。

### 当前方案与快照分离

模型 hook 保持一份可替换的当前设计状态，并提供“导出完整状态”和“恢复完整状态”的明确接口。快照列表、名称、颜色、可见性和时间由经典预设的快照管理层维护。恢复操作用快照完整替换当前设计状态，不修改快照记录；后续编辑只更新当前状态。

自由探索模式恢复不同对象时，通过工作台对象选择回调同步对象上下文，再恢复同一快照保存的设计状态。Arena 上下文中的对象固定，恢复不会改变任务对象。

### 四图以只读比较系列叠加

为每个可见快照独立生成控制分析请求并缓存其完成结果。当前方案仍是唯一可交互系列；快照系列不携带可拖拽根轨迹手柄，也不响应当前方案的参数编辑。

时域、Bode、根轨迹和 Nyquist 面板接收当前分析结果及命名的比较系列。快照在所有面板使用同一稳定颜色，图例或快照列表明确关联名称、颜色和可见性。保留每个面板已有的信号/来源选择：该选择控制当前方案的基础系列，快照使用其保存时的有效校正后分析结果。

### 提交边界不变

快照仅是客户端分析状态。Arena artifact 仍由当前 `correctionState` 构建，快照不会传入提交挂载、评价器或 API。用户必须先恢复目标快照或调出目标参数，才能将其作为当前方案提交。

## Risks / Trade-offs

- [多个快照会并行触发控制分析，增加浏览器计算负载] → 限制为会话内的经典四视图，按可见快照请求分析，并复用已完成的快照结果。
- [快照 JSON 损坏或版本不兼容] → 读取时验证结构并忽略无效记录，保留当前实时方案。
- [恢复对象可能与工作台上下文脱节] → 仅在自由探索中通过既有对象选择路径切换；Arena 任务对象不允许变更。
- [共享图表 API 扩展影响现有调用方] → 为比较系列提供可选输入，缺省时维持单方案渲染与现有测试行为。

## Migration Plan

该功能没有数据库或服务端迁移。部署后，旧会话不存在快照键时以空列表启动；删除会话存储键即可回退到单方案行为。

## Open Questions

无。快照范围、默认显示、恢复语义和预设范围已在 Issue #1013 的访谈中确定。
