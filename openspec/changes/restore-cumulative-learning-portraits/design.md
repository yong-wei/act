## Context

当前平台已经具备 portrait v2、学习事实、增量处理、画像回填、学生画像页面和教师学情页面。已归档的 `backfill-cumulative-learner-attainment` 与 `restore-teacher-cumulative-portraits` 建立了累计读取基础，但也保留了 `scope=recent`、30 天兼容画像和只能表达能力均值的 `class-competency.cumulative.v1`。Issue #989 锁定从当前分支继续收敛这些合同，不恢复任何 stash。

1. 学生端可以读取累计 portrait v2；
2. 教师 API/UI 仍提供近期范围，部分诊断、趋势和风险依赖 30 天窗口；
3. 班级页混用当前成员、旧累计能力物化和控制校正专项投影。

结果是同一学生在不同页面显示不同能力状态，已有累计数据仍会出现“无证据”“待生成”，趋势、风险、成长档案和班级对比也因日历窗口为空而消失。本变更复用现有 learner-state、增量 journal、portrait v2、回填脚本和权限边界，只建立新的累计物化版本，不建立第二套画像架构。

## Goals / Non-Goals

**Goals:**

- 让学生端、教师个体页、班级页和整体诊断读取同一学生级累计画像。
- 让画像、趋势和风险只由合格学习事实变化触发，不受日历时间窗口影响。
- 删除近期范围 API/UI 与 30 天画像、趋势、风险和诊断计算，并拒绝遗留 `scope=recent` 请求。
- 保持普通更新为单生增量处理，并使重试、分批和重建结果一致。
- 让班级只作为当前成员集合的聚合边界。
- 在个人和班级页面完整呈现已有画像、诊断、证据、趋势、风险、成长事件及明确的不可用原因。
- 通过真实生产数据副本演练后，以停服迁移完成旧结果切换。

**Non-Goals:**

- 不改变 LearningFact 的身份、来源、原知识修订或准入规则。
- 不创建班级所有的学习事实，也不按入班时间复制或截断学生历史。
- 不引入置信度时间衰减、在线双版本读取、全库日常重算或新画像模型。
- 不新增复杂的事实来源授权矩阵；沿用当前班级成员授权和现有角色级敏感字段脱敏。
- 不恢复 stash 或以 stash 内容作为实现输入。
- 不让 AI 生成新的诊断事实、风险判断或未注册资源建议。
- 不重做专项学习目标、控制校正报告或自适应路径。

## Decisions

### 1. 以学生级 portrait v2 作为唯一规范累计画像

所有有效历史学习事实归属于学生。学生端、教师个体页、班级聚合和整体诊断读取同一个最新 portrait v2；角色只改变证据明细和敏感字段的可见性，不产生不同口径的画像。

画像保留 `evidenceAsOf` 和证据年龄用于解释来源，但时间流逝不得改变分数、置信度、趋势、风险或可用性。近期画像 API/UI、30 天画像、趋势、风险与诊断计算全部删除；`scope=recent` 是不支持的输入并返回显式错误，不得被忽略或映射为累计口径。最新活动可以按发生时间倒序展示，但只是累计画像旁的活动记录，不形成独立画像或诊断口径。

### 2. 使用稳定的事实级折叠实现增量与重建一致

同一学生的画像计算使用一个确定性 reducer：

- 只接收通过治理校验且具有明确画像贡献的事实；
- 按事实发生时间排序，同一时间以稳定事实身份打破并列；
- 每条事实逐条折叠并按稳定身份去重；
- 每个事实变化先追加到 per-user sequence 的持久化转换 journal，操作仅为 `UPSERT`、`CORRECT` 或 `REVOKE`，转换记录 append-only 且引用原始 LearningFact；
- 新增且顺序位于水位线之后的事实执行增量更新；
- 撤销、更正、迟到事实或算法版本变化对该学生执行完整有界重建；
- 同一学生保持现有事务级串行保护，worker 批次只并行不同学生。

不采用批次级合并计算，因为批次大小和重试边界不应改变最终画像。更正和撤销通过 journal 表达，不更新或删除原始 LearningFact。

`StudentPortraitV2Snapshot` 继续作为不可变累计画像历史。新的 calculation version、state watermark、current pointer 与 `no-evidence-after-revocation` tombstone 只决定哪个状态可以作为当前结果；任何切换、重建或无证据结果都不得物理删除历史快照或 journal。

### 3. 将趋势、风险和成长事件建模为证据触发状态

个人总体趋势比较连续两次证据触发的累计总体分：变化大于 `+5` 为上升，小于 `-5` 为下降，其余为稳定；首次有效状态为尚无可比。没有新事实时保留最后趋势。

风险拆分为不可由人工处置改写的 evidence risk state，以及教师关注、干预、完成等人工 disposition。风险只由相关的新事实或事实撤销、更正改变；教师处置不得清除、覆盖或降级 evidence risk，只能与其并列展示。

累计迁移不得从活动量、缺勤或模型使用信号生成 `participation` 或 `ai_misuse` 风险；既有此类记录只保留审计，不能进入新的累计画像、诊断或班级风险分布。`constraint` 风险保持有效，直到其支持事实被治理更正或撤销；人工处置或后续无关事实不能解除。`stagnation` 与 `cross_domain` 只能由已注册的确定性事实条件和 portrait 状态重算，不能从日历时间、活动窗口或 AI 推断生成。

成长档案只记录有意义的状态变化和重要里程碑，不复制全部活动流水。成长事件以稳定派生身份幂等追加；当其支持事实被更正或撤销时，追加失效状态并停止对外展示该事件，但保留事件、失效原因和来源链用于审计。

### 4. 顶层诊断固定为七维整体诊断

个人总体分只平均具有有效证据的 portrait v2 维度，缺失维度单独报告且不计零分。整体诊断由七维累计画像、最后趋势、最后风险、成长事件和证据覆盖确定性生成，输出总体结论、优势、待提升点、限制和建议。

控制校正及其他目标诊断保留为下一级专项入口，不再作为个人或班级页面的默认顶层诊断。诊断建议只能引用已注册且当前角色可访问的资源。

### 5. 班级按当前成员等权聚合学生状态

班级总体分和每个维度分别对当前成员中具有相应有效画像的学生等权平均，并同时返回纳入人数、缺失人数和平均置信度。班级趋势和风险不计算“聚合值的趋势”，而是聚合成员最后一次个人趋势和风险状态。

学生加入、离开或转班时，只把其最新累计投影加入或移出班级聚合。事实来自哪个课程或班级不影响当前成员画像的聚合资格。

班级累计状态写入新的不可变 `class-competency.cumulative.v2`。每个物化记录绑定 generation、migration run、输入 digest、计算版本、成员集合、所引用个人画像版本、证据截至时间和生成身份，携带总体与逐维覆盖、成员最后趋势分布、证据支持的风险分布及七维整体诊断。发布在受保护事务中重验 generation、run 与 digest 后原子推进 current pointer；旧 generation、输入不完整或 digest 不一致的记录不得成为 current。`class-competency.cumulative.v1` 只包含前置变更的累计能力结果，不能原地扩展或继续作为新读取合同；停服迁移完成后，读路径只接受 v2，不提供 v1/v2 在线双读。

### 6. 统一返回数据和不可用原因

个人和班级 API 分别返回规范累计画像、整体诊断、最后趋势、最后风险、累计证据摘要、最新活动、成长事件及各自的证据截至时间。字段不可用时返回区分明确的原因，例如无合格事实、迁移中、处理失败、无匹配资源或角色不可见，不再用笼统的“暂无”“待生成”“无证据”覆盖已有数据。

教师查看当前班级成员时可以读取该学生完整历史事实的标准教师摘要和成长档案摘要；原始答案、私人 AI 对话、隐藏评测内容和高频轨迹仍按现有规则脱敏。学生离开班级后，教师访问立即失效。

### 7. 手动更新只执行幂等对账

学生和获授权教师的“更新画像”操作只查找尚未进入画像的新增、更正或撤销事实。单生对账是最小处理单元；班级操作为当前成员分别排队，报告处理中、完成数和失败数。没有待处理事实时不创建新快照，也不改变画像时间。

### 8. 通过同一停服迁移完成唯一累计版本切换

迁移复用现有回填和 worker 能力，并通过最小 Prisma migration 增加 journal、pointer/tombstone、成长事件失效、班级 publication generation 和 durable migration receipt 所需的持久化结构；这是累计切换必需的 schema/data migration，不建立新的在线画像架构：

1. 导出最新生产数据库并恢复到本地隔离环境；
2. 在本地执行与生产完全相同的 dry-run、数据/模式迁移、完整重建、v2 班级聚合更新及个人/班级页面抽样；
3. 本地演练通过后停止生产 app、worker 和 scheduler，确认不再产生写入；
4. 创建停服前数据库备份并验证可读取性、完整性和恢复步骤；
5. 部署与迁移合同匹配的版本，在生产执行同一迁移；迁移原子推进全局 cutover fence，并使 BullMQ 中所有旧版本 pending、retry、delayed 和 in-flight 队列任务失效，旧任务在受保护写入中重验 fence 后不得发布画像或班级物化；
6. 持久化 migration run、各阶段输入摘要、计数、pointer/publication、队列失效和验证回执；只有回执闭合且代表性页面只读新累计物化后才启动服务，失败则恢复备份数据库和旧 app/worker/scheduler 版本。

本地副本只用于演练，不覆盖生产数据库。切换是一次停服迁移，不是累计/近期或 v1/v2 双版本画像架构。

## Risks / Trade-offs

- [历史事实量导致单生重建较慢] → 普通路径保持增量，仅对受影响学生重建，并保持不同学生并行。
- [成员变化使缓存聚合短暂落后] → 成员变更直接按学生最新投影更新聚合，并提供幂等班级对账。
- [部分维度没有合格证据] → 排除缺失维度并明确报告覆盖，禁止以零分填补。
- [教师可见历史扩大数据暴露] → 访问仍以当前班级成员关系为边界，继续应用既有角色级脱敏。
- [迁移产生新旧混合结果] → 停服执行、使旧版本迁移队列失效并以完整核验作为启动条件，不提供部分结果上线。

## Migration Plan

1. 完成 reducer、读模型、对账任务和页面/API 改造，保持现有数据只读兼容。
2. 使用测试数据库验证增量、重试、迟到事实、撤销和完整重建的结果一致性。
3. 使用最新生产导出在本地完成同一 Prisma schema/data migration 的全量演练，记录学生、事实转换、画像 current/no-evidence 结果、成长事件失效、v2 班级 publication、旧 BullMQ 队列失效、失败和缺失计数及 durable receipts。
4. 浏览器验收学生画像、教师个体学情和班级整体学情，包括有数据、部分维度缺失和无合格事实三类样本。
5. 停止 app、worker 和 scheduler，创建并验证生产数据库备份，部署匹配版本并执行同一迁移；核验通过后恢复服务。
6. 若任一步失败，恢复停服前数据库备份和旧 app/worker/scheduler 版本，修正后重新从本地完整演练开始。
