## Context

当前平台已经具备 portrait v2、学习事实、增量处理、画像回填、学生画像页面和教师学情页面，但消费者仍存在三种相互冲突的口径：

1. 学生端可以读取累计 portrait v2；
2. 教师个体页和部分诊断仍依赖近 30 天或当前班级来源的事实；
3. 班级页混用当前成员、课程目标和控制校正专项投影。

结果是同一学生在不同页面显示不同能力状态，已有累计数据仍会出现“无证据”“待生成”，趋势、风险、成长档案和班级对比也因近期窗口为空而消失。本变更复用现有 learner-state、增量 journal、portrait v2、回填脚本和权限边界，不另建画像体系。

## Goals / Non-Goals

**Goals:**

- 让学生端、教师个体页、班级页和整体诊断读取同一学生级累计画像。
- 让画像、趋势和风险只由合格学习事实变化触发，不受日历时间窗口影响。
- 保持普通更新为单生增量处理，并使重试、分批和重建结果一致。
- 让班级只作为当前成员集合的聚合边界。
- 在个人和班级页面完整呈现已有画像、诊断、证据、趋势、风险、成长事件及明确的不可用原因。
- 通过真实生产数据副本演练后，以停服迁移完成旧结果切换。

**Non-Goals:**

- 不改变 LearningFact 的身份、来源、原知识修订或准入规则。
- 不创建班级所有的学习事实，也不按入班时间复制或截断学生历史。
- 不引入置信度时间衰减、在线双版本读取、全库日常重算或新画像模型。
- 不新增复杂的事实来源授权矩阵；沿用当前班级成员授权和现有角色级敏感字段脱敏。
- 不让 AI 生成新的诊断事实、风险判断或未注册资源建议。
- 不重做专项学习目标、控制校正报告或自适应路径。

## Decisions

### 1. 以学生级 portrait v2 作为唯一规范累计画像

所有有效历史学习事实归属于学生。学生端、教师个体页、班级聚合和整体诊断读取同一个最新 portrait v2；角色只改变证据明细和敏感字段的可见性，不产生不同口径的画像。

画像保留 `evidenceAsOf` 和证据年龄用于解释来源，但时间流逝不得改变分数、置信度、趋势、风险或可用性。仅为兼容近期页面继续构造投影会再次造成口径分叉，因此不保留累计/近期切换。

### 2. 使用稳定的事实级折叠实现增量与重建一致

同一学生的画像计算使用一个确定性 reducer：

- 只接收通过治理校验且具有明确画像贡献的事实；
- 按事实发生时间排序，同一时间以稳定事实身份打破并列；
- 每条事实逐条折叠并按稳定身份去重；
- 新增且顺序位于水位线之后的事实执行增量更新；
- 撤销、更正、迟到事实或算法版本变化对该学生执行完整有界重建；
- 同一学生保持现有事务级串行保护，worker 批次只并行不同学生。

不采用批次级合并计算，因为批次大小和重试边界不应改变最终画像。

### 3. 将趋势、风险和成长事件建模为证据触发状态

个人总体趋势比较连续两次证据触发的累计总体分：变化大于 `+5` 为上升，小于 `-5` 为下降，其余为稳定；首次有效状态为尚无可比。没有新事实时保留最后趋势。

风险只由相关的新事实或事实撤销、更正改变。教师的关注、干预、完成属于独立处置状态，不直接解除风险。成长档案只记录有意义的状态变化和重要里程碑，不复制全部活动流水。

### 4. 顶层诊断固定为七维整体诊断

个人总体分只平均具有有效证据的 portrait v2 维度，缺失维度单独报告且不计零分。整体诊断由七维累计画像、最后趋势、最后风险、成长事件和证据覆盖确定性生成，输出总体结论、优势、待提升点、限制和建议。

控制校正及其他目标诊断保留为下一级专项入口，不再作为个人或班级页面的默认顶层诊断。诊断建议只能引用已注册且当前角色可访问的资源。

### 5. 班级按当前成员等权聚合学生状态

班级总体分和每个维度分别对当前成员中具有相应有效画像的学生等权平均，并同时返回纳入人数、缺失人数和平均置信度。班级趋势和风险不计算“聚合值的趋势”，而是聚合成员最后一次个人趋势和风险状态。

学生加入、离开或转班时，只把其最新累计投影加入或移出班级聚合。事实来自哪个课程或班级不影响当前成员画像的聚合资格。

### 6. 统一返回数据和不可用原因

个人和班级 API 分别返回规范累计画像、整体诊断、最后趋势、最后风险、累计证据摘要、最新活动、成长事件及各自的证据截至时间。字段不可用时返回区分明确的原因，例如无合格事实、迁移中、处理失败、无匹配资源或角色不可见，不再用笼统的“暂无”“待生成”“无证据”覆盖已有数据。

教师查看当前班级成员时可以读取该学生完整历史事实的标准教师摘要和成长档案摘要；原始答案、私人 AI 对话、隐藏评测内容和高频轨迹仍按现有规则脱敏。学生离开班级后，教师访问立即失效。

### 7. 手动更新只执行幂等对账

学生和获授权教师的“更新画像”操作只查找尚未进入画像的新增、更正或撤销事实。单生对账是最小处理单元；班级操作为当前成员分别排队，报告处理中、完成数和失败数。没有待处理事实时不创建新快照，也不改变画像时间。

### 8. 通过停服迁移清除旧窗口结果

迁移复用现有回填和 worker 能力，新增确定性累计重建及核验，不建立新的在线切换框架：

1. 导出最新生产数据库并恢复到本地隔离环境；
2. 在本地执行 dry-run、完整重建、班级聚合更新及个人/班级页面抽样；
3. 本地演练通过后停止生产应用、worker 和 scheduler；
4. 创建停服前数据库备份，在生产执行同一迁移并核验相同计数和摘要；
5. 验收通过后启动新版本；失败则恢复数据库备份和旧版本。

本地副本只用于演练，不覆盖生产数据库。

## Risks / Trade-offs

- [历史事实量导致单生重建较慢] → 普通路径保持增量，仅对受影响学生重建，并保持不同学生并行。
- [成员变化使缓存聚合短暂落后] → 成员变更直接按学生最新投影更新聚合，并提供幂等班级对账。
- [部分维度没有合格证据] → 排除缺失维度并明确报告覆盖，禁止以零分填补。
- [教师可见历史扩大数据暴露] → 访问仍以当前班级成员关系为边界，继续应用既有角色级脱敏。
- [迁移产生新旧混合结果] → 停服执行并以完整核验作为启动条件，不提供部分结果上线。

## Migration Plan

1. 完成 reducer、读模型、对账任务和页面/API 改造，保持现有数据只读兼容。
2. 使用测试数据库验证增量、重试、迟到事实、撤销和完整重建的结果一致性。
3. 使用最新生产导出在本地完成全量演练，记录学生、事实、画像、班级聚合、失败和缺失计数。
4. 浏览器验收学生画像、教师个体学情和班级整体学情，包括有数据、部分维度缺失和无合格事实三类样本。
5. 停服、备份生产数据库、部署新版本并执行同一迁移；核验通过后恢复服务。
6. 若任一步失败，恢复停服前数据库备份和旧版本，修正后重新从本地完整演练开始。
