## Context

经典四视图页面已经维护当前方案分析状态、会话级方案快照，以及每个可见快照重新计算得到的 `ControlAnalysisResult`。这些结果已用于四类曲线叠加，但快照管理区域只展示名称和操作，没有统一的量化指标投影。

本变更受 `docs/grill/control-workbench-metric-comparison/CONTEXT.md` 约束：默认基线是第一个可见快照；基线失效后选择最早的剩余可见快照；没有快照时显示引导；自由探索不生成任务约束或方案优劣结论。

## Goals / Non-Goals

**Goals:**

- 复用当前方案与快照的既有分析结果，展示十项时域和频域指标。
- 以稳定的方案身份管理基线，并在快照生命周期变化时确定性修正基线。
- 对原值、差值、单位和不可用原因使用一致、可测试的格式化规则。
- 保持方案颜色和名称与快照及图表图例一致，并支持 320px 横向阅读。

**Non-Goals:**

- 不修改 Rust/WASM 数值算法或增加新的控制指标。
- 不计算综合评分、最佳方案或任务约束满足情况。
- 不修改快照持久化格式、Arena 评价、排行榜或正式提交输入。
- 不把指标对照推广到黑箱辨识、复合控制或预测控制预设。

## Decisions

### 从既有分析状态生成只读指标投影

新增特性内的指标定义和格式化层，把当前方案及可见快照转换为统一的只读列模型。数值只来自 `ControlAnalysisResult.metrics`，差值只执行同指标相减；不在前端推导新的控制学结论。该投影保留方案身份、名称、颜色、响应类型和分析状态，以便组件只负责渲染。

直接在页面 JSX 中逐项格式化会使单位、空值和差值规则难以单元测试；把分析结果持久化进快照又会扩大现有会话数据格式，因此均不采用。

### 使用显式分析状态阻止过期结果

快照分析回调从只传递结果扩展为传递 `loading`、`ready` 或 `error` 状态；当前方案使用模型已有的 `analysisState`。处于计算中或失败状态的方案列不读取此前结果。分析成功但单项指标为空时，依据响应类型和 `phaseCrossoverStatus` 显示不适用、数据不可用或“未在当前频率范围内观测到相位交叉”。

### 基线身份与可见方案集合协调

基线状态使用当前方案的保留身份或快照稳定 ID。首次出现可见快照时默认选择最早的可见快照；当前基线被隐藏或删除时选择最早的剩余可见快照，没有可见快照时回退当前方案。重命名不改变基线身份，恢复快照只更新当前方案分析，不改变快照基线。

### 表格保持量化中立

方案作为列，指标作为行；每个非基线数值附带相对基线差值。超调量差值使用“百分点”，其他指标沿用秒、度、分贝或弧度每秒。差值不使用表示好坏的红绿语义。没有可见快照时显示操作引导。窄屏保留表格最小列宽并横向滚动，不压缩指标和单位。

## Risks / Trade-offs

- [多个可见快照会使表格横向变宽] → 使用横向滚动和稳定最小列宽，不限制现有快照数量。
- [当前方案调参期间保留了旧分析结果] → 以显式 `isLoading` 状态优先显示计算中，不读取旧结果。
- [旧分析结果缺少 `phaseCrossoverStatus`] → 有有限交叉频率时按有限交叉展示；有频率响应数据但没有交叉频率时沿用既有图表语义展示“未在当前频率范围内观测到”，不推断无穷增益裕度；频率响应也不可用时保持数据不可用。
- [通用工作台没有权威任务阈值] → 本变更不显示满足/未满足，避免把自由探索误写成正式评测。
