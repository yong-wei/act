## Context

个人中心页面位于展示层，现有学习者状态服务是画像、证据、置信度和新鲜度的权威来源。路径规划已经支持学习目标、资源图、约束、候选解释和低置信度回退，但缺少稳定的规划输入快照与画像字段到路径决策的显式映射。

本变更涉及学习者状态读取、路径规划、路径轮次持久化和学生可见解释。已有路径必须保持可恢复，继续原路径不能因为画像更新而重新规划。

## Goals / Non-Goals

**Goals:**

- 让服务端路径规划直接消费现有权威学习者状态。
- 在规划开始时固定学习者状态快照，保证一次生成过程使用一致的画像版本和证据窗口。
- 用确定性规则把掌握度、薄弱点、资源偏好、能力表现、节奏和时间约束映射到路径决策。
- 保留证据来源、置信度、新鲜度和降级原因，并生成学生可理解的解释。
- 只对新建路径生效，不修改已保存路径或执行状态。

**Non-Goals:**

- 不新建个人画像模型或推荐引擎。
- 不从 `/profile` 页面抓取数据。
- 不引入强化学习、上下文 bandit 或不可解释的黑箱排序。
- 不改变候选路径比较、继续原路径和路径执行的既有交互契约。

## Decisions

### 1. 以学习者状态服务作为唯一规划输入来源

路径顾问在服务端调用现有学习者状态读取接口，按学习目标取得允许的状态切片。个人中心和路径生成可以展示或消费同一份状态，但路径服务不依赖页面渲染结果、浏览器状态或页面格式。

备选方案是从个人中心接口复制展示数据。该方案会把展示结构变成领域接口，容易产生过期数据、字段缺失和权限耦合，因此不采用。

### 2. 使用一次性规划快照，不复制画像

新路径生成开始时记录学习者状态引用、状态版本或计算时间、证据窗口、置信度和新鲜度。路径节点和解释引用该快照，后续画像更新不会重写已经生成的路径。

备选方案是每次渲染路径时重新读取画像。该方案会导致同一条路径在页面刷新后出现不同解释或不同节点，不采用。

### 3. 采用服务端确定性映射

服务端根据既有学习者状态和目标策略计算路径规划上下文：

- 薄弱知识点影响目标节点和顺序；
- 掌握度与练习表现影响难度、练习比例和检查点；
- 资源偏好影响视频、讲义、知识卡片、仿真等组合；
- 时间和节奏影响总时长与节点密度；
- 置信度、新鲜度和证据覆盖决定个性化强度。

前端只渲染服务端返回的决策和解释，不复制领域计算。

### 4. 低置信度时显式降级

当状态缺失、过期、部分可用或证据覆盖不足时，规划器返回通用 starter path 或部分个性化路径，并保留限制原因。不得用隐藏错误、伪造差异或默认高置信度文案替代缺失证据。

### 5. 解释文案与内部元数据分离

路径结果同时保留机器可审计的证据引用和学生可见的直接中文说明。学生文案不暴露内部字段名、服务名、批次 ID 或模型术语；教师/管理员诊断仍可在授权范围内查看更完整的证据元数据。

## Risks / Trade-offs

- [画像字段尚未覆盖所有规划维度] → 只对已有事实做映射；缺少事实时显示数据不足并走降级路径。
- [画像更新与路径生成并发] → 在生成入口固定快照，继续原路径始终读取持久化路径状态。
- [不同入口的状态切片不一致] → 使用统一学习目标切片和服务端读取函数，并增加输入快照一致性测试。
- [解释元数据增加响应体大小] → 只保存版本、证据引用、摘要和限制原因，不嵌入原始学习记录。

## Migration Plan

1. 先补充服务端规划上下文和映射测试，保持现有路径生成输出兼容。
2. 对新建路径写入规划快照和解释元数据；旧路径继续按已有持久化数据恢复。
3. 对低置信度和无画像用户启用明确的 starter/fallback 状态。
4. 完成浏览器验收后再启用学生可见解释；出现问题时可关闭个性化投影，回退到现有通用规划，不影响路径执行。
