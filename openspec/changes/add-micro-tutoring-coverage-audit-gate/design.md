## Context

微辅导的运行时编排已经对单次错误的归因、资源和验证题执行受治理选择，但没有批量审计层。现有目录有 576 道题，当前人工审核后有 54 道 `practice` 题满足常规练习条件；每题三项选择，形成 108 个错误选项审计行。题目级 `semanticRefs` 不能证明错误选项级归因，且既有运行时编排的资源与验证题校验不应被复制成一套可能漂移的规则。

本变更只建立审计事实与门禁，不填补后续 Issue 负责的选项归因、节点映射、资源和验证题数据。

## Goals / Non-Goals

**Goals:**

- 固定 54 道合格常规练习题的 ID 与内容哈希基线，并显式发现分母漂移。
- 将每个错误选项解析为可定位的链路记录，区分归因、资源、验证题及引用漂移等缺口。
- 以同一纯函数同时服务报告命令和自动化测试，保证确定性及严格模式的 fail-closed 行为。
- 复用既有微辅导编排的受治理资源和验证题资格规则，避免审计与学生端的判断出现分叉。

**Non-Goals:**

- 不向 54 道题补写选项归因、知识节点、资源或验证题。
- 不修改学生端微辅导的任务选择、持久化结果、学习路径或掌握度。
- 不将题干、选项文本或答案写入审计产物。

## Decisions

### 1. 分母以“审核阶段为 practice”而非所有允许练习的题目定义

目录中 135 道题具有路径资格并允许 `low-stakes-practice`，但只有审核阶段目的明确为 `practice` 的 54 道题是本 Epic 所称的合格常规练习题。审计将同时验证目录状态、人工审核、审核阶段和允许阶段，并与包含 ID+哈希的 54 项基线比较。v1 将 54 作为显式数量契约：目录和基线同时变为 55 项同样属于漂移，必须失败；未来扩大范围需要新基线版本和独立 OpenSpec 变更。

这种定义避免把 checkpoint、readiness 和 remediation 题误计为常规练习覆盖，也避免“目录允许练习”掩盖审核用途不同的事实。

### 2. 引入显式的选项级审计输入，不从题目级语义推断

新增受版本控制的选项归因审计源，键为 `catalogItemId` 与错误选项键。每行只允许声明一个学习目标、一个错因标签和一个规范节点，并携带来源版本或哈希。该源可在本变更落地时为空；空源应令当前 108 个错误选项以 `ATTRIBUTION_UNCERTAIN` 公开为缺口。

后续“选项级错因归因”Issue 负责填充该源。本变更的审计器只读取并验证其结构、唯一性和题目哈希绑定，不允许从 `semanticRefs` 或稳定裕度默认值补全。

### 3. 资源与验证题资格复用编排的纯校验边界

将 `remediation-orchestration` 中对资源和验证题的纯解析、可达性与独立性判断提取为可复用的只读资格模块。运行时编排和审计器共同调用该模块；数据库访问仍留在各自适配层。

审计器接收受限投影后的资源、知识节点和验证题候选。输出仅保留 IDs、版本、内容哈希、时长和动作地址；访问撤销与无合格资源或独立验证题分别记录 `ACCESS_REVOKED`、`RESOURCE_UNAVAILABLE` 与 `VALIDATION_QUESTION_UNAVAILABLE`。

### 4. 产物按可公开治理信息设计

机器产物使用稳定的 `errorOptionRef`（由题目 ID、内容哈希和选项键构造的不可逆哈希）来标识错误选项。内部计算使用目录中的正确性标记筛选错误选项，但 JSON/Markdown 报告不输出题干、选项键、选项文本、答案或正确性标记。

每行的状态为 `COMPLETE` 或 `GAP`，并含排序后的原因数组。汇总包含分母统计、完成率、原因计数及基线异常；严格模式在任一状态为 `GAP` 或基线异常时返回非零。

### 5. 命令总是先写报告，再返回严格模式状态

新增 `verify:micro-tutoring-coverage` 命令，支持 `--strict` 和显式输出目录。命令会加载当前目录、审核快照、选项归因源与数据库只读投影，写出 JSON 和 Markdown；只有报告完成后才依据严格结果设置退出码。

这样 CI 或维护者可在失败时直接获得可定位工件。命令不更新基线；基线更新必须经显式受审变更完成。

## Risks / Trade-offs

- 当前选项归因源为空，因此严格模式会立即失败。这是预期的 fail-closed 基线，后续 Issue 应逐步消除缺口；报告模式仍是可用治理工具。
- 数据库资源和验证题配置会影响实时结果。测试使用受限 fixture 投影覆盖资格规则，命令同时报告数据库读取失败为明确缺口，不将其视为“没有资源”。
- 将运行时校验提取为纯模块会触及既有编排代码；迁移必须保留当前单元测试和运行时行为。

## Migration Plan

1. 增加纯审计模型、54 项基线和空的选项归因源。
2. 提取资源/验证题资格的共享纯模块，保持运行时 API 与投影不变。
3. 实现报告命令、脚本测试和严格门禁入口。
4. 运行报告模式，提交生成的基线工件；严格模式预期在后续覆盖 Issue 完成前因真实缺口失败，测试仅验证其失败行为。
