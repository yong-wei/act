## Context

第一阶段已经把候选路径的聚合推荐依据持久化在 `pathOptions[].recommendationProvenance` 中，但学生确认候选路径后，活动路径的 `planNodes` 只保留通用 `reasonCodes`。随后确认纠偏时，服务端仅用权威前后节点序列更新 `mainPathNodeIds` 与 `planNodes`，没有留下节点相对上一版活动路径的调整结果。页面因此无法区分历史入选依据、最近一次已确认调整和当前锁定原因。

活动路径节点由 JSON payload 持久化，不需要 Prisma migration。纠偏确认已经在服务端写入围栏内计算权威前后序列，适合作为节点调整投影的唯一写入边界。readiness 则在路径读取和执行状态变化时刷新，是当前锁定原因的真值来源。

## Goals / Non-Goals

**Goals:**

- 在学生确认候选路径时，把该候选的生成时推荐依据投影到对应活动节点。
- 在学生确认纠偏时，以确认前的权威活动路径为基线，保存最近一次直接影响节点的调整解释。
- 在节点详情中分别呈现历史入选依据、最近调整和当前锁定依据。
- 保留完成或跳过节点已有的历史决策字段，并为缺少投影的旧路径明确说明限制。

**Non-Goals:**

- 不修改纠偏候选生成、评分、先修约束、WASM 或 Prisma 模型。
- 不接受客户端提交节点顺序或节点解释。
- 不在节点详情复制完整纠偏历史。
- 不提供证据事件类型、发生时间或事件级回跳；这些属于 #1186 第三阶段。

## Decisions

### 1. 历史解释随节点持久化，当前锁定解释动态读取

每个新采用的活动节点保存 `decisionExplanation.selectionBasis`；确认纠偏后，受影响节点保存或替换 `decisionExplanation.latestAdjustment`。这些字段记录当时已经成立的历史事实，不随当前画像重新计算。

锁定说明不写入历史投影。页面每次读取节点的受治理 `readiness`，仅在节点当前锁定时展示学生安全的原因与解锁动作。

备选方案是在页面读取时从当前画像和纠偏历史重建全部解释。该方案会把当前状态误当成历史依据，也使页面承担跨轮决策重放，因此不采用。

### 2. 候选采用是初始入选投影的写入边界

选择路径的服务端路由读取已持久化候选的 `recommendationProvenance`，按 `affectedNodeIds` 把相关条目的学生安全摘要映射到 `planNodes`。若某节点没有专属条目，则保留候选级摘要和限制说明，但不构造新的画像判断。

旧路径没有该字段时保持缺失。页面显示“该路径生成时尚未记录节点级入选依据”，而不是根据当前画像补写。

备选方案是在 planner 生成每个候选时同时改写共享 `mainPath`。多个候选可能包含不同节点或不同依据，共享节点会混淆尚未采用的候选，因此不采用。

### 3. 纠偏确认按相邻版本计算最近调整

`buildAdaptivePathCorrectionApplication()` 已经拥有确认前的权威 `nodeIds` 和确认后的 `nextNodeIds`。它按两条序列中的索引变化投影：

- 新索引小于旧索引：提前；
- 新索引大于旧索引：延后；
- proposal 明确替换：替换目标获得替换说明；
- proposal 明确移除且节点仍作为历史节点保留：记录移除说明；
- 索引未变但 proposal 明确影响：记录保留说明。

只覆盖本次直接影响节点的 `latestAdjustment`，未受影响节点保留原值。完整多轮记录仍由 append-only 纠偏决策历史承担。

调整文案只使用候选中已经持久化的学生安全标题、原因和 supporting facts，不暴露 node ID、reason code 或 fingerprint。

### 4. `mainPathNodeIds` 保持执行序列，`planNodes` 允许保留历史节点

`mainPathNodeIds` 继续表示纠偏后的可执行顺序。`planNodes` 更新可执行节点顺序时，保留已经完成或跳过的历史节点及其决策解释，使历史状态仍可在活动路径中查看；执行推进仍由 `mainPathNodeIds`、current node 和 execution metadata 决定。

不保留尚未执行且被纠偏移除的普通节点，以免把已退出路径的未来动作继续显示为可执行节点。

### 5. UI 使用独立标签，不复用通用“推荐理由”

节点详情新增“入选依据”“最近调整”“当前锁定原因”三个独立区域。通用 `reasonCodes` 仅作为旧路径的既有说明，不冒充可核验的生成时依据。非锁定节点不显示锁定区域；缺少历史投影时显示明确限制。

桌面和 320px 视口使用现有纵向详情布局，不增加固定宽度、横向表格或第二套时间线。

## Risks / Trade-offs

- [旧路径没有节点级入选投影] → 明确展示历史记录限制，不回填推断内容。
- [纠偏后历史节点与执行序列含义不同] → `mainPathNodeIds` 保持执行真值，`planNodes` 仅额外承载已完成或跳过节点的展示历史，并用测试覆盖推进不受影响。
- [替换或移除可能涉及不在新序列中的节点] → 只为仍需展示的历史节点保存说明；完整变更继续由纠偏决策历史核验。
- [文案意外泄露内部标识] → 投影函数只接受学生安全字段，UI 测试断言不出现内部 code、fingerprint 和 node ID。

## Migration Plan

该变更只扩展 JSON payload，部署不需要数据库迁移。新采用路径和新确认纠偏开始写入投影；旧记录保持可读并显示限制说明。回滚时旧代码会忽略新增 JSON 字段。
