## Context

教师编辑页需要在同一工作区处理作业信息、题目组织、内容、评分项和发布设置。业务合同由其他 changes 分别提供共享嵌入编辑器、评分结构、发布基线和统一作答 projection；本设计只负责把这些合同组织成清楚、中文化、可定位的页面，不重新定义它们。

## Goals / Non-Goals

**Goals:**

- 建立左侧题目大纲与主栏编辑的稳定信息架构。
- 用评分项手风琴控制长表单密度，并在折叠状态保留关键操作。
- 把发布设置放入主栏，提供摘要、自动展开和字段级错误定位。
- 持续显示保存状态，区分草稿保存问题与发布校验问题。
- 自动汇总作业总分，消除重复输入。
- 移除教师侧 active `TEXT`/`FILE` 分支，让题目编辑和预览只消费统一作答 projection。

**Non-Goals:**

- 不定义评分细则分档、精度或 AI 生成算法。
- 不定义发布幂等、保存基线服务端判定或学生响应模型。
- 不重写共享内容编辑器。

## Decisions

### 1. 左侧只承担题目组织，主栏承担内容与发布

左侧固定显示题库入口、新建入口和有序题目列表；选中题目的内容在主栏编辑。作业标题与说明位于题目区之前且只出现一次。发布设置作为主栏末端的默认折叠区，避免形成第三个业务面板。

### 2. 评分项使用受控手风琴

每个评分项折叠时显示名称、分值、上移、下移和删除；展开时显示评分标准与可选评分细则。展开状态使用稳定 criterion id 保存，排序后仍跟随完整记录。

### 3. 保存校验与发布校验分层

自动保存允许不完整草稿，字段问题留在原位置且不移动焦点。发布时运行完整发布条件，生成可点击的问题清单；选择问题后展开对应题目、评分项或发布设置，并把焦点移到字段。

### 4. 发布设置摘要由字段值派生

折叠摘要使用教师可读的班级名称、发布时间和截止时间。缺失或阻止发布时自动展开。内部枚举和标识统一通过集中映射显示中文标签。

### 5. 总分只从题目分值派生

页面不提供独立总分输入。每次题目分值改变后重新计算一位小数总分，并由 rubric change 的数值校验决定字段是否合法。

### 6. 响应能力只来自统一 projection

教师编辑与预览不再按 `TEXT`、`FILE` 或其他旧响应类型显示互斥控件。页面消费 `unify-assignment-response-contract` 提供的正文加附件能力、格式和额度摘要；旧字段只在历史审计投影中可见，不参与 active 表单或发布预览。

## Risks / Trade-offs

- [长作业仍产生大量滚动] → 左侧列表保持选中态，错误清单提供直接定位，手风琴降低默认展开量。
- [自动展开打断教师操作] → 只在显式发布校验或设置自身成为阻断项时自动展开。
- [中文标签遗漏新枚举] → 未映射值视为开发错误并在测试中失败，不向教师回退显示工程标识。
- [跨 change 状态接口未齐] → 页面适配层只消费声明的保存、评分和发布状态，不自行推断。

## Migration Plan

1. 建立布局和中文标签映射，保持现有字段读写。
2. 接入共享嵌入编辑器、统一作答 projection、评分项手风琴和派生总分，并移除教师侧 active 响应类型分支。
3. 接入保存状态、发布摘要与问题定位。
4. 以功能开关或路由级回退保留旧编辑页，完成浏览器验收后移除。
