## Context

`resolveLearningFactProfileWeight()` 在治理记录缺失或 `profileWeight` 缺失时返回 `1`。Portrait V2 与能力向量直接使用该值；推荐引擎、学生证据特征缓存和学习者状态服务还会读取原始学习事实作为活动、覆盖度和偏好输入。已有历史事实缺少统一治理声明，不能在没有来源级质量判定的情况下被自动升级。

## Goals / Non-Goals

**Goals:**

- 建立唯一的学习事实完整治理判定，并在画像、能力与个性化读取路径复用。
- 让新的未知事件物化为可审计的上下文事实，而不是无声明记录。
- 保持已审核文档评分和正式 Arena 证据的明确画像资格。

**Non-Goals:**

- 不修改 Prisma 模式，不回填历史记录，也不按来源猜测其质量。
- 不改变证据时间线、审计和运维读取原始事实的职责。
- 不新增推荐规则、能力维度或 AI 推荐能力。

## Decisions

### 完整治理是参与个性化的前提

完整治理至少包含有限的 `profileWeight`、布尔 `skipProfileContribution` 和非空策略原因。画像权重解析对不完整记录返回零；显式跳过也返回零。这样历史和未知来源会保留为上下文而不会形成能力信号。

替代方案是在缺失时使用低权重或来源白名单。前者仍会制造无依据的能力结论，后者把信任规则分散在消费者中，均被拒绝。

### 新写入明确记录治理结论

通用事件物化对未识别来源写入上下文事实策略。已审核文档评分与正式 Arena 写入同时写入完整的正向贡献声明；仿真和代理证据在没有独立画像资格规则时明确写为上下文事实。生产者不再依赖消费者的默认值。

### 个性化读取先排除未治理事实

推荐引擎、学生证据特征缓存和学习者状态服务在把学习事实用于活动、覆盖度、能力汇总或偏好推断前应用完整治理判定。显式的零权重上下文事实可以保留在已治理的活动与可解释性边界内，但不得产生能力贡献或高置信度能力结论。

替代方案是只修正 Portrait V2 与能力向量。该方案遗漏推荐的直接事实查询，会让未治理历史继续改变连续学习和证据覆盖判断，因而被拒绝。

## P1 整改：context-only 消费边界

共享的个性化资格谓词要求治理字段完整且解析后的画像权重为正值。各消费者不得用治理字段完整替代该资格判定。

context-only 事实不得进入推荐活动、最近活动、连续学习、证据覆盖、学习者状态的资源/媒体偏好，以及 feature cache 的事实、活动和时间窗口聚合。审计和时间线读取者仍可访问原始事实。

## Risks / Trade-offs

- [历史画像和推荐可能显示较少证据] → 这是质量边界收紧的预期结果；记录不删除，来源可在后续明确治理后重新参与。
- [新生产者忘记声明治理] → 失效封闭为零权重，并由针对物化和直接写入路径的测试防止回归。
- [原始事实读取仍存在] → 审计、调试、迁移和时间线读取保持原样；个性化路径必须使用共享判定。

## Migration Plan

部署后读取侧立即对历史未治理事实失效封闭。新事件写入带有上下文事实治理声明；无数据迁移。若需要回滚，可恢复旧解析规则，现有 JSON 字段保持兼容且不会丢失。
