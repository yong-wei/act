## Context

覆盖审计从 `course-content/runtime/resource-governance/` 的已提交输入捕获 54 道合格 practice 题及其选项级归因。当前错误归因在学习目标没有唯一 K/A/Q 节点时回退到 `PRIMARY_REMEDIATION_NODE_BY_LEARNING_GOAL`，该常量只有稳定裕度一项。资源和验证题选择则使用归因结果中的节点标识，因此映射缺口会在不同消费点以不同方式暴露。

本设计以 `proposal.md` 的范围和两份 delta spec 的行为契约为准。目录必须与 #1391 的覆盖基线和 #1392 的选项级归因使用同一知识节点标识，但不改变知识图谱权威切换或资源、验证题内容。

K/A/Q 图谱将 `kn:` 知识节点和 `cap:` 能力节点建模为不同域：能力节点可以关联多个知识节点，不能替代学习目标的唯一规范主知识节点。#1392 合入后的选项归因仍包含 `cap:` 和 `qual:` 值；本 change 在发布目录时同步修正该受治理工件及其生成器，使生成器直接读取显式目标目录，而不是在运行时把能力或质量节点转换成知识节点。

## Goals / Non-Goals

**Goals:**

- 建立一份可随 runtime 资源治理输入一同捕获的、版本化目标目录。
- 将目标解析集中到单一纯函数入口，并使错误归因和覆盖审计消费该入口。
- 在加载期和严格审计期发现映射、节点和版本冲突，保持 fail closed。

**Non-Goals:**

- 创建或迁移知识图谱节点、学习资源、验证题或错因标签。
- 为旧的历史答案回填或改写已持久化的错误归因快照。
- 用相似度、文本启发式或模型生成候选替代作者态目录决策。

## Decisions

### 冻结为知识域 `kn:` 主节点合同

微辅导目标目录和选项归因的 `knowledgeNodeId` 只接受处于 knowledge 域、启用且规范的 `kn:` 节点。`cap:` 标识表示能力目标，不是知识节点；即使其图谱关系指向一个或多个 `kn:` 节点，也不得作为目录主节点、别名、兼容回退或审计等价值。

#1392 已合入且其最终选项归因仍使用非知识域节点，因此 #1393 将生成器改为以本目录的显式决策写入唯一 `kn:` 主节点，并重新生成归因工件。审核快照中的 K/A/Q 候选集合继续保留原语义；它不再被误作主知识节点来源。消费端不提供 `cap:`/`qual:` 到 `kn:` 的兼容转换，旧工件或冲突值仍按无效输入处理。

### 目录是受治理的 runtime JSON 工件

在 `course-content/runtime/resource-governance/` 增加一个版本化目录工件，并将它加入覆盖审计的受提交输入捕获。每项包含规范学习目标、唯一且属于 knowledge 域的 `kn:` 主节点、显式别名、目录版本、来源引用、节点投影修订和启用状态。选择 JSON 而非在 TypeScript 中维护记录，是因为目录需要被审计命令、测试和运行时共同读取，并保留作者态来源和版本证据。

目录记录不直接复制题目或选项文本，只引用学习目标、节点和已存在的受治理标识，以维持当前审计的隐私边界。

目录级 `source` 固定引用当前选项归因工件版本；每条记录的 `sourceRefs` 同时引用固定 practice 基线版本和选项归因版本下的同一学习目标。加载器从已提交基线的目录项集合和选项归因中的目标绑定重新计算允许的来源引用，要求目录级来源版本、记录目标和两条记录级引用完全一致。任意路径字符串或仅非空的自由文本不构成来源证据。选项归因随后由覆盖审计继续与语义审核快照的 `reviewSourceHash` 交叉核验，由此形成“基线目录项 → 已审核选项归因 → 目标目录记录”的可验证证据链。

### 一个解析器产生结果或受控缺口

新增目标目录模块负责读取、结构校验、来源核验、去重和解析。规范目标标识优先；别名只有在目录显式声明且全局唯一时可解析。解析结果包含主节点、目录版本、记录级来源引用和解析方式。未知标识、重复规范目标、别名冲突、非 `kn:` 标识、缺失/停用节点、来源或版本不一致都返回稳定的失败码。

不复用现有 `graphNodeIds` 的“第一项”或集合交集作为映射替代方案：它们是题目语义候选，不是学习目标的受治理主节点，无法表达歧义或版本漂移。

### 消费端保留各自职责，但共享节点事实

错误归因以目录解析结果替换稳定裕度特例；当 K/A/Q 已提供唯一规范 `kn:` 节点时，仍须与目录解析结果一致，否则归因保持不确定。#1392 的 `cap:` 归因不会被接受为等价值，必须先在其上游工件中更正。覆盖审计接收目录输入并在资源/验证题查询之前对每条选项归因执行一致性检查。审计报告补充可定位的目标目录缺口类型，并使这些缺口在严格模式下失败。

资源与验证题选择继续只接收已验证的规范节点和错因标签，不承担目标别名解析或目录修复职责。

### 以覆盖基线作为完整性分母

生成目录时从 #1391 固定的 54 题基线及其审核快照提取学习目标集合，并与 #1392 的选项级归因逐项交叉核验。目录完整性以该集合为分母；重复项、遗漏项、停用项或节点不一致均阻断发布，而不是运行时临时补全。

## Risks / Trade-offs

- [#1392 合入后的选项级归因使用 `cap:`/`qual:` 节点] → 由本 change 的生成器从显式目录写入唯一 `kn:` 主节点并重生成工件；加载与审计继续拒绝任何非知识域或冲突值。
- [知识图谱投影更新可能使节点失效] → 在目录加载和覆盖审计中同时核验节点活动状态和声明的投影修订。
- [目录与 K/A/Q 已有节点信息不一致] → 不选择其中任一候选；输出冲突缺口并阻止错误归因和编排。
- [一次性配置 54 题相关目标容易漏项] → 使用覆盖基线派生的目标集合和全量单元测试，而非手工计数。

## Migration Plan

1. 从 #1391 基线和 #1392 已审核目标集合建立显式目录，并由生成器重生成只含受治理 `kn:` 主节点的最终选项归因；不对 `cap:` 值做运行时转换或兼容。
2. 在不启用新解析器前提交目录工件、加载校验和覆盖测试，确保覆盖基线中的全部学习目标均有有效记录。
3. 将错误归因和覆盖审计切换至新解析器，并移除稳定裕度专用常量；在同一变更中扩展审计输入捕获和严格失败原因。
4. 对 #1392 合入后的选项级归因运行离线覆盖审计与严格模式，确认目录冲突为零后再允许编排消费结果。
5. 若目录或投影出现问题，保留历史持久化快照不变，并使新编排返回受控不可用状态；通过修正并版本化目录工件恢复，而不回退到启发式映射。
