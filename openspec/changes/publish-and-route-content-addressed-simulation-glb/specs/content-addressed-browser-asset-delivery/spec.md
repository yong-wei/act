## ADDED Requirements

### Requirement: Browser Delivery manifest closes the asset cohort
The system SHALL create a versioned canonical manifest for one public browser
asset cohort. It SHALL bind captured Git commit/tree, cohort identity, complete
included/excluded denominator, logical asset ID, Git source blob identity and
SHA-256, generated-output provenance, final SHA-256 and size, media type,
public-eligibility decision, immutable Delivery key, Range/cache class,
same-origin fallback URLs, manifest digest, and builder version.

#### Scenario: Seven simulation models form the first cohort
- **WHEN** the first GLB manifest is built from the captured repository and declared generated outputs
- **THEN** every original simulation model SHALL appear exactly once as included or excluded and all totals and hashes SHALL balance

#### Scenario: Working-tree output has no governed provenance
- **WHEN** an ignored optimized file is known only by filename or local path
- **THEN** it SHALL be excluded or rejected and SHALL NOT enter the manifest or Delivery Bucket

### Requirement: Generated GLBs bind captured source and optimizer identity
An optimized GLB SHALL be eligible only when its Git-managed source identity,
optimizer name/version/configuration digest, output digest, size, and validator
result match the manifest. Regeneration that changes bytes SHALL create a new
output identity and Delivery key rather than update an existing key.

#### Scenario: Optimized output validates
- **WHEN** source Git blob, optimizer evidence, output hash, size and GLB validator all match
- **THEN** the output MAY be included under its exact generated identity

#### Scenario: Optimizer or output drifts
- **WHEN** tool/configuration identity or generated bytes differ from the sealed manifest
- **THEN** publication and production routing SHALL fail until a new manifest revision is qualified

### Requirement: Delivery publication is append-only and allowlisted
The publisher SHALL accept only included public `.glb` entries, target only the
private `act-course-delivery` Bucket, derive
`assets/<sha256>/<safe-basename>.glb`, and use conditional no-overwrite writes.
A pre-existing object SHALL be reused only after exact key, size, digest
metadata, media type, and immutable cache metadata match. A terminal publication
receipt SHALL be written only after the complete included set verifies.

#### Scenario: New cohort object is published
- **WHEN** its manifest entry and local bytes validate
- **THEN** the publisher SHALL write the immutable object once and record its verified identity

#### Scenario: Caller supplies an arbitrary path or Authority Bucket
- **WHEN** target Bucket, key, extension, public eligibility or manifest membership is invalid
- **THEN** the publisher SHALL reject before any object mutation or terminal receipt

### Requirement: Production resolution requires qualified evidence
The simulation asset resolver SHALL use a Delivery URL only when a qualified
static ESA PoC receipt, compatible traffic baseline receipt, exact Delivery
manifest, and complete publication receipt all match. Local development SHALL
remain same-origin by default. Missing, incomplete, drifted, or mixed-revision
evidence SHALL keep the asset on its same-origin candidates.

#### Scenario: All Delivery evidence matches
- **WHEN** the production build consumes matching qualified receipts and manifest identity
- **THEN** the resolver SHALL place the immutable ESA URL first for each included model

#### Scenario: ESA or publication qualification is absent
- **WHEN** any required receipt is missing, blocked or mismatched
- **THEN** the resolver SHALL not emit a production Delivery URL for the affected model

### Requirement: Model resolution preserves ordered local fallback
Each logical simulation model SHALL resolve through one shared registry to an
ordered set consisting of qualified ESA output, existing same-origin optimized
output, and Git-managed original output as applicable. A loader SHALL advance
only after a load or integrity failure and SHALL preserve progress, error, and
scene behavior. Scattered production GLB path constants SHALL not remain as
independent authority.

#### Scenario: ESA model loads successfully
- **WHEN** the first qualified candidate returns valid expected GLB bytes
- **THEN** the scene SHALL use it without requesting a same-origin fallback

#### Scenario: ESA model fails
- **WHEN** the Delivery request, CORS, integrity or GLB parse check fails
- **THEN** the loader SHALL try the declared same-origin candidates and keep the simulation usable

### Requirement: First production cohort is limited to simulation GLBs
The first routed cohort SHALL contain only the seven declared simulation model
sources and their qualified optimized GLBs. Runtime blobs, manifests, receipts,
knowledge resources, cards, textbooks, private media, video, audio, PDF, images
outside the cohort, WASM, and assessment data MUST NOT be projected or served by
this publisher.

#### Scenario: Non-GLB resource is presented
- **WHEN** a caller proposes video, audio, PDF, WASM, Runtime or governance content
- **THEN** the manifest builder and publisher SHALL reject it without reducing the declared GLB denominator

#### Scenario: One GLB remains unresolved
- **WHEN** a model lacks qualified generated output or delivery evidence
- **THEN** it SHALL remain explicitly excluded and use its same-origin original without being silently omitted

### Requirement: Activation and rollback are browser- and traffic-verified
Production routing SHALL not be accepted until all included scene routes prove
full-object digest, media type, CORS, `206` and correct `Content-Range`, cache
MISS-to-HIT, model progress, visual equivalence, fallback, and unchanged
simulation drive-chain behavior. A before/after traffic observation SHALL report
ECS, OSS and ESA class changes. Rollback SHALL restore local-first resolution
without deleting image-local or immutable Delivery objects during retention.

#### Scenario: Routed cohort passes acceptance
- **WHEN** every included model and simulation scene passes asset, browser, fallback and traffic checks
- **THEN** the publication/routing receipt SHALL qualify the exact manifest and application revision

#### Scenario: One scene or delivery check fails
- **WHEN** any included model fails loading, integrity, Range, cache, CORS, visual, fallback or drive-chain verification
- **THEN** routing SHALL remain blocked or roll back to local-first resolution while immutable evidence is retained
