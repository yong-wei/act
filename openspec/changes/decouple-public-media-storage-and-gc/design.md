## Context

见proposal。现有Python发布器以工作树文件元数据和SQLite判断增量，条件PUT并最后写入v2清单；未改文件不做OSS HEAD/GET。ESA的v1索引记录7250个逻辑路径、7247个正文对象，并把路径分发绑定到整个Runtime身份。物化视图把全部文件链接到原桶的`.act-runtime-blobs`；私有签名、课堂正文读取、doctor和开发者网关也默认原桶。GC只删除未引用视图与清单，不删除正文。

生产基线为v0.7.34，当前Runtime为`runtime-b24b84a4ddea4d450ce813a87757298855c5476f26e9e79a782c752`，回退为`runtime-32868ff565c7968eefbf478dcfc7c01312a9102ef61d3a944032a45`。本轮只读查询未发现CourseBundleRevision记录；实现仍必须发现并保护未来课堂引用。主规范中的旧Git-tree、兼容性收据和多状态lifecycle已被已实现的`simplify-runtime-cas-publish-activate`及`simplify-runtime-app-compatibility-validation`修订；本变更沿用真实工作树发布和两指针，不恢复旧协议。

## Goals / Non-Goals

**Goals:** 规范正文只存一份；未改媒体跨Runtime复用；新公开媒体直接进入当前分发桶；发布与回收并发时不产生缺失引用；既有正文读取、课堂版本及恢复路径保持可用。

**Non-Goals:** 不设计v3 Runtime清单，不重写内容治理或生成器，不改模型发布目录、用户与学习数据、图谱选择器或课堂模型，不进行新的Runtime激活，不由publish或deploy隐式调用GC/doctor。

## Decisions

1. **清单保持内容身份，存储位置由独立摘要目录决定。** 清单仍使用现有v2路径/SHA/size和逻辑blob键。将现有公开索引升级为摘要目录，支持读入历史v1；目录仅允许批准的媒体类型和固定`act-course-models/teaching-media/sha256/<sha>/asset.<ext>`。目录不是新Runtime选择器，也不决定课程是否发布。备选是在清单增加位置字段；否决，因为迁移会改变历史清单身份。
2. **先证明版本，再解析位置。** 路径入口从选中且校验通过的物化清单取精确摘要；课堂入口继续使用固定清单。正文摘要、大小和类型命中目录才可使用ESA；无关Runtime修订不再关闭分发。停用ESA只停止公开重定向，不删除规范正文目录；内部读取和短时OSS签名仍可使用同一对象。
3. **新增独立只读媒体helper。** 在每个受保护视图保留原私有Blob helper，增加`.act-runtime-public-media`绑定到媒体桶的SHA前缀。物化器、正文校验、doctor和开发者网关按同一摘要目录定位；应用仍只bind现有Runtime视图。helper不成为可浏览的公共路径。备选合并两个FUSE文件系统；否决，现有双helper足以提供同一逻辑视图。
4. **增量发布同时记录放置位置。** 复用现有公开路径与信息图资格校验，先验证用于资格判断的元数据与本次清单一致。合格媒体条件PUT到分发桶，内部文件条件PUT到原桶；成功后再提交目录、收据及终止清单。SQLite记录已放置摘要/位置；未变化发布不读正文或远端对象，不因来源Git变化重新上传媒体。初次迁移导入已验证目录，避免再次复制6GB正文。
5. **发布与回收共用既有宿主选择锁。** OSS发布通过有界SSH控制程序持有该锁，进行中及成功未激活发布保留摘要清单与有限期限租约；发布失败不切Runtime。缓存基线已不受保护时拒绝直接复用，并要求显式bootstrap恢复，避免GC后由旧缓存生成缺失正文的清单。离线夹具使用同一文件锁，不新增云写身份或远端源码构建。
6. **显式正文GC与默认行为分开。** `runtime:gc --reclaim-blobs`才计划正文回收，默认dry-run；执行必须重新发现current、previous、CourseBundleRevision、人工pin、有效开发者租约及发布/签名保留租约，并严格验证其清单。选择、发布和删除在同一锁内完成；任一引用、清单、租约或凭据资格不可判定时不删除。删除只限两个正文前缀，保留模型、内部治理元数据、历史Release证据及范围外对象。
7. **本次等字节副本退役是独立迁移。** 先核验目标对象、更新受保护视图的媒体叶并验证真实消费，生成绑定清单与目标摘要的迁移回执；随后原桶精确副本才可退役。保存从规范正文恢复原键的计划。删除后应用部署须拒绝不支持媒体位置目录的旧镜像，除非先恢复副本；不把回退旧镜像当作自动数据恢复。
8. **课堂引用写入与正文删除也须互斥。** 宿主锁不能覆盖应用内的数据库事务。正文执行阶段在发现课堂引用前取得独占PostgreSQL advisory锁；新Runtime课堂版本持久化先尝试同键事务共享锁，并在锁内核验捕获的清单仍为活动版本。已有revision继续复用，DB原生教案与未发布工作树不视为OSS引用。无班级课堂同样使用现有Prisma事务。回收期间新Runtime课堂立即返回明确的可重试冲突，避免等待整批删除；不新增表、API或课堂身份格式。

## Risks / Trade-offs

- [仍有消费者固定读取原桶] → 审计文件、Blob、签名、信息图、doctor和开发者网关；用删除原副本后的真实读取回归证明。
- [发布与GC竞争或旧缓存复用] → 同一宿主锁、进行中清单、有限保留和已退休缓存拒绝；不逐对象增加远程预检。
- [目录损坏或资格过宽] → 固定桶/前缀/类型、SHA/size校验、受控原子更新；拒绝无资格对象和错误正文映射。
- [已签发URL尚未到期] → outgoing previous增加不短于最大签名期的保留租约，重复保留只能延长；时间倒退失败关闭。
- [权限不足] → 先只读核验实际身份，回收不用ESA读取身份或ECS只读身份写入；权限变更按实际需要单独处理。

## Migration Plan

先实现并验证目录、增量发布、双helper、读取消费和正文GC；用离线完整生命周期与模拟OSS证明增量、并发、失败和恢复。保存本轮代码验证与可执行迁移/删除计划。生产按已授权操作边界先部署支持目录的应用及只读挂载，再迁移所有受保护媒体叶、验证目标正文与入口，最后执行精确副本退役。Runtime、图谱及数据库选择保持不变。

恢复分两级：ESA不可用时回到规范对象的内部读取；需要旧应用时先按迁移回执恢复原桶副本，再允许旧镜像部署。新发布的媒体日常使用直接写入；发布、激活和显式GC保持可分别审计。
