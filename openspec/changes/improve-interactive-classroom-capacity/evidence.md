# 200 人互动课堂容量验证

## 测试口径

同一份生产构建在本机隔离环境分别运行原有双轮询和新版同步。两组分别创建独立的 200 人课堂，使用同一课次、相同的进场和互动动作、PostgreSQL 10 连接池与独立 Redis 数据库。200 个独立学生会话同时发起六位码查询、请求正式学生页、读取个人状态；压测端最多复用 96 条 HTTP 长连接。持续互动包含两次教师切步及发布、个人状态写入、20 名学生重新进入与个人状态核对。末尾 200 人集中交卷，并重复提交其中 10 人的同一答卷。

签名会话由测试夹具生成。该口径覆盖学生页面和鉴权后的业务接口。统一登录、学生设备性能、教室无线网络、生产反向代理及 ESA/OSS 均需按各自环境验证。传输数据为已压缩 HTTP 响应正文，不含协议开销和课程静态资源。

## 新版 10 分钟持续测试

第二次启动从扫码到全员就绪耗时 26.90 秒。200 人持续互动 600 秒，课堂业务发送 29,057 个请求，收到 30.78 MB 响应正文，约 0.41 Mbps 的平均应用响应吞吐。该数字不含首屏、脚本和媒体。全程收到 758 次预期等待和 1 次预期跨班拒绝，其余请求均返回 HTTP 200。两次教师发布分别在 5.60 秒、5.77 秒内到达全员。20 名模拟重连学生恢复了本人状态。200 份首次交卷全部成功且唯一，重复请求未增添答卷。该轮交卷 P95 为 1.08 秒。

## 浏览器和回归验证

Chrome 首次进入及刷新均读到了本人课堂状态。等待提示通过注入一次 HTTP 202 验证，真实分批放行由 200 人 HTTP 压测验证。全新浏览器的源站脚本传输量约 2.02 MB，采用浏览器 Resource Timing 的 `transferSize`。项目已有按构建版本向静态域名分发脚本的能力，冷缓存下的生产命中率和教室出口带宽需要单独测量。

课堂应用、作答证据、入口重试、同步通道、学生页面与状态鉴权共 6 个测试文件、51 条通过。生产构建、Web 和 Worker 类型检查、修改文件 ESLint、OpenSpec 严格校验通过。

## 瓶颈

- 稳态的可削减开销来自重复的个人查询和共享状态查询。新版请求下降约 41%，响应字节下降约 60%，PostgreSQL 提交事务速率下降约 53%。应用进程稳态 CPU 没有下降。
- 入场队列削平状态初始化高峰，但学生页面在排队前已生成。200 份完整首屏 HTML 合计约 9.06 MB，占入场响应约 93%。HTML P95 约 4.07 s。首屏阶段仍短时占用约两个核心，队列对全段平均负载的改善大于对首屏峰值的改善。真实教室的网络表现需要另行测量。
- 同一课堂的正式作答与结束课堂共用数据库事务锁。集中交卷时原模式最多同时采到 9 个等待该锁的连接，新版最多 7 个。两组都成功落库，仍需保留交卷与闭课的先后语义。增加数据库连接不会消除同一课堂的串行阶段。
- 在早期不限制为 96 条复用连接的本机试验，集中建立连接时曾出现 HTTP 响应之前的 TCP 重置。后续一次 96 连接的长测启动中，首屏有一个请求收到 HTTP 200 响应头后，15 秒仍未读完响应正文，试验在入场阶段停止。该现象与初始扫码的传输重置分别记录，真实课堂断连需由生产端反向代理和教室网络进一步定位。

本机测试入口为 `.tmp/run-interactive-classroom-capacity.py`，配套 HTTP 与浏览器驱动是 `.tmp/interactive-classroom-capacity.mts`。设置 `INTERACTIVE_MEASURE_DOCUMENT=1` 时每名学生读取正式页面。运行参数依次为模式、应用端口和持续互动秒数。采样与计数脚本为 `.tmp/summarize-interactive-classroom.py`。

本机原始结果保留在 `.logs/interactive-classroom-{baseline,optimized,sustained}.json`，请求和采样流水分别为同名前缀的 `.jsonl` 和 `-host.jsonl`。

## 入场前置的本机复测

沿用 200 名独立学生、同一课次、96 条复用连接和 100 秒互动。在第一轮优化中，200 次首屏请求返回完整课堂 HTML。新版同一批请求中 188 次先返回等候页，12 次直接进入。整批首响应正文由 9.06 MB 降至 2.53 MB，扫码到首文档的 P95 由 5.26 秒降至 2.90 秒。最后一人就绪由 27.91 秒降至 26.12 秒。新版测试中两次教师发布均到达 200 人，200 份首次交卷成功且写入唯一序号。

后续加载完整课堂的内容仍然发生。HTTP 负载驱动以普通 HTML 请求模拟放行后的导航，真实浏览器通过页面刷新请求下载后续内容。Chrome 在本机独立 Redis 暂时不可用时实际显示候场页，Redis 恢复后进入课堂，并在整页刷新后恢复本人状态。新增回归验证共 9 个文件、63 条通过。

## 阿里云第一轮上线

应用版本 0.7.66 在阿里云应用和 worker 上生效。新镜像的 669 个程序资源在应用切换前已装载到版本化媒体路径，使用摘要核对抽查的 JS、CSS 和字体，并确认 ESA 命中。Chrome 首次进入和刷新抽样中，应用域名的程序资源跳转由 118 次变为 0 次，浏览器继续从 ESA 成功读取 118 次资源。浏览器实际先显示候场页，再进入课堂和恢复本人状态。

部署选用每秒 2 人放行。10 人与 25 人测试分别全员进入、跟随两次教师发布和交卷，最后一人分别耗时 47.34 秒和 167.05 秒。25 人测试的 33 次放行后整页请求中，10 次在驱动的 25 秒期限内未完成，后续重试成功。旧版阶梯探测的 1、2、3、4 份并发完整页面各组最大响应时长分别为 6.52、7.92、12.90、17.34 秒。

10 人新版本的入场阶段，应用容器平均占用 1.11 核，数据库和 Redis 容器分别约占 0.02 核和 0.01 核。进入 60 秒互动阶段后，应用平均占用降至 0.09 核。源码显示同一课堂每份完整页面都会读取课程版本和构建同一课程图谱。200 人试跑在进场阶段出现多次 25 秒超时，未进入持续互动验收，202 个测试账号已清理。追加同课堂并发读取合并，保留独立权限。核验通过的绑定内容最多复用 5 秒，再到期核对；其他状态不在完成后复用。

### 200 人公网课堂验收

在阿里云现有 2 vCPU 主机上，从应用公网入口同时发起 200 个独立已登录学生请求，压测端最多复用 48 条 HTTPS 连接。198 人先收到候场页，扫码到首文档 P95 为 17.76 秒，末位在 258.00 秒就绪。200 份首文档共 1.69 MB。入场期间共 4,652 次预期等候回执，另有 1 次预期跨班拒绝，驱动记录的其余请求均为 HTTP 200。完整课堂加载继续经过应用授权和课程版本核验。

全员就绪后持续互动 300 秒，共 14,385 次课堂请求和 17.00 MB 应用响应正文，平均约 0.45 Mbps。两次教师发布分别在 6.00 秒、6.19 秒内到达全员，20 名模拟重连学生恢复本人状态。200 份首次集中交卷全部返回成功并落库，序号唯一，重复提交未增加答卷。包含幂等校验的交卷请求 P95 为 10.11 秒。202 个测试账号和关联的课堂测试记录已清理。

入场与持续互动阶段，整台主机平均 CPU 分别为 72.8% 和 73.7%，P95 分别为 97.5% 和 98.0%。新版在该口径下达到一个 200 人课堂。仍可观察到入场排队、应用 CPU 高峰和集中交卷排队。课堂业务响应量排除了公共静态文件、媒体、协议开销及校园 Wi-Fi，未包含统一登录的集中负载。另用 Chrome 独立核验真实页面的候场、放行、刷新及 ESA 资源。

可复核结果在 `.logs/interactive-classroom-v0767-sustained-200.json`、同名前缀的请求与主机流水、`.logs/v0767-live-components.json` 和 `.logs/v0767-static-esa-before.json`。
