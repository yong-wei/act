## Decisions

入场许可绑定学生账号和课堂。正式互动学生页在加载课程版本和组件前请求许可，二维码与直达链接使用同一逻辑。服务端保留课堂和班级校验，按课堂分批发放短期许可。已入场学生的写入和教师操作继续使用原接口。排队状态和许可存放在 Redis。等待中的浏览器继续查询时保持队位，已获得的许可可在 45 分钟内复用。短暂网络错误自动重试。排队时只返回轻量页面，客户端查询只读的入场状态。放行后刷新同一路由并挂载完整课堂。发布开关为 `INTERACTIVE_CLASSROOM_CAPACITY=1`，默认每课堂每秒最多初始化 12 人，可用 `INTERACTIVE_CLASSROOM_ADMISSION_BATCH` 调节。

合并课堂进度与可供学生读取的教师状态。共享读取使用短时缓存和同进程请求合并。本人状态仍使用授权后的原接口，进入时先恢复本人状态，持续低频对账，作答走独立持久化路径。教师状态更新后清除缓存。持续同步、备用读取和排队回执使用分散的等待时间。

用本机隔离 PostgreSQL、Redis 和 HTTP 应用，复用同一课程与等量独立账号，对照原模式和新版。记录进入时长、传输及请求量、师生同步延迟、积压清空、返回状态、写入一致性和重连。应用阶段与真实浏览器媒体加载的证据分别记录。

现有静态资源路径继续按构建修订版本区分。发布时先从新镜像备齐该版本公开资源并核验 ESA，然后应用页面直接引用静态域名。课堂身份、作答、当前状态和含权限的课程数据继续由应用授权返回。

同一课堂已授权的并发入场共享一次正在执行的内容版本读取和课程图谱构造。已核验的绑定结果最多复用 5 秒，过期后读取课程版本和知识选择记录。旧版未绑定课堂和版本偏移只合并正在执行的读取。个人状态和路由参数仍单独取得。

## 主机负荷与候场轮询

Linux 互动课堂和已启用自适应放行的实验空间读取同一主机 CPU 采样。存在容器 CPU 配额时，同时检查配额使用率，取限制更紧的一侧。采样达到 90% 时停止发放新许可，达到 80% 时提前减速，低于 70% 且连续有余量时逐步增加放行。采样缺失或过期时等候。已获得的许可、续租和已在处理的正式核验保留原语义。

每个课堂继续使用 Redis 维护队位与放行窗口。队首较快查询，后排以更长且分散的间隔查询。互动课堂在 Linux 的容量功能开启时默认使用自适应模式，可设 `INTERACTIVE_CLASSROOM_ADAPTIVE_ADMISSION=0` 作固定速率对照。90% 是新放行反馈阈值。已经运行的任务和其他服务仍可造成短时峰值。

## 集中交卷

同一应用进程内，同课堂的正式交卷和闭课申请按进入持久化命令的先后排队，等到可执行才申请数据库连接。其他课堂独立处理。保留同一 PostgreSQL 会话事务锁，作为多进程与滚动发布期间的最终顺序保障。

接受提交时，用一条有课堂状态条件的更新语句分配下一个序号，继续在同一事务写入源互动日志和正式答卷。重复请求返回原回执，错误回滚后释放应用队列。闭课固定同一顺序水位，后续交卷保留为复盘证据。

## 教师状态推送与首次加载

学生端先完成现有课堂进度读取和入场，再连接应答流。每个应用进程共享一条 Redis 订阅连接，同一课堂共享一份状态读取与序列化结果。教师前进、结束或更新共享教学状态后发布通知。应用重新读取已保存状态，仅发送课堂进度及现有学生投影。个人作答、课堂权限与正式提交沿用现有接口。推送有心跳与有限连接寿命。断开后浏览器立即核对状态并恢复原频率查询，重连后回到低频核对。HTTP 与推送分别核对课堂进度和教师记录版本，防止旧响应回退前端状态。

Redis 仍按实际时间窗口与当期有效配额发放许可。队首暂未查询时预留可用名额 1.5 秒。到期后可把当期空闲名额补给随后已查询的候场学生，队首学生查询时仍按原队位判断。CPU 压力为暂停时既有许可可继续使用，候场学生等恢复后再发放新许可。

正式课件按当前页面声明渲染。共用控制分析工作台按需导入，首屏无该模块时浏览器可省去对应依赖；直接进入包含工作台的步骤时流式渲染继续等候该模块。上线对照分别测量浏览器初始冷缓存下载及后续进入工作台时的新增资源。

跨域 ESA 只处理适合跨域加载的前端静态资源。控制分析 Worker 本体及其内部代码块通过应用的同源修订路径请求，确保 Worker 能按浏览器安全规则启动，并与当前页面修订匹配。

候场响应只需要当前排队状态。容量开关启用时，候场可在进程内短暂复用学生身份与班级记录。Redis 查询可以续队并返回等待时间，不消耗放行名额。检测到可用许可后，读取当前学生与课堂权限，再原子竞争许可。已有许可也必须完成新鲜权限核验。等待缓存不能提供课程内容、个人记录或提交权限。

公开的版本化 JS、CSS 与 WASM 同时出原始文件和 gzip 制品，通过同一发布路径提供。验证版本 URL 的编码、缓存、内容摘要及真实冷缓存传输量。1-2 课先按当前入口载入对应角色页面，独立核验浏览器资源和服务端响应。

工作台首次加载时，分析请求允许最多 30 秒取得结果。Worker 已就绪后继续使用 12 秒分析期限和 4 秒备用路径触发时间。冷启动期间，页面等待首次 Worker 结果或明确错误，避免过早发起第二次内核下载；对失联的 Worker 保留有界等待和备用执行路径。

课堂浏览器及 Worker 使用只导出线性与非线性分析的构建产物。两个构建复用同一 Rust 实现并分别标注实际产物身份。服务器计算、仿真和其他数值能力使用完整构建。用同一输入核对输出，并比较 gzip 制品大小和浏览器冷启动。
## 队尾轮询

Redis 依据排在前面的学生数与当期配额估算下一次查询时间，队尾的基础等待上限为 14 秒，再按学生分散最多 1.799 秒。浏览器接受该范围的回执。靠近队首的学生仍按最近一个放行窗口查询。30 秒排队租约覆盖正常回执等待与请求时间。压测同时采集整机 CPU 执行与 I/O 等待、磁盘读写、进程读写及 PostgreSQL 写入活动。

中央核验区分服务暂不可用与明确拒绝。已登录会话每次核验最多等待 5 秒，浏览器的课堂查询期限为 7 秒。核验暂不可用时，候场页只返回等待提示，3 秒后重新核验。扫码入口和普通课堂接口返回可重试的 503；各课程入口共用已有的有界扫码重试。匿名访问返回 401，中央明确拒绝返回 403。每次放行仍须取得当前中央准入并确认本地班级归属。

课程页面与就绪接口共用已完整核验的发布清单。读取者打开当前文件，以文件描述符的设备、inode、大小及纳秒级修改和变更时间识别版本。首次读取前后核对文件身份，单进程只保留一个只读结果；v2 激活回执逐次核验。采样过期继续暂停新许可。使用相同班级、200 条短连接、7 秒候场期限及 5 分钟互动，对比修复前后的入场时间分布。

根布局和互动课堂页面在同一次 React 服务端渲染中读取同一份当前会话。请求之间不复用准入决定。扫码和课堂读取接口在成功响应上分别给出会话核验与业务处理耗时，保留私有、不可缓存的响应语义。开场分段测试将会话读取、扫码、页面请求分别集中执行；完整课堂另行测量，浏览器取得候场文档后按服务端首轮回执和原有抖动发起第一次查询。

## 学生在入口候场

扫码查询只识别课堂。学生点击加入后，已开启容量控制的互动课堂在当前页面显示等待状态，使用现有准入接口取得许可，再加载正式课堂。入口地址的片段仅记录目标课堂路径，用于刷新恢复和历史导航。教师、演示与直接访问正式课堂沿用原有入口。服务端分别核对会话、班级和课堂，撤权后的许可不能用于读取内容。

诊断分别测量客户端收到响应头、网关等待应用响应头和响应体传输时间。完整入场以学生读取和写入个人状态并收到首个推送快照为准。
