## Context

`/api/user/profile` 已经读取学生自己的受治理证据，并且 Personalization 已提供 `recommendLearning` 公共用例和 `mapRecommendationsToResourceCards` 映射函数；但个人中心响应仍把 `personalizedReinforcement.resources` 固定为 `[]`。页面因此只能显示空状态，推荐服务与个人中心之间形成断链。

该变更跨越 API 投影、推荐公共用例、个人中心 UI 和验收测试，必须保持学生归属、证据降级、可执行入口和现有推荐策略不变。

## Goals / Non-Goals

**Goals:**

- 在个人中心调用唯一的受治理推荐公共用例，并将结果映射为既有资源卡片。
- 保留推荐理由、优先级、证据窗口、来源覆盖、置信度和隐私范围。
- 对无可用推荐的学生展示真实的证据收集或 starter 学习行动。
- 验证推荐卡片进入真实资源路由，不生成仅供展示的死链接。

**Non-Goals:**

- 不新增推荐模型、规则集合或旁路缓存。
- 不改变推荐引擎的排序、资格判断、策略版本或正式成绩。
- 不把页面浏览、推荐点击或固定默认值写成学习掌握证据。
- 不扩大个人中心的统计字段或改变教师/管理员数据范围。

## Decisions

### 复用 Personalization public API

个人中心服务端直接调用 `recommendLearning`，并使用 `mapRecommendationsToResourceCards` 进行已有 DTO 映射。这样推荐的证据边界与学生推荐 API 保持一致，避免在画像路由复制规则。

备选方案是直接调用底层 `generateRecommendations` 或在 profile route 自行筛选资源；不采用，因为会绕过公开用例的 owner-scope 和治理边界，并形成第二个推荐入口。

### 将证据限制随卡片传递

推荐结果中的 rationale 作为可选的学生安全字段保留在资源卡片中；UI 只显示产品语言的理由、置信度或限制，不展示内部 reason code 或原始证据载荷。

备选方案是只传标题和链接；不采用，因为学生无法判断推荐依据，且无法满足证据可解释与降级要求。

### 无推荐时提供证据收集行动

当推荐公共用例返回空结果时，个人中心继续显示现有自适应练习入口，并明确说明尚未形成可用补强资源；不制造默认推荐卡片。

备选方案是用通用资源填充列表；不采用，因为会把通用规则误称为个性化推荐。

## Risks / Trade-offs

- [推荐读取增加个人中心响应耗时] -> 与现有画像读取并行执行，并复用已经使用的受治理数据库端口。
- [推荐策略异常影响个人中心] -> 将推荐失败降级为空资源和明确限制状态，不能阻断个人中心其他统计与证据展示。
- [资源 actionUrl 失效] -> 增加路由契约测试，覆盖现有资源类型对应的真实入口。

## Migration Plan

无需数据库迁移。先完成 API 投影和测试，再完成浏览器验收；若推荐读取出现运行时问题，可暂时回退为受治理的空状态，不影响原有个人中心统计。

## Open Questions

无。现有推荐公共用例、资源卡片 DTO 和证据降级策略已经提供实现所需的产品边界。
