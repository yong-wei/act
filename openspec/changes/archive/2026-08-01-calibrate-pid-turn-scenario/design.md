## Context

PID 参数推荐器以一个 90 度硬切换、坐标起点不一致的路径和未受限的舵角命令计算质量分数。路径误差、舵速、超调和稳定时间并不来自同一个可重放的控制任务，导致推荐器会把可调 PID 参数判为不合格。

该推荐器服务于控制学习中的参数建议，不是 Arena 官方提交、排行榜或学习证据写回。修复必须保持通用快速 Nomoto 仿真的既有调用兼容。

## Goals / Non-Goals

**Goals:**
- 定义从仿真起点出发、可由同一航向日程重建的 90 度转向场景。
- 用实际舵角而非 PID 舵角命令计算舵速，并在推荐场景中施加 5 度每秒的舵机限制。
- 以最终参考航向完成时刻为起点，计算 5 度容差内的持续稳定时间。
- 使推荐器能够搜索并验证至少 60 分的可行参数组合，并让评分场景参与重放校验。

**Non-Goals:**
- 修改 Arena 官方挑战、排行榜、任务进度、学习证据或个人中心统计。
- 修改前端推荐面板的展示结构或公共 API 返回字段。
- 为未提供转向场景的通用 `nomoto_quick_sim` 请求强制舵机速率限制。

## Decisions

### 以显式航向日程定义推荐场景

推荐器使用 `turn90-calibrated-v1`：仿真从 `(0, 0)` 出发，0 至 60 秒保持 0 度，60 至 150 秒线性过渡到 90 度，150 至 240 秒保持 90 度。参考轨迹由这一日程、船速和同一仿真起点积分得到；Rust 运行时从请求中的同一日程插值得到控制目标航向。

硬切换被拒绝，因为它要求无限快的目标变化，不能用于评价有限舵机速率下的学习者控制策略。仅把路径起点改为零被拒绝，因为它仍保留了不可达的 70 度每秒舵角跳变。

### 将舵机速率限制建模为可选运行时输入

`nomoto.maxRudderRateDegPerSec` 为正数时，PID 输出仅作为舵角命令；运行时以 `rate * dt` 限制相邻实际舵角的差值，船模和 `maxRudderRate` 指标均使用实际舵角。省略该字段时维持当前直接截断到最大舵角的行为，避免破坏其他快速仿真调用。

### 用持续稳定而非首次穿越衡量调节时间

转向完成后，扫描图表数据中第一个进入目标航向正负 5 度并持续保持到仿真结束、且早于最终采样点的采样点。该点与 150 秒参考完成时刻的差值为稳定时间；若没有满足条件的点，则以验证窗口 90 秒计，并将稳定性评分项计为零分。最大允许稳定时间校准为 90 秒。

### 将场景语义纳入推荐重放输入

优化器的重放载荷包含场景标识、航向日程、仿真时长、参考起点和舵机速率限制，并把运行时版本更新为 `simulation-optimizer-runtime-v2`。这样重放校验能识别评分语义变化，而不是只复现最终分数。

### 将浏览器证据绑定到稳定代码检查点

浏览器证据只能从干净工作区采集。证据页公开启动时注入的完整 `APP_REVISION`，采集器要求它与采集前 Git HEAD 完全一致，并记录采集器、推荐 API、优化器、Rust runtime、生产推荐面板和 WASM 批次的 SHA-256。采集结束后再次验证 HEAD、输入哈希和工作区漂移，除既定截图、指标及清单外不允许出现其他修改。证据提交因此只承载生成结果，其清单仍明确指向前一个包含全部执行代码的稳定检查点。

## Risks / Trade-offs

- [Risk] 圆弧参考比硬拐角更宽容。 -> 它仍保留 90 度航向、路径误差、实际舵速、超调和持续稳定四项约束，且明确模拟了教学任务中的执行器物理限制。
- [Risk] 速率限制会影响未计划使用它的调用。 -> 该字段是可选的，仅由优化器场景显式传入。
- [Risk] 随机搜索可能漏掉可行解。 -> 在确定性测试中固定已校准参数，同时将 `Kd` 上界扩展到 5，使默认搜索空间包含该解。
- [Risk] 本地或外部开发服务与证据工作树不一致。 -> 运行实例必须公开完整修订并与干净采集检查点一致；缺失、不匹配或采集期间漂移均失败关闭。
