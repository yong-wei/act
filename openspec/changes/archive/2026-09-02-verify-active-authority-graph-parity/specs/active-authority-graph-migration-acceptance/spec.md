## ADDED Requirements

### Requirement: Migration acceptance covers a closed real-data denominator
The completed migration SHALL have an immutable acceptance manifest covering all fifteen active domains, three navigation levels, supported object types, relation families, 2D/3D, desktop/mobile, student/teacher/admin and Chinese/English. Every required row MUST pass on one exact clean revision.

#### Scenario: Acceptance manifest is evaluated
- **WHEN** the final candidate is prepared for review
- **THEN** every denominator row SHALL reference current hashed evidence and a passing result
- **AND** missing, stale, fixture-only or manually waived rows SHALL fail completion

### Requirement: Force parity is proven behaviorally
Acceptance SHALL record unpinned node movement, collision separation, bounded settlement, drag, pin, unpin, component reheat, manual reflow, camera fit and state restoration in both dimensions. Component names, D3 configuration calls and source-string assertions MUST NOT count as force evidence.

#### Scenario: Force acceptance runs
- **WHEN** a bounded overview and one-hop network are exercised
- **THEN** coordinate traces and settlement metrics SHALL prove real force ownership within budget
- **AND** static automatic anchors or zero-work simulations SHALL fail the gate

### Requirement: Integrated presentation has no known migration regressions
Acceptance SHALL verify default concept labels, governed Formula rendering, complete bilingual switching, dedicated multi-select filters, screen-reader semantics and absence of a visible all-node directory without fallback to old data or another release.

#### Scenario: Integrated matrix passes
- **WHEN** the exact candidate is exercised across roles, viewports, dimensions and locales
- **THEN** every graph surface SHALL satisfy the declared hierarchy and presentation contracts
- **AND** any plain-text formula substitution, mixed-language frame, full-domain payload or visible node grid SHALL fail completion

### Requirement: Performance budgets are blocking
The acceptance gate SHALL define and measure maximum request count/bytes, domain usable time, main-thread blocking, force-settle time, frame cost, visible node/label counts and KaTeX execution count. Exceeding a blocking budget MUST fail the change.

#### Scenario: Dense domain is measured
- **WHEN** the largest active domain is opened and one concept network is disclosed
- **THEN** network, CPU, force and DOM measurements SHALL remain within all declared budgets
- **AND** the result SHALL not be downgraded to an advisory note
