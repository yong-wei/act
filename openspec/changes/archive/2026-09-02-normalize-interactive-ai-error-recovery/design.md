## Context

`InteractiveProvider` 在多个正式互动课程中挂载 `InteractiveAIPanel`，而 `useInteractiveAI` 直接处理 `/api/ai/chat` 的响应。共享聊天失败契约已经被 #1814 使用，但当前 hook 没有接入它，因此互动课程仍是学生可见错误的旁路。

## Goals / Non-Goals

**Goals:**

- 让互动 AI 的 HTTP、网络和会话失败在离开传输边界前变成受限失败类别。
- 让面板展示中文学生安全文案，并在状态允许时给出能改变下一次请求条件的恢复动作。
- 保持输入、已恢复消息和当前互动课程上下文的现有语义。

**Non-Goals:**

- 不修改 `/api/ai/chat` 的任务上下文授权、答案揭示或服务端提示词。
- 不把互动 AI 消息写入成绩、LearningFact 或学习画像。
- 不删除服务端脱敏诊断，也不让生产诊断进入学生可见文本。

## Decisions

### 1. 在 hook 边界复用共享失败契约

网络拒绝和非 2xx 响应由 `useInteractiveAI` 转换为共享失败类型；409、404 等已有会话状态仍保留其专用恢复语义。页面不根据状态码或错误字符串自行猜测。

### 2. 面板只渲染安全投影

`InteractiveAIPanel` 只读取失败类型对应的安全文案和恢复动作。任何原始状态码、JSON、供应商错误、内部路径和英文异常均不进入面板 DOM。

### 3. 以真实互动入口验证

测试覆盖组件状态和 hook 传输边界，并在一个由 `InteractiveProvider` 挂载面板的正式课程页面上验证失败文案、动作、键盘焦点和窄屏可用性。

## Risks / Trade-offs

- 共享失败契约的分类变化可能影响旧入口，因此必须保留 #1814 已覆盖的 Copilot/全局行为回归。
- 旧调用者可能依赖异常对象，内部 hook API 只保留兼容的安全错误投影，不向 UI 暴露原始消息。

## Migration Plan

先补充互动 hook 的失败回归，再接入共享归一化边界，最后更新面板的安全呈现和浏览器证据。无需数据迁移。

## Open Questions

None. 现有控灵错误领域语言已经确定安全文案与恢复动作的边界。
