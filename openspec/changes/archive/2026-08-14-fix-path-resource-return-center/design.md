## Context

资源页由路径执行上下文打开时，现有页面同时承载资源内容和旅程控制。此前返回链接沿用执行态参数，用户点击后仍停留在执行工作区；Issue #1386 确认返回动作应先回到路径中心入口，再由入口区分继续已有路径和新建路径。

## Goals / Non-Goals

**Goals:**

- 让资源页返回动作稳定指向路径中心入口。
- 保留学习目标，清除执行态和候选态路由参数。
- 保留已保存路径、进度、当前节点和配置，由路径中心负责恢复。
- 用 OpenSpec 和浏览器证据明确新的导航合同。

**Non-Goals:**

- 不改变路径生成算法、候选方案内容或资源完成回写。
- 不新增数据库字段、API 或依赖。
- 不修改非路径来源资源页的原有返回目标。

## Decisions

1. **返回由路径中心接管。** 资源页只负责导航到 `/assessment/adaptive-practice?goal=<goal>`；路径中心负责展示继续原路径和新建路径入口。相比保留 `pathId/nodeId/intent`，该方案不会把中心入口误判为执行页，也避免重新打开候选比较。
2. **学习目标保留，执行参数清除。** 目标是恢复正确的路径上下文，`pathId`、`nodeId`、路径执行意图和候选批次属于一次执行或生成流程的状态，不应由返回链接携带。
3. **共享旅程控件继续作为唯一返回动作拥有者。** 只调整其返回目标归一化，不在每个资源页新增独立导航逻辑，避免重复按钮和非路径来源回归。

## Risks / Trade-offs

- [Risk] 路径中心恢复逻辑若无法读取已保存路径，返回后可能只显示新建入口 → 保留现有中心恢复逻辑，并用已有路径与无路径场景分别验收。
- [Risk] 旧链接仍包含执行参数 → 归一化函数统一清除执行态参数，测试断言最终 href。
