## Context

平台已经通过 `useKonlingConversationLibrary` 和 `/api/ai/sessions/**` 提供用户级会话列表、创建、选择、改名、置顶、删除、消息恢复和跨页面上下文追加。全局控灵侧栏使用该能力，独立 `/ai/copilot` 页面却仍通过 `useChat` 维护页面内消息，并在请求中只发送 `pageContext` 与受限任务描述符。页面的“清空”只是 `setMessages([])`，不会删除或新建服务端会话。

这不仅造成刷新丢失。学生从作品集反思或证据复盘入口进入 Copilot 后形成的连续推理无法重新打开，页面也无法区分“没有历史”和“恢复失败”。另建页面专用存储会重复既有身份、权限、删除和审计语义。

## Goals / Non-Goals

**Goals:**

- 让认证学生在独立 Copilot 中创建、选择、继续和恢复既有控灵会话。
- 每次模型请求绑定当前用户拥有的 `conversationId`，并持久化用户、助手和允许的工具记录。
- 保留当前页面和任务态上下文的服务端校验，不用恢复会话扩大证据或写回权限。
- 将新建、删除、加载失败和未登录状态表达为可操作的真实状态。

**Non-Goals:**

- 不建立新的会话表或第二套消息 API。
- 不改变 Evidence Copilot、作品集反思或普通聊天的事实来源和提示词边界。
- 不把聊天消息自动转为正式反思、LearningFact、画像、成绩或排行榜数据。
- 不新增全文搜索、分享会话或跨用户协作。

## Decisions

### 1. Reuse the existing user-scoped conversation library

独立页面调用现有会话库 hook 或提取其共享控制器，使用相同的列表、创建、选择、删除和消息读取 API。首条消息发送前通过 `ensureConversation()` 获得当前用户会话；聊天请求携带该 `conversationId`。服务端继续校验会话归属，客户端 URL 或本地状态不能选择其他用户的会话。

页面不复制全局侧栏的全部视觉结构，但必须提供当前页面所需的新建、选择和删除入口，并在桌面端和窄屏保持消息区与编辑器可达。

### 2. Hydrate visible messages without duplicating persisted context

选择或恢复会话时，页面只将用户和助手可见消息同步到 `useChat`；服务端 system 页面上下文和内部工具记录不作为普通聊天正文展示。切换会话使用请求身份或取消机制，较早加载结果不得覆盖较晚选择。

消息完成后以现有聊天路由的会话持久化为真源，再刷新活动会话和列表摘要。页面刷新应重新加载同一活动会话或按照既有列表选择规则进入可解释的会话，而不是显示空的本地数组。

### 3. Keep task context current and server-owned

`portfolio-reflection`、`evidence` 和普通 Copilot 入口仍为当前轮次构造既有有界描述符。会话历史可以跨入口继续，但新一轮任务上下文必须重新通过服务端契约和证据授权；旧任务态不能被客户端从历史中恢复为当前权限。

服务端跨页面上下文记录继续隐藏于学生消息列表，且不得改写历史 system prefix 或既有消息。

### 4. Replace local clear with governed lifecycle actions

“新对话”创建一个空白用户会话；“删除”要求确认并调用既有删除 API。删除活动会话后进入新的空白状态。不得用 `setMessages([])` 单独表示持久历史已清除。加载失败保留错误和重试入口，不把失败归一化为空会话。

未认证用户不能创建或恢复用户级会话；页面应引导登录或明确标注临时能力，不能显示会话已保存的暗示。

## Risks / Trade-offs

- [Risk] 会话加载与 `useChat` 流式状态竞态。 -> 切换前停止当前流，并以选中会话身份丢弃过期加载结果。
- [Risk] 旧会话上下文与当前反思或证据入口不一致。 -> 每次发送重新校验当前任务描述符并追加服务端页面上下文，不从历史消息推断权限。
- [Risk] 独立页与全局侧栏同时编辑同一会话。 -> 以服务端消息顺序为真源，发送或切换后重新读取，不在两个客户端间做浏览器内共享状态。
- [Risk] 页面增加会话导航后窄屏拥挤。 -> 使用抽屉或紧凑选择器，并以 320px 浏览器证据验证编辑器、焦点和无横向溢出。

## Migration Plan

1. 增加独立页会话控制器和失败回归，保持聊天任务契约不变。
2. 接入会话创建、选择、消息恢复和持久化发送。
3. 替换本地清空并补充未登录、恢复失败和竞态状态。
4. 运行 focused tests、typecheck、严格 OpenSpec 校验及桌面端/320px 浏览器验收。

Rollback 仅回退页面接入；既有会话数据和全局侧栏不受影响。
