## Context

控制工作台、课程仿真和其他支持入口已经写入 `SimulationRun`，但 `/profile` 和 `/profile/portfolio` 仍以 `SimulationLog` 作为主要读取来源。当前缺陷表现为学生完成标准仿真后，普通个人中心的统计、最近活动或仿真设计档案不包含该训练证据。已有 `simulation-scene-trace-protocol` 已将 `SimulationRun` 定义为 canonical run envelope，已有个人档案规则要求区分 empty 与 unavailable。

## Goals / Non-Goals

**Goals:**

- 以统一学生安全投影连接标准 `SimulationRun` 与个人中心两个消费入口。
- 在迁移期兼容可验证的旧 `SimulationLog`，并阻止同一产物重复统计。
- 保留预览、官方结果、学习证据和能力达成之间的边界。
- 为身份隔离、显示资格、去重和空值语义建立可测试合同。

**Non-Goals:**

- 不删除或批量重写旧 `SimulationLog`。
- 不改变官方评分、排行榜、正式提交或画像能力达成算法。
- 不把高频轨迹、输入载荷或原始仿真日志直接返回个人中心。
- 不新增前端物理计算、仿真模型或独立的个人中心事实表。

## Decisions

### 1. 统一学生安全投影

新增或复用服务端投影函数，先读取当前学生拥有的可展示 `SimulationRun` 摘要，再读取仅用于兼容的旧日志。两个入口共享相同的展示资格和空值语义，避免统计口径分裂。

### 2. 稳定身份去重

优先使用 `SimulationRun` 的稳定来源引用、关联领域记录或显式外键判定旧日志是否已被 canonical run 覆盖；无法证明等价时保留两条各自可追溯的历史记录，不使用时间窗口猜测重复。

### 3. 显示资格与权威边界

只投影拥有者、完成状态、预览可见性和完整质量摘要均满足要求的记录。预览训练可进入个人学习记录，但不能写入官方成绩、排行榜或正式能力达成。

### 4. 渐进迁移与故障语义

不要求一次性迁移历史数据。标准运行读取失败、兼容源不可用或字段不足时由 projection 明确返回 `empty` / `unavailable`，页面不得把未知转成 0 或已完成事实。

## Risks / Trade-offs

- [Risk] 新旧表缺少稳定关联时，可能无法证明两条记录是否同一产物 → 仅接受显式来源身份或关联字段，不能凭时间和数值猜测；对无法证明者保留可追溯独立记录并记录限制。
- [Risk] 统一投影扩大个人中心读取范围 → 使用用户过滤、字段白名单、摘要读取和稳定分页；不读取高频轨迹。
- [Risk] 旧日志质量字段不足 → 标记不可用或排除，不将缺失字段补成零值。
- [Risk] 新运行与旧统计口径短期不一致 → 两个页面共享同一投影和回归，确保同一学生看到一致结果。

## Migration Plan

1. 增加 projection contract、兼容去重和路由/组件回归。
2. 先在 `/profile` 与 `/profile/portfolio` 以 feature-flag 或受控发布接入投影。
3. 对历史记录执行只读核验，确认稳定来源身份覆盖范围；不做无证据回填。
4. 稳定运行后移除页面级直接 `SimulationLog` 读取，但保留兼容适配器直至历史数据迁移窗口结束。
5. 出现回归时关闭新投影入口，保留原始记录和审计数据，不删除 `SimulationRun` 或 `SimulationLog`。

## Open Questions

- 当前 schema 中哪些字段能够稳定关联 `SimulationRun` 与 `SimulationLog`，需要实现阶段以实际迁移和数据样本确认。
- 个人中心是否需要展示来源类型标签，需结合现有页面信息密度决定；无论是否展示，服务端都必须保留来源语义。
