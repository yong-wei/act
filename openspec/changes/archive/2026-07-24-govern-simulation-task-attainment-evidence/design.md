## Context

现有 `SimulationLog`、`SimulationRun`、`InteractionLog`、`ArenaSubmission` 和奥德赛成绩保存了不同强度的仿真产物。它们分别缺少任务归属、稳定的产物去重或进入受治理学习事实的实时写入边界；现有事实中的大量 `param_change` 也不能证明完成验证。累计画像已经以不可变 `LearningFact` 和按学生增量折叠为基线，本变更必须提供可由后续画像投影消费的统一任务证据，而不创建第二套事实或画像系统。

## Goals / Non-Goals

**Goals:**

- 建立由既有注册表和任务定义汇集的只读仿真任务目录。
- 将白名单内、学生归属明确的仿真产物规范化为稳定、可去重、可审计的任务证据。
- 覆盖虚拟仿真、自由控制工作台、竞技场和奥德赛的实时入口，并为历史数据产生同构候选。
- 在来源自身的评分或通关语义之上，明确任务满分与三个不同有效运行的通用规则。

**Non-Goals:**

- 不新增数据库任务目录、独立学习事实表、通用撤销工作流或原始轨迹读取路径。
- 不修改 Rust/WASM 数值内核、Arena 官方评分算法、奥德赛关卡规则、课程内容或既有建模/参数设计映射。
- 不计算 portrait 分子、班级聚合或页面展示；这些由后续依赖变更消费任务证据。
- 不把参数调整、浏览、结果查看或重复重放作为独立任务证据。

## Decisions

### 1. 以只读目录作为任务事实的共同语义源

目录从 Arena 挑战定义、奥德赛关卡定义、资源注册表和控制工作台会话定义汇集任务，而不是维护第二份数据库配置。每个目录项包含稳定 `taskKey`、来源、学生可见名称、当前发布状态、完成规则和展示分组。Arena 项必须在挑战定义中具有确定的任务完成谓词；奥德赛项必须具有可持久化的通关状态。

只纳入当前已发布且可供学生完成的项。奥德赛每关和 Arena 每挑战各自为一项；具名虚拟仿真按资源或任务标识为一项。自由控制工作台和无标识历史虚拟仿真分别使用稳定的通用任务项。目录变动是目录增量，不重放事实，也不建立 retired/tombstone 目录：已下线或不再可解析的具名任务不属于当前分母，其历史记录以 `task-no-longer-published` 或 `task-unresolvable` 跳过并保留原始审计。

备选方案是在各入口临时推导任务集合。它会使回填、写入和后续分母使用不同任务集合，故拒绝。

### 2. 任务证据附着在不可变学习事实的受治理上下文中

每个合格产物写入或引用一个不可变学习事实，并在受治理上下文中保存 `taskKey`、稳定 `artifactKey`、来源、证据层级、发生时间、语义指纹、可复核摘要和可用的来源有效性状态。任务证据事实在本变更内使用零画像权重，不触发现有按 `LearningFact.id` 的累计画像贡献；它保留原有能力映射标签及“仿真验证与证据”映射，供后续任务画像投影按任务键产生唯一贡献。

`artifactKey` 必须由学生归属、来源族、规范化 `taskKey` 与来源的规范化产物身份组成；内容相同而学生不同的产物不得互相去重。语义指纹只用于判定同一任务中的不同运行，使用版本化的被控对象、模型、控制器配置和关键输入字段，不含处理时间、包装事件标识或证据层级。对同一学生、来源、任务和产物的保存、运行、评测或提交只选择最高层级作为该产物的有效任务证据。较低层过程不删除，但不产生画像贡献；正式任务结果由后续层按任务键读取，避免修改或删除原始 `LearningFact`。

备选方案是新增任务证据表。当前累计事实和治理管线已经提供稳定来源、不可变审计和增量触发，额外表只会复制写入与回填边界，故拒绝。

### 3. 白名单按产品语义界定，参数调整必须附着到结果

有效过程候选包括虚拟仿真的完成运行、控制工作台的持久化模型或控制器以及完成运行、评估、提交、竞技场的有效运行、已接受提交及其关联评测、奥德赛的持久化通关结果。Arena `ArenaEvaluationRun` 只提供关联提交的评测指标，不能独立决定学生任务完成。参数调整只可作为其后保存、运行、评估或提交产物的过程上下文；浏览、打开面板、结果查看和孤立参数调整不产生任务证据。

所有实时写入由服务端确认学生身份和来源身份后执行。教师预览、管理员操作和未确认归属的事件不得写入学生任务证据。

### 4. 完成规则由来源任务定义，通用任务采用三次不同有效运行

Arena 任务仅使用已持久化、学生归属已确认且被接受的 `ArenaSubmission`；其关联挑战定义必须提供明确完成谓词。缺少该谓词的挑战不得进入当前任务目录，直到在挑战定义中补齐来源级规则。奥德赛任务仅使用持久化通关状态，不从裸 `score` 推断完成。具名虚拟仿真、无标识历史虚拟仿真和自由控制工作台均要求三个不同且可复核的有效运行达到任务上限。

不同运行要求被控对象、模型、控制器配置或关键输入至少一项不同；完全相同的重放或重复提交不计入。自由控制工作台的有效结果还必须包含持久化设计或结果，并在所选对象具有目标或评价指标时满足该指标。

不使用跨来源的统一分数阈值或按事件数量自动满分。

### 5. Arena 指派奥德赛运行优先归入 Arena 任务

具有持久化 Arena 指派标记与关联 Arena 任务标识的奥德赛运行只归入对应 Arena `taskKey`，不得同时计入普通奥德赛关卡任务。未指派的普通奥德赛通关只归入关卡任务，不得制造 Arena 任务完成。

### 6. 历史物化复用实时身份与目录规则

历史回填先输出可审计 dry-run 候选和跳过原因。候选必须同时具备学生、发生时间、来源语义和当前目录可解析的任务身份；缺失虚拟仿真任务身份但保留稳定来源语义的记录进入通用虚拟仿真项。已下线或不再可解析的具名任务、没有足够上下文的记录均不伪装为正式验证，也不把旧 `param_change` 事实直接提升为新任务证据。

实时和历史路径共享来源身份、产物键和语义指纹，确保先实时后回填或重试回填都不会为同一产物重复创建任务贡献。

## Risks / Trade-offs

- [旧记录缺少任务字段] → 仅在来源语义可确认时进入稳定通用任务；其余记录保留审计但不形成任务证据。
- [不同入口重复报告同一产物] → 使用稳定 `artifactKey`、层级选择和语义指纹幂等去重。
- [过程行为被误当作验证] → 采用产品语义白名单，并把参数调整附着到后续持久化结果。
- [目录项发布状态变化] → 以目录增量重新发布任务集合；已下线的具名历史项输出跳过原因，不重放历史事实、不读取原始轨迹，也不建立存档目录。
- [受治理摘要暴露敏感内容] → 仅保存来源标识、质量摘要与脱敏指标，不复制原始答案、隐藏评分细节或高频轨迹。

## Migration Plan

1. 先实现目录与实时写入合同，并用每种来源的最小代表性产物验证稳定身份和去重。
2. 运行历史候选 dry-run，输出来源、任务归属、通用任务回退、跳过原因和受影响学生计数。
3. 与后续画像投影变更共同在生产副本演练中应用回填；本变更本身不独立启动全量画像重建。
4. 若候选或实时写入发现身份、归属或摘要不完整，停在来源级修复，不以宽松默认值写入任务证据。
