## Why

学情诊断已有结构、语言、证据引用与归因测试，但缺少以"已知真值场景"为基础的准确性回归门禁（Issue #1729）。最近一次 8 类场景、24 次重复仿真实验中弱点集合完全匹配率仅 54.17%、宏平均 F1 65.83%；模型、提示词、阈值或投影逻辑变更后，现有测试无法回答"真实薄弱节点是否仍被发现、是否引入新误报、完整薄弱集合是否一致、重复运行是否稳定"。#1728 已修复薄弱判定校准，本变更把同一套评测固化为可重复、可比较的质量门禁，防止准确性再次回归。

## What Changes

- 新增版本化学情诊断基准集：8 类场景（健康班级、单薄弱节点、多薄弱节点、局部子群风险、分层风险、作业与测评冲突、30% 数据缺失、知识节点归因压力），每场景携带明确真值（真实薄弱节点集合、首要薄弱节点、数据覆盖状态、允许的诊断结论边界）与固定随机种子。
- 新增确定性仿真 governedInput 生成器：按场景参数生成诊断 governedInput（学生数、节点数、分数与进度分布可配置），基准集不含真实学生身份、原始答案或私密对话。
- 新增分层评测 runner 与指标计算：节点级 precision/recall/F1、宏平均与微平均 F1、弱点集合完全匹配率、首要弱点命中率、健康场景假阳性率、中文输出合规率、证据引用有效率、知识节点归因有效率、资源覆盖判断准确率、数值主张证据支持率、重复运行均值/离散/最差、生成成功率与耗时。
- 两种执行模式：确定性 fixture 评测进入常规验证（验证指标计算、阈值判断与报告生成，不调用外部服务）；真实 provider 重复评测（每场景 ≥3 次）作为候选模型、提示词或发布版本变更时的手动/计划评测。
- 每次运行以统一 run ID 输出 JSON/CSV 明细与汇总（同批次真值、原始输出、解析结果、汇总指标可追溯且不相互覆盖）；阈值失败时明确列出失败场景、运行编号、预期真值与实际输出。
- 阈值门禁：微平均 precision ≥ 80%、recall ≥ 80%、宏平均 F1 ≥ 80%、弱点集合完全匹配率 ≥ 75%、首要弱点命中率 ≥ 85%、健康场景知识节点级假阳性率 ≤ 10%、中文输出/证据引用/知识节点归因合规率 100%、资源覆盖判断准确率 ≥ 95%。
- 新增回归用例：至少一个在 #1728 修复前的过度诊断行为下触发失败、修复后通过的确定性用例。
- 文档：如何添加新场景、更新真值、运行 fixture 评测与真实 provider 评测。

## Capabilities

### New Capabilities

- `diagnosis-accuracy-regression-gates`: 版本化基准集、分层评测流程与质量阈值门禁的行为要求。

### Modified Capabilities

- None.

## Impact

- 新增代码：`scripts/diagnosis-benchmark/`（场景定义、governedInput 生成器、指标计算、runner、fixture 断言）与相关测试、npm scripts、文档。
- 行为影响：不改变生产诊断链路；fixture 评测纳入常规验证命令，真实 provider 评测显式手动触发，外部服务波动不会变成普通提交的不稳定门禁。
- 验证：fixture 评测自身确定性通过；指标计算对已知输入的单测；过度诊断回归用例在旧门禁语义下失败、新语义下通过。
