## Context

互动课程 AI 目前通过 `useInteractiveAI` 调用通用 `/api/ai/chat`。Provider 已有 `sessionId`、资源身份、进度和完成状态，但 AI hook 只发送当前问题；本地 `messages` 仅存在于组件内存，`contextData` 没有服务端消费。项目已有用户级控灵会话和页面上下文追加约定，本变更应接入这些能力，而不是再建立互动课程专用的平行会话模型。

约束包括：互动课程资源边界不能被聊天历史或客户端字段突破；课程进度只能作为当前辅导上下文，不能被解释为成绩或掌握度；现有互动资源的追踪、提交和完成语义不能改变。

## Goals / Non-Goals

**Goals:**

- 让同一互动课程 AI 会话的后续请求包含可用的历史消息。
- 让服务端能够验证当前资源、课程步骤和进度上下文，并在进度变化时使用最新值。
- 让认证学生刷新或重新打开资源后能够恢复同一会话，且切换资源时不会串用历史。
- 保留明确的加载、恢复失败和不可用状态，并提供回到当前学习资源的真实入口。

**Non-Goals:**

- 不改变互动课程评分、完成判定、追踪事件或提交证据格式。
- 不把 AI 对话自动写入官方成绩、LearningFact、排行榜或学习画像。
- 不把客户端 `contextData`、URL 参数或自由文本描述提升为学生事实。
- 不新建独立于既有控灵会话治理的会话库。

## Decisions

### Reuse the existing governed conversation boundary

互动课程 AI 请求使用既有用户级会话身份和消息持久化能力。互动资源标识、当前课程步骤和页面变化作为受控上下文记录或受控字段进入服务端，不覆盖历史消息，也不伪装成学生消息。

这比只在组件内维护数组可靠，因为刷新、重开和跨页面继续都要求恢复；也比新建互动课程专用会话库简单，因为认证、权限、审计和保留策略已有统一实现。

### Validate current resource and progress on the server

请求只携带用于定位的 bounded resource/session hints。服务端依据认证身份、当前会话和已授权互动资源重新解析资源边界、步骤、进度与完成状态；无法验证时返回显式 unavailable 或 rejected 状态，不使用客户端值补齐。

### Send bounded history to the model

服务端从受治理会话读取按稳定顺序排列的历史用户/助手消息，按既有模型输入上限裁剪，并与当前资源上下文一起构造模型消息。裁剪不能改变持久化历史，当前资源之外的消息不能被带入另一个资源的辅导上下文。

### Keep the existing one-turn fallback explicit

未认证开发入口或旧调用方没有会话身份时，保留现有兼容行为，但不得把它标记为可恢复的连续会话。生产认证学生如果会话恢复失败，应显示恢复失败或不可用状态，并允许重试，不应静默创建空历史掩盖数据丢失。

## Risks / Trade-offs

- [历史消息增加模型输入成本] -> 使用既有有界历史策略；完整历史仍持久化，模型只读取当前请求所需窗口。
- [会话恢复与互动资源身份不匹配] -> 以用户身份、会话身份和资源身份共同校验；不匹配时隔离历史并返回明确状态。
- [客户端伪造进度或资源描述] -> 服务端从认证会话和授权资源重新解析，客户端字段仅用于导航提示。
- [旧入口没有可恢复会话] -> 保留一轮兼容路径并在 UI/响应元数据中明确其不可恢复，不声称已保存学习对话。

## Migration Plan

1. 先增加请求/服务端上下文契约、会话恢复和边界回归，再接入互动 AI hook 与面板。
2. 新会话从首次成功请求开始持久化；既有仅存在浏览器内存的历史不做虚假迁移。
3. 发布后观察认证互动资源的会话恢复、跨资源隔离和 AI 请求失败率；出现问题时可关闭恢复入口并回退到显式的一轮兼容行为，不改变互动课程进度数据。

## Open Questions

- 既有用户级控灵会话与互动课程 AI 面板是否共享同一会话列表中的可见名称，需要在实现时依据当前会话 API 的资源分类能力确定；无论采用何种显示方式，底层身份和权限必须保持统一。
