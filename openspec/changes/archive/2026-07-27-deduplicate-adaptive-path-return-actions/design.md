## Context

`AdaptivePathJourneyControl` 同时渲染固定 `returnAction` 与服务端投影的 `nextAction`。正常情况下后者指向下一节点；当路径中心请求的节点与当前有效节点不一致，或服务端将恢复动作投影为 ready action 时，两者可能具有相同规范化 href 和相同标题，从而在同一操作组内产生两个“返回学习路径”。此外，部分目的页还拥有局部返回操作，形成共享控制与页面操作之间的重复。

## Goals / Non-Goals

**Goals:**

- 所有有效学习路径上下文页面的同一可见区域最多显示一个等价“返回学习路径”入口。
- 在共享组件边界统一处理服务端动作与固定返回动作的等价性。
- 保持真正指向下一节点的继续操作、进度、完成和恢复状态。
- 保持非学习路径来源的上下文返回操作。

**Non-Goals:**

- 不改变学习路径规划、节点完成判定或服务端 journey 数据模型。
- 不改变返回目标的规范化规则。
- 不借此重构各目的页壳层。

## Decisions

1. 在共享 `AdaptivePathJourneyControl` 内以规范化 href 判定动作等价。相比仅比较中文标题，href 能覆盖标题变化并直接表达导航语义；仅当目标有效且等价时才抑制后渲染的重复动作。
2. 固定 `returnAction` 保留所有权。它是连续旅程合同要求的稳定退出入口；当 `nextAction` 与其等价时，隐藏 `nextAction`，而不是隐藏固定返回入口。
3. 页面局部操作继续按有效 `pathLaunchContext` 让渡所有权。非路径来源不挂载共享返回语义，因此仍显示原上下文返回入口。
4. 测试分两层：组件渲染测试证明等价动作去重且不同目标保留；源码挂载审计证明所有共享旅程控制入口复用同一实现。浏览器验收统计真实 DOM 文案与 href。

## Risks / Trade-offs

- [服务端错误地把下一节点 href 指向返回页时，学生只看到返回入口] → 这是比显示两个等价操作更真实的降级；组件测试同时确保不同 href 的下一步不被隐藏。
- [仅处理共享组件不能覆盖页面局部重复] → 保留资源详情页的 `pathLaunchContext` 所有权判断，并审计所有共享组件挂载面。
- [字符串形式不同但语义相同的 href 漏判] → 使用既有内部 href 规范化函数后比较。
