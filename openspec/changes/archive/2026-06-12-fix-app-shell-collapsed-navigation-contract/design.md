## Context

Browser inspection on `http://127.0.0.1:3001/arena` and `/interactive-learning/control-workbench` showed that the collapse button changes `data-shell-navigation-state` to `collapsed`, but the grid remains `248px 1177px` at a 1440px viewport. The visible collapsed links also combine the original screen-reader label and a first-character fallback into duplicated text.

## Goals / Non-Goals

**Goals:**

- Make AppShell collapse a real layout state with a narrow navigation rail and expanded content area.
- Render collapsed navigation with stable icons or registered icon fallbacks, accessible labels, and clear active state.
- Verify the behavior through unit/contract tests and browser-visible evidence for representative mission workspaces.

**Non-Goals:**

- Migrating Interactive Learning, adaptive practice, knowledge graph, or data center routes.
- Redesigning individual page content or workspace panels.
- Changing domain behavior, auth behavior, or floating dock registration.

## Decisions

### Decision 1: Use AppShell state as the layout source

The collapsed state should be reflected in the grid column definition generated by AppShell or by a deterministic class that wins over the expanded grid class. Relying on a global `:has()` rule is fragile because utility classes can override it and the failure is hard to detect in static tests.

### Decision 2: Collapsed navigation is an icon rail, not abbreviated text

Collapsed navigation should render approved icons from the route item `iconKey` mapping or a registered fallback. The full label remains available through `aria-label`, `title`, or tooltip semantics. A first-character text fallback is not acceptable for Chinese labels because it produces ambiguous route identity and can duplicate hidden text in browser inspection.

### Decision 3: Tests must check state outcome, not just marker presence

Existing tests check that `data-shell-navigation-state` and collapse icons exist. New tests must prove collapsed width, grid column change, hidden full labels, accessible labels, and no duplicate visible text. Browser evidence must include expanded and collapsed screenshots for Arena and Control Workbench.

## Risks / Trade-offs

- Shared AppShell changes can affect many routes -> keep the patch limited to layout, labels, and icon rendering, then verify fixed and collapsible modes separately.
- Icon mapping may be incomplete -> use the central navigation icon key contract and fail tests for primary entries that lack usable icons.
- CSS specificity can regress later -> add contract tests or script checks that inspect the emitted class/data-state combination and browser evidence.
