## Context

路径规划器已经生成并持久化 `targetDeficits`、聚合证据数量、置信度、候选资源节点和生成时证据窗口；候选路径展示层却只把这些数据压缩为“面向 N 个薄弱项安排资源”。因此第一阶段的问题不在规划算法，而在缺少稳定的学生安全聚合解释投影及其页面呈现。

已有 `explain-adaptive-path-option-differences` 负责两条候选路径之间的结构差异。本变更只解释单条候选路径为何被推荐，不复用或扩展差异解释语义。

## Goals / Non-Goals

**Goals:**

- 从已有生成时聚合事实构造“学习状态摘要 → 能力判断 → 推荐资源”的学生安全解释链。
- 将解释随候选路径持久化，恢复页面时保持原始推荐依据，不以当前画像重新解释历史推荐。
- 在候选路径卡片中提供常显摘要、按需展开详情和学习记录复核入口。
- 对低证据状态使用明确、可执行且不暴露内部 reason code 的产品语言。

**Non-Goals:**

- 不改变路径候选生成、排序、评分、资源选择或差异解释。
- 不修改活动路径执行区、节点详情、Prisma、WASM 或学习记录数据模型。
- 不提供证据类型、发生时间、事件标识或从推荐条目回跳到具体证据事件的能力。
- 不解释活动路径节点为何被选择、提前、延后或锁定。
- 不展示原始答案、私密对话、内部标识、原始证据 JSON 或模型提示词。

## Decisions

### 1. 在候选路径投影中持久化推荐依据快照

每个正式候选路径增加结构化 `recommendationProvenance`。它由生成时的 `targetDeficits`、候选路径节点及路径置信度构造，包含学生安全聚合摘要、置信度、按薄弱项组织的解释条目、受影响节点和通用学习记录入口。

页面只消费该投影，不根据最新画像重新计算。这样恢复已保存路径时，学生看到的依据与当时的推荐决策一致。直接在页面读取当前画像虽然代码更少，但会使历史路径的理由随新证据漂移，因此不采用。

### 2. 以薄弱项为解释单元

解释生成器按薄弱项目标筛选当前候选路径中覆盖该目标的资源节点，并形成一条解释链：证据摘要、能力判断、受影响资源。若现有节点语义无法建立目标关联，不声称具体资源受该证据影响，而是返回明确限制。

按路径整体生成一段理由无法核验资源影响；按每个资源重复证据会放大卡片和移动端负担，因此均不采用。

### 3. 只输出学生安全字段

学生可见字段使用目标显示名、百分比状态、证据数量、置信度、资源标题、产品化判断和固定学习记录入口。内部 `reasonCode`、数据库 ID、原始证据引用及未治理载荷不进入展示合同。

学习记录复核沿用 `/profile/evidence`。该入口只提供通用复核路径，不表示当前摘要能够定位具体证据事件；本变更不建设第二套证据时间线或新的查询接口。

### 4. 低证据路径保留但不伪装成个性化结论

当路径或任一薄弱项证据不足时，路径级投影和对应条目都明确标为低置信度，说明路径主要依据课程结构、先修规则和可用资源生成，并给出完成诊断或练习的补证动作。页面不隐藏缺口，也不把缺失证据按零分表述为能力不足。

### 5. 采用渐进披露

桌面端和移动端候选卡片常显一行推荐依据摘要；完整解释链放在原生可访问的按需展开区域中。该区域与“解释差异”操作保持独立，避免两个概念混淆。

## Risks / Trade-offs

- [部分目标缺少稳定显示名] → 使用受控能力标签和既有知识名称规范化；无法安全转换时退回路径级限制，不直接显示内部 ID。
- [旧路径没有新投影] → 展示现有概括性理由，不尝试用当前画像回填历史路径；新生成路径具备完整解释链。
- [候选卡片内容增加] → 默认只显示摘要，完整内容按需展开，并为 320px 布局增加回归测试。
- [证据摘要可能被误解为原始证据] → 明确标注为生成时摘要，并通过既有学习记录入口提供复核路径。
- [Issue 范围大于本阶段交付] → PR 只标记部分关联并保持 #1186 开放，后续补充活动路径节点解释与事件级证据追溯。
