## Context

`/profile/growth` 从 `/api/student/competency-snapshot` 读取推荐和 `RoleBasedLearningDiagnosis`。当前 `buildRecommendations()` 的返回类型允许 `actionUrl`，但实际对象没有填充；页面因此把建议链接降级为 `#`。同时，`buildCumulativeDiagnosis()` 为每个诊断维度生成的学习行动仍指向不存在的 `/courses`。

平台正式的互动课程目录是 `/interactive-learning/courses`，并且已有路由和入口测试覆盖该地址。成长诊断只负责提供学生可执行的导航提示，不应借导航参数修改证据、成绩、解锁状态或路径状态。

## Goals / Non-Goals

**Goals:**

- 让每个可执行的成长建议进入有效的学生学习入口。
- 在没有足够信息定位单个资源时，进入正式互动课程目录。
- 让缺失或不可用的行动以明确状态呈现，不产生空链接。
- 用测试证明 API 投影、诊断组件和真实页面导航保持一致。

**Non-Goals:**

- 不重新设计能力评分、风险判断、证据计算或推荐排序。
- 不为诊断臆造具体课程、路径节点或学生应当完成的任务。
- 不改变学习路径选择、解锁、成绩和学习记录写回逻辑。

## Decisions

### 1. 使用正式互动课程目录作为安全降级入口

当服务端无法从当前诊断确定具体课程资源时，行动地址使用 `/interactive-learning/courses`。能够确定并通过既有契约校验的具体资源时，才使用资源正式学习地址。这样既避免失效旧路由，也避免把泛化诊断误报为具体任务。

### 2. 服务端负责产生行动地址，客户端不猜测

推荐和诊断行动地址由服务端投影随数据一起返回。客户端只渲染服务端确认的地址；地址缺失时显示不可执行状态，不以 `#`、当前页或通用自适应练习替代。

### 3. 导航只表达入口，不授予权限

学生点击行动后仍由目标页面和服务端执行归属、证据和路径状态校验。导航参数不能直接解锁课程、改变学习记录或写入成绩。

## Risks / Trade-offs

- [具体资源映射暂时不可用] -> 使用正式课程目录作为诚实降级，并在诊断中保留证据限制，而不是生成虚假任务。
- [路由再次迁移] -> 复用现有互动课程入口契约，并加入有效路由回归测试。
- [推荐对象缺少地址] -> API 与 UI 同时 fail closed，避免空链接对学生形成无反馈点击。

## Migration Plan

无需数据迁移。先补充失败回归和 OpenSpec 验收，再更新 API 投影与学生端渲染，最后执行相关单测、浏览器导航、typecheck、OpenSpec strict validation 和 diff check。

## Open Questions

无。当前可由仓库路由契约和已有产品边界确定默认入口。
