## Context

Arena 的当前实现已经包含 `/arena` 大厅、挑战详情页、任务种子、官方评测、工作台提交面板和多表征联动工作台。现有问题集中在学生体验和口径一致性：大厅与详情页视觉结构分散，详情页仍能提交参数和运行预评测，评价规则混有英文硬约束 id，知识点只是字符串，工作台参数抽屉与控制器表达不一致，官方白箱稳定性检查和工作台图表判断存在冲突。

CRG 索引显示本次变更风险较高：Arena UI、白箱评测、多表征工作台模型和共享控制图表会共同受影响。实现应把改动分层：先建立展示层标签和页面壳层，再改数据契约，再修工作台参数语义，最后收束官方评测和测试。

## Goals / Non-Goals

**Goals:**

- 让竞技场大厅、挑战详情和工作台形成一致的学生路径：选择挑战，进入工作台，仿真调试，提交官方评测，进入榜单。
- 详情页和大厅只展示挑战、规则、知识点和榜单，不承载提交参数和工作台仿真。
- 将白箱模型、控制器表达和工作台公式全部使用 LaTeX 渲染。
- 将硬约束、榜单摘要和工作台文案全部改为中文。
- 让知识点链接到真实知识图谱节点，并能显示知识卡片和信息图。
- 修复 PD/PI/PID 等效传函和闭环稳定检查，使官方提交和工作台稳定判断一致。

**Non-Goals:**

- 不删除 `/review` 路由、课程审查页面或内部审查工具，只从公开学生入口和竞技场导航中移除评审入口。
- 不删除底层 `class`、`season`、`pareto` 榜单类型，只收束学生可见的大厅和详情页入口。
- 不重写黑箱辨识、MPC、控制奥德赛等非多表征工作台的完整实现。
- 不新增平行官方评测 API；`/api/arena/evaluate` 仍是官方提交入口。

## Decisions

### 1. 新增竞技场页面壳层，而不是在大厅和详情页复制布局

将左侧项目入口、顶部面包屑和用户区域抽成 Arena 专用页面壳层或局部共享组件。大厅和详情页复用同一套导航结构，避免两个页面在后续维护中出现不同的入口名称、面包屑或评审入口残留。

替代方案是分别重写 `arena-hall.tsx` 和 `challenge-detail.tsx`。该方案短期更快，但会重复左导航和面包屑逻辑，风险是后续再次漂移。

### 2. 展示层收束榜单类型，数据层保留完整类型

学生可见 tabs 只渲染主榜、方法榜、指标榜。`LeaderboardType`、leaderboard policy 和教师配置中的 `class`、`season`、`pareto` 暂不删除，因为它们仍服务教师配置、历史测试和潜在后台分析。

替代方案是直接移除类型定义。该方案会扩大破坏面，容易影响现有教师配置和测试。

### 3. 相关知识点存储真实节点引用，同时保留可迁移显示标签

将 `relatedKnowledge` 从字符串数组升级为 `{ label, nodeId }` 结构，渲染时根据 `nodeId` 请求 `/api/knowledge/nodes/[id]`。`label` 用于卡片标题和搜索兼容，`nodeId` 作为验收真源。

替代方案是在渲染时按字符串模糊搜索节点。该方案不可验证，也会在重名节点上产生不稳定链接。

### 4. 控制器增益进入校正状态模型

多表征工作台新增校正器增益字段。校正启用后，参数抽屉的“校正装置”页显示控制器增益和结构参数；对象页只保留对象零极点。官方 artifact mapper 和控制分析请求都从同一状态模型读取等效控制器，避免 UI 显示、图表计算和提交参数使用不同口径。

替代方案是继续保留独立开环增益 `gain` 并在提交时临时相乘。该方案已经导致用户无法判断当前参数属于对象还是校正装置，也容易让根轨迹闭环极点和官方提交参数不一致。

### 5. 官方稳定性修复优先使用等效传函构造

PID 家族根据实际参数构造控制器传函：PD 无积分器时分母为 `[1]`；PI/PID 有积分器时分母为 `[1, 0]`；微分滤波启用时按滤波极点构造。闭环稳定检查仍通过统一的特征多项式和 Hurwitz/Routh 逻辑判断。

替代方案是只给用户指出的 PD 参数加特判。该方案不能解决 PI/PID 等价性，也会留下同类评测误判。

### 6. 图表行为局部修复，不重构控制分析引擎

时域响应 y 轴默认范围在稳定响应下按响应信号最大值的 1.1 倍计算；根轨迹状态栏显示当前等效开环增益；闭环极点位置使用等效控制器后的根轨迹数据。图表组件只增加必要的 axis/status 参数，不改 Rust/WASM 或分析引擎主接口。

替代方案是重写分析请求和图表状态管理。该方案代价过高，且超出本次 UI 与口径修复目标。

## Risks / Trade-offs

- 共享图表组件被多个互动课程使用 → 将新增行为限制在传入显式参数或稳定响应自动范围内，并补多表征定向测试。
- 知识图谱节点存在重名 → 所有 Arena seed 使用固定 `nodeId`，测试校验 id 必须存在于 `nodes.json`。
- 参数抽屉状态模型变更会影响 artifact mapper → 先补 artifact mapper 等价性测试，再改实现。
- 详情页移除提交面板会破坏旧测试 → 更新测试断言为“详情页不得渲染提交面板，工作台才提交”。
- 评审入口移除可能影响内部审查使用 → 只移除公开首页和竞技场导航，不删除 `/review` 路由。

## Migration Plan

1. 添加展示标签 helper 和 Arena 页面壳层，更新大厅与详情页布局。
2. 扩展 `TransferFunctionModel` 与 `relatedKnowledge` 数据结构，并完成 seed 数据迁移。
3. 更新详情页评价规则、榜单摘要、知识点预览和详情页提交边界。
4. 更新工作台状态模型、参数抽屉、artifact mapper 和控制器 LaTeX 表达。
5. 修复白箱官方稳定性检查，补用户给定 PD 参数回归测试。
6. 更新 smoke scripts、Vitest 和浏览器验证。

回滚策略：若工作台参数模型变更阻塞，可先回滚工作台状态模型和 artifact mapper，保留大厅/详情页只读入口改造；官方评测修复可独立保留。

## Open Questions

无阻塞性开放问题。实现时如发现某个旧 `relatedKnowledge` 词没有合适真实节点，应优先选择同章节真实节点；如果完全没有节点，则新增 seed 显示标签但不得渲染成可点击知识卡片。
