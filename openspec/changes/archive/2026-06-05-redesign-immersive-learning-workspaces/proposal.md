## Why

Simulation, Arena, Control Workbench, and interactive runtime are the platform's strongest product experiences, but they still compete with explanatory cards, local headers, and dense configuration blocks. They need one mission-workspace shell that foregrounds the active object, step, main visualization, command actions, evidence, and support.

## What Changes

- Redesign mission workspaces around context strip, command bar, instrument area, evidence rail, support drawer, and mobile bottom sheets.
- Ensure Control Workbench mobile first viewport exposes object, current step, and a main view before long configuration text.
- Align Arena challenge, simulation, and representative lesson runtime surfaces to the same workspace grammar.
- Include classroom student player, independent lesson runtime, course-launched simulation, Arena-launched Workbench, and course-launched Workbench routes in the ledger or explicit exceptions.
- Verify runtime lesson workspaces consume `interactive-manifest.json` truth and preserve step navigation, activity submission, telemetry summary, teacher insight, and teacher controls.
- Verify completed mission tasks connect to evidence rail, learner record, or next recommendation where evidence is available.

## Capabilities

### New Capabilities

- None.

### Modified Capabilities

- `commercial-workspace-surface-system`: adds mission-workspace visual and mobile structure requirements.
- `simulation-arena-workbench-experience-ui`: adds simulation/Arena/workbench convergence requirements.

## Impact

- Affects `src/features/control-workbench/**`, `src/features/arena/**`, `src/app/simulations/**`, representative interactive runtime pages, floating dock placement, and workspace visual QA artifacts.
