## Context

`generic-chat` 已通过 Konling runtime、Source Pack 和平台引用组件生成受治理的学习支持答案。当前运行时只以 `fact-explanation` 表示通用学科问答，回答的教学结构与引用验证无法区分公式、代码、概念或规范性内容。现有 Citation Hydrator 已禁止模型自造链接，Citation Guard 可报告回答级引用状态，引用面板可呈现已验证来源。

## Goals / Non-Goals

**Goals:**

- 在已有 `generic-chat` 中判定学科问题类型，并把对应分步讲解要求写入系统提示词与流式 metadata。
- 将关键回答单元的引用锚点由模型输出文本中的受控标记表示，并仅映射到服务端已验证的 CitationTarget。
- 为规范性内容使用现有来源 authority、限制状态和 Citation Hydrator，缺少合格来源时明确降级。
- 在现有消息引用区域呈现回答结构、规范性限制和步骤级证据映射。

**Non-Goals:**

- 不建立新的聊天入口、向量数据库、外部搜索服务或引用数据库。
- 不把模型自写链接、来源名称或未验证脚注转化为平台引用。
- 不承诺对所有自由回答自动判定为规范性结论，也不生成法律、化学等领域的新规则库。

## Decisions

### 以受控问答配置扩展现有 `generic-chat`

在 `konling-agent-runtime.ts` 中增加专业问答子意图、回答段落合同及答案偏好。路由从最新用户消息和可选的结构化偏好构建运行时合同，再由 `buildKonlingSystemPrompt` 生成对应格式要求。

直接建立多个独立的聊天模式会重复鉴权、工具范围与流式引用链路，因此不采用。

### 使用服务端生成的回答证据锚点

系统提示词只允许模型在关键结论或步骤后输出与可用证据清单相匹配的受控引用标记。服务端解析这些标记，映射至已由 Citation Hydrator 验证的 CitationTarget，并在最终 metadata 中保存回答单元、引用目标与限制状态。无法映射的标记不会显示为引用。

仅依赖回答末尾引用面板无法让学生核查具体推导或修复建议；让模型直接输出 URL 则会绕过现有安全边界，因此均不采用。

### 规范性内容采用现有 authority 与限制状态

规范性意图只接受现有 Source Pack/Citation Hydrator 中服务端验证、可导航且具 authority 的来源支撑确定性表述。若不满足，运行时合同和 metadata 标记为 `verification-required`，提示词要求输出核验说明而非标准答案。

不为本次变更新增官方来源爬取或验证器；来源供给仍属于既有 Source Pack 治理范围。

### 用户偏好只影响表达，不影响证据门槛

讲解深度、示例、格式和提示强度写入回答偏好，允许调整组织与表达；回答类型、引用锚点和规范性证据门槛由服务端合同决定。

## Risks / Trade-offs

- [模型可能遗漏受控锚点] → 复用最终 Citation Guard，并将缺少锚点的规范性回答标为需核验。
- [关键词误判问题类型] → 保持 `fact-explanation` 作为默认回退，并仅对明确的规则、格式、法条、标准等请求启用规范性门槛。
- [UI metadata 与旧消息不兼容] → 新字段均为可选；没有结构化 metadata 的历史消息继续使用现有引用面板。
- [来源 authority 覆盖不完整] → 显示来源不足，而不是凭模型常识补足规范性结论。

### 以章节引用策略度量回答单元追溯覆盖（#1819）

每类 study-question 意图的章节目录携带 `evidence-required` / `model-derived` 引用策略：证据必需章节（外部定义、规范结论、适用条件、修复建议等）要求逐结论绑定服务器验证引用；推导变形、教学讲解等章节按模型推导呈现，不要求机械引用，也不得表述为来源原文。引用守卫按章节解析回答单元绑定，输出 per-section 追溯覆盖率，未覆盖的证据章节以 section-scoped 原因降级；规范性 fail-closed 回答不计入覆盖分母。无效编号（缺失、越界、未验证）在两条持久化路径（流式 finalize 与 session 消息修订）统一清除，合法编号保留。

不在模型自由文本中要求新的脚注语法；映射规则只复用已分配的 `[n]` 编号与既有结构章节标题，避免与 Citation Hydrator 的服务端验证边界冲突。
