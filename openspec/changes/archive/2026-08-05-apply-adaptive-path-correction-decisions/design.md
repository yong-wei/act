## Context

P1 在 `buildAdaptivePathJourneyCorrection()` 中从既有路径、执行元数据和偏离记录确定性派生候选，但候选只存在于读取投影中。P2 需要跨 Prisma、旅程 API 和学生端界面形成写入闭环，同时保证并发执行、候选变化或路径更新不会让旧候选覆盖最新路径。

## Goals / Non-Goals

**Goals:**

- 记录确认、拒绝与暂缓决策，并冻结候选、原路径、依据、版本与应用结果。
- 确认时保留已完成节点和已进入执行的当前节点；对受治理偏离明确标记为 skip、replacement 或 abandonment 的未完成历史节点允许排除，其余仅替换可调整的未完成未来节点。
- 通过候选指纹与路径更新时间戳校验阻止陈旧客户端写入。
- 让学生查看当前候选的决策状态和历史，而不自动应用任何候选。

**Non-Goals:**

- 不重新生成规划策略，不向候选加入未受治理资源，不修改已完成节点。
- 不提供恢复原路径，不让客户端提交候选节点序列或证据内容。
- 不把纠偏决策写入 `LearningPathIntervention`，该模型承载控灵干预而非学生路径选择。

## Decisions

### 使用专用的追加式纠偏决策记录

新增 `LearningPathCorrectionDecision`，每个写入保存路径、用户、候选指纹、路径 `updatedAt`、候选及原路径快照、依据、决策和应用结果。暂缓、拒绝、确认都新增记录，当前状态以同一候选最近记录为准；这允许暂缓后继续确认，也使拒绝不再主动提示同一候选。

备选方案是复用 `LearningPathIntervention` 或仅修改 JSON 字段；前者混淆控灵干预和学生决策，后者无法形成可审计的版本化历史，均拒绝。

### 服务端重算候选并使用双重版本校验

客户端只提交候选指纹、路径 `updatedAt`、决策类型和幂等键。服务端读取授权路径并重算 P1 候选，要求指纹一致，再在事务内用 `id + updatedAt` 条件更新写入。任一条件不成立均返回冲突和刷新动作，禁止把旧候选局部合并到新路径。

备选方案是信任客户端提交的候选节点列表；这会允许越过受治理资源和先修条件，拒绝。

### 确认以候选剩余节点替换可调整节点

确认时保留主路径中完成节点和当前已进入但未完成节点，排除受治理偏离明确放弃的未完成历史节点，并将其余可调整的未完成未来节点替换为候选序列。路径 payload、`nodeIds`、`currentNodeId` 和剩余工作估计一起更新；原快照保存在决策记录中，执行、偏离和干预记录不改写。

备选方案是创建新路径轮次；它会让学生离开正在执行的路径且超出 P2 范围，拒绝。

## Risks / Trade-offs

- [执行状态与候选在读取后变化] -> 服务端重算候选，并以 `updatedAt` 条件写入返回冲突。
- [同一请求重试] -> 以路径和幂等键去重，返回已有记录而不重复应用。
- [历史路径缺少可验证结构] -> 保留 P1 的不可用原因，拒绝写入且不伪造修复。
- [已拒绝候选继续出现] -> 旅程投影显示历史状态，不再呈现同一指纹的操作按钮；新指纹仍可提示。

## Migration Plan

1. 增加决策表和 `LearningPath` 关系，并运行 Prisma 迁移。
2. 发布服务端决策路由和旅程状态投影，再发布学生端操作界面。
3. 迁移不改写既有路径；回滚时可停用写入路由，已有决策记录保留为审计数据。

## Open Questions

- 无。P2 的决策边界、冲突语义与不提供恢复操作已由访谈确认。
