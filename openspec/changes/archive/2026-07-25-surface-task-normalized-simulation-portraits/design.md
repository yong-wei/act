## Context

前置变更 `govern-simulation-task-attainment-evidence` 将四类仿真来源规范为零画像权重的不可变任务证据：它解决来源身份、证据强度、任务目录和历史候选，却不直接改变 portrait。现有累计画像按 `LearningFact` 增量折叠，因此不能把保存、运行、评测或提交分别计入第七维；必须在该折叠器中读取任务证据的唯一最高层和当前任务目录，形成一次任务级贡献。

学生与教师现有的个人及班级画像已经以个人事实为原子、当前成员为班级聚合边界。本变更只让同一原子事实投影出透明的仿真任务达成，不能把事实写给班级或按班级历史重算。

## Goals / Non-Goals

**Goals:**

- 将第七个 portrait v2 维度计算为当前相关任务的等权满分完成比例，并保留可展示的任务组成。
- 以单学生、可幂等的既有画像物化路径处理实时任务证据、历史候选应用、目录变动与用户主动更新。
- 在学生与授权教师的既有画像读模型中显示累计任务完成数、总任务数及来源分组，不以缺失值伪造零分。
- 由当前班级成员的个人任务投影计算班级结果，不写入任何班级事实。

**Non-Goals:**

- 不创建任务目录表、任务完成表、独立学习事实、班级事实、通用撤销机制或新的计分引擎。
- 不把部分进度、低层过程、旧 `param_change`、浏览事件或重复运行转换为第七维分子。
- 不重放原始仿真轨迹，不全量重算所有学生，也不修改 Arena 评分、奥德赛规则、Rust/WASM 或其他六个画像维度。
- 不重做页面视觉层级；只在既有画像组成区域增加可展开的完成构成。

## Decisions

### 1. 任务完成比例由目录和最高任务证据直接投影

每次计算读取当前任务目录中平台已发布、学生可完成的全部任务作为所有学生共享的分母；任务相关性不从班级、课程、指派或既有证据推断。分子是这些任务中已经依据前置来源规则达到上限的任务数；每个任务权重相同，任务只计一次。第七维的分数、证据数、最后证据时间和受限说明都从这个投影产生。

同一 `artifactKey` 的多个来源结果先按来源定义的确定结果排序取最高贡献结果；同分时才以证据层级作为稳定决胜条件，处理时间和到达顺序不参与选择。该结果达到来源完成规则后才使对应任务形成唯一 dimension 贡献。低层任务证据保留在事实上下文中供审计，但不返回到学生或教师画像 UI。目录中没有任务或学生没有任何满分完成任务时返回明确无证据，而不是零分或任意默认比例。

备选方案是累加每条 LearningFact 的 profile weight。它会把同一产物的多层事件、部分进度或重试放大为能力分数，故拒绝。

### 2. 增量物化以学生为事务单位

新任务证据、已接受历史候选和“更新画像”按钮都只排入目标学生的既有画像物化请求。单个学生即使一次新增多条任务证据，也使用一套完整任务投影计算，并继续由现有事务锁与 generation fencing 保证一致性。批量 worker 可以并行处理不同学生，但不得把同一学生的多条事实拆成不一致的多个最终写入。

任务目录的发布、下线或完成谓词变动生成新的目录摘要，并排入所有已有仿真任务投影或合格任务证据的学生；它不创建或重放 LearningFact。每个更新请求的预期输入摘要至少包含事实水位、目录摘要、任务投影计算版本和适用历史候选 plan 摘要；事务内重新核验该摘要，不匹配时 fail closed 并重新排队。该输入身份必须参与 snapshot/current-pointer 的幂等选择，不能只以事实水位决定不变。班级聚合在这些个人 portrait 完成后，以当前班级成员的最新有效个人投影更新。

备选方案是把目录变动或人工更新触发全库重建。它扩大了运行成本且违背已有累计增量链路，故拒绝。

### 3. 历史候选应用复用实时路径

前置变更的 dry-run 是历史输入的准入门槛。应用阶段绑定不可变 plan 标识、候选摘要和目录摘要，只写入经过该准入的零画像权重任务证据，再为每个受影响学生排入同一物化路径；事务内输入摘要不匹配时不应用候选。不从原始 `SimulationLog`、`ArenaEvaluationRun` 或参数轨迹临时另算分数。实时先写、回填重试或重复 dry-run 依旧通过稳定产物身份保持幂等。

### 4. 读模型返回数值与受限的任务组成

个人 portrait API 在第七维可用时返回 `completedTaskCount`、`relatedTaskCount` 和按 Odyssey、Arena、控制工作台、虚拟仿真分组的二元任务摘要；只有满分完成项进入完成数，未满分项不能显示过程进度、阶段或近似得分。学生只能读取自己的摘要，教师只能在既有班级授权内读取学生与班级汇总摘要；响应不包含原始答案、轨迹、隐藏评分细节或其他学生的任务明细。

班级汇总来自当前 roster 的可用个人 projection，使用个人任务完成比例的算术平均；由于所有学生使用相同全局目录，该值等价于成员完成数之和除以成员任务数之和。响应同时返回有可用投影成员数和 roster 总数。没有可用个人投影或班级均值时保留不可用状态，不填零，不推断排名或趋势。

### 5. 用户主动更新只触发现有受限调度

学生在 `/profile/growth`、教师在当前班级学生详情页使用独立的“更新画像”动作。服务端按照现有身份和班级授权解析目标学生，再写入同一去重的单学生重算请求，并返回请求状态和目标 generation；它不接收客户端的任务、分数、事实或来源参数，也不跳过当前目录与证据治理检查。页面将“刷新数据”保持为读取动作；更新按钮在已提交或处理中显示状态并防止重复提交，仅在请求完成后重新读取最新 generation，失败时给出可重试状态。

## Risks / Trade-offs

- [目录变更影响较多学生] → 选择所有已有仿真任务投影或合格任务证据的学生，并沿用现有按学生队列与 generation fencing；不以新任务键的既有证据关联作为选择条件。
- [学生只有过程证据] → 保留治理审计，不在画像 UI 显示任务进度；第七维保持无证据，不以部分进度提高能力分数。
- [历史候选重复应用] → 先由稳定产物身份去重，再通过单学生物化保证同一任务只产生一次贡献。
- [班级成员变化] → 每次班级汇总读取当前 roster；班级不保存学习事实或班级历史所有权。
- [任务摘要泄露评分或轨迹] → 仅输出任务名称、来源分组、满分完成状态及有限计数。

## Migration Plan

1. 前置任务证据目录、实时写入和历史 dry-run 验证通过后，先对代表性学生执行候选应用和单学生 portrait 更新。
2. 验证第七维分子、全局目录分母、任务组成和班级聚合均与当前目录和个人事实一致，再以相同单学生路径处理其余已有仿真任务投影或合格任务证据的学生。
3. 发布读模型和既有页面中的任务组成展示；更新按钮仅调用同一受限请求。
4. 回退时停止新任务候选应用和重算请求，保留原始事实及先前可审计 portrait，不删除来源产物。
