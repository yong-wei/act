## Context

目标测验把完成回调放在最后一题“检查”动作中，但操作区仍渲染禁用的“下一题”。资源页的完成回调会吞掉路径写入异常，因此测验无法得知失败状态。

## Goals / Non-Goals

**Goals:**

- 将答案检查与测验完成拆分为两个明确动作。
- 让目标测验能够等待路径写入并展示成功或失败。
- 防止快速重复点击产生并发完成请求。

**Non-Goals:**

- 不批量重构所有历史测验组件。
- 不改变学习路径完成 API、证据结构或计分规则。

## Decisions

- 最后一题“检查”只记录答案；随后显示“完成检测”。
- 目标测验通过 ref 锁定进行中的提交，并用状态机呈现提交中、成功和失败。
- 资源页仅向 `lesson15-series-precheck` 传播完成写入异常；其他资源沿用既有容错行为，避免产生未处理的异步拒绝。
- 同模式核查确认多个历史测验仍采用“最后检查即完成”的旧模式；本次只修 Issue 指定资源，批量治理另行立项。

## Risks / Trade-offs

- [完成请求失败] → 保留当前答案和得分，解除提交锁并提供重试。
- [用户连续点击] → ref 在首次调用同步置位，后续调用直接返回。
