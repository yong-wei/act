## Context

当前教材检索在请求内读取所有 runtime search-document JSONL，并以 JavaScript `includes()` 和有限词元规则扫描排序。教材正文约 54 MB、候选超过一万条，既没有向量召回，也没有独立检索质量基准。生产为单个 Node 应用进程，教材内容静态且版本变化少，不需要引入独立向量数据库。

本变更建立共享检索能力和测试接口，但不接入生产 Source Pack 或 Konling。

## Goals / Non-Goals

**Goals:**

- 用项目真实问题和最小结构单元建立轻量、固定的语义基准。
- 建立内存可控的文件型中文词面与向量混合索引。
- 通过硅基流动生成离线/查询向量并执行外部重排。
- 为服务不可用、超时和模型切换提供确定性回退与可复查指标。

**Non-Goals:**

- 不引入 PostgreSQL `pgvector`、专用向量服务或 ANN 基础设施。
- 不索引学习者事实、原始答案、私有记忆或用户标识。
- 不在本变更中改变控灵工具、引用格式或生产路由。
- 不预先选择参数规模最大的嵌入模型。

## Decisions

### 语义基准由独立 GPT 子代理标注

基准问题来自真实控灵用法并覆盖概念、公式、图表、中英文术语和跨教材表达。标注代理读取结构单元，为每题记录所有能够直接、完整支撑回答的合格单元，并按既定来源优先级标记首选单元。调试集与独立验收集按类型和来源分层拆分。

### 先测模型，再固定索引合同

正文候选为 Qwen3 Embedding 0.6B/768，基线为 BGE-M3/1024，质量对照为 Qwen3 Embedding 4B/768。选择达到 Top-10 合格单元召回率 80% 且成本最低的方案。索引 manifest 固定模型标识、维度、规范化规则和内容摘要。

### 文件索引按进程共享

运行态包含紧凑词面索引、连续 Float32 向量文件、窗口元数据和正文偏移。模块级只读加载器在一个 Node 进程内共享实例，请求只分配小型候选数组。正文不常驻内存，命中后按偏移读取。

### 精确扫描优先

当前窗口规模可用连续向量矩阵精确计算相似度。只有实际并发基准证明内存或延迟不达标时，后续才引入 ANN；本变更不为假设规模增加索引服务。

### 嵌入缓存不是真源

本地缓存键由模型、维度、规范化版本和内容哈希组成，只避免重复调用未变化窗口。每次导出仍重建完整运行态索引并验证行数、维度、偏移和 manifest；缓存不部署。

### 外部调用只接收最小文本

离线调用只发送教材检索窗口，查询调用只发送规范化教材搜索文本；不发送学习者事实、原始答案、私有记忆、用户 ID 或完整页面状态。重排只接收已召回的少量教材候选。

## Risks / Trade-offs

- [外部模型延迟或故障] → 查询嵌入失败退回词面召回，重排失败退回本地融合顺序，并记录安全诊断。
- [精确扫描在并发下变慢] → 先测真实并发和 P95；只有不达标才提出 ANN 后续。
- [GPT 标注存在偏差] → 固定提示合同、保留全部合格来源与首选来源，并对已知失败案例做显式回归。
- [缓存与模型配置错配] → 缓存键包含模型、维度和规范化版本，最终索引进行独立完整性验证。

## Migration Plan

1. 从 v2 测试运行态生成语义基准候选并完成 GPT 标注。
2. 比较三个嵌入配置和重排效果，固定通过门槛的模型。
3. 生成文件索引、缓存和完整性报告。
4. 在单进程内执行延迟、并发、内存和回退测试。
5. 暴露共享只读检索接口，等待最终集成变更接入生产。
