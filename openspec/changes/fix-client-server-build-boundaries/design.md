## Context

Next.js 16 的客户端分包会沿静态导入链解析模块。当前若干客户端组件通过共享 barrel 或混合领域模块间接引入了 `node:crypto`、`node:fs` 与 `node:path`；此外，两个 App Route 直接导出了仅供内部复用的辅助函数，触发 Next 的 Route 类型检查失败。

## Goals / Non-Goals

**Goals:**

- 让作业和互动课程的浏览器入口只导入客户端安全代码。
- 保留服务端散列、签名、对象完整性和教学投影解析行为。
- 将 Route 内部辅助函数移到可复用模块，恢复生产构建门禁。

**Non-Goals:**

- 不改变作业提交、教学投影或图谱的产品行为。
- 不重构数据治理或课程内容模型。
- 不修改微辅导功能 PR 的范围。

## Decisions

### 拆分混合领域模块

将提交对象完整性、题目快照和目录选择签名迁移至服务端专用完整性模块；保留浏览器所需的 schema、常量及纯校验函数在现有领域模块中。服务端调用方显式导入完整性模块，避免浏览器从共享领域模块进入 Node 运行时。

替代方案是为浏览器构建配置 Node polyfill。该方案会掩盖边界错误、增加包体积，并不适用于 `fs` 与 `path`，因此不采用。

### 拆分图谱客户端 API

将课程范围、抽屉条目和纯绑定投影分别放入客户端安全模块；客户端页面改为直接导入这些模块。保留服务端 resolver 与 store 的现有公开出口，避免改变服务端调用和测试的语义。

替代方案是继续从根 barrel 导入并依赖 Tree Shaking。该方案无法保证 Turbopack 与 Webpack 都不解析服务端 re-export，不采用。

### 移出 Route 辅助函数

将默认班级错误响应和课程库上传 MIME 归一化函数放入 `src/lib`，Route 仅导出 Next 允许的 HTTP handler 与配置项。

## Risks / Trade-offs

- 拆分导入时可能遗漏服务端调用方；以领域单测、类型检查和两种构建验证覆盖。
- 客户端缺少服务端重算能力时必须依赖页面提供的投影数据；现有页面已提供对应 payload，客户端仅保留对初始 payload 的安全回退。

## Migration Plan

1. 建立客户端安全模块并迁移导入。
2. 更新相关单测，验证服务端完整性与客户端契约。
3. 执行 OpenSpec、类型、定向测试和两种生产构建验证。

回滚仅需恢复各调用方到原模块；没有数据库迁移或持久化格式变更。
