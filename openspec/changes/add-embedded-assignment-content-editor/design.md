## Context

平台已有面向备课文档的项目级编辑器适配层，但其主合同是全屏、多区域工作台。作业只需要在题目、参考答案和学生正文处复用内容编辑与渲染能力，不能把全屏导航、AI 审阅和 BOPPPS 结构带入作业页面，也不能在作业域另建 Markdown 编辑器。

## Goals / Non-Goals

**Goals:**

- 在共享编辑器适配层增加明确的 `assignment-embedded` 模式。
- 让教师和学生字段使用同一 Markdown、公式、图片编辑与渲染合同。
- 将编辑中、保存中、保存失败/冲突和保存后阅读状态交给宿主业务协调。
- 为内嵌图片返回稳定资产引用，供作答合同计数和证据处理。

**Non-Goals:**

- 不实现作业整页布局、评分细则、发布或学生提交 API。
- 不复制作业专用 Markdown parser、公式渲染器或图片上传栈。
- 不把全屏编辑器的结构导航、AI 建议栏或 BOPPPS 约束带入嵌入模式。

## Decisions

### 1. 以模式扩展共享适配器，不建立第二套编辑器

共享适配器暴露嵌入模式所需的受控值、保存请求、资产插入和渲染结果接口；宿主决定字段身份、权限、保存时机和状态文案。这样可以复用同一内容语义，同时避免作业模块依赖全屏工作台结构。

备选方案是在作业域组合 textarea、Markdown preview 和独立上传逻辑。该方案会产生两套解析、资产和可访问性合同，因此不采用。

### 2. 编辑状态与阅读状态分离

字段进入编辑状态后显示 Markdown 输入和即时预览；只有宿主确认当前值保存成功后才切回渲染结果。失败或版本冲突保留本地值，不以旧渲染结果覆盖。

备选方案是持续显示编辑器。该方案不符合“保存后退出编辑状态”的阅读体验，也增加长作业页面的视觉负担。

### 3. 图片插入统一返回资产引用

文件选择、拖入和粘贴最终经过同一受保护上传接口，并把返回的资产引用写入 Markdown。编辑器不自行决定附件额度；学生宿主使用统一作答合同把这些引用与独立附件共同计数。

### 4. 嵌入模式只声明内容能力

字段必填、题目身份、发布条件、附件上限和提交状态均由宿主域负责。共享适配器只验证可解析的 Markdown 和合法资产引用。

## Risks / Trade-offs

- [全屏与嵌入模式样式互相影响] → 以模式级样式边界和共享内容契约测试隔离布局。
- [粘贴图片上传完成前保存] → 宿主在存在未完成资产时保持保存未完成，并保留本地内容。
- [渲染结果与编辑值版本错位] → 渲染只消费宿主确认的已保存值和修订标识。

## Migration Plan

1. 扩展共享适配器和内容渲染合同，并增加模式级测试。
2. 提供教师与学生 host example、接口测试和接入说明，不在本 change 连接生产作业字段。
3. 由 `redesign-assignment-authoring-workspace` 接入教师题目与参考答案，由 `redesign-student-assignment-response-editor` 接入学生正文并移除各自旧控件。
4. 回滚时恢复原宿主控件，已保存 Markdown 和资产引用保持可读。

## Open Questions

- 无；附件计数和持久化由 `unify-assignment-response-contract` 定义。
