# 建立真实硬件预算、渐进加载与自适应画质 — 设计

基线：`37a988f5928d73c2af7eabad57284a771c9d3519`。共同依据与上游来源：[研究报告](../../../docs/research/2026-09-17-marine-environment.md)。所有性能/误差数值为待验证目标。

## 技术先决条件

基于 `unify-marine-scene-runtime` 的可重复快照/QA 与当前新船包。该项应早于大规模效果堆叠开始，并持续用于后续模块，不等最后才测。

## 决策

记录实际 drawing buffer、CSS 尺寸、DPR、设备/GPU、浏览器、船包身份、镜头、海况、图表和全部 pass。桌面 1920×1080 DPR1 目标 60fps，预热后 60s 测试 p95 目标约 18.2ms；移动目标 30fps 并记录实际像素数。目标尚未实测，失败必须反馈到默认参数而非改报告。

有 timer-query 扩展时异步采 GPU 段、丢弃 disjoint；无扩展只报告帧间隔/CPU，不硬性要求浏览器支持。记录 p50/p95/p99、长帧和分阶段成本；纹理/RT 字节只作为估算，不冒充显存测量。

默认质量可用能力提示，但 CPU 核心数不等于 GPU 等级。保留 governor 冷却和手动覆盖，忽略后台标签页、启动编译窗口。先降附加反射/后处理、天气粒子和 DPR，再远场/模型 LOD；基础海面、DOF 所有权、数值结果不变。保持旧模型可见直到下一 LOD 就绪，遵循当前回退链。

海面和天空先出，船按当前交付加载；环境资源按布局延迟加载。用既有工具验证 meshopt/KTX2、纹理色彩空间和缓存，不重复全量哈希/导出。避免默认 double-sided transparent、重复 composer、逐帧 PMREM 或每推进器独立满额粒子。

检查 preset 切换、route 卸载、StrictMode 和 WebGL context 恢复；释放不再使用的 RT/材料/几何，不能释放仍被缓存共享的纹理。提供效果开关，用含真实高精船模和教学图表的场景测 A/B。

## 验证

Windows 集显、Apple Silicon、Android、iOS 分别记录，不用软件渲染代替硬件。十次预设切换、三轮七路由进入退出后资源应回到合理稳态。只跑有依据的定向测试；文档提案不触发全站构建。
