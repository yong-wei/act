## Context

现有 WebGL 路线使用 GLSL ShaderMaterial 和离屏纹理 FFT，WebGPU 路线逐轮分配计算资源、读回四组缓冲、CPU 参考校验和重建网格。两侧船体、反射及泡沫消费并不同源。安装的 Three.js 提供 WebGPURenderer 的原生 WebGPU / forceWebGL WebGL2 后端及共同 TSL 节点编译。

## Goals / Non-Goals

目标：相同输入和时间下，两个 API 的同算法路线使用相同场景、网格、材质和交互，实际波场常驻 GPU；显式 QA 才读回。

非目标：迁移 destroyer 等正式路由、自动硬件选路、跨硬件性能结论、逐像素确定性、升级依赖或改变正式船舶动力学模型。

## Decisions

1. 对比页只保留一个客户端和场景。复用 ComparisonQueries、ComparisonVessel、MarineFrameProvider 和 FoamHistoryField。
2. 采用共同节点材质，移植当前 GGX/Fresnel、微法线脚印过滤、泡沫历史、浅水吸收和反射消费。底层 API 差异交由 Three.js 后端处理；不复制两份 GLSL/WGSL 光学。
3. 共享 FFT 节点数学和逐阶段调度。第一版以 GPU 离屏 pass 执行演化、位反转、蝶形和位移生成，两后端均执行真实 GPU 计算，无 CPU 中转。WebGPU 暂不额外维护第二套 compute FFT；未来优化须以同源数值验收证明收益。
4. 数据适配负责显式后端创建、目标纹理与异步读回。常规帧不整场读回或重建 CPU 网格；后续授权的船体三点接触采样可低频异步读回，资源持久复用。
5. 光学开关按真实资源和消费者报告。反射隐藏水面、保留船体；浅水只渲染底面。WebGPU 不可用时显示明确失败，不静默使用 WebGL。
6. 保留既有视觉基线，以固定时间截图、实际 GPU 读回、接触查询和光学开关验证迁移；更新仅依赖旧源码字符串的测试，不能靠测试文本掩盖功能缺失。
7. 实际 GPU 接触读回揭示旧 FFT 网格的 N−1 间隔与周期 N 样本错位，以及解析曲面与可见三角面混用。新网格使用 N 间隔和 texel 中心，主线程与 Worker 复用独立的三角面插值函数；解析 DFT 查询保留用于数值参照。Gerstner 查询消除重复水位叠加，并与同场景岸线衰减一致。两种 API 共用这些修复。

## Risks / Trade-offs

- 节点编译后不同后端纹理坐标约定不同：用已知频谱、多个时刻和 DPR=1/2 的实际读回验证。
- WebGL 入口迁移可能改变色彩或环境采样：使用同一天空资产、颜色、曝光和参数，进行旧画面与新路线对照。
- 首次编译耗时：初始化时准备资源，运行时复用；报告首帧和稳态分别测量。
- 暂用离屏 FFT 而非专用 compute 优化：先实现正确、共享、无读回的连续路线，不预先承诺 WebGPU 快于 WebGL。

## Migration Plan

仅对比页切至共享入口；正式路由继续使用现有实现。保留本次开始时的工作区快照作为迁移视觉和差异依据，不覆盖既有未提交修改。验收失败时继续修复，不能把缺失功能改标为已实现。

## 后续视觉校准（2026-09-29）

用户反馈显示器问题修复后 FFT 波浪过大、浪尖白斑不自然，授权修正 FFT 尺度和白沫表现。

- 默认 ss4 的有效波高从 6.5m 调为 2m，保留跨分辨率归一化。6.5m 是旧外观匹配目标，不能代表中等海况；2m 是本实验选择的代表值，不是风速唯一决定的实海预测。
- 删除为了突出船尺度波峰加入的 36m 频带增益；保留既有 Phillips 谱、方向扩散和网格带限。
- 两种 API 仍共用同一材质：中心差分法线消除半格偏移；GGX 直射贡献补上入射余弦；FFT 白沫由较强压缩驱动，缩小纹理尺度、降低覆盖和亮度。保留现有岸边泡沫历史。
- FFT 白沫仍是带限网格的视觉近似，没有新增破碎水体、喷溅或 FFT 白沫历史模拟。不能将压缩阈值解释为真实破碎判据。
- Gerstner 几何参数保持原值，两算法暂不宣称等有效波高；同算法跨 API 的输入、波场和光学保持同源。
- 验收：ss4 在多个时刻 Hs=2m±2%；128/256/512 归一化及独立 DFT 回归通过；两种 API 的固定时间截图、接触误差及 DPR=1/2 回归通过。

参考：[Met Office 海况分级](https://weather.metoffice.gov.uk/guides/coast-and-sea)、[Tessendorf 海洋渲染讲义](https://people.computing.clemson.edu/~jtessen/reports/papers_files/coursenotes2002.pdf)。

## 圆周航行、船行波与持久泡沫（后续授权）

1. 对照页船舶采用半径300m、航速12m/s的规定圆轨迹；这是检验轨迹，不增加 TypeScript 船舶动力学积分器。复用 tactical 相机预设并随船移动，可切为自由观察。
2. GPU 以移动椭圆高斯压力驱动线性深水重力波：每个频率箱满足 eta'' + g|k|eta = -|k|p/rho，以固定1/60秒和分段常力解析更新谱状态；共享现有二维逆FFT输出实际高度。全局弱阻尼限制周期域历史回绕，不模拟岸线反射和船体浸没边界。
3. 船行波加到同一个海面几何和法线上；不绘制凯文臂贴片。保留世界空间的波和泡沫历史，转弯不会旋转旧尾流。
4. 泡沫为GPU双缓冲持久场：压缩/陡度触发破碎，船艉湍流补充源，半拉格朗日漂移、扩散、指数衰减；新生泡沫与残留泡沫用不同寿命。按固定步更新，暂停冻结，重置/倒放重建，前跳分批重放；正常帧不整场读回。
5. 共享相同节点波面供材质和破碎检测。船体低频异步采样可见三角面三点，含船行波；避免为CPU另造一份动态谱求解器。波浪纯数值QA保留独立DFT参照。
6. 验收覆盖双API、零源/非零源、真实位移、源停止后的传播和泡沫消散、固定时间重放、暂停、重置、船体三点、圆轨迹和默认相机。声明本机硬件范围和表面破碎近似，不能称为完整三维流体。

本节取代初版对照页 CPU 泡沫历史及仅背景波的 Worker 接触查询；正式路由与独立 DFT/Worker 工具保留。三点查询只报告端到端延迟，compute/queue/transfer 子项未独立测量时为 null。泡沫沿用既有26秒半衰期，新增短寿命通道表示刚产生的白沫；固定1/60秒更新船行波，每4个固定步更新一次泡沫，避免显示帧率改变沉积量。远跳分帧补算，单帧最多120步；暂停时复用已算纹理，不重复FFT。

船行波参考：[时间变化压力源的波浪解](https://arxiv.org/abs/1511.02610)、[船波频谱与线性波模型](https://arxiv.org/abs/1604.05812)。泡沫采用压缩与坡度触发的表面近似及持续输运，不声称依据阈值即可精确预测真实浪花破碎。
