## Context

ACT 的文档批改域已经覆盖受保护附件、文档转换、证据锚点、`GradingRun`、分项评分、结构化批注、教师复核、派生文档和学生发布门禁。缺失的是一个受控的质量评测层，用同一套真实作业、教师基准和冻结配置反复运行 ACT 项目 AI，并以可复现指标判断评分、批注和文档处理是否达到进入正式流程开发的条件。

首轮材料是 30 至 50 份同一套 T1 自动控制原理作业。题目真源为 `T1S.md`，包含题号、题干、参考答案和评分标准；学生作业是含电子文本、Word 内置公式、MATLAB 曲线截图和开放式回答的 `.docx` 或 `.doc`，不包含手写答案。现有教师批改只在 Word 正文中插入无稳定格式的扣分文字，因此首轮必须人工删除批改痕迹，并把扣分及题目归属录入结构化教师基准。

原始第一阶段只建设评测工作台和必要的真实处理链路。负责人于 2026-08-26 明确授权后，本变更补充阶段 A 的受控正式闭环：仅可在本地专用验收任务中由已核验测试账号完成教师确认、发布、学生查看和四份 PDF 下载。学生上传、截止任务、补交授权、迟交调整，以及向真实学生或现有课程受众发布，仍不进入本次实现。

## Goals / Non-Goals

**Goals:**

- 用 ACT 现有 AI、认证、转换、评分、锚点和复核契约完成真实 Word 作业评测，不使用假上传、固定演示结果或平行 Provider。
- 让命令行和教师网页调用同一个评测核心，得到相同的数据校验、运行、指标和报告语义。
- 对每次实验冻结完整输入与配置，保留三次独立运行，支持逐题一致性、重复稳定性、批注质量和处理成功率评估。
- 用不可反复试探的一次性隐藏验收集约束调优，并要求调优集与隐藏集分别通过。
- 以结构化评分、批注和人工判定为权威数据，生成可核验、可再生的批注 PDF。
- 对真实学生数据执行本地隔离、自动脱敏、人工确认、随机编号和可审计删除。
- 在不扩大真实教学受众的前提下，完成现有正式教师批改页与学生结果页的最小安全投影，并用三个已核验测试账号完成一次阶段 A 闭环。

**Non-Goals:**

- 不新建独立 Next.js 应用、独立数据库、平行 assignment/submission 模型或另一套 AI 接入层。
- 不比较多个外部模型，也不绕过 ACT 的模型配置和调用约定。
- 不支持 `.wps`、扫描件或手写答案；WPS 保存的 `.docx` 和 `.doc` 属于支持范围。
- 不把第一轮 T1 结果表述为跨学科、跨教师或跨作业的客观准确率。
- 不实现新的学生端上传、截止后定时批改、教师开放补交或迟交扣分；受控阶段 A 只能使用现有正式确认、发布和学生查看能力，且不得用于真实学生或生产成绩。
- 不允许评测页面把 AI 输出直接写成正式成绩、学生反馈或学习证据。

## Decisions

### 1. GitHub Fork 负责实验隔离，ACT 单体负责能力归属

实现目标仓库是 ACT 的 GitHub Fork：`origin` 指向实验 Fork，`upstream` 指向 `yong-wei/act`。实验分支直接修改 ACT 的教师页面、文档批改服务和数据治理模块，保持普通可审查 Git 历史。当前本地 worktree 只用于准备方案，不替代 Fork，也不构成最终交付。

评测能力可以拥有自己的包格式、指标和运行编排，但不能复制认证、对象存储、文档转换、评分引擎、AI Provider、教师复核或生产业务表。发现生产管线缺陷时，应修复或扩展现有深模块，而不是在评测目录中实现一个行为不同的替代版本。

### 2. 共享评测核心是唯一执行入口

在数据治理边界新增教师 AI 批改评测模块，公开少量稳定操作：

- 校验并导入评测包；
- 创建可复现的数据划分；
- 冻结实验配置；
- 对指定数据集运行或恢复批量评测；
- 记录人工批注判定与 PDF 核验；
- 计算并导出不可变报告。

命令行脚本直接调用该服务模块，教师网页通过教师专用 Route Handler 调用同一模块。页面不得自行实现 ZIP 解析、模型调用、指标计算或隐藏集状态机。底层转换和评分继续通过现有 `math-document-grading-*`、`document-rubric-grading-workbench` 和教师复核契约完成。

### 3. 单个 ZIP 使用明确、可校验的包契约

首轮包采用下列逻辑结构：

```text
manifest.json
T1S.md
assets/**
submissions/<sample-id>.docx|doc
baseline.json
```

`manifest.json` 保存数据集标识、版本、样本随机编号、文件引用、内容校验和、分层所需的成绩区间和主要错误类型标签。`baseline.json` 保存每个样本的逐题满分、扣分记录、教师基准得分及人工确认状态。包内不得包含姓名、学号或身份映射。

为 1 至 2 份已脱敏真实样本的本地 CLI 联调，包可标记为 `pilot`。`pilot` 仍须满足完整 ZIP、量规、校验和、教师基准和脱敏确认契约，但只允许校验和导入，用于验证受控数据边界；共享核心必须拒绝其创建划分、冻结配置、运行、恢复、报告和 PDF 核验，且不得将其用于调优、隐藏验收或指标。

为恰好 2 份已确认脱敏样本的端到端连通性验证，包可标记为 `preflight`。该类型仍复用正式导入、脱敏确认、转换、Provider、`GradingRun` 和三次独立执行链，但其划分只创建 `TUNING` 成员，不创建隐藏集或隐藏验收记录。系统必须拒绝 `preflight` 的隐藏运行、揭示、报告和 PDF 核验；结果仅用于判断链路是否可运行，不得作为调优、首轮指标或验收结论。

导入器必须拒绝路径穿越、重复样本编号、未声明文件、校验和不匹配、缺失资源、非法扩展名和未确认的清理状态。网页与命令行使用同一 schema 和错误码。真实 ZIP 解压后的数据和运行产物只进入配置的本地受控数据根目录；仓库提供 schema、合成样例和 `.gitignore` 规则，不提供真实数据。

### 4. `T1S.md` 是题目与量规真源

解析器直接识别 `## <题号>` 以及其下的 `### 题干`、`### 参考答案`、`### 评分标准`。允许评分标准内部存在更深层级，例如 T1-4 的场景分组和扣分项，但每题仍需形成可计算的结构化评分项。

导入时严格验证题号唯一、必填章节存在、题目满分可确定、评分项合计与题目满分一致，以及 Markdown 相对图片可在同包 `assets/` 中读取。失败时返回具体题号、章节或资源路径，不调用 AI 补写缺失内容。解析产物保留到 Markdown 标题和源片段的追溯信息，使后续评分理由可回查。

### 5. Word 结构和固定版面 PDF 共同构成一次评分输入

服务端为每份 `.docx` 或 `.doc` 建立源校验和和不可变处理记录。旧版 `.doc` 先通过受控转换进入可提取的规范化表示；`.docx` 直接提取正文、题号结构、OMML 公式和内嵌图片。随后由同一服务端处理链生成固定版面 PDF 和锚点映射。

ACT AI 同时接收两类可追溯表示：

- Word 侧的结构化文本、公式和图片，用于题号关联、等价表达判断和量规推理；
- 同次转换生成的 PDF 页面，用于版面校验、图像趋势判断和批注定位。

两类表示通过源校验和、转换版本、页码、块或区域锚点关联。公式缺失或乱码、图片丢失、文字截断、题号无法关联，或者分页变化造成定位失真时，转换判为失败或对应题目标记教师复核，不能只因 PDF 可打开就视为成功。

### 6. 每次实验冻结输入与配置，三次运行互不覆盖

实验配置至少冻结：数据集版本与划分、题目和量规哈希、样本源哈希、提示词版本、模型与推理参数、文档提取和 PDF 转换版本、评分实现版本、指标版本及随机种子。冻结后不得原地修改；任何变化创建新配置版本。

首轮评测对每个样本使用完全相同的冻结配置运行三次。每次调用形成独立运行和结果记录，不能用重试或新结果覆盖旧 `GradingRun`、分项评分、批注或模型原始输出。单份样本失败时隔离该样本并按既定策略自动重试，其他样本继续；重试耗尽后记录失败阶段和安全错误码。

正式流程未来默认只运行一次；低置信度题才追加一次复核。两次结果冲突时保留两份依据并交教师判断，不进行模型投票。该正式策略不改变首轮固定三次的稳定性评测。

### 7. 调优集和隐藏验收集使用受控状态机

系统按教师总分区间和主要错误类型，以记录的随机种子对 30 至 50 份 T1 样本进行随机分层，目标比例约为 70% 调优集、30% 隐藏验收集。划分结果一经建立不可就地调整；重新划分必须产生新版本和新种子。

调优阶段可反复运行调优集，但隐藏集的样本明细、基准和结果在配置冻结前不可查看或执行。冻结配置后，隐藏集只允许启动一次完整验收。隐藏结果一旦揭示，无论通过与否，该隐藏集立即标记已消耗；失败后的样本转为调优数据，后续验收必须从从未用于隐藏评测的样本中建立新隐藏集。

调优集和隐藏集分别计算并判定全部硬门槛，不能合并分子或分母。

### 8. 指标按逐题实例和批注维度计算

评分指标以预期的逐题评分实例为分母，分别报告 AI 与单一教师基准的完全一致率和题目满分 10% 容差内一致率。通过门槛为完全一致率至少 80%，容差内一致率至少 95%。处理失败、缺失结果或无法评分的实例必须显式计入报告，不能通过排除异常样本提高指标。

稳定性按同一样本同一题目的三次结果分组：至少 90% 的题组三次得分完全一致，其余题组三次得分最大差值不得超过该题满分的 10%。批注稳定性按是否命中同一评分项、同一问题实质和同一证据内容判断，不要求自然语言逐字一致。

教师对每条 AI 批注分别标注定位、扣分原因和改正建议是否正确，并单独标记严重误导。通过门槛为定位正确率至少 95%、扣分原因正确率至少 90%、改正建议正确率至少 85%，严重误导批注为 0。隐藏集批注评判时不显示提示词版本、模型配置或运行序号。由于首轮教师原始批改没有完整原因与建议基准，批注质量以教师盲评记录为准，同时报告应批注扣分项的覆盖情况，但首轮不为覆盖率设置额外硬门槛。

文档转换与 AI 批改处理成功率至少为 95%。首轮不设置耗时和成本硬门槛，但报告必须包含单份与整批耗时、模型调用量、重试次数和估算成本。

### 9. 结构化结果是权威数据，PDF 是受版本约束的派生产物

每条结构化批注保存关联样本、题号、评分项、短标记、详细原因、改正建议、证据锚点和定位粒度。原始 AI 结果不可变；人工判定、位置修正和文字修正以独立版本记录，保留操作者和时间。

调优阶段可只评估结构化结果。配置冻结后，隐藏集每份作业都必须基于同次转换的固定版面生成批注 PDF：页面直接显示简短分数或错误标记，详细反馈写入可选中和展开的 PDF 原生注释，末尾追加总分与逐题得分汇总页。原作业页面内容、顺序和可读性不得改变。

所有隐藏集 PDF 都需要人工核验原版面完整性、页面标记、原生注释、定位和汇总页。相同源文件、结构化结果、生成器版本和锚点版本应产生语义等价的派生物。

### 10. 访问、脱敏和数据生命周期均采用拒绝式门禁

评测网页沿用 ACT 登录，只允许服务端配置的项目负责人教师用户 ID 访问；普通教师、管理员、学生和未登录用户均不得看到页面、接口响应、文件名或指标。命令行必须在受控本地环境中运行，并显式指定数据根目录。

导入前的学生作业必须已人工删除教师扣分文字并录入结构化基准。发送云端 AI 前，系统还要检查文件名、文档属性、正文、页眉页脚和批注中的姓名、学号等身份信息，生成脱敏副本；项目负责人逐份确认后，样本才进入可运行状态。云端只接收随机样本编号，身份映射始终位于包外的本地受控目录。

项目完成并合并回 ACT 后删除真实作业和身份映射。不可逆脱敏样本、实验配置和聚合指标只有在无法恢复学生身份时才可长期保留。日志、错误和报告不得泄露原文、身份、绝对本地路径或云端凭据。

### 11. 受控阶段 A 不等同于质量放行，正式教学仍需跨章节复测

首轮只有在调优集和隐藏集分别达到全部评分、稳定性、批注、处理成功率门槛，并完成隐藏集全部 PDF 人工核验后才算通过。任何必要条件失败都不能输出“通过”。

负责人授权的阶段 A 仅验证现有正式流程的安全投影与操作闭环：专用本地验收任务只能包含三个已核验测试账号；教师必须确认后才可发布；学生只能在发布后查看自己的当前版本和四份受保护 PDF；所有账号、任务与结果不得连接真实课程受众。阶段 A 的成功不代表模型质量通过，也不得据此启动生产成绩发布。

首轮通过后，使用自动控制原理不同章节的第二套作业复测，例如时域分析、根轨迹或频域分析。第二套样本数量在首轮后根据误差类型和标注成本确定。只有两套题组均通过，才能把学生上传、截止后定时批改、补交授权和面向真实学生的发布流程作为后续变更的候选。

正式流程必须保持这些既有不变量：AI 结果先由教师按整份作业确认；教师可修改逐题分数、批注文字和位置；AI 原始结果及完整修改历史不可覆盖；学生只看到教师确认后的最新版本；旧提交及审计历史继续保留。补交只能由教师为指定学生开放，补交成功后进入待批改队列并由教师确认启动，迟交扣分由教师手动调整。

## Risks / Trade-offs

### 12. 每题独立的受控答案文件

T1 的每个匿名样本由四份独立的 Word 文件组成，分别对应 `T1-1` 至 `T1-4`。评测包的 manifest 以 `sample.submissions[]` 声明每个 `questionId` 的逻辑路径和 SHA-256；路径固定为 `submissions/<sample-id>/<question-id>.docx|doc`。同一 sample 的题目提交、源校验和、脱敏文档和人工确认记录均以 `(sampleId, questionId)` 为键。

系统不得把多份 Word 文件拼接为单一文档。该做法会破坏公式、内嵌图片、关系部件、页序和可审计的源文件谱系。运行单个题目时只读取同一题号的已确认脱敏副本；任一题缺失、校验和不符或未确认时，必须阻断该题执行。

- [现有教师基准缺少稳定结构] -> 首轮采用人工清理和逐题录入，不用不可靠的格式或正则推断代替教师确认。
- [`.doc`、OMML、图片和 PDF 版面转换存在环境差异] -> 固定服务端转换版本，保存源哈希与转换证据，并把内容损坏纳入处理失败率。
- [隐藏集样本规模较小] -> 使用分层随机和一次性消耗规则，调优集与隐藏集分开判定，并在第二套不同章节作业上复测。
- [批注正确率可能掩盖批注过少] -> 报告应批注扣分项覆盖情况；首轮保持已冻结的正确率门槛，不额外声称已验证批注召回率。
- [网页可能扩大敏感数据暴露面] -> 采用单用户服务端门禁、受控本地数据根目录和安全投影，浏览器不接收身份映射或原始教师基准。
- [评测代码可能演化成平行业务系统] -> 评测层只拥有数据集、配置、指标和人工判定语义；转换、评分、批注、复核和 AI 调用始终复用 ACT 域。
- [阶段 A 被误作生产发布] -> 专用验收任务、三个已核验测试账号、现有课程受众隔离和教师确认前置均由服务端契约与验收记录共同约束；任何真实受众接入需另行授权。

## Migration Plan

1. 在 ACT GitHub Fork 中建立功能分支，并配置 `upstream` 指向 `yong-wei/act`；把当前 OpenSpec 变更带入该分支。
2. 先实现评测包 schema、严格导入、脱敏门禁和合成样例，确保真实数据不会进入 Git 或云端。
3. 实现共享评测核心并接入现有 Word 提取、PDF 转换、ACT AI 批改、运行快照和失败隔离能力。
4. 实现数据划分、隐藏集状态机、三次重复运行、指标、报告和命令行入口。
5. 实现仅项目负责人可访问的教师网页、人工批注判定和隐藏集 PDF 全量核验界面。
6. 使用 30 至 50 份 T1 数据完成调优与一次隐藏验收；失败时消耗隐藏集并按规则重新划分。
7. 先完成阶段 A 的受控正式闭环与 G.6/G.7/G.8 门禁；首轮通过后建立不同章节的第二套复测；两套均通过后，另立变更接入面向真实学生的正式教学流程。
8. 合并回 ACT 后按数据生命周期计划删除真实作业和身份映射，只保留允许长期保存的不可逆脱敏资产和聚合结果。

回滚时可停用评测路由和命令行入口，并保留既有生产批改记录；不得删除或改写现有 `GradingRun`、教师复核快照或生命周期审计事实。

## Open Questions

- 第二套跨章节复测的具体题组和样本量在首轮误差分析完成后确定，不阻塞第一阶段实现。
- 首轮只报告批注覆盖率而不设硬门槛；是否把批注召回率纳入正式流程发布门槛，需要根据首轮人工标注成本和漏注类型另行决定。
- 正式环境的定时批改调度、补交队列、真实学生受众接入和生产成绩发布需要独立设计，不在本变更中预先绑定实现。
