## Why

All nine LearningGoals need diagnostic, practice, checkpoint, remediation, and terminal-validation support where applicable. Current diagnostics show repeated missing baseline categories, especially checkpoint and remediation. Static questions and assessment items cannot support adaptive learning until each item is reviewed for concept, capability, quality, difficulty, cognitive level, misconception, remediation target, evidence behavior, and source lineage.

This batch completes assessment/checkpoint resource semantics and binds them to LearningGoal K/A/Q objectives so paths can include meaningful checks and remediation rather than only content resources.

## What Changes

- Process remaining assessment, quiz, exercise, homework-derived item, adaptive practice, checkpoint, remediation, and terminal-validation workqueues.
- Review each item semantically against problem statement, solution intent where available, graph nodes, LearningGoal K/A/Q objectives, Bloom/cognitive level, difficulty, misconception/remediation mapping, evidence behavior, scoring status, and source/version state.
- Build minimal stage-complete item sets for every path-ready LearningGoal: diagnostic, practice, checkpoint, remediation, and terminal validation where required by policy.
- Preserve evidence-lineage boundaries and avoid treating unsupported legacy questions as governed mastery evidence.

## Impact

- Directly improves path diversity, checkpoint behavior, adaptive practice routing, and learner-state evidence.
- Does not create large new question banks unless a required stage lacks any suitable existing item; new items must be semantically reviewed.
- Does not block Yang Fan fixture completion; fixture data can use whichever reviewed resources are available at the time.
