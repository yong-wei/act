## Context

覆盖审计已将当前 54 道合格 practice 题固定为 108 个错误选项，并加载了预留的选项归因源。现有错误答案归因在不可变题目快照中读取题目级语义，无法区别同一题内不同错误选项。详见 `proposal.md` 与覆盖审计规范。

## Goals / Non-Goals

**Goals:**

- 用内容哈希绑定的显式记录替代新归因的题目级推测。
- 以同一目录同时服务覆盖审计和运行时，使两处的唯一性、当前性与 fail-closed 判定一致。
- 为每个记录保留足以复核的受治理证据摘要和限制说明，不泄露题目或答案。

**Non-Goals:**

- 不补充资源和验证题配置，不调整其选择策略。
- 不重写已持久化的历史归因或微辅导结果。
- 不为目录覆盖范围外的题目生成推测性归因。

## Decisions

### 1. 采用单一受版本控制的选项归因目录

归因目录以 `catalogItemId`、`contentHash` 与错误选项键作为复合身份，保存一个学习目标、规范节点、受控错因、版本、证据摘要和限制说明。运行时和审计均经同一加载器读取，避免两个表或两套解析规则漂移。

替代方案是在题目 `semanticRefs` 上补充默认节点。该方案不能表达同一题中两个错误选项的不同错因，也会重新引入题目级猜测，故不采用。

### 2. 按精确键建立不可歧义索引，并在加载时拒绝不安全记录

加载器先验证字段格式、受控目标/节点、目录项资格与内容哈希，再构建索引。缺失、重复、正确选项、未审核或内容漂移的记录都不会产生可用归因；调用方得到受控不确定状态而非部分匹配结果。

替代方案是按题目 ID 或学习目标回退。该方案会让内容更新或新增选项无声继承旧归因，违反内容绑定与 fail-closed 要求，故不采用。

### 3. 新归因以答案选项和不可变快照共同验证目录

创建新的错误答案归因时，从已验证的答案快照取得目录项、内容哈希和实际选择的选项，再查询精确目录记录。命中后使用目录事实；未命中则保留既有受控不确定路径。已持久化记录继续按其既有版本读取，不被目录回填或改写。

替代方案是修改历史记录或在读取时重新解释历史答案。该方案破坏归因不可变性，故不采用。

### 4. 108 条数据以审核证据为原子提交

每条记录依据该题的题干、选项、正确性、人工语义审核、学习目标和知识节点目录写入。证据摘要描述错误概念与判定依据，限制说明明确该记录只适用于相同内容哈希。生成校验测试确认 54 题、108 错误选项、无重复且不含正确选项。

替代方案是用关键词或批量脚本生成标签。该方案不能提供每个选项的审核事实，不满足本 Issue 的交付约束，故不采用。

## Risks / Trade-offs

- [维护成本] 题目变更会使相关归因失效 → 内容哈希校验显式暴露缺口，必须随题目审核一并更新。
- [运行时兼容性] 旧快照可能不含选项键 → 仅对新归因使用目录；缺少精确证据时维持不确定状态。
- [数据质量] 108 条人工记录可能出现遗漏或重复 → 加载器和覆盖审计双重校验，并由测试固定全量计数。

## Migration Plan

1. 提交归因目录与加载校验，并在覆盖审计中验证全量记录。
2. 将新错误答案归因切换为精确目录解析，保留不确定回退。
3. 运行严格覆盖审计、相关单元测试和类型检查后发布。
4. 如需回退，撤销运行时目录解析；现有归因和资源配置无需数据迁移。
