## Context

ACT 目前把 `destroyer` 视为单个逻辑 GLB：共享 browser-delivery registry 给出 optimized/original 候选，活动场景通过 `FallbackGltfModel` 和 `useGLTF` 加载一个 URL。质量档位控制阴影、水面和特效，但没有模型 LOD 角色；武器 payload、发射演示和碰撞体也没有版本化包级身份。

3DModels 已输出 `type055-nanchang-101` v2.0.0：主舰 LOD0/1/2、collision、weapon payload、weapon demo 共六个 GLB，另有 manifest、模型侧验证和校验和。主舰三档均保留 127 个动画，demo 含 8 个组合片段；模型经 glTF 转换后为 Y-up、舰艏沿 +X。该包只负责模型输出，ACT 接线中的资产缺陷必须返回 3DModels 发布新版本。

## Goals / Non-Goals

**Goals:**

- 在 ACT 内建立可审计的版本化模型包描述符和字节接收门禁。
- 让 `destroyer` 活动场景按质量档位选择 LOD，并保留原有加载进度和回退行为。
- 明确处理 +X 舰艏、Y-up、左右舷、吃水线与尾迹锚点，不依赖旧模型朝向假设。
- 保留活动节点、动画名称和自定义接口属性，并按需加载 payload/demo。
- 证明接入不改变固定步长仿真、控制器、遥测或 Arena 评分。

**Non-Goals:**

- 不修改上游 Blender、GLB 网格、贴图、动画或 manifest。
- 不发布到 ESA/Delivery Bucket，不切换生产默认模型，不退役现有 `destroyer.glb`。
- 不在首屏加载武器 payload 或 demo，不把模型演示时间线解释为仿真物理事实。
- 不修改受保护的旧式 `src/resources/simulations/destroyer-simulation.tsx`；接入活动的模块化场景路径。

## Decisions

### 1. 以发布包为最小身份单元

新增一个只读模型包描述符，至少保存 `ship_id`、`model_version`、发布 manifest SHA-256、六个角色文件的路径/哈希/大小、坐标约定、LOD 映射和接口清单。导入脚本在复制前后核验全部哈希；任一文件漂移都拒绝整个包，不能只登记通过的子集。

替代方案是继续把 LOD0 覆盖成 `destroyer.glb`。该方案会丢失版本、角色和回退证据，也会让 payload/demo 与主舰生命周期混在一起，因此否决。

### 2. 候选路径与现有生产路径分离

源包进入版本化目录，例如 `public/assets/model-releases/type055-nanchang-101/v2.0.0/`。现有 browser-delivery registry 和内容寻址生产对象保持不变；`destroyer` 场景通过显式候选开关或等价受控配置选择新包，失败时退回当前 registry 候选。

生产激活需要后续独立变更重新完成 Delivery manifest、发布和浏览器流量门禁。本变更不扩大当前七模型生产 cohort。

### 3. 质量档位映射模型 LOD

共享场景质量状态提供稳定映射：高档使用 LOD0，中档使用 LOD1，低档使用 LOD2。自动降档只替换主舰 GLB，不重置仿真状态、相机状态或船舶世界变换。切换完成前保留当前模型；加载失败则回退到上一可用 LOD或旧模型。

### 4. payload 与 demo 按生命周期分开加载

普通航向仿真只加载 ship GLB。碰撞体由需要碰撞查询的场景按需加载；weapon payload 和 weapon demo 只在明确进入武器演示功能时加载。demo 的 8 个组合片段按名称调用，payload 中的弹药模板由运行时生成/销毁，不成为主舰常驻节点。

### 5. 通过语义名称与模型元数据接线

接线查找稳定节点名、动画名和 extras，不读取 Blender 自动序号或 glTF 数组索引。实现必须验证 127 个主舰动画、8 个 demo 动画、112 个 VLS 与 24 个 HQ-10 装填实例的约定，并为运行时真正消费的节点建立有界映射。

模型坐标适配显式登记为 `forward=+X`、`up=+Y`；旧场景中按 +Z 编写的尾迹锚点和朝向假设必须在一个适配层转换，不能散落补偿旋转。

### 6. 上游模型缺陷只通过新版本修订

ACT 不对接收的 GLB 做网格、动画或贴图补丁。若回导、浏览器、动画或性能验证发现资产缺陷，接入保持旧模型或上一个合格版本，并记录失败的发布版本、文件哈希和复现证据，由 3DModels 发布新版本后重新走完整接收门禁。

## Risks / Trade-offs

- [六文件包增加仓库与网络体积] → 首屏仅加载一个主舰 LOD，payload/demo/collision 延迟加载；实现记录每种质量档位的实际请求字节。
- [LOD 切换造成视觉闪烁或状态重置] → 保留当前对象直到下一 LOD 完成，复用同一世界变换和场景状态，失败时不卸载当前模型。
- [新模型 +X 舰艏与旧场景 +Z 假设冲突] → 通过唯一坐标适配器和固定航向/左右舷/尾迹测试锁定，不允许组件内追加补偿旋转。
- [动画名称存在但绑定错误] → 浏览器测试实际播放代表性主舰和 demo 动画，并检查可见节点变换，而不只枚举名称。
- [候选接入被误当生产切换] → 默认配置继续解析旧 registry；提案、代码和验收证据均明确生产激活不在范围内。

## Migration Plan

1. 导入并核验 v2.0.0 发布包，生成 ACT 侧只读描述符与接收收据。
2. 扩展共享模型加载边界和 `destroyer` 场景接线，保持旧模型为默认回退。
3. 加入 LOD、坐标、贴图、动画、延迟加载和驱动链回归测试。
4. 以候选配置完成浏览器验收；失败时关闭候选并继续使用旧模型。
5. 生产发布与默认切换由后续独立授权变更处理。

## Open Questions

- 候选开关最终采用构建期配置、开发者参数还是治理 manifest，由实现代理结合现有配置边界确定；无论形式如何，默认必须保持旧模型。
- 具体哪些教学任务允许加载 weapon demo 需要后续产品范围确认；本变更只建立按需接口，不默认暴露发射控制。
