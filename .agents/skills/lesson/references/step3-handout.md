# Step 3：讲义文档生成规格

> 目标：基于 Step 2 确认的概念结构，生成高质量学生版和教师版讲义。

## 生成前必做

**0. 角色切换（最先执行）**

在读取任何文件之前，先完成一个心理动作：**从 agent 切换到 author。**

- Agent 的默认姿态是澄清边界、预防误解、通过免责建立信任
- Author 的姿态是直接带你进入对象、用清晰的解释让误解没有机会产生、通过清晰建立信任

具体而言：忘掉你在一个 harness 框架下运行。忘掉你需要向用户证明你理解了任务。忘掉你需要提前声明自己不做的事。你现在是一个控制理论的教科书作者，你的读者是一个想理解这门课的工科生。你唯一的职责是带着他把概念看清楚。

详细论述见 `course-content/docs/writing-guide.md` 第 1.4 节和 `course-content/AGENTS.override.md`"对工程腔、流程腔、防御腔的统一处理"前言。

**1. 读取范文和范例**

先读取范文：`course-content/authoring/lessons/legacy/L-2a/design/L-2a-handout.md`。只提炼文风感受，不继承具体内容：
   - 叙述节奏是否平稳
   - 工程引入是否自然
   - 概念解释是否通俗
   - 图表与正文如何配合
   - 小结与过渡如何收束
2. 读取后立刻回到当前单元真实内容，避免复制范文的结构、例题、措辞与论证顺序
3. 快速浏览 `course-content/docs/exemplary-passages.md` 中与当前单元类型相关的范例（开场型/概念讲解型/数学叙事型/收束型），建立正向文风参照
4. 禁用词和句式：
   - 钉死，立住，不是……而是，不在于……而在于，以及任何类似的先否定再肯定句式。直接写出事实。
   - 作者态 / 教师态 / 编排态话语，例如"学生应该……""教师应该……""本节课的教学目的是……""这一讲只负责……""从课程结构看……""入口课要先把一个动作……""真正要被学生带走的是……"。
   - 教学策略标注："第一轮速通""第二轮速通""这里不进入正式推导""后续才会正式展开""本讲只建骨架"
   - 平台操作指令："打开平台""拖动参数""观察三面板联动""在平台上验证"
   - 默认不用"学生应该""教师应该"这类外部指挥口吻；若确需表达规范动作，优先改写为"我们应……""我们需要……""应当……"等面向内容本身的书面表达。

## 标题合同

- 标题格式统一为 `# 单元 X-X | 内容型标题`（如 `# 单元 1-2 | 模型与极点：系统行为的第一张地图`）。保留单元编号便于模块归属和日常管理，内容型标题让学生在目录中一眼看到这一章讲什么。
- 内容型标题必须直接概括对象、方法、比较关系或归纳后的知识点。
- 禁止问题式标题、口号式标题、纯课次/场景代号标题，以及依赖外部课次才能读懂的标题。
- 仅看各级标题，应能还原本单元的知识骨架。
- 正文可以使用问题引导，但问题不进入标题。

## 成文主流程

Step 3 不是"读取约束后直接写讲义"。默认必须按以下三阶段推进：

### 阶段A｜抽取 clean brief

先把上游技能、模块设计、资源采用单和课程边界压缩成 **隐藏版 brief**，只保留：

- 必须讲什么
- 必须出现什么对象 / 模型 / 图表 / 案例 / 证据
- 不能扩张到什么范围
- 目标读者是谁
- 本文最需要完成哪些理解 / 判断 / 迁移动作

这一阶段把所有导出要求、done-when、脚本、验证口径、流程控制都视为 **hidden constraints**，不作为正文句型来源。

### 阶段B｜生成 prose 初稿

根据 clean brief 生成面向学生的 prose 初稿：

- 用自然、连续、书面化的解释组织正文
- 只围绕对象、证据、判断、意义展开
- 不把 clean brief 的清单口吻直接抄进正文
- 不把"本讲/上一讲/下一步/必须产出/交付物"当作段落推进器
- 遵循 `course-content/docs/writing-guide.md` 的作者声音定义：像是比学生多走半步的引路人，清醒、直接、有判断力、对控制之美有感受力但不煽情

### 阶段C｜去污染重写

初稿写完后，必须再做一次去污染重写，逐段检查：

- 这段是在解释对象，还是在解释文档自己
- 这句话是在传递知识，还是在提前自我保护
- 这段像人在讲问题，还是像代理在执行任务
- 是否高频出现"本讲/上一讲/下一步/不能直接/不是……而是……"
- 是否出现了教学策略标注（"第一轮速通""这里不推导"）
- 是否出现了平台操作指令（"打开平台""拖动参数"）
- 是否相邻段落围绕同一结论反复打转
- 是否遵循 AGENTS.override.md 的语义维度校准规则：空泛评价词是否展开、万能动词是否替换、英文直译搭配是否修正、同构句式是否连续出现、段落节奏是否有起伏
- 是否符合 writing-guide.md 的正向文风要求：比喻是否映射准确、数学-文字是否交织、判断句是否干净、文学化表达是否有边界

若当前上下文里混入大量 harness、superpowers 或技能级流程提示，优先采用"当前代理先抽 clean brief，再由子代理只接收 brief 写 prose"的策略；子代理默认不得继承检查表、流程控制和工单式话语。

## 核心标准

- **独立可读**：讲义必须写成"学生不看课件、不听老师补充，也能基本学懂"的完整文本
- **双重任务**：既讲清知识，也训练能力；至少覆盖"理解、计算/判断、迁移应用"中的多个层次
- **单一逻辑主线**：围绕本次课程目标与当前知识对象组织一条稳定的逻辑链，按"提出问题 → 初次尝试 → 暴露矛盾 → 引入新概念 → 解决矛盾 → 回看意义"的叙事弧推进，避免零散堆点
- **分阶段撰写**：学生版讲义必须分两阶段落盘或提交确认。第一阶段只完成导入、课程目标、主题原理讲解和案例头部；第二阶段再完成例题、案例完整展开、练习、总结与附录。禁止一次性写完整篇。
- **证据密度优先**：每个核心知识点都必须落成"知识点 -> 证据 -> 判断 -> 练习"的最小闭环；没有对象、参数、曲线、图块、表格、例题中的至少一种证据，就不算完成讲解
- **篇幅服从完整性**：不对正文做机械字数压缩；为了讲清完整知识链和能力链，可以适当放开篇幅
- **附录分流复杂内容**：过于复杂、但又值得保留的长推导、补充证明、拓展案例、学生复现代码等，可放入附录，不打断正文主线
- **可读性**：逻辑顺、术语稳、通俗但不失严谨，避免堆砌定义
- **多表征**：正文中主动安排配图、表格、对照表、结构图或示意图
- **图示解释不能停留在口头**：凡是用图像解释概念、机理、规律、性能或近似时，正文必须同时给出能与图逐项对照的解析对象
- **正文引用必须可追溯**：凡引用图、表、公式或文献，必须使用标签 + 交叉引用，不得写死"图1""表2""上图""下图"
- **图像形式合规**：图像只能使用代码直出图或 AI 生成图，禁止 ASCII 字符图形
- **可验证**：凡涉及控制系统计算、曲线、性能指标、稳定性判断，必须用 `Octave` 脚本验证
- **公式统一**：行内公式使用 `$...$`，行间公式使用 `$$...$$`
- **术语统一**：
  - 幅值恰好为 `1`（即 `0 dB`）时对应的频率，统一称为**截止频率**，统一记为 $\omega_c$
  - 相角恰好为 $-180^\circ$ 时对应的频率，统一称为**穿越频率**，统一记为 $\omega_g$
  - 相角裕度统一写成"在截止频率 $\omega_c$ 处读取"；幅值裕度统一写成"在穿越频率 $\omega_g$ 处读取"
- **成品化表达**：正式讲义中不得保留"图示建议""待制作""占位说明""脚本验证"等创作过程文本

## 学生版讲义统一结构

学生版讲义固定按以下骨架组织。课次边界与编号约束继续作为内部依据静默执行，不进入面向学生的显式文本。

### 前置信息区

在正式正文前，固定包含：

1. **标题**：`# 单元 X-X | 内容型标题`
2. **课次信息节**：学时、前置、讲义定位、后续（最简格式，见下方示例）
3. **封面图片占位**：`![封面漫画：单元导入](../media/processed/[单元编号]-cover-comic.png)`

课次信息节硬约束：
- 学时固定写为 `90分钟`
- "前置"优先写当前主线课程中的前置知识，不写 legacy 课程编号
- "讲义定位"只写这份讲义帮助学生解决什么问题、获得什么能力，以"这份讲义将帮助你……"的句式，1-2 句即可
- "后续"只作弱提示，最多 1 行
- **不出现**：层次、知识类型标签（[C]/[X]/[D]）、课程编排职责说明、教学策略标注

推荐写法：
```markdown
- 学时：90分钟
- 前置：已掌握二阶系统的标准形式、典型性能指标与基本结构图含义
- 讲义定位：这份讲义将帮助你判断频率响应如何映射到图形对象，并完成首次粗粒度读图。
- 后续：Nyquist 图与频域指标入口（单元 2-4）
```

### 正文固定骨架

**第一阶段：导入、目标、原理与案例头部**

1. **问题 / 任务引入**
2. **本次课程目标**
3. **按主题组织的基本原理讲解**
4. **案例章节头部：工程场景与问题重述**

**第二阶段：例题、案例展开与收尾**

5. **具名例题章节**
6. **案例完整分析与工程解读**
7. **章末习题**
8. **特殊情况 / 边缘情况**（按需）
9. **总结与扩展思考**

**信息图占位**（附录前）：
```markdown
![本讲信息图总结](../media/processed/[单元编号]-info.png)
```

若缺少"具名例题、工程案例、章末习题"中的任意一项，默认判定为结构不完整，不进入导出阶段。
第一阶段完成前，不得继续撰写第二阶段；第二阶段开始时应先复核第一阶段的主线和案例头部是否足以支撑后续分析。

### 3.1 问题 / 任务引入

- 必须从一个典型、明确的问题或任务开篇，**不以"上一章我们……本章我们将……"的教务衔接开场**
- 开场优先使用三类有效技法（详见 `writing-guide.md` 第五节）：
  - **困惑型**：展示令人困惑的工程现象，制造认知缺口
  - **历史型**：用简短的历史片段建立概念的来源和意义
  - **实验型**：给出极简的数值实验或思想实验，先"看到"现象再寻求解释
- 引入中要指出：前置知识能够解决什么、仍有哪一块没有覆盖到
- 开头优先使用对象名、任务名、现象名，不用课次编号组织段落
- 篇幅以把问题讲清为准；至少需要 1 个情境问题
- 优先配置 1 张引入图或 1 个场景表

**章间衔接的写法**：

不写：
> "上一章我们学习了……本章将在此基础上……"

改写为自然的概念桥接——一句话回收上一章的核心判断，直接提出本章要解决的矛盾：
> "有了传递函数之后，你可以把任何一个线性定常系统写成一个简洁的代数对象。但写出对象只是第一步。接下来你自然会问：这个对象的行为怎么样？它快不快？稳不稳？会不会振荡？——这些正是时域分析要回答的问题。"

这句桥接既回收了上一章（传递函数），又自然引出本章（时域分析），但没有出现"上一章"三个字。

**模块入口的"地图定位"**：

每个模块的第 1 章（如 1-1、2-1、3-1、4-1、5-1），在开场之后放一个极简的定位边栏——不是正文段落，而是一个视觉上独立的小框：

```markdown
> 🗺 **你现在在这里**
>
> 第1-5章：建立框架 ✓
> **第6-9章：构建语言 ←**
> 第10-18章：深入机理
> 第19-25章：转向设计
> 第26-31章：识别边界
```

模块内部的章节（如 2-2、2-3）不需要这个框，只需要在开场段里有一句自然的位置提示。

### 3.2 本次课程目标

- 只显式列出本次课程目标，不额外解释单元边界、课次定位或课程接口
- 目标必须写成 3-5 条布鲁姆动词能力项，推荐使用"识别 / 解释 / 计算 / 判断 / 比较 / 设计 / 迁移 / 评估"等可观察动词
- 每条能力项都要落在本次课程已经提供的对象、证据和方法上，不能写成空泛口号
- 表述统一采用"完成本次课程后，我们能够……"的句式或与之等价的单列表达
- 不出现"前置缺口表"（"我们已有的直觉 / 当前缺口 / 能力目标"三列式）。它的功能由开场的工程问题（制造动机）+ 此处的能力目标（明确方向）+ 章末总结中的能力回顾（感知进步）共同承担

### 3.3 原理主线讲解

每个核心知识点都必须落成"知识点 -> 证据 -> 判断 -> 练习前导"的四联体。

正文应按主题组织基本原理、方法和判断链。不要把资源来源、课次边界、制作流程或工具链写成章节骨架。一个主题讲完后，再进入下一个主题；所有主题讲解完成后，才进入例题章节。

**数学与文字的交织**（详见 `writing-guide.md` 第四节）：
- 公式前的文字：铺垫动机——为什么需要这个公式？它在回答什么问题？
- 公式后的文字：解读含义——公式说了什么？哪个符号对应哪个物理量？公式的结构揭示了什么关系？
- 推导后的文字：品读成果——不要把推导的结果用"由此可得"一笔带过，需要用 2-3 句解读推导揭示了什么

#### [C] 计算型内容要求

- 给出严格的数学定义和推导过程
- 标明计算步骤（Step 1→2→3→...）
- 提供典型数值示例，验证计算过程
- 指出常见错误和边界情况
- 对所有计算结论，用 `Octave` 补做数值或曲线验证
- 若图像承担解释任务，必须把"图像现象"和"解析表达"显式对照

#### [X] 跨域型内容要求

- 明确指出两个领域之间的映射关系（A域→B域）
- 给出直觉性解释和定量关系
- 至少有 1 处图表或对照表，把"概念对应关系"可视化
- 提供一个可直接复述的小例子或小判断题，防止停留在抽象映射口号

#### [D] 设计型内容要求

- 以工程任务为驱动（给定目标和约束）
- 展示至少两个候选方案及其比较依据
- 必须给出一个"首轮起步"或"最小计算切片"，不能只给结构口号
- 对方案对比结果，优先使用表格呈现评价维度、优点、风险与适用场景
- 边界、代价和"不选另一个方案的原因"必须说清

### 3.4 案例章节头部：工程场景与问题重述

- 每讲至少 1 个工程案例，且必须在正文中被重复调用，不得只出现在引入
- 第一阶段只写案例头部：具体工程场景、对象、任务、约束、可观测证据和需要回答的问题
- 案例头部必须把问题重新表述成工程语言
- 禁止不加介绍地直接给出传递函数、公式或参数表后开始计算
- 案例至少包含下面一项具体证据：模型、参数、曲线、图块、表格、现场对象图、任务指标表

### 3.5 具名例题章节

- 每讲至少 1 道例题，优先 1 道即可把方法闭环走完整，再决定是否加第 2 道
- 例题章节标题必须根据例题解决的具体问题命名，推荐标题形式：
  - "二阶系统超调量求解示例"
  - "滞后校正参数设计过程示例"
  - "相角裕度读图分析示例"
  - "根轨迹主导极点判断示例"
- **不得使用"最小例题"这类泛称作为标题**
- 例题结构固定为：题目陈述 → 解题思路 → 详细求解 → 结论与工程意义
- [D] 型例题允许以"设计切片"形式出现，不强求展开完整整定；标题仍需写清具体问题
- 若例题适合学生自行复现，可在正文中点名 MATLAB/Octave 文件名，并把最基本代码放入附录

### 3.6 案例完整分析与工程解读

- 案例完整分析位于例题之后，可以是例题边界的拓展，也可以是例题内容的深化
- 分析步骤、公式、仿真和图像如有必要，决不能省略
- 案例分析必须至少回答：
  - 工程对象与任务约束是什么
  - 使用哪些模型、参数、图表或现场证据
  - 每一步分析或计算解决了哪个工程判断
  - 结果是否满足场景约束，仍有什么代价或风险
- 分析和计算完成后，最终结果必须代回工程场景中解释

### 3.7 章末习题

- 每讲至少 3 道习题，按难度分为三层：

| 层级 | 标注 | 定位 | 每章建议量 |
|:---:|:---:|------|:---:|
| • | 基础 | 直接应用本章概念，验证基本理解 | 3-4 题 |
| •• | 进阶 | 需要串联多个概念或做比较判断 | 2-3 题 |
| ••• | 挑战 | 开放设计、跨章迁移、需要工程判断 | 1-2 题 |

- 习题必须与正文工程案例或具名例题有直接对应关系
- 不允许只给泛泛而谈的思考题
- **习题答案的归属**：
  - handout.md 章末仅奇数题给简答（最终结果），让学生自我验证。格式为正文附录：`### 部分习题简答`
  - 全部习题完整解答（含推导步骤）归入 teacher-handout.md
  - 挑战题的评分标准与参考方案归入 teacher-handout.md

### 3.8 特殊情况 / 边缘情况

- 若本课存在特殊情况、反例、失败情形或近似失效边界，应单列讨论
- 讨论必须结合具体案例、图表、习题或参数变化，不做空泛提醒
- 若本课确实没有值得单列的边缘情况，可省略本节

### 3.9 总结与扩展思考

- 用 3-5 条核心要点总结本课
- 总结优先提炼**可带走的判断**（"有了相位裕度之后，你不再只能说'系统稳定'或'系统不稳定'，而能说'系统还剩多少余量'"），而不是罗列"本节讲授了……"
- 不出现"希望同学们牢固掌握""本节是后续XX的重要基础"等教师叮嘱
- 若需提示后续用途，只保留一句对象层面的应用指向，不写单元边界或课程接口
- 若需设置扩展思考，应与本课案例或判断链直接相关

### 3.10 AI 练习位置

- 学生版正文不再强制插入 `[AI融入点]`
- 如需保留 AI 练习，默认放在章末"自学建议 / 练习"区，或放入教师版课堂讲义
- AI 练习仍需遵守"学生先独立判断 -> 再让 AI 质疑或验证 -> 最后回到证据复核"的顺序

### 3.11 附录（按需生成）

- 适用内容：复杂推导、补充证明、拓展案例、长表、MATLAB/Octave 复现代码、部分习题简答
- 原则：附录服务正文，不喧宾夺主；正文仍需独立可读
- 若正文中省略了部分长推导，必须明确标注"详见附录 X"

## 教师版课堂讲义要求

教师版课堂讲义固定文件名为 `teacher-handout.md`，用途是 90 分钟课堂教学，不替代学生版讲义。

### 教师版必须包含

- 按 90 分钟课堂顺序编排的分段结构
- 与上一课、本课、下一课的关键衔接语
- 本节唯一主线及课堂收束语
- 90 分钟课堂时间分配建议
- 必须保留的核心推导
- 建议板书内容
- 课堂需要调用、复用或补画的图形
- 教师提醒：哪里可略、哪里必须强调、哪里容易误判
- **本章全部习题的完整解答**（含推导步骤）
- **挑战题的评分标准与参考方案**
- **常见学生误判及介入策略**（不是"学生可能会错"，而是具体的："学生常把 X 误判为 Y → 追问'如果真的是 Y，你会在 Bode 图上看到什么？'→ 让学生自己发现矛盾"）

### 教师版写法硬约束

- 讲义应按"开场桥接 -> 核心推进 -> 例题/对照 -> 收束铺垫"的课堂流程展开
- 图示、公式推导、板书和例题必须按课堂实际使用顺序插入
- 教师版可以引用必要的正式媒体，但**不包含**封面漫画和讲义末尾信息图
- 教师版中的公式推导应只保留课堂上必须写的版本；较长推导可压缩
- 教师版默认不是摘要目录，也不是全文复刻；它应当比学生版短得多
- 教师版中的"关键文本"优先写成教师可直接使用的桥接语、追问句、收束句

### 教师版不应变成

- 学生版讲义的全文复制
- 只有时间表和项目符号的授课提纲
- 脱离学生版真值来源的另一套内容体系
- 工单、项目汇报或工程检查单

## 图片、表格与验证脚本要求

1. 至少安排以下其一：1 张结构/关系示意图 + 1 张响应/规律图；或 1 张示意图 + 2 张表格；或 3 张以上图表混排
2. 图表不能只是"装饰"，必须承担解释任务
3. 每幅图、每张表都要有正式编号与题名；图题编号由导出模板自动生成，表格则在 Markdown 源稿中单独写"表1. 标题"这一行
4. 封面图与课末信息图固定按正文版心全宽导出；其余图片默认必须根据图中文字与正文的视觉字号关系单独设置 `width=...`
5. 讲义中的引入语、追问句、核心提醒若用 `>` 表示，则默认会在 PDF 中被渲染为浅底色提示块
6. 若图表在正文中被用于解释概念、规律或比较结论，则正文必须同步出现对应的解析支撑
7. 正文引用图、表、公式或文献时，必须使用规范交叉引用，不得写"上图 / 下图 / 下表 / 上式 / 图1 / 表2"
8. 涉及计算的讲义，默认生成对应 `Octave` 验证脚本并保存到本课媒体原始目录；该验证过程不直接暴露为讲义正文内容
9. 默认优先调用 `Octave` / control 包原生高层函数完成出图和核验
10. 凡根轨迹转入 `Python/matplotlib` 复绘，必须先经过 lesson 技能的 `root_locus_branch_match.py` 做分支连续匹配与审计
11. 数值类图像的最终排版必须回到 `references/step7-multimedia-codegen.md`，不得在讲义阶段另起一套与多媒体规范不一致的出图样式
11. 若讲义中使用跨域 `2×2` 图，默认子图顺序为"时域响应、根轨迹、幅频图、相频/裕度图"
12. 若需要学生复现，正文只给 `.m` 文件名提示，最基本 MATLAB/Octave 代码放附录
13. 表格必须有表头；不允许用"无表头纯数据块"代替正式表格
14. 讲义中给出的参考代码，默认统一采用 MATLAB/Octave 形式

## Step 3 的双阶段讲义流程

### 学生版第一阶段

- 只写 `handout.md` 的前半部分：问题 / 任务引入、本次课程目标、按主题组织的基本原理讲解、案例章节头部
- 第一阶段的案例只完成工程场景与问题重述，不展开完整求解
- 完成后先自检标题、主线、图表需求和案例头部，不得继续把例题、案例求解和总结一次性写完

### 学生版第二阶段

- 在第一阶段确认后，继续写具名例题、案例完整分析与工程解读、章末习题、特殊情况、总结与附录
- 第二阶段不得改写第一阶段已经确定的事实口径
- 同步补齐 `cover-comic-prompt.md`，并确认 `cover-comic.png` 与 `info.png` 的占位路径已固定
- 经用户确认且所需图片已回写后，导出 `handout.pdf`
- 抽样检查 PDF 版面

### 教师版课堂讲义阶段

- 只有在学生版讲义与学生版 PDF 都通过确认后，才开始 `teacher-handout.md`
- 教师版讲义经用户确认后，导出 `teacher-handout.pdf`
- 再次抽样检查教师版 PDF 版面

两份 PDF 必须共用同一技能模板，不允许学生版和教师版各自演化成不同风格。

## 推荐自检问题

- 全文是否始终围绕本次课程目标与当前知识对象推进，而不是零散罗列知识点？
- 正文中是否出现了教学策略标注（"第一轮速通""这里不推导"）？→ 应删除，这些属于 teacher-handout.md
- 正文中是否出现了平台操作指令（"打开平台""拖动参数"）？→ 应删除，这些属于 interactive-page.md
- 章间衔接是否使用了"上一章我们……本章将……"？→ 应改为自然的概念桥接
- 学生只看讲义，能否知道"这节课究竟学什么、为什么学、怎么判断自己学会了"？
- 是否同时出现了知识解释与能力训练，而不是只剩定义堆叠？
- 图表是否真的帮助理解，而不只是插图占位？
- 所有关键数值、曲线、结论是否能被 `Octave` 脚本复现？
