# Step 6：互动页面设计规格

> 目标：将讲义内容映射为结构化的数字学习页面，为前端开发提供内容蓝图。

## 平台技术背景（cruise-classroom，无需重新探索代码库）

| 要素 | 说明 |
|------|------|
| 技术栈 | Next.js 14 App Router + TypeScript + Tailwind CSS + shadcn/ui |
| 仿真 | iframe嵌入 `/simulations/cruise`，通过 postMessage 桥接数据 |
| 数学公式 | KaTeX |
| 图表 | Recharts；3D场景：React Three Fiber |
| 主色调 | `slate-950` 背景 + `cyan-300/400` 主色 + `border-white/10~20` 边框 |

### 三页架构

- **入口页**：教师创建课堂获得6位码；学生凭码加入；演示模式 `sessionId='demo'` 绕过同步
- **教师页** `/teacher/[sessionId]`：控制全局节奏，通过 PATCH `/api/session/[sessionId]` 推送 `currentItemId`
- **学生页** `/student/[sessionId]`：每2.5秒轮询跟随教师步骤；demo模式可自由浏览

### 步骤驱动机制

课程流程由 `CRUISE_LESSON_STEPS` 数组定义，每个步骤包含：
- `id`：步骤唯一标识
- `title`：步骤标题
- `stage`：BOPPPS阶段（bridge-in / objective / pre-assessment / participatory / post-assessment / summary）
- `duration`：预计时长（分钟）

## 设计哲学（由 L-2a 案例确认）

### 页面密度与信息完整性

互动页面是"活动的PPT"，**不能以互动为由省略文案**：
- 一节90分钟课程对应约 **15-20 个步骤页**
- 每步骤的正文文字、公式、图例说明**必须完整呈现**，不能以"见讲义"代替
- 图片以 `[占位：资源编号 描述]` 标注，纳入资源占位清单

### 知识传授与互动引导的平衡

互动页面承担**双重功能**：知识载体（替代传统PPT）+ 认知引导（互动与探索）。两者应均衡，不可偏废：

- **知识传授优先**：定义、公式、例题、工程数值等知识性内容是每个核心内容页的**主体**，应完整、准确地呈现，互动设计附着在知识之上，而非替代知识
- **互动适度嵌入**：预测框、探索任务、AI融入点等互动元素应在知识内容呈现完毕后出现，而不是以互动流程为主线、知识点填空的方式组织页面
- **"核心内容页"的重心**：该类型页面的主体是知识讲解（定义+公式+例子+工程含义），"分步揭示"是呈现节奏，不是以揭示带动学生填空的游戏设计
- **层0速通单元的特殊说明**：层0不做推导，但仍需完整呈现直觉定义、类比说明、跨域关系和工程数值；"速通"是指省略推导，不是省略内容

### 双视角设计原则

每个步骤页**必须分别设计**教师端和学生端：
- **教师端**：面向全班的展示内容 + 教学控制操作（释放/收回题目、揭示标注、抽签等）
- **学生端**：以教师端信息为基础，学生自主完成的个性化任务
- 两端**操作完全独立**：教师控制展示节奏，不干预学生的探索操作

### 学生端自主性——认知记录循环

```
预测（先写下自己的假设）
    ↓
探索（在工作区自由操作，完全独立）
    ↓
对比（预测与探索结果并排展示）
    ↓
记录（保存发现，课后总结时回顾）
```

工作区（仿真参数调节）的操作权**完全属于学生**，教师无法干预。

### 页面布局原则——"按需互动"

**核心原则**：互动只在需要的时候才出现；没有互动的页面显示纯文本或静态图片，不强制填充交互控件。

**布局规则（由学生设备适配需求确认）**：
1. **纵向布局优先**：文本提示区在**最上方**，互动环节（如仿真面板、探索区）排在下方
   - 不采用固定左右分栏，避免小屏幕下内容被截断
2. **互动按需出现**：
   - 无互动的步骤（纯展示、过渡、总结）→ 全幅纯文本/静态图片页面
   - 有互动的步骤（探索、前/后测）→ 文本在上，互动区在下，自然流式排列
3. **响应式考量**：内容区宽度随屏幕自适应；仿真面板高度可折叠，避免占满视口

> **设计动机**：学生使用终端多样（手机、平板、小屏笔记本），固定左右双栏在小屏设备上
> 会导致内容无法正常显示；上下流式布局在所有屏幕尺寸下均可正常使用。

## 步骤类型划分

| 步骤类型 | 特征 | 示例 |
|----------|------|------|
| 纯展示页 | 教师端完整文案，学生端只读或简单互动 | 知识图谱定位、过渡页 |
| 核心内容页 | 教师端分步揭示，学生端同步预测+探索 | 家族图示、指标定义、参数规律 |
| 自由探索页 | 教师端等待+汇总，学生端完全自主 | 工作区探索任务 |
| 测验页 | 教师端分布统计，学生端逐题作答 | 前测、后测 |
| 知识整合页 | 教师端逐行揭示，学生端核对+填表 | 速记表、总结页 |

---

## 同步机制

| 教师操作 | 学生端变化 |
|----------|------------|
| 切换步骤（`currentItemId`） | 学生页自动跟随当前步骤 |
| `postTeacherSyncState()` 释放 | 解锁题目/功能（如前测显示） |
| 点击"揭示标注"控制按钮 | 通过同步状态推送图上高亮状态 |
| demo 模式（`sessionId='demo'`） | 学生可自由浏览所有步骤，无同步 |

## 两阶段工作流

**重要**：Step 6 分两阶段执行，避免大范围返工：

1. **第一阶段**：输出步骤列表框架（步骤ID、标题、类型、时长），供用户确认步骤拆分
2. **第二阶段**：确认框架后，逐步补全每个步骤的完整文案（教师端 + 学生端）
