# 变更审查

范围、严重度和输出规则以仓库 AGENTS.md 的 Code Review Rules 为准。先确定 base/Reviewed commit 与 HEAD；基线无法确定时不回退为全面复审。

查看实际 diff 后按风险追踪调用、数据与测试。需要图谱时用 detect_changes/get_review_context，再按尚未解决的问题查询执行流。缺少测试本身不构成阻断 finding；每项缺陷需要位置、触发场景与实际影响。不要为得到 clean 结论追加审核。

## 证据与工具

选择能回答当前问题的工具，不要求固定调用顺序或调用次数。已知路径/错误可直接读取文件、定向搜索和查看 `.logs/`；跨文件关系适合图谱。缺少工具时查当前工具目录，仅加载需要的能力；不可用或索引过期时用源码、Git 和测试补证据。

图谱使用最小输出；需要时再展开一个执行流或源码片段。大型结果只展示摘要，不同时输出重复的 content 与 structuredContent。图谱只能辅助定位，不能替代实际源码、动态装配、运行态或测试证据。证据足够即停止扩展。
