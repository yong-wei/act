# 问题诊断

从可达的失败场景、报错或日志开始。检查相关实现及测试；需要判断回归来源时查看对应 diff，需要跨模块追踪时使用图谱。找到根因后修复本次授权范围内的缺陷，并运行能区分修复前后的验证；无关失败单列。

用户只要求诊断时报告根因与证据；已经要求修复时，普通实现错误不需要再次确认。仅重要目标或授权缺失时提问。

图形/缓存故障涉及 ForceGraph 时，参考 [已知图形验证要点](references/graph-runtime-checks.md)，其他任务不加载。

## 证据与工具

选择能回答当前问题的工具，不要求固定调用顺序或调用次数。已知路径/错误可直接读取文件、定向搜索和查看 `.logs/`；跨文件关系适合图谱。缺少工具时查当前工具目录，仅加载需要的能力；不可用或索引过期时用源码、Git 和测试补证据。

图谱使用最小输出；需要时再展开一个执行流或源码片段。大型结果只展示摘要，不同时输出重复的 content 与 structuredContent。图谱只能辅助定位，不能替代实际源码、动态装配、运行态或测试证据。证据足够即停止扩展。
