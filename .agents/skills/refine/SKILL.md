# 讲义润色技能 (Refine)

## 概述

对 `course-content/authoring/lessons/{unit}/design/{unit}-handout.md` 进行系统性文风润色与中文专业表达校准，直接回写到同一个 `handout.md`。

**定位**：整条生成链中的最后一道文风清扫工序与语言校准工序。不替代 `lesson` 技能的结构生成，不负责重新发明知识结构；遇到结构性污染时返回 `lesson`，不靠润色强行补救。

本技能的写作规则与 `course-content/AGENTS.override.md` 保持同步，两者均构成润色的约束来源。

**核心目标**：让讲义读起来像受过专业写作训练的中文作者所写——准确、克制、有判断、有节奏。

**核心原则：**
- 面向学生，不面向教师或课程设计者
- 保留全部知识内容和数学推导，只改文风
- 以"我们"为主导视角，营造共同探索的氛围
- 删除教案语言、教育意图外显和冗余元叙述
- 形容词必须有评价维度，动词必须具体
- 语体稳定：书面讲解，不是课堂讲稿也不是论文

## 启动方式

1. 如果用户已指定单元编号（如 `2-1`），直接进入工作流
2. 如果未指定，列出 `course-content/authoring/lessons/` 下所有含 `design/{unit}-handout.md` 的单元，让用户选择
3. 支持批量指定（如"润色 2-1 到 2-4"）

## 工作流

### Phase 0: Brief抽取（内部，不展示给用户）

在动笔前先内部确认：
- 文档类型、目标读者（学生）、核心对象
- 关键判断（本讲要证明什么）
- 证据基础（数据/案例/机制/对比）
- 语体要求（自读讲义）

### Phase 1: 判边界，确大纲

读取这些文件：
1. `course-content/authoring/lessons/{unit}/design/{unit}-handout.md`
2. `course-content/syllabus-refactor/main.md`
3. `course-content/syllabus-refactor/unit-design-details/module{N}.md`

确认三件事：
1. 当前课次在模块中的定位和后续接口
2. 本单元"必须首次出现"的知识点
3. 哪些内容明确留给后续单元，不能因润色而偷跑

如果原稿已与大纲边界高度一致，润色只改表达，不重构知识顺序。

### Phase 2: 抽主线，审结构

从原稿中提取：
1. 本讲的中心结论
2. 支撑该结论的3-5个关键小点
3. 哪些段落只是重复提醒、课程调度语或作者态解释

**结构性缺陷检测**：如果原稿缺少以下任一要件，标记为"需回到 `lesson` 的讲义生成阶段重写结构"，不靠润色强行补救：
- 没有明确的问题/任务引入
- 没有前置知识缺口与能力目标
- 没有锚点案例
- 没有最小例题
- 没有分层练习

如果原稿的主要问题不是句法，而是以下污染来源，同样标记退回 `lesson`：
- brief 本身带着流程控制口吻（"本讲/下一步/产出/交付"）
- 正文按工程检查表推进而非围绕对象展开
- 相邻段落反复解释课程编排而不解释对象

### Phase 3: 执行润色

按以下顺序逐段处理：

1. **先保留知识骨架和证据链** — 不动公式、图表、核心数据
2. **再删除作者态/教师态/课程编排元叙述** — 规则1-2
3. **清理AI味绕行句和口头动作词** — 规则3
4. **重构段落结构** — 规则4-9
5. **语义维度校准** — 规则10-12，形容词展开、动词精准化、搭配审校
6. **句式节奏整理** — 规则13-14
7. **统一语气，检查图表公式编号** — 规则15-16

### Phase 4: 写入并汇报

输出直接覆盖到 `course-content/authoring/lessons/{unit}/design/{unit}-handout.md`。
不要另存为 `handout-refine.md` 或其他平行副本。

完成后汇报四类信息：
1. 主要删改了哪些元叙述、教师态和AI味表达
2. 语义校准项：多少空泛评价词展开为具体维度、多少万能动词替换为实义动词
3. 是否保留了公式、图片、表格和章节结构
4. 是否已直接回写 `handout.md`

## 润色规则

### 第一部分：内容清洗（规则1-3）

#### 规则1：只保留学生真正需要的信息

**必须删除或改写的内容：**
- "本节课的教学目的是……" → 删除或转化为自然的问题引入
- "本节首要解决的问题是……" → 直接呈现问题本身
- "此安排具有重要的学习意义" → 删除
- "您不会误以为……" → 删除教师预判
- "真正要被学生带走的是……" → 删除
- "从课程结构看""从课程主线看" → 删除或改写为内容衔接
- "入口课要先把一个动作立住" → 删除
- "不急着讨论……先把……立住" → 删除
- "这一讲只负责……" → 删除
- "后续哪一课再处理……"（除非确有必要帮助定位边界）

**课程编号引用限制：**
- 正文中每个后续单元最多引用 **1 次**
- 引入和小结可适当放开
- 将"将在 2-2 中学习""将在 2-3 中看到"等预告式引用压缩到引入或小结中

**判断标准：** 如果一句话主要是在解释课程怎样设计、教师为什么这样安排、作者此处准备怎么讲，而不是帮助学生理解知识本身，就删掉或改写。如果某一节大篇幅在说明"上一课讲了什么、这一课承担什么课程接口、下一课会怎么接"，而没有尽快回到当前问题、对象或案例，应优先压缩。

#### 规则2：以"我们"视角书写，禁止"您"

- **主导视角**：使用"我们"（"我们来看""先考虑""接下来分析""回到前面的例子"）
- **偶尔提示**：可用"你"（"注意""你会发现""这里值得留意"），但不频繁
- **禁止**：不使用"您"
- **禁止**：不要把"我们"写成"老师带着学生做动作"，要写成"我们一起理解内容"
- **语气**：严谨但有亲和力，像共同探索而非教师叮嘱

**替换示例：**
- "本课先并排回收两个对象" → "我们先并排回看两个对象"
- "此处必须特别重视" → "值得留意的是"
- "首次学习此公式时，不必急于记忆所有细节" → "第一次接触这个公式，不需要急着记住所有细节"

#### 规则3：删除AI味绕行句

重点压缩以下三类高风险表达：

**3a. 先否定再肯定**（"不是……而是……"）
除非确实存在必要的概念对比，否则直接改成正面陈述。

示例：
- "我们把任务表达卡固定成七项，而不是只留抽象标题" → "任务表达卡采用七个字段。"
- "4-1 产出的不是控制器方案，而是后续设计共享的输入卡" → "4-1 的产出是后续设计共享的输入卡。"

**3b. 元说明过多**
- "这一讲真正要做的是……"
- "到了这里，需要带走的是……"
- "这一步的作用是……"

能并入标题或小结，就不要在正文中反复解释。

**3c. 口头动作词堆积**
- "立住、钉死、压住、压成、压实、回收、接走、写浅一层"

这些词不够精确，替换为直接书面表达：
- "明确"、"写清"、"概括为"、"整理为"、"归纳为"、"作为后续输入"

### 第二部分：段落结构（规则4-9）

#### 规则4：每段只做一件事

每段优先完成一个明确功能：
- 给出结论
- 解释原因
- 呈现证据
- 归纳比较
- 提醒误区

不要在同一段里同时：讲知识 + 讲教学安排 + 提前铺垫后文 + 防御可能误解。如果一段承担任务过多，拆句或删去元说明。

#### 规则5：优先正面陈述，少用防御修辞

以下句式慎用，只在"纠正常见误判"部分才适合集中出现：
- "不要急着……"
- "不能直接……"
- "先别……"
- "不要把……等同于……"
- "这并不意味着……"

普通正文优先直接说明结论。

示例：
- "这并不意味着客船场景不追求速度" → "客船场景仍追求速度，但速度必须服从于平顺和储备边界。"

若正文长期停留在"你要怎样/不能怎样/应当怎样"的训导句式，而没有及时落到对象、证据或案例，应视为结构失衡。

#### 规则6：标题承担信息，正文不重复喊口号

如果标题已经表达了本节主旨，正文第一段应直接解释内容，不再用近义句重复一遍标题。

#### 规则7：压缩重复强化，避免原地打转

遇到同一结论在相邻段落反复出现时：
- 保留第一次完整表达
- 后文只在需要推进论证时简要引用
- 不重复使用同一套强调句式

#### 规则8：重点前置，结论不藏铺垫后

段落优先采用以下顺序：
1. 先给结论句
2. 再给原因或证据
3. 最后补充例子或说明

避免把真正有用的信息放在：段末、多层铺垫之后、对比句的后半截、长串"先……再……最后……"之后。

#### 规则9：讲义是书面文本，不是课堂讲稿

润色后的讲义应偏向学生自读文本，而不是教师讲述稿。可以保留少量自然引导语，但不要让全文充满课堂声口：
- "接下来我们先……"
- "到这里……"
- "这一讲先……"
- "我们还要再把一个边界……"

若这些句子不影响知识表达，优先删除；若需要保留，只保留最低限度。

### 第三部分：语义维度与语言校准（规则10-14）⭐ 核心新增

#### 规则10：形容词必须展开为具体维度

禁止把以下单字/泛化词作为默认评价词：
**硬、稳、强、深、全面、显著、有效、优质、到位、扎实、完善、精准、高效、闭环**

如果确需表达相近含义，必须改写为具体判断，回答"在哪个维度上更好"：

| 低质表达 | 问题 | 展开维度 |
|----------|------|----------|
| 更硬的结论 | 英文 solid 映射 | 论证强度更高 / 适用边界更清晰 / 对前提假设依赖更低 / 在更多场景下仍能成立 |
| 结果更稳 | 未说明稳定维度 | 可复现性更高 / 参数敏感性更低 / 随机波动更小 / 跨样本表现更一致 / 多次运行差异更小 |
| 方法更强 | 无评价坐标 | 收敛速度更快 / 约束满足率更高 / 跨场景迁移能力更强 / 对初始条件依赖更低 |
| 融合更深 | 空洞 | 嵌入到任务流程中 / 与课程目标形成明确对应 / 贯穿完整教学环节 / 改变了原有组织方式 |
| 体系更完整 | 泛化 | 覆盖更多关键环节 / 明确了要素之间的关系 / 补足了诊断或反馈中的缺口 / 形成从目标到证据的闭合链条 |
| 整理到位 | 口语化 | 满足设计要求 / 达到预定指标 / 覆盖关键环节 |
| 全面提升 | 未经定义 | 说明具体提升了哪些指标、环节或能力 |

**核心原则：形容词必须回答"在哪个维度上更好"；动词必须说明"对象发生了什么变化"。**

#### 规则11：动词必须具体，少用万能动词

**谨慎使用的万能动词**（每次出现前判断能否换成更具体的动作）：
进行、实现、提升、加强、打造、赋能、推动、深化、聚焦、助力、构建、优化、完善

**替换示例：**
- "进行分析" → 分析 / 拆解 / 比较 / 刻画 / 验证
- "实现提升" → 提高 / 降低 / 缩短 / 扩大 / 增强 / 稳定 / 压缩
- "构建体系" → 建立结构 / 定义关系 / 串联流程 / 形成机制
- "深度融合" → 嵌入流程 / 对齐目标 / 连接数据 / 改写任务结构
- "赋能教学" → 支撑诊断 / 辅助反馈 / 驱动推荐 / 改进评价

**优先使用的精确实义动词：**
揭示、刻画、约束、映射、分解、校准、筛选、验证、支撑、压缩、转化、追踪、聚合、对齐、嵌入、迁移、外推、收敛、扰动、退化、补偿、削弱、放大、固化、沉淀

#### 规则12：审校中文搭配，避免英文直译

检测并修正英文思维直译式表达：

| 英文直译 | 自然中文 |
|----------|----------|
| 更硬的结论 (solid conclusion) | 论证更充分 / 结论更有说服力 / 证据链更完整 |
| 更稳的结果 (stable result) | 结果更可复现 / 波动更小 / 对扰动更不敏感 |
| 更深的融合 (deep integration) | 融入更具体的教学环节 / 与任务流程结合更紧 |
| 更强的能力 (strong capability) | 在某一指标或场景下表现出更高能力 |
| 高性能 (high performance) | 根据语境：响应更快 / 精度更高 / 通量更大 |
| 鲁棒性 (robustness) | 可保留，但需说明在哪个维度上鲁棒 |

禁止出现："得到一个更硬的结论""让结果变得更稳""方案更强"等英语思维直译。

#### 规则13：避免同构句式连续出现

以下句式不得作为默认组织方式。若使用，必须有真实辨析价值：
- "不是……而是……"（目标：每文件 ≤ 3 次）
- "既……又……"
- "从……到……"
- "一方面……另一方面……"
- "通过……实现……"
- "围绕……构建……体系"
- "以……为抓手，以……为路径，以……为目标"

这些结构不是绝对禁用，但不得连续使用同一结构。

#### 规则14：保持段落节奏，句子有起伏

- **短句用于判断**（一行以内，干脆利落）
- **长句用于展开机制**（两到三行，逐步说明因果链）
- 不要把所有句子写成同一长度、同一重心、同一节奏
- 避免连续3句以上主谓宾结构完全相同的句子
- 段落应有自然起伏，不要读起来像机器生成

### 第四部分：保留与结构（规则15-16）

#### 规则15：保留不动的内容

以下内容**原样保留**，不做任何修改：
- 所有数学公式和推导过程（`$$...$$` 和 `$...$`）
- 所有图片引用（`![...](...)` 语法），含 `{fig-pos=...}` `{width=...}` 等属性
- 表格结构和列数（可微调单元格内文字表述）
- 例题的计算步骤和数学内容
- 章节编号和大标题结构（一、二、三……）
- 附录内容（仅做文风微调）
- `> 引用块`中的核心论断（可微调措辞使其更自然）
- 单元知识边界
- **中文引号**：原文中的中文双引号 `""` 必须保留，不得替换为英文双引号 `""`；新写入的引文内容同样必须使用中文引号

#### 规则16：允许有限结构修正

**可以做：**
- 合并表达同一层含义的连续段落
- 删除纯粹重复前文结论的段落
- 压缩过长的过渡段
- 把过强的教学提示改写成自然过渡
- 将长段落重写为"结论句 + 解释句 + 证据句"的结构
- 可改标题为内容型标题（如"为什么……""何时开始失效"）
- 在同层相邻章节逻辑断裂时可合并或微调顺序

**不可做：**
- 删除任何知识点
- 调换主要章节顺序
- 新增原稿没有的知识结论
- 不得新增单元外知识
- 把本单元边界外的内容提前写进来
- 不得改公式/图表/核心数据
- 为了"简洁"而删掉必要的证据链

如果缺的是整块知识结构，退回 `lesson` 重写，而不是把 `lesson` 级重构伪装成纯润色。

## 风格目标

润色后的文本应同时满足：
1. **学生一眼能看到重点**：中心句前置，少绕行
2. **像成熟讲义，不像提示词产物**：少口头动作词，少模板腔
3. **像书面讲解，不像课堂指挥**：少"先……再……""不急着……"
4. **评价有坐标，判断有依据**：不说"更好"，说"在哪方面更好"
5. **保留工程判断感，但不过度喊口号**
6. **读起来有推进感，但不靠重复强调制造推进感**
7. **语体稳定**：不漂移于课堂讲稿、工程检查表和学术论文之间

## 附录：常见低质表达替代表

以下对照表用于快速查证，非穷举，核心是理解替换原则：

### 评价词展开

| 低质 | 替换（按语境选一） |
|------|---------------------|
| 硬的结论 / 更硬的结论 | 论证强度更高 / 证据链更完整 / 适用边界更清晰 / 对特定假设的依赖更低 |
| 稳的结果 / 更稳 | 可复现性更高 / 随机波动更小 / 对参数扰动更不敏感 / 跨样本表现更一致 |
| 强的方法 / 更强 | 收敛速度更快 / 约束满足率更高 / 跨场景迁移能力更强 / 在多目标权衡中保留更多可行解 |
| 深的融合 / 更深 | 嵌入到任务流程的具体环节 / 与课程目标形成明确对应 / 贯穿诊断、推荐、反馈和评价 |

### AI句式改写

| AI句式 | 改写 |
|--------|------|
| 不是A，而是B | 直接陈述B（除非A是常见误区需要纠正） |
| 通过X实现Y | X使Y成为可能 / 经过X，Y得以发生 / 用X来完成Y |
| 既A又B | A的同时也B / A，同时B / 分两句说（判断+机制） |
| 从X到Y | 分两步：先说X的贡献，再说Y如何在此基础上推进 |
| 立住一个判断 | 明确一个判断 / 首先确认 |
| 把X压得更实 | 更充分地证明X / 进一步验证X |
| 这一讲不讨论X | 删除（直接跳到本讲讨论的内容） |
