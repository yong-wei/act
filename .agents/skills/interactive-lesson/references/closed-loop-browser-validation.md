# 闭环浏览器验收参考

## 触发时机

本文件只在以下前提已经满足后使用：

1. 代码实现已完成
2. 已重新执行一次"设计稿 vs 实现稿"核对
3. 已确认当前实现与设计文稿在结构、步骤、资源和课堂链路上基本对齐

不要在实现中途就开始整轮浏览器逐页验收。先完成设计对照，再进入本文件定义的闭环浏览器验证。

设计稿对照与课程笔记更新规则见 [verification-and-note-update.md](verification-and-note-update.md)。

## 目标

浏览器验收的目标不是"随便点一遍"，而是对教师端和学生端做逐页闭环验证：

- 教师端先完成当前页的主要操作
- 学生端验证同步、提交、AI 调用、抽屉等学生动作
- 教师端回看统计、词云、答案揭示、在线人数等反馈
- 当前页闭环完成后，教师端推进下一页
- 学生端验证不同步提示与跟页能力，再进入下一页

主代理负责调度、汇总和判断是否通过，不要把全部测试细节长期堆在主上下文里。

## 启动方式

浏览器闭环验收默认使用：

```bash
npm run startup
```

不要使用 `npm run start` 作为本地浏览器验收基线。当前仓库启用了 `output: 'standalone'`，若只直接执行 `next start` 或不完整的 standalone 运行方式，可能出现 `/_next/static/*` 资源缺失、页面只有 SSR HTML 而未完成 hydration、看起来"只加载一半"的问题。

当前推荐基线：

- 使用 `npm run startup`
- 等待启动脚本中的页面就绪探针完成
- 再启动双子代理或其他浏览器自动化

额外注意：

- `window.confirm` 会阻断"结束课堂"等按钮动作，浏览器代理必须显式处理
- 浏览器可能对弱密码弹出保存/泄露提醒，因此验收账号统一使用复杂密码

## 智能体分工

推荐采用双子代理并行浏览器验收：

- 子代理 A：教师端代理
  - 独立浏览器 profile
  - 使用教师账号登录
  - 读取 `references/browser-validation-teacher-subagent.md`
  - 负责建课、翻页、揭示答案、查看统计、结束课堂
- 子代理 B：学生端代理
  - 独立浏览器 profile
  - 使用学生账号登录
  - 读取 `references/browser-validation-student-subagent.md`
  - 负责课堂码加入、填写输入、提交作答、打开知识卡片、触发页内 AI
- 主代理：
  - 启动本地应用
  - 给两侧代理明确页面范围和通过标准
  - 不需要读取两个子代理规范文件本体，只负责按角色分发
  - 收集每页结果与缺陷，不逐条复述操作细节

## 验收前准备

1. 启动本地应用，确认目标课次入口页可访问
2. 教师代理登录并进入课程入口页
3. 学生代理登录并停留在课程入口页
4. 教师代理创建课堂，记录课堂码和教师页 URL
5. 学生代理通过课堂码加入
6. 在第一页先确认：
   - 教师页可显示课堂码
   - 学生已成功进入真实课堂页
   - 教师端在线人数可见

如果学生已经加入，但教师端在线人数仍为 `0 人`，这属于课堂在线统计链路异常，应优先记录为缺陷。

## 逐页闭环流程

每一页都按同一个顺序验收：

1. 教师代理确认当前页标题、步骤序号、课堂提示与设计稿一致
2. 教师代理执行本页主功能
3. 学生代理验证教师翻页后的跟页机制
4. 学生代理完成本页需要的输入或交互
5. 教师代理验证教师端是否收到反馈
6. 双方确认当前页通过
7. 教师代理翻到下一页，学生代理重复同样流程

### 学生跟页规则

当前平台精品互动课的默认行为不是"强制自动翻页"，而是：

- 首次进入时对齐教师页
- 教师后续翻页时，学生端出现"当前页面与教师不同步，点击跳转"提示
- 学生端点击后跳到教师当前页

因此，浏览器验收时应把"不同步提示 + 手动跳转"视为预期行为，而不是误判为同步失败。

## 当前页主功能的默认检查项

### 1. 纯展示页

教师端检查：

- 标题、导语、提示块、媒体是否与设计稿一致
- 若为 runtime 首页或课堂导入页，入口区顺序是否正确

学生端检查：

- 同页内容是否可读
- 知识卡片入口是否按设计出现

### 2. 媒体页

教师端检查：

- 图片、SVG、视频是否成功加载
- 图中中文是否可见
- SVG 是否无明显错位、遮挡、断线

学生端检查：

- 同一资源在学生端也可加载
- 移动端下资源未超出主要阅读区

### 3. 单选 / 测验页

教师端检查：

- 能看到题目
- 学生提交后可见选项统计
- 点击"显示答案"后，学生端可同步看到正确答案

学生端检查：

- 能选择选项并提交
- 提交后页面无异常
- 教师揭示答案后学生端出现答案

### 4. 文本输入页

教师端检查：

- 学生提交后能看到词云
- 回复列表默认折叠
- 回复列表按提交时间排序

学生端检查：

- 文本框可输入并提交
- 提交后页面状态正常

### 5. 页内 AI 页

教师端检查：

- 当前步骤设计为 AI 页时，教师端标题、提示词和引导语正确

学生端检查：

- "打开 AI 助手"在当前页面内弹窗
- 不跳到独立 AI 页面
- 推荐提示词可复制
- 可填写 AI 对照记录并提交

教师端回看：

- 若该页设计要求教师侧看到学生回填内容，应确认反馈链路正常

### 6. 知识卡片页 / 任意带知识卡片入口的页

教师端与学生端都要检查：

- 标题区右上角出现"知识卡片"按钮
- 点击后打开抽屉
- 抽屉标题为"页面知识卡片"
- 抽屉说明为"当前页面相关的知识卡片"
- 卡片默认显示 `## 首页`
- `详情 / 概览` 切换正常

若该步骤本不应有知识卡片：

- 不应渲染空抽屉入口

### 7. 总结页

教师端检查：

- 本节收束文案与下节预告一致

学生端检查：

- 能看到开场记录 / AI 记录 / 课程总结的回看入口或回填位

## 必须覆盖的闭环验证细项

无论是否采用双子代理并行，闭环浏览器验收至少要覆盖以下内容。

### 基础覆盖项

- 步骤数、标题、顺序是否与设计稿一致
- 媒体资源是否可读取
- 教师端 / 学生端内容与动作是否对应设计稿
- 工作区是否只在需要时出现
- 互动输入、汇总、记录、埋点是否通路正常
- 选择题是否在教师端形成选项统计；有标准答案时，教师端"显示答案"后学生端是否同步可见
- 文本题是否在教师端生成词云；回复列表是否默认折叠且按提交时间排序
- 当前在线学生清单是否默认折叠，折叠态是否仅显示人数
- AI 助手是否在当前页面直接弹出对话框，而不是跳转到独立助手页
- `dashboard`、`/classroom/join`、课程入口页输入同一课堂码后是否落到同一正确课堂页面
- 教师是否能从课程页结束课堂，后台是否能停止进行中的课堂
- 学生端在教师翻页后是否出现不同步提示与手动跳转能力

### 代码直出图 / 前端 SVG 额外覆盖项

如果课程包含代码直出图或前端 SVG 图，额外验证：

- runtime 图是否生成到正确目录
- 页面实际渲染时中文文本是否可见
- 前端 SVG 图是否存在布局错位、遮挡或回路线断裂
- 绘图脚本是否固定了系统中文字体与 SVG 导出策略

### runtime 首页额外覆盖项

如果课程首页接入了 runtime 资源，额外验证：

- `bash course-content/scripts/export-runtime.sh <lesson>` 能否完整导出
- 教师入口、自由浏览、学生入口是否位于首页最上方
- 知识点网络模块是否正确出现，默认节点是否可读
- 知识点网络是否用箭头表达前置与后置关系
- 点击节点后是否显示卡片正面，`详情 / 概览` 是否工作且标题保持不变
- 卡片预览顺序是否与 lesson sequence 一致
- 讲义入口是否可打开，LaTeX、图片和媒体链接是否正确，`导出 PDF` 是否可用
- 当前步骤若有知识卡片，抽屉是否按编排出现；若无卡片，抽屉是否不出现
- `course-content/runtime/knowledge/cards/nodes/*.md` 是否按 `## 首页 / ## 详情` 分节正确渲染，并支持 `详情 / 概览` 切换
- `course-content/runtime` 是否已经成为页面读取的唯一来源
- 深色模式与浅色模式下是否都可读，不要为了浅色模式去硬编码模块样式

## 逐页验收输出格式

建议每页只要求子代理回报一个极简结构，不要提交长叙述：

```text
step-07
- 教师主功能：通过 / 失败
- 学生同步与提交：通过 / 失败
- 教师回看反馈：通过 / 失败
- 缺陷：无 / <一句话>
```

主代理汇总时只保留：

- 哪些页面通过
- 哪些页面失败
- 失败的复现条件
- 是否阻断整课上线

## L-2c 实测经验

L-2c 本轮浏览器验收已验证过以下链路，可作为后续同类课次的默认参考：

- 入口页 runtime 模块可正常显示知识点网络、知识卡片预览、讲义入口与 `导出 PDF`
- `student/demo?step=step-01..17` 适合做静态逐页核对
- 真实课堂链路中，教师建课后学生用课堂码加入，再做双端同步验证更适合检查课堂行为
- 前测页适合验证：
  - 学生单选与文本提交
  - 教师端选项统计
  - 文本词云与折叠回复列表
  - 教师揭示答案后的学生同步可见
- AI 页适合验证：
  - 页内弹窗
  - 复制提示词
  - AI 对照记录提交

## 验收后动作

浏览器验收结束后，主代理应立即回到课程笔记，记录：

- 哪些页面已实测通过
- 哪些页面存在缺陷
- 缺陷是否已修复
- 使用了哪组测试账号
- 是否完成了教师 / 学生双端闭环验证

课程笔记更新格式见 [verification-and-note-update.md](verification-and-note-update.md)。

同时记录以下差异维度：

- 本次实现了什么
- 仍有哪些差异
- 哪些差异是有意偏离，并说明原因
- 哪些媒体还未补齐
- 下次优化建议
