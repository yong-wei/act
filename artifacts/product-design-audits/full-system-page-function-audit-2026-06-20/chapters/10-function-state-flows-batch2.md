## 2. 学生控制工作台参数抽屉

证据：

- `screenshots/37-function-state-flows-batch2/student-control-workbench-parameter-drawer-desktop.png`

健康度：中等偏好。

观察：

- “打开参数抽屉”后，右侧抽屉展示对象/校正分段、开环增益、响应类型、开环极点、开环零点和恢复默认。
- 抽屉不遮挡顶部任务链，也保留了四类图表的可见上下文。
- 右下控灵仍浮在抽屉附近，但没有遮挡主要参数输入。

问题：

- P2：参数抽屉占据右侧较大宽度，Bode 图和 Nyquist 图被截断，学生一边调参数一边观察频域图时需要频繁关闭抽屉。
- P2：抽屉标题为“参数抽屉”，没有直接说明当前正在编辑“对象”还是“校正”，初次用户需要先识别 tab。
- P2：对象选择折叠项在自动化中无法通过 role button 定位，可能存在可访问语义不足。

建议：

- 参数抽屉支持窄版和覆盖版两种宽度，或在打开时自动把图表布局压缩为一列对照。
- 抽屉标题同步当前 tab，例如“对象参数”或“校正参数”。
- 折叠项统一使用原生 button 或补足 `aria-expanded` 与可访问名称。

## 3. 教师空教案发起课堂

证据：

- `screenshots/37-function-state-flows-batch2/teacher-empty-lesson-start-desktop.png`

健康度：阻断。

观察：

- 第 09 章已确认 `0 个环节` 教案可以保存；本轮继续点击该教案的“开始上课”。
- 系统成功创建教师课堂，进入 `/classroom/teacher/cmqltdhz50004vmyf76d2txz3`。
- 课堂顶部显示加入码 `673906`、`0 在线` 和“结束”，主体显示 `Waiting for content...`，底部页码显示 `1 / 0`。

问题：

- P0：空教案不仅可保存，还能发起课堂。教师会进入无教学内容的正式课堂界面，学生加入后也无法获得明确任务。
  - 整改状态（2026-06-21，`audit-remediation-p0-stability`）：已修复。保存、列表发课和直接 API 发课均阻断 0 环节教案，既有异常课堂显示恢复状态；证据见 `../remediation/audit-remediation-p0-stability/evidence.md`。
- P1：`1 / 0` 是明显异常状态，说明分页状态没有处理空内容边界。
- P1：主体 `Waiting for content...` 使用英文，不符合当前教师端中文工作流。

建议：

- 发起课堂前必须阻止 0 环节教案，提示“请至少添加 1 个教学环节”。
- 若历史数据已存在空教案，应把“开始上课”置灰并提供“继续编辑”动作。
- 课堂 runtime 层需要显式空内容页，而不是 `Waiting for content...` 和 `1 / 0`。

## 4. 教师班级搜索空态

证据：

- `screenshots/37-function-state-flows-batch2/teacher-class-search-empty-desktop.png`

健康度：良好。

观察：

- 输入不存在的班级关键词后，列表区域显示“没有找到匹配的班级”和“请尝试其他搜索词”。
- 空态位置与班级列表原位置一致，用户能理解当前只是筛选结果为空。

问题：

- P2：空态没有“清空搜索”按钮，教师需要手动删除输入。
- P2：如果教师实际想创建新班级，空态没有把“新建班级”作为下一步强化。

建议：

- 空态增加“清空搜索”和“新建班级”两个动作。

## 5. 管理员用户详情与移动新建弹窗

证据：

- `screenshots/37-function-state-flows-batch2/admin-users-detail-panel-desktop.png`
- `screenshots/37-function-state-flows-batch2/admin-users-create-modal-mobile.png`

健康度：桌面详情良好，移动弹窗偏弱。

观察：

- 点击“查看”后，右侧账号详情卡能显示姓名、角色、学号、班级、工号、创建时间，并提供修改密码和删除账号。
- 移动端新建账号弹窗可打开，字段包括姓名、角色、账号/邮箱、学号、班级和初始密码。

问题：

- P2：桌面详情面板里的删除账号与修改密码距离较近，且删除仍是高风险动作；需要更强二次确认说明。
- P1：移动端新建账号弹窗出现在长页面中部，背景表格仍完整可见；视觉焦点被表格和弹窗竞争。
- P1：移动端弹窗高度接近屏幕下半区，底部操作按钮较小，字段较多时容易被键盘遮挡。

建议：

- 移动端弹窗改为底部 sheet 或全屏表单，打开后固定焦点和滚动范围。
- 删除账号入口在详情面板中降低视觉强度，必须进入系统内确认弹窗。

## 6. 管理员系统配置保存与供应商添加

证据：

- `screenshots/37-function-state-flows-batch2/admin-config-save-unchanged-desktop.png`
- `screenshots/37-function-state-flows-batch2/admin-config-add-provider-empty-desktop.png`

健康度：保存反馈良好；供应商添加偏弱。

观察：

- 不修改配置直接点击“保存配置”，页面顶部显示“配置已保存”，用户能确认保存动作完成。
- 点击“添加供应商”时，页面没有字段级错误；系统生成 `provider-2`，切换当前供应商，并出现空 API 端点、默认密钥引用 `env:PROVIDER_2_API_KEY`、空模型列表和“删除当前供应商”。

问题：

- P1：空供应商可以被创建为当前供应商草稿。相比“添加模型”会提示模型 ID 不能为空，供应商添加缺少同等字段校验。
- P1：空供应商生成后会切走当前供应商选择，管理员可能误以为运行时配置已切换。
- P2：保存成功反馈位于页面主体顶部，离右上“保存配置”按钮较远。

建议：

- 添加供应商前至少校验 provider id、名称和 API endpoint，不应自动生成当前供应商。
- 未保存的新供应商应标记为草稿，并与运行时当前供应商明确区分。
- 保存成功反馈同时出现在保存按钮附近或按钮本身短暂变为“已保存”。

## 7. 本轮结论

- 教师空教案链路从保存继续扩大到发起课堂，优先级应从 P1 提升为 P0。
- 管理员配置页的模型添加已有空值校验，但供应商添加缺少同级校验，容易产生看似当前可用的空供应商。
- 控制工作台参数抽屉可用，但对象选择折叠项的可访问语义仍需单独补证据。
