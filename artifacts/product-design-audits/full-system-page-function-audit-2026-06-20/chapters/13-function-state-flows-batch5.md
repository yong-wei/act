## 2. 管理员有效 Excel 导入

证据：

- `screenshots/40-function-state-flows-batch5/admin-users-valid-import-result-desktop.png`

健康度：良好。

观察：

- 上传官方模板列名后，页面顶部显示成功提示：新增 1，更新 0，失败 0。
- 左侧“导入结果”卡同步显示新增、更新、失败、数据行数和空行跳过。
- 账号列表首行出现 `audit_import_20260620040618`，角色为学生，说明导入结果不只是 toast，而是进入列表数据。

问题：

- P2：导入完成后没有明确说明默认密码、是否已初始化学习进度、是否需要通知学生。
- P2：结果卡固定在左侧操作栏，列表滚动较长时用户可能看不到导入摘要。
- P2：成功导入后没有“查看本次新增账号 / 导出失败行 / 撤销导入”入口。

建议：

- 成功态增加“本次新增账号”快捷筛选和“复制通知信息”。
- 导入结果应保留在列表顶部或支持跳转，避免用户在长列表中丢失反馈。
- 对学生账号补充默认密码和进度初始化说明。

## 3. 管理员 AI 模型测试 loading

证据：

- `screenshots/40-function-state-flows-batch5/admin-config-ai-model-test-loading-desktop.png`

健康度：中等。

观察：

- 点击测试后，按钮文本变为“测试中...”，按钮呈禁用态。
- 其他模型测试按钮仍可见，页面没有跳转或遮罩。
- 配置表单仍处于可编辑状态，测试中没有全局阻断。

问题：

- P2：loading 只体现在按钮文本上，缺少测试目标、预计耗时、可否离开页面的说明。
- P2：测试中页面仍允许编辑当前供应商配置，用户可能在请求过程中改变被测配置。
- P2：没有取消、超时提示或失败前的进度反馈。

建议：

- loading 态在结果区预留一行“正在测试 Qwen3.6 35B A3B”，避免只依赖按钮文字。
- 当前被测 provider/model 在请求期间应锁定关键字段或显示“变更会影响下一次测试”。
- 超过 10 秒时给出“仍在等待响应”的状态，避免用户误以为卡死。

## 4. 教师课后复盘失败态

证据：

- `screenshots/40-function-state-flows-batch5/teacher-empty-classroom-review-after-end-desktop.png`

健康度：较弱。

观察：

- 访问已结束空课堂复盘页后，页面只显示“课堂记录详情”和“该课堂记录未绑定班级，无法展示课后分析信息。”
- 页面没有返回按钮、关联教案入口、课堂历史入口或修复建议。
- 这与上一轮“结束课堂后回到教案列表”的行为合在一起，会让教师无法从结束动作进入可解释的结果页。

问题：

- P1：课堂结束后复盘链路存在断点。空教案课堂可以被发起和结束，但复盘页没有可行动的恢复路径。
- P1：失败态没有沿用教师后台视觉壳，页面显得像临时错误页，降低可信度。
- P2：没有展示课堂标题、开始/结束时间、教师、教案等可帮助用户判断记录的基础信息。

建议：

- 对未绑定班级或无学生记录的课堂，复盘页仍应展示课堂摘要和“返回教案 / 查看课堂历史 / 复制问题信息”。
- 空教案课堂从源头禁用开始上课；如果已产生历史记录，复盘页应说明为什么无法生成分析。
- 失败态应进入统一教师后台框架，保留导航与角色上下文。

## 5. 学生移动端官方提交

证据：

- `screenshots/40-function-state-flows-batch5/student-arena-official-submit-mobile-before-click.png`
- `screenshots/40-function-state-flows-batch5/student-arena-official-submit-result-mobile.png`

健康度：可用但成本高。

观察：

- 移动端可以进入 Arena 控制工作台，并在长页面深处找到“提交官方评测”按钮。
- 点击后可生成官方评测结果，结果区展示得分、硬约束、排名提示、指标详情和提交/榜单入口。
- 页面大量图表、参数卡和评测说明在单列中连续堆叠，官方提交按钮需要较长滚动才能到达。

问题：

- P1：移动端提交入口过深。学生必须穿过多段对象分析、指标卡、图表和折叠区，才能执行最关键动作。
- P1：提交后结果与原指标、图表混在同一长页中，移动端难以判断“本次提交是否完成、是否计入排名、下一步看哪里”。
- P2：右侧参数浮钮、底部 floating dock 和控灵入口与评测区距离很近，形成多浮层干扰。

建议：

- 移动端应提供固定的“查看评测 / 提交官方评测”底部行动栏，状态随是否已提交变化。
- 提交结果应在移动端生成顶部成功摘要，明确“已计入/未计入排名、得分、下一步”。
- 图表分析、参数调节和官方提交应通过分段标签或锚点组织，减少长页面滚动成本。

## 6. 本轮结论

- 有效 Excel 导入已经可用，成功反馈与列表落点均能证明数据进入系统。
- AI 模型测试 loading 可见，但状态表达偏轻，测试期间的配置锁定和超时反馈不足。
- 课堂结束后复盘链路在空课堂场景下仍断裂，属于教师工作流高风险问题。
- 移动端官方提交可完成，但入口过深、结果解释分散，移动端任务效率明显低于桌面端。
