## 1. 本批审计顺序

1. 学生打开 `/knowledge`，检查知识图谱默认状态、局部工具、画布和焦点路径。
2. 学生打开筛选工具并搜索 `PID`，检查筛选后的图谱、关系统计和结果状态。
3. 学生打开 `/knowledge?node=Bode图_1_1`，检查节点深链是否选中节点并展开详情。
4. 学生尝试打开知识图谱布局工具，检查布局控制可发现性。
5. 学生打开 `/playlists`，检查公开课程流卡片、环节数、作者、开始上课入口。
6. 学生打开 `/playlists/{id}/play`，检查公开课程流开始上课是否进入播放器。
7. 学生打开 `/playlists/new`，检查新建课程流默认状态。
8. 学生空标题点击“保存课程流”，检查校验反馈。
9. 学生搜索 `PID`，检查知识库过滤。
10. 学生添加第一个知识点，检查课程编排条目、模式、时长、上移/下移/删除。
11. 学生填写标题和描述后保存，检查列表回流、环节数和数据保留。
12. 学生移动端打开 `/knowledge`，检查图谱和工具抽屉。
13. 学生移动端打开筛选抽屉，检查关系、分类、认知层级和重置操作。
14. 学生移动端打开 `/playlists/new`，检查知识库与课程编排的窄屏布局。
15. 教师打开 `/knowledge`，检查同一知识资源表面在教师角色下的壳层和入口。

API 与路由证据：

- `/api/knowledge/graph` 返回知识图谱数据，manifest 记录节点与关系摘要。
- `/api/knowledge/nodes` 返回知识节点列表。
- 学生 `/knowledge` 返回 200，默认展示 613 节点、1306 关系。
- 学生搜索 `PID` 后页面展示 23 个节点、34 条关系，筛选工具打开并展示 23 种关系图例。
- 学生访问 `/knowledge?node=Bode图_1_1` 返回 200，但控灵上下文显示“节点未解析 / 请求的知识节点暂不可用”。

观察：

- 桌面默认图谱有清晰的局部工具组：目录、筛选、图例、视图，并能在画布上展示大型知识关系。
- 搜索 `PID` 后关系筛选面板给出当前关系数、节点数、关系密度、类型统计、强度阈值和“仅显示存在可见关系的节点”，筛选状态比前几批模板截图更具体。
- 节点深链没有形成可见选中态或详情面板。URL 中的节点 id 有效进入页面，但页面仍只展示默认图谱，控灵面板明确说“节点未解析”。
- 尝试通过可访问名称打开“布局”工具失败；工具视觉上叫“视图 2D · 0 固定”，但可访问按钮名称不是“布局”，脚本记录为 `not-found`。
- 移动端图谱保持同样的抽屉工具，但筛选抽屉内容非常密集，关系统计、关系密度、类型列表、分类、认知层级和重置操作全部堆在一个窄面板内。
- 教师打开 `/knowledge` 与学生相同使用知识资源壳层，能看到图谱和控灵，不存在明显教师专属备课动作。

问题：

- P1：知识节点深链无法解析到节点详情。`/knowledge?node=Bode图_1_1` 返回 200，但控灵提示“节点未解析”，用户无法从资源、课程或推荐入口稳定落到目标知识点。
- P2：知识图谱布局工具可发现性不足。视觉按钮显示“视图”，但脚本按“布局”无法找到对应按钮；对读屏用户和自动化验收不稳定。
- P2：移动端筛选抽屉信息密度过高。关系类型长列表挤在窄面板中，主图谱状态和下一步学习动作被推后。

建议：

- 统一 URL 节点 id 与图谱运行时节点 id；深链失败时应给出可见错误、搜索替代项和返回图谱目录动作。
- 给“视图/布局”工具提供稳定的 aria-label，例如“打开知识图谱视图与布局工具”。
- 移动端筛选抽屉分层展示：先搜索与关系密度，再展开关系类型、分类和认知层级。

## 3. 播放列表列表与开始上课

证据：

- `05-student-playlists-list.png`
- `06-student-playlist-play-redirect.png`

API 与路由证据：

- `/api/knowledge/playlists` 返回公开课程流列表。
- 公开课程流“柔性之海——豪华邮轮的舒适度控制”显示 8 个环节、公开状态和开始上课按钮。
- 学生访问 `/playlists/cmkaxvc11000n11d46jntz6nf/play` 返回 200，但最终 URL 为 `/`，截图显示平台首页“海上半潜平台动力定位”。

观察：

- `/playlists` 卡片能表达标题、作者、日期、描述、环节数、公开状态和“开始上课”。
- “开始上课”按钮视觉上像主动作，但学生点击后没有进入课堂播放器，也没有播放列表上下文、权限说明或错误状态。
- 源码层 `/playlists/[id]/play` 校验教案存在后跳转 `/admin/lesson-plans`；学生实际运行时又被权限/壳层逻辑带到 `/`。用户只能看到首页，无法知道播放失败的原因。

问题：

- P1：公开课程流开始上课静默落到首页。真实用户点击“开始上课”后丢失课程流上下文，播放列表功能主承诺失效。
- P1：播放入口缺少权限和替代路径说明。即使播放页暂不支持学生，也应说明原因并提供回列表、查看课程流详情或联系教师动作。

建议：

- `/playlists/[id]/play` 应进入实际 `ClassroomPlayer` 或专门的播放列表播放器，不应跳管理员教案页。
- 若只有教师可播放，列表页需要在按钮文案和权限上明确，不要让学生看到可点击但不可完成的主动作。

## 4. 新建课程流、保存与移动端布局

证据：

- `07-student-playlist-builder-empty.png`
- `08-student-playlist-builder-empty-title-alert.png`
- `09-student-playlist-builder-search.png`
- `10-student-playlist-builder-item-added.png`
- `11-student-playlist-builder-after-save.png`
- `14-student-playlist-builder-mobile-empty.png`

API 与数据证据：

- 空标题保存触发原生 alert：`请输入标题`。
- 新建课程流保存后列表出现临时标题 `PD Batch38 审计课程流 ...`，但卡片显示 `0 个环节`。
- 脚本完成截图后已通过 Prisma 按标题删除临时课程流，manifest 记录清理 `count=1`。
- `src/app/api/knowledge/playlists/route.ts` 创建 `LessonPlan` 时明确不创建 items，注释称 endpoint 保留兼容但 items 需要 `TeachingResource` 引用。

观察：

- 新建课程流默认状态左侧加载完整知识库，右侧是课程标题、描述、空编排区和底部保存按钮。
- 完整知识库一次渲染 820 个知识点，DOM/a11y 快照记录 821 个无名按钮，桌面 full-page 截图高度超过 60,000px。
- 搜索 `PID` 后知识库缩小为可浏览列表，点击无名加号能添加一个条目；条目显示序号、知识点名、讲授/测验/讨论、15 分钟、上移/下移和删除。
- 添加知识点后的“加号、上移、下移、删除”等图标按钮缺少可访问名称；移动端同样继承完整长列表，截图高度超过 61,000px，几乎不能形成有效手机任务流。
- 保存后回到 `/playlists`，新课程流卡片出现，但环节数为 `0 个环节`，说明用户刚添加的知识点没有进入真实课程流数据。
- 空标题校验使用原生 alert，页面没有把错误绑定到“课程标题”字段，也没有 `role=alert` 或 `aria-live` 状态。

问题：

- P1：课程流构建器保存后丢失已添加知识点。用户在右侧编排的条目没有成为 `LessonItem`，列表只保留标题和描述。
- P1：新建课程流默认渲染规模过大。未搜索时 820 个节点和 821 个无名按钮直接进入页面，桌面和移动端都形成超长滚动。
- P1：课程流保存校验使用原生 alert。错误不在页面内、不绑定字段，也不能稳定服务读屏和键盘用户。
- P1：课程流构建器图标按钮缺少可访问名称。加号、上移、下移、删除在 DOM 中大量无名，用户无法理解按钮作用。
- P2：移动端课程流构建器没有分步结构。知识库和课程编排顺序堆叠，底部保存按钮远离标题/条目上下文。

建议：

- 保存课程流时要么创建真实 `LessonItem`，要么在 UI 明确“知识点草稿暂不保存为环节”，不能保存后显示 `0 个环节`。
- 知识库默认应分页、虚拟滚动或先要求搜索；移动端建议拆成“选知识点 / 编排 / 保存”三段式步骤。
- 把空标题校验改为页面内字段错误，保存按钮触发后聚焦标题输入框并写入状态区。
- 为所有图标按钮补充 `aria-label`，例如“添加 策略监督层调度”“上移第 1 个环节”“删除第 1 个环节”。
