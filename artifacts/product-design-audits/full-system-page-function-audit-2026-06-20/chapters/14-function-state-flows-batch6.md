## 2. 有效课堂复盘链路

证据：

- `screenshots/41-function-state-flows-batch6/teacher-valid-classroom-review-desktop.png`
- `screenshots/41-function-state-flows-batch6/teacher-valid-classroom-review-mobile.png`

健康度：中等。

观察：

- 有效已结束课堂复盘页能展示课程标题、班级、时间、状态、课堂记录人数、互动日志、提交人数、学习事实和同步错误。
- 课前 vs 课后能力追踪、课后补强路径、学生摘要和雷达图均能渲染。
- 页面底部提供“前往评审聚合入口”。

问题：

- P1：有效复盘页没有教师后台壳层，只有“返回班级详情”和底部评审入口；教师从课堂结束进入后缺少“回到教案/课堂历史/班级分析”的完整路径。
- P1：本样本能力追踪显示课前 89 到课后 50，全部维度 -39，但页面没有解释数据来源、是否代表倒退、是否由评分口径变化导致。
- P2：补强路径和个性化题单为空时，只显示“暂无”文本，没有告诉教师如何生成或补齐。
- P2：移动端控灵浮层贴近能力追踪卡片，仍存在跨页浮层遮挡风险。

建议：

- 复盘页应纳入教师后台导航壳层，并在顶部提供“返回课堂历史 / 继续查看班级 / 导出报告”。
- 能力下降应附带数据口径说明和可信度提示，避免教师误读为单纯学习退步。
- 空补强路径应给出生成条件、数据不足原因或手动补充入口。

## 3. AI 模型测试失败态

证据：

- `screenshots/41-function-state-flows-batch6/admin-config-ai-model-test-forced-error-desktop.png`

健康度：中等。

观察：

- 模型测试失败后，错误在对应模型卡片下方以内联红色提示展示。
- 错误内容为“审计模拟：模型供应商连接失败”，没有泄露密钥或请求头。
- 页面保持在原配置位置，管理员可以继续编辑或再次点击测试。

问题：

- P2：失败态没有时间戳、重试建议、provider/model 摘要或“查看配置项”定位。
- P2：错误提示直接占据模型卡片宽度，但没有区分网络失败、认证失败、能力不支持和超时。
- P2：失败后按钮恢复为“测试”，但没有“重试”语义或最近一次测试状态。

建议：

- 失败态应显示“刚刚测试 / provider / model / 失败类型 / 下一步”。
- 常见失败应给出配置检查清单：密钥引用、base URL、模型 ID、能力开关。
- 保留最近一次测试记录，避免管理员离开视口后无法判断是否已测。

## 4. 登录页键盘焦点抽查

证据：

- `screenshots/41-function-state-flows-batch6/login-mobile-keyboard-focus-after-tabs.png`
- `function-state-flows-batch6-manifest.json` 中 `login-mobile-keyboard-focus-after-tabs.focusables`

健康度：部分可用。

观察：

- 移动视口连续 Tab 8 次后，焦点落在“学号/工号”输入框，蓝色焦点环清楚可见。
- DOM focusable 抽样能识别顶部回调按钮、账号输入、密码输入、登录按钮等关键元素。
- 右下“工具”浮层继续覆盖意图卡列表区域。

问题：

- P2：焦点可见性在表单内可用，但这只是登录页抽查，不能替代全站键盘审计。
- P2：移动端工具浮层与键盘焦点路径无关，却遮挡“实验/复盘”等意图卡，读屏和键盘用户可能遇到上下文干扰。
- P2：当前报告还没有覆盖模态框焦点陷阱、Escape、aria-live 表单错误和图表替代文本。

建议：

- 后续 a11y 审计应按角色选取登录、注册、课堂加入、Arena 工作台、管理员弹窗和教师复盘页做系统化键盘路径。
- 全局工具浮层需要对焦点态和读屏顺序进行合同化约束，避免成为每页最后的不可预测焦点。

## 5. 本轮结论

- 有效课堂复盘链路可以打开并展示核心数据，但解释层和教师回流路径不足。
- AI 模型测试失败态可见且不泄露密钥，但故障分类和恢复指导不足。
- 登录页键盘焦点基本可见；全站键盘、读屏、模态框和图表语义仍未完成审计。
