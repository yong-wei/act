## 1. 本批审计顺序

本批沿教师完成教案编排后发起课堂的真实顺序展开：

1. 在“我的教案”列表确认开始上课入口。
2. 通过现有 UI 路径创建课堂，并进入课程专属教师投影运行态。
3. 检查桌面和移动端教师投影首屏、课堂码、二维码和在线学生入口。
4. 翻到下一页，检查同步/进度反馈。
5. 触发结束课堂确认，先取消，再确认结束。
6. 检查结束后的落点、上课历史和课后复盘页面。

## 2. 教案列表发起课堂

证据：

- `01-teacher-lesson-plan-start-entry-desktop.png`
- Manifest `createdSessionId=cmqm628kp001a4tyfn5dou3pp`

观察：

- 教案列表每张卡片都有“开始上课”入口，点击后通过 `/api/session` 创建 `ClassSession`。
- API 支持 `classId`，但教案列表 UI 没有班级选择、班级默认值或创建前确认；本批创建结果 `classId=null`。
- 本批采集前数据库已有多条同一教师、同类教案、`classId=null` 的 ACTIVE 课堂；教案列表没有提示已有进行中直发课堂。
- 教师名下存在多个班级，包括 111 人、143 人和 30 人班级，但发起课堂路径没有利用这些上下文。

问题：

- P1：教师发起课堂缺少班级绑定步骤。教师在拥有多个班级时无法选择本次课堂所属班级，最终产生无班级课堂。
- P1：无班级直发课堂会绕开班级进行中课堂冲突校验。后端只在传入 `classId` 时检查该班级 ACTIVE session；UI 不传 `classId` 时可持续创建多个无班级 ACTIVE 课堂。
- P1：开始上课入口没有影响说明。教师不知道课堂码如何发放、是否绑定班级、是否会影响课后复盘、报告生成和学生证据归属。

建议：

- “开始上课”前加入班级选择或确认层，至少默认推荐最近授课班级，并允许明确选择“临时公开课堂”。
- 对同一教案和教师已有 ACTIVE 直发课堂时，提示继续旧课堂、结束旧课堂或新建课堂。
- 创建前显示课堂将绑定的班级、预计学生范围、课堂码发放方式和结束后的复盘位置。

## 3. 教师投影运行态、二维码与在线学生

证据：

- `02-teacher-direct-start-runtime-desktop.png`
- `03-teacher-direct-start-runtime-mobile.png`
- `04-teacher-direct-start-qr-dialog-desktop.png`
- `05-teacher-direct-start-online-students-desktop.png`
- `06-teacher-direct-start-next-item-desktop.png`

观察：

- `/classroom/teacher/{sessionId}` 会重定向到课程专属教师运行态 `/interactive-learning/courses/unit-4-1-design-task-expression/teacher/{sessionId}`。
- 首屏显示课程名、教师投影、课堂码 `548923`、`1/13` 页码、当前阶段和底部“上一页/下一页”。
- 二维码弹窗能展示二维码、课堂码、复制课堂码、复制链接和加入链接。
- 在线学生入口显示 `0 人`，但点击后的页面结构没有形成明显新面板；截图仍主要停留在投影页面。
- 翻页能进入下一页，但页面没有可见“已同步/同步失败/学生已收到”的完成反馈，结构化快照 `alerts` 为空。
- 本批脚本需要 JS 可见文本 fallback 才能点击“二维码”“当前在线学生”“结束课堂”；这些控件在 DOM 中是可见按钮，但 Playwright role 查询未能定位，说明可访问树/命名需要人工复核。

问题：

- P1：教师投影首屏没有明确班级归属。页面展示课堂码，但不展示“未绑定班级/临时课堂/面向哪个班级”，教师无法确认这节课会进入哪个班级报告。
- P1：二维码弹窗缺少班级与课堂身份。弹窗只强调扫码加入和课堂码，不显示课程、班级、教师、有效期、已加入人数或复制状态播报。
- P1：翻页同步缺少可见完成反馈。教师点击下一页后无法确认学生端是否收到同步、多少学生在线、是否有失败。
- P2：在线学生入口在 0 人状态下缺少解释和下一步。教师需要知道是否应复制链接、等待学生、重新生成课堂码或检查班级邀请。
- P1：关键运行态控件的可访问查询不稳定。二维码、在线学生和结束课堂控件可见但 role 查询失败，风险集中在键盘/读屏/自动化可达性。

建议：

- 投影顶部加入班级/临时课堂状态，明确“未绑定班级时课后复盘受限”。
- 二维码弹窗加入课程名、教师名、班级名/临时课堂状态、有效期、复制成功 live/status。
- 翻页后显示短暂同步状态：已发送、在线学生数、失败重试和最后同步时间。
- 为关键控件补稳定 accessible name，并用 role 查询、Tab 顺序和读屏快照复核。

## 4. 结束课堂、历史与复盘

证据：

- `07-teacher-direct-start-end-confirm-dismissed-desktop.png`
- `08-teacher-direct-start-ended-redirect-desktop.png`
- `09-teacher-history-after-direct-start-end-desktop.png`
- `10-teacher-review-after-direct-start-end-desktop.png`

观察：

- 结束课堂仍使用浏览器原生 confirm，文案为：`确定要结束课堂吗？结束后学生将停止同步课堂进度。`
- 取消确认后页面保持在教师投影；确认结束后，课堂状态更新为 `FINISHED`。
- 结束后落点是课程入口页，而不是课堂结束成功页、历史页或复盘页。
- 上课历史能看到结束后的课堂记录，但直发课堂缺少班级上下文。
- 直接进入 `/classroom/teacher/{sessionId}/review` 显示“课堂记录详情：该课堂记录未绑定班级，无法展示课后分析信息。”

问题：

- P1：结束课堂确认仍不解释数据影响。原生 confirm 只说学生停止同步，没有说明提交、证据、报告、未绑定班级后果、是否可恢复或复盘位置。
- P1：结束后落点不承接教师课后工作流。教师被带回课程入口页，看不到“课堂已结束”、课堂码、提交人数、复盘、历史或报告入口。
- P1：直发课堂复盘被未绑定班级阻断。系统允许无班级发起课堂，但结束后又无法展示课后分析，形成前后流程矛盾。
- P2：上课历史能找到记录，但缺少对“未绑定班级”的修复动作。教师需要在历史页直接补绑班级或进入可恢复说明。

建议：

- 结束课堂改为系统内确认模态，展示在线人数、提交数、证据处理、报告生成、班级绑定状态和可恢复性。
- 结束后进入课堂结束成功页，提供“查看复盘、返回历史、绑定班级、复制报告、继续下节课”。
- 对无班级课堂提供补绑班级动作；如果不允许补绑，则发起前必须明确提示复盘受限。

## 5. 本批新增优先问题

81. P1：教师发起课堂缺少班级绑定步骤。
    教师有多个班级，但教案列表“开始上课”直接创建 `classId=null` 的课堂，教师无法选择班级或确认临时课堂。

82. P1：无班级直发课堂可重复创建 ACTIVE session。
    后端只有传入 `classId` 时检查班级进行中课堂；本批前已存在多条同教师无班级 ACTIVE session，UI 没有提示继续旧课堂或结束旧课堂。

83. P1：教师投影首屏和二维码弹窗缺少班级/临时课堂身份。
    课堂码和二维码可见，但页面没有明确本课堂未绑定班级，教师无法预判课后复盘会受限。

84. P1：翻页同步与复制/加入状态缺少 live/status。
    二维码弹窗可复制课堂码和链接，翻页也能改变页码，但结构化快照 `alerts` 均为空，缺少同步完成、复制成功和失败重试状态。

85. P1：结束课堂后落点不承接课后工作流。
    确认结束后落回课程入口页，没有课堂已结束成功态、提交摘要、复盘入口、历史入口或报告入口。

86. P1：直发课堂结束后复盘被未绑定班级阻断。
    `/classroom/teacher/{sessionId}/review` 只显示“该课堂记录未绑定班级，无法展示课后分析信息”，但发起课堂前没有提示这种后果。

87. P1：关键教师运行态控件可访问查询不稳定。
    “二维码”“当前在线学生0 人”“结束课堂”在 DOM 中可见，但 Playwright role 查询无法定位，本批脚本必须使用 JS 可见文本 fallback；需要独立键盘和读屏复核。
