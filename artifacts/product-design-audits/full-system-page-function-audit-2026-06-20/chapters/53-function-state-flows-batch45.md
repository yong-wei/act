## 6. 主要问题

### 277. P1：管理员用户无匹配搜索的 API、总览和列表口径不一致

`/api/admin/users?page=1&pageSize=12&q=zzzz-no-match-audit-20260620` 返回 `total=298` 和 12 个用户；页面列表区域显示“暂无账号数据/共 0 条”，但总览仍显示用户资产 298、学生 293、教师 4。管理员无法判断这是全局统计、筛选统计还是搜索失败。

建议：管理员用户搜索应让 API、总览、表格、分页和空态共享同一过滤条件；若总览保留全局口径，必须明确标注“全局总量”，并另设“当前筛选结果 0 条”。

### 278. P1：教师和管理员教案长列表缺少搜索、分页和无匹配状态

教师教案列表高 6351px，管理员教案列表高 7350px，均未发现可见搜索控件；无匹配搜索尝试后截图与默认状态一致。教案是高频编辑对象，长列表没有快速定位能力会直接拖慢教师和管理员工作流。

建议：教案列表需要关键词搜索、课程/作者/状态筛选、分页或虚拟滚动、清除条件和无匹配空态；搜索条件应进入 URL 或至少可复制恢复。

### 279. P2：学生任务大厅缺关键词搜索和搜索空态

任务大厅只提供“全部/可挑战/已完成”状态筛选，没有可见搜索控件。学生无法按任务标题、控制主题、难度或目标快速定位任务，也无法看到“没有匹配任务”的恢复路径。

建议：补任务标题/主题搜索，结果区显示数量和空态；状态筛选与搜索叠加时应有可清除条件。

### 280. P2：学生证据页缺少关键词搜索和筛选状态播报

证据页未发现可见搜索控件，筛选状态下仍显示长卡片流；结果变化没有 `role=status`、`aria-live` 或结果数量播报。学生在复盘或找错题证据时难以快速定位。

建议：证据页补关键词、课次、来源、证据类型组合筛选，并在结果区播报“当前筛选 X 条证据”。

### 281. P2：教师班级、资源和历史空态可见但不可访问状态不完整

教师班级无匹配显示“没有找到匹配的班级”，资源无匹配显示“没有找到匹配的互动组件”，历史无匹配显示“0 节课/暂无已结束课堂”；三者 DOM 摘要均为 `alerts=0`。

建议：搜索输入变更和结果为空时，把结果数量和空态文案放入 `role=status` 或 `aria-live=polite` 区域，并提供清除搜索条件。

### 282. P2：教师资源移动端默认列表过长

移动端 `/teacher/resources` 默认 full-page 高 7936px，说明教师在手机上需要大量滚动才能覆盖资源分类和卡片。搜索无匹配能缩短页面，但没有从默认态降低信息密度。

建议：移动端资源管理默认使用折叠分类、分页、虚拟列表或 sticky 搜索/筛选栏，把高频资源操作固定在首屏附近。

### 283. P2：教师上课历史默认列表过长且分页信号不足

`/teacher/history` 默认 full-page 高 7465px，DOM 摘要没有分页信号。上课历史是课后复盘与报告交付入口，长列表会使教师难以找到目标课堂。

建议：上课历史补按班级/课程/日期搜索、分页或分组，并在空态和搜索结果中提供清除条件。

### 284. P2：管理员用户角色筛选的自动化可达性不稳定

页面可见“全部角色/管理员/教师/学生”，但脚本按按钮语义查找“教师/TEACHER”未命中，说明角色筛选控件语义可能不是标准按钮或命名不稳定。筛选控件对键盘和读屏用户不够可靠。

建议：角色筛选使用明确的 segmented control、radio group 或 select 语义，并设置当前选中状态。

### 285. P2：移动管理员用户默认页仍横向溢出

移动默认 `/admin/users` 在 390px viewport 下导出为 945px 宽；搜索空态后才恢复 390px。表格或顶部操作区仍会撑宽页面，真实移动端会出现横向滚动和浮层定位偏移。

建议：移动端用户表格改为卡片或列优先折叠，批量导入、模板下载和筛选控件进入固定操作区，不让表格撑宽文档。

### 286. P2：跨列表状态变化普遍缺少 live/status

本批 20 个 DOM/a11y JSON 的 `alerts=0`。搜索填入、空态出现、列表缩短、分页变化和无匹配状态都没有可访问状态播报。

建议：建立列表状态播报合同，覆盖搜索、筛选、分页、排序、加载、无结果、重置和错误状态；列表组件应复用统一的 `ListStatusAnnouncer` 或等价模式。
