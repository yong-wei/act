## 2. 控制工作台任务区合同

证据：

- `01-control-workbench-official-desktop.png`
- `02-control-workbench-official-mobile-top.png`
- `03-control-workbench-official-mobile-bottom.png`

API 证据：

- `/api/arena/submissions?taskId=task-second-order-lead-pid` 返回 200，当前官方榜单存在多条有效提交。

观察：

- 桌面态能正确进入 Arena 官方任务上下文，页面显示“控制工作台”和“二阶对象快速稳定挑战”。
- DOM 标记能识别 `context-strip`、`instrument-area`、`command-bar`、`evidence-rail`、`support-drawer` 和 `floating-dock-safe-area`。
- 三张控制工作台截图的结构化摘要均记录 `missingZones: ["bottom-tools"]`。
- 移动端顶部先显示任务上下文、指标卡、响应曲线和策略面板，提交与证据动作需要较长滚动才能到达。
- 移动端底部能看到证据流、设计流程、参数面板和支持说明，但仍没有独立、固定或清晰命名的底部工具区。
- `floating-dock-safe-area` 在结构中存在，但可见控灵浮层仍贴近右侧内容区；底部截图中浮层与长工作台内容一起滚动时，不能作为真实留白策略证明。

问题：

- P1：任务工作区合同中的 `bottom-tools` 没有实际可见落点。当前页面靠长滚动承载命令、证据和支持，不存在可被用户稳定理解为底部工具区的区域。
- P1：移动端控制工作台过长，关键动作被仪表和说明流稀释。学生需要跨过多个图表、参数卡和说明区才能确认当前可提交或可复盘动作。
- P2：浮动控件缺少可见避让策略。DOM 标记存在不等于布局已留白，移动端仍能看到浮层贴近内容边缘。

建议：

- 将 `bottom-tools` 做成移动端固定或半固定的任务动作区，至少承载提交、查看结果、证据、返回挑战等主动作。
- 移动端首屏应保留“当前任务、当前成绩/门槛、下一步动作”三件事，复杂图表折叠到任务确认之后。
- `floating-dock-safe-area` 应转化为真实布局约束，确保控灵浮层不覆盖提交、图表缩放、表单输入和底部动作。

## 3. 已结束课堂教师直达与复盘

证据：

- `04-ended-teacher-runtime-desktop.png`
- `05-ended-teacher-review-desktop.png`
- `06-ended-teacher-runtime-mobile.png`

API 证据：

- `/api/session/cmqm6s1s1001f1wyf4ggkifs5` 返回 200，`status=FINISHED`，`joinCode=113718`，`currentItemId=step-03`。
- `/api/session/cmqm6s1s1001f1wyf4ggkifs5/state?scope=teacher-view` 返回 200，含 2 名学生的课堂状态记录。

观察：

- 已结束 session 的教师投影直达页仍显示“教师投影”“教师控制”“已发放作答”“隐藏参考答案”“学生提交汇总”和底部翻页控件。
- 直达页没有明确显示“已结束”“只读”“课堂已归档”或结束时间。
- 直达页结构化摘要显示 `liveTeachingCopy=true`、`endedCopy=false`、`reviewAction=false`。
- 同一 session 的 `/classroom/teacher/cmqm6s1s1001f1wyf4ggkifs5/review` 能打开复盘页，显示 `状态: FINISHED`、学生数、提交数、同步错误、能力追踪和个性化补强路径。
- 复盘页提供“前往评审聚合入口”，但首屏仍缺少面向教师的报告交付动作，例如导出、发送给学生、生成补强作业或回到历史课堂。
- 移动端直达页比桌面更容易把已结束课堂误读为仍可上课：顶部有课程导航和教师投影标签，底部仍是“上一页/下一页”课堂控制。

问题：

- P1：已结束课堂直达投影页仍呈现直播态。API 已确认 `FINISHED`，但页面没有只读状态、结束时间、复盘入口或报告入口。
- P1：已结束直达页没有把教师带到复盘/报告工作流。复盘页存在，但直达页首屏没有“查看课堂复盘”“生成报告”“返回上课历史”等动作。
- P1：复盘页能显示数据，但报告交付动作仍不足。页面提供内部评审聚合入口，却没有把复盘结论转成教师可交付的班级报告、学生补强或消息发送。
- P2：已结束投影移动端状态更容易误导。直播控件和底部翻页保留，缺少结束态提示。

建议：

- 已结束 session 的教师投影直达页应改为只读摘要，顶部显示结束状态、课堂码、学生人数、提交人数、结束时间和复盘入口。
- 若保留历史投影查看，应禁用发放、翻页同步、参考答案切换等直播动作，并明确“只读回看”。
- 复盘页首屏增加报告交付动作：导出报告、发送给学生、生成补强作业、回到班级历史。
- 移动端优先显示结束态和复盘 CTA，避免教师先看到直播控制。
