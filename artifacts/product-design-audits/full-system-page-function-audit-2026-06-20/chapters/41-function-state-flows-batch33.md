## 1. 本批审计顺序

1. 教师打开真实课后复盘页，检查导出、发送、补强路径、图表替代文本和焦点顺序。
2. 从复盘页进入“评审聚合入口”，验证是否承接同一课堂上下文。

## 2. 教师课后复盘与报告出口

证据：

- `01-teacher-review-delivery-a11y-desktop.png`
- `02-teacher-review-linked-destination-a11y-desktop.png`
- `03-teacher-dashboard-report-ledger-a11y-desktop.png`

API 证据：

- `/api/teacher/classes/cmma7g0590004g9q2nl2jyzdf/control-correction-report?export=true` 返回 200，包含 `report` 和 `export`。
- `/api/teacher/classes/cmma7g0590004g9q2nl2jyzdf/assistant-effect-report?export=true` 返回 404，错误为“演示效果报告不存在”。

观察：

- 课后复盘页显示真实班级、课堂记录 2 人、有互动日志 2 人、有提交 2 人、形成学习事实 2 人、同步错误 0 人。
- 复盘页能展示能力追踪、学生短板、补强路径空态、个性化题单空态和能力雷达图。
- 复盘页首屏没有“导出报告”“发送给学生”“复制摘要”“生成补强路径”这类交付动作；唯一明显出口仍是“前往评审聚合入口”。
- “评审聚合入口”跳转到 `/review/extracurricular-showcase`，页面内容是课外展示聚合入口，展示班级为 `2023启航班`，不再是 `2024自动化` 或本课堂。
- 教师工作台存在报告账本/导出语义文案，但没有显示本次复盘对应的真实导出状态、发送状态或补强路径生成记录。
- 移动端复盘页同样主要呈现长报告内容，顶部没有固定报告交付动作区。

问题：

- P1：课后复盘真实数据与报告交付仍断开。后端导出 API 已存在，但复盘页和教师工作台没有把它呈现为可执行交付任务。
- P1：复盘页出口仍指向内部 review 聚合面。跳转后丢失本课堂上下文，教师无法确认这是否是给学生或班主任的正式报告路径。
- P1：教师工作台报告账本没有节次级交付状态。教师看不到某节课是否已导出、已发送、等待补强或导出失败。
- P2：移动端复盘缺少固定交付动作区。长页面中“报告交付”没有成为教师完成课后工作的稳定入口。

建议：

- 复盘页顶部增加报告交付操作区：导出报告、发送给学生、复制摘要、生成补强路径、查看同步异常。
- 将内部 review 入口改为次级入口，并明确标注“内部展示/审查”，不要作为教师课后报告主出口。
- 教师工作台报告账本按课堂列出导出状态、发送状态、补强生成状态和最后操作者。

## 3. 文档评分与学生反馈

证据：

- `04-teacher-grading-workbench-empty-a11y-desktop.png`
- `05-document-feedback-demo-a11y-desktop.png`

API 证据：

- `/api/teacher/document-grading/submissions` 以 GET 调用返回 405；该端点当前是创建提交的 POST 方法边界。

观察：

- 报告评分工作台空态显示“当前没有打开的文档评分草稿”，并提示选择已转换学生提交或通过评分草稿标识进入审批工作台。
- 空态有来源质量、隐私范围、状态图例和导出受限脱敏标签，但没有“从班级复盘创建草稿”“从报告账本选择提交”“返回课堂报告”的明确路径。
- 学生报告反馈 demo 正确显示 `报告反馈` 页面、PDF 文档内容、量规得分、证据胶囊、学情影响和后续动作。
- 学生反馈页的后续动作以大量重复按钮呈现，例如查看学情画像、查看练习入口、练习相关任务、复习关联资源；页面没有清晰说明哪些动作已发送、哪些只是 demo 建议。
- 学生反馈页没有 live/status 区域，且浮层控灵在长页面底部覆盖部分视线。

问题：

- P1：报告评分工作台空态缺少真实来源路径。教师不能从空态直接回到某节课堂、某个学生提交或报告账本。
- P1：学生反馈 demo 的后续动作过多且缺少状态分组。学生难以判断哪些是必须完成、可选复习、已完成或教师已指派。
- P1：文档评分工作流状态播报不足。评分草稿、审批、写回、反馈发送和导出受限都没有可访问完成状态。
- P2：GET 405 暴露出接口方法边界与页面发现性分离。创建提交能力存在，但教师端缺少自然入口解释该 POST 流程。

建议：

- 评分工作台空态提供三个明确入口：从课堂复盘生成评分草稿、从报告账本选择提交、查看最近草稿。
- 学生反馈页把后续动作按“教师指派”“推荐复习”“可选资源”分组，并显示完成状态。
- 审批、写回、发送反馈和导出操作统一写入 `role=status` 状态区。

## 4. 管理员配置、导入与治理

证据：

- `06-admin-config-save-state-a11y-desktop.png`
- `07-admin-users-batch-state-a11y-desktop.png`
- `08-admin-data-governance-action-state-a11y-desktop.png`
- `10-admin-config-mobile-action-zone-a11y.png`

API 证据：

- `/api/admin/data-governance/status` 返回 200，`activeRiskFlags=170`，`freshness.status=stale`。
- `/api/admin/users/template` 返回 200，文件名为 `users-template.xlsx`。

观察：

- 系统配置页顶部有“重置为默认”“保存配置”，AI 模型卡有“选用”“测试”，但页面没有配置差异摘要、影响范围、最近保存结果或测试完成状态区。
- 系统配置桌面和移动端 DOM 都没有 alert/live/status；移动端页面很长，保存/测试/重置动作容易与配置内容混在一起。
- 用户管理页有“下载模板”“批量导入”，但未显示导入预览、失败行导出、通知、撤销/回滚或批次审计。
- 用户管理页 Tab 顺序进入导航和操作按钮后才进入业务列表，批量导入入口没有形成可追踪批次状态。
- 数据治理页能展示 170 个待处理风险、约 3101 分钟前的数据新鲜度、队列健康度和最新风险清单，但风险表仍无查看证据、分派、标记处理、创建待办或导出。
- 数据治理页 DOM 没有 alert/live/status，刷新时间可见但缺少操作完成播报。

问题：

- P1：系统配置保存缺少影响范围、差异摘要和完成状态。管理员无法在保存前后确认改了什么、影响哪些 AI 路由、是否测试成功。
- P1：用户批量导入仍缺完整批次状态机。模板下载可用，但上传、校验、导入、失败行导出、通知、撤销和审计没有串成同一流。
- P1：数据治理风险清单仍是只读列表。170 个待处理风险没有处置动作，stale 数据也没有修复入口。
- P1：管理员刷新/保存/下载都缺少可访问完成播报。视觉时间戳或文件下载不能替代 `role=status`。
- P2：管理员移动端缺少固定关键操作区。配置页长屏中保存/测试/重置动作缺少稳定位置和状态回显。

建议：

- 系统配置页增加保存前 diff、影响范围、最近保存时间、操作者和模型测试结果。
- 用户导入按批次建模：模板下载、上传预览、字段校验、确认导入、失败行导出、通知、撤销、审计记录。
- 数据治理风险行提供查看证据、分派、标记处理、创建待办和导出摘要。
- 管理员长页移动端固定关键操作条，并使用统一的 live/status 区域反馈刷新、保存、下载和导入结果。
