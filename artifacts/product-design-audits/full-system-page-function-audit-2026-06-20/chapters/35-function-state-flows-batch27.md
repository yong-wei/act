## 2. 数据治理总览与风险处置

证据：

- `01-admin-home-governance-overview-desktop.png`
- `02-admin-data-governance-overview-desktop.png`
- `03-admin-data-governance-after-refresh-desktop.png`
- `06-admin-data-governance-mobile.png`

API 证据：

- `/api/admin/data-governance/status` 返回 200，`activeRiskFlags=170`，`freshness.status=stale`，最近快照约 `3009` 分钟前。
- `/api/admin/overview` 返回 200，用户 298、学生 293、教师 4、管理员 1。
- `/api/admin/system-usage` 返回 200，包含互动、提交、Arena、知识图谱等使用量统计。

观察：

- 管理员首页把“治理源检查”“用户批次”“配置保存”放在下一步动作中，但首页只提供导航，没有直接处置动作。
- 数据治理页能显示系统状态、数据新鲜度、学习事实总量、待处理风险 `170`、课堂质量 `3/16` 和最新风险清单。
- 风险表列出学生、风险类型、级别、触发时间和说明；没有“查看证据”“分派教师”“标记已处理”“导出风险”“创建修复任务”等动作列。
- 点击“刷新状态”后页面仍无明确完成态或 live/status 区域；DOM 结构化快照 `alerts` 为空。
- 移动端数据治理页保留概览，但风险表和后续明细依旧是长页阅读，没有固定处置工具区。

问题：

- P1：数据治理能列风险，但不能处置风险。`activeRiskFlags=170` 时，管理员仍只能阅读，不能分派、标记、导出或进入证据核验。
- P1：刷新状态缺少完成反馈。点击刷新后没有可见成功态、更新时间差异解释或 `aria-live`。
- P1：数据新鲜度 stale 没有修复动作。页面显示快照过旧，但没有“重建快照”“重试队列”“查看失败原因”。
- P2：移动端治理长页缺少固定操作区。管理员在移动端无法快速回到风险、刷新和处置入口。

建议：

- 风险表增加动作列：查看证据、分派教师、标记处理中、标记已解决、导出风险。
- stale 数据卡片增加重建快照和队列重试入口，并展示预计耗时和最近失败。
- 刷新按钮需要完成态和 live/status；移动端需要固定治理操作条。

## 3. 用户批次与配置调整

证据：

- `04-admin-users-batch-operations-desktop.png`
- `05-admin-system-config-actions-desktop.png`
- `07-admin-users-batch-operations-mobile.png`
- `08-admin-system-config-actions-mobile.png`

API 证据：

- `/api/admin/users?search=admin` 返回 200，能按关键字查到管理员账号。
- `/api/admin/users/template` 返回 200，`Content-Disposition` 为 `attachment; filename="users-template.xlsx"`，文件约 3102 字节。

观察：

- 用户管理页提供新建账号、下载模板、批量导入、搜索、角色筛选和账号列表。
- 右侧风险提示当前显示“暂无违规记录”，但导入批次、通知、撤销和失败行导出不在首屏操作区中。
- file input 仍使用 `aria-label="搜索管理员功能"`，上传控件语义与任务不一致。
- 系统配置页提供重置为默认、保存配置、基础设置、默认密码、维护模式、数据中心演示来源标签、AI 供应商与模型配置。
- 系统配置页的保存/错误提示依赖顶部 notice，但初始截图 `alerts` 为空；保存状态与具体配置分组的影响范围没有解释。
- 移动端用户管理和配置页可打开，但用户表格/配置表单仍是长页，批量导入和保存后的状态不够固定可见。

问题：

- P1：用户批量导入缺少批次治理。模板和导入入口存在，但没有导入预览、撤销批次、通知账号、复制默认密码、失败行导出或批次审计。
- P1：上传控件可访问名称错误。隐藏 file input 仍命名为“搜索管理员功能”，读屏和自动化都会误解该控件。
- P1：配置保存缺少影响范围和状态播报。管理员不知道保存会影响哪些运行中功能，保存结果也缺少明确 live/status。
- P2：移动端管理长表格和长表单缺少固定关键动作。搜索、批量导入、保存、重置容易随滚动丢失。

建议：

- 批量导入改为确认式工作流：预览、字段校验、执行、结果、失败行导出、撤销和通知。
- 上传 input 改为“上传用户导入 Excel”，并在按钮旁显示选中文件、校验中、导入成功/失败状态。
- 系统配置保存前展示影响范围，保存后提供成功/失败 live/status 和变更摘要。
- 移动端保留 sticky 操作条，用户表格改为分组卡片或列选择模式。
