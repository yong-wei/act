## 1. 本批审计顺序

本批沿管理员真实使用顺序展开：

1. 进入数据治理页，先看系统状态、风险清单和刷新状态。
2. 切换课堂质量、证据源、缓存健康标签，判断治理页是否把问题转成可行动项。
3. 回到用户管理，触发批量导入，检查 file chooser 是否前置于风险确认。
4. 分别上传畸形 Excel、缺列 Excel、混合有效/无效 Excel、重复更新 Excel。
5. 搜索导入账号，并用数据库复核导入后资料是否真实写入。

## 2. 管理员数据治理状态

证据：

- `01-admin-data-governance-overview-mobile.png`
- `02-admin-data-governance-refresh-result-mobile.png`
- `03-admin-data-governance-session-quality-mobile.png`
- `04-admin-data-governance-source-catalog-mobile.png`
- `05-admin-data-governance-cache-health-mobile.png`
- `06-admin-data-governance-overview-desktop.png`
- `07-admin-data-governance-session-quality-desktop.png`

观察：

- 数据治理总览能展示系统状态、数据新鲜度、学习事实总量、待处理风险、课堂质量、队列健康度、事实类型分布、最新风险清单和快照明细。
- 移动端风险清单表格有 8 行，表头为“学生、风险类型、级别、触发时间、说明”。
- 课堂质量标签页能切换到 13 行课堂质量表，表头为“课堂、质量、原因、更新时间”。
- 证据源标签页能切换到 13 行来源表，表头为“来源、范围、价值、资格、物化、行数、排除原因”。
- 缓存健康标签页能展示缓存条目类内容，但没有转换成表格，也没有把过期条目直接导向处理动作。
- 点击“刷新状态”后，页面仍主要表现为时间戳变化和原有数据展示；结构化快照中 `alerts` 为空。

问题：

- P1：数据治理页现在更像只读看板。风险清单、课堂质量、证据源和缓存健康都能展示数据，但缺少处置、导出、分派、标记已处理、查看关联学生证据等直接治理动作。
- P1：刷新状态没有清晰的开始、完成、失败或局部更新说明。移动端和桌面结构化快照里 `alerts` 均为空，用户只能通过时间戳推断刷新是否发生。
- P1：标签页缺少可访问的 selected 状态和切换播报。Manifest 记录各标签点击后内容变化成立，但没有 `aria-selected` 或 live/status 信号，读屏用户难以确认当前处于总览、课堂质量、证据源还是缓存健康。
- P1：移动端仍保留密集桌面表格。风险清单、课堂质量和证据源都在 390px 视口下横向压缩，管理员很难按“谁需要处理、为什么、下一步做什么”的顺序扫描。

建议：

- 把数据治理从“表格看板”提升为“异常处置台”：每类风险行至少提供查看学生、查看证据、标记已处理、导出当前列表或创建待办。
- 刷新状态应使用 `role=status` 或等效 live 区域说明“刷新中/刷新完成/刷新失败”，并展示最近刷新耗时和影响范围。
- 标签页使用标准 tab 语义，保持 selected 状态、键盘切换和内容区关联。
- 移动端把风险行改为卡片摘要，先显示学生、风险等级、最新触发时间和主原因，低频字段折叠。

## 3. 批量导入入口与错误状态

证据：

- `08-admin-users-import-entry-mobile.png`
- `09-admin-users-import-filechooser-trigger-mobile.png`
- `10-admin-users-import-malformed-workbook-mobile.png`
- `11-admin-users-import-missing-headers-mobile.png`

观察：

- 用户管理页顶部操作区提供“新建账号、下载模板、批量导入、打开系统配置”，并有“模板前三列必填：账号、姓名、角色”的说明。
- 点击“批量导入”后直接触发原生 file chooser，本批 manifest 记录 `fileChooserObserved: true`。
- 隐藏上传 input 的 `accept` 为 `.xlsx`，但 `ariaLabel` 为“搜索管理员功能”，与上传任务不一致。
- 畸形 Excel 场景会尝试展示解析失败信息，但结构化快照中 `alerts` 为空，错误没有被稳定表达为 live/status。
- 缺列 Excel 场景没有在最终 DOM 快照中留下稳定可读的缺列结果。Manifest 的预期是缺列应显示必填列说明，但页面快照仍主要回到账号列表。

问题：

- P1：批量导入第一步直接打开 file chooser，没有可见确认层。批量创建或更新账号会影响登录身份、班级归属和个人资料，不应把原生文件选择作为第一层确认。
- P1：上传控件可访问名称错误。隐藏 file input 被命名为“搜索管理员功能”，这会让读屏、自动化脚本和辅助技术把导入文件控件误判为搜索输入。
- P1：导入错误状态不够持久。畸形文件和缺列文件都缺少靠近上传入口的稳定错误摘要、官方模板链接、必填列说明和重新上传动作。
- P2：页面有模板必填列说明，但错误状态没有把当前文件的问题与这条说明建立关系，用户需要自行对照模板。

建议：

- 批量导入应先进入一个导入面板或模态：展示模板字段、支持角色、更新规则、默认密码/通知策略、回滚能力和隐私影响，再触发文件选择。
- file input 的可访问名称应改成“上传用户导入 Excel”或同等任务名称，并与“批量导入”按钮建立明确关系。
- 错误结果应持久显示在导入区域，包含文件名、错误类型、失败原因、模板下载、重新选择文件和保留/清除当前结果。

## 4. 混合导入、重复更新与回查

证据：

- `12-admin-users-import-mixed-result-mobile.png`
- `13-admin-users-import-update-existing-mobile.png`
- `14-admin-users-imported-account-search-mobile.png`
- `15-admin-users-import-state-desktop.png`

观察：

- 混合文件上传后，页面出现“导入结果”，能显示 `新增 1`、`失败 1` 和失败原因“角色无效”。
- 重复更新文件上传后，页面出现“导入结果”，能显示 `更新 1`，并继续围绕同一账号 `audit20260620070435`。
- 导入后可以通过全局用户搜索框找到该账号，搜索结果表格只有 1 行。
- 桌面刷新后账号出现在用户列表首行，总量从本批早期的 297 增至 298。
- 数据库复核确认账号已真实写入并更新：姓名为“审计导入学生更新20260620070435”，邮箱为 `audit20260620070435@example.com`，角色为 `STUDENT`，学生号为 `audit20260620070435`，班级为“审计班级二次”，专业为“自动化”，年级为 2026。

问题：

- P1：导入成功和更新成功缺少批次治理。页面能显示新增/失败/更新数量，但没有批次 ID、文件名、操作者、导入时间、按本批筛选、撤销本批、导出失败行、通知学生或复制登录信息。
- P1：混合导入的失败行没有形成可下载或可复用的修复清单。管理员只能看到失败摘要，无法直接导出失败行补录。
- P1：重复更新没有解释更新规则。页面显示“更新 1”，但没有告诉管理员哪些字段被覆盖、哪些字段保持不变、是否影响登录凭据或是否通知用户。
- P2：导入后回查依赖全局搜索。用户管理页没有“查看本批导入账号”或“仅显示本次新增/更新”入口。

建议：

- 建立批量导入记录：批次号、文件名、操作者、导入时间、新增/更新/失败数量、失败行下载、撤销范围、通知状态和审计日志入口。
- 混合导入结果应把失败行保持为可导出的结构化列表，并允许用户下载修正模板。
- 重复更新结果应展示字段级变更摘要，至少说明姓名、邮箱、班级、专业、年级、角色和密码是否改变。

## 5. 可访问性结论

本批所有结构化快照的 `alerts` 均为空，关键状态包括刷新、标签页切换、文件解析失败、缺列错误、导入结果、重复更新结果都没有形成稳定的 live/status 语义。

上传控件的可访问名称错误是本批最明确的 a11y 缺陷：它不仅影响读屏，也实际导致审计脚本第一次搜索导入账号时命中了隐藏 file input。脚本已改为限定可见非 file/search 输入，但产品问题应单独修复。

## 6. 本批新增优先问题

1. P1：数据治理缺少从风险到处置的动作链。
2. P1：数据治理刷新和标签切换缺少完成状态与 selected/live 语义。
3. P1：批量导入入口直接打开 file chooser，缺少确认、预览和影响范围说明。
4. P1：批量导入 file input 可访问名称错误为“搜索管理员功能”。
5. P1：导入错误状态不够持久，缺列文件没有在最终 DOM 快照中留下稳定结果。
6. P1：导入成功/更新缺少批次治理、失败行导出、撤销、通知和字段级更新说明。
