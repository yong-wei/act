## 2. 任务大厅与筛选

证据：

- `02-missions-completed-filter-desktop.png`
- `03-missions-unlocked-filter-desktop.png`
- `05-missions-query-context-desktop.png`

API 证据：

- `/api/auth/session` 返回学生 `demo`，`role=STUDENT`。
- `/api/missions` 返回 200，`total=7`、`completed=5`、`unlocked=2`。

观察：

- `/missions` 返回 200，页面能展示 7 个任务、5 个完成、2 个可挑战，完成率为 71%。
- 筛选按钮能切换“全部 / 可挑战 / 已完成”，可挑战状态下只展示第 6、7 个任务。
- 筛选切换后的结构化快照 `alerts=0`、`liveRegion=false`，没有结果数量变化的可访问播报。
- 任务卡整体是链接，卡片内部又有“再次挑战/开始挑战”按钮；DOM 首批控件同时出现整张任务卡链接和内部按钮，形成重复交互目标。
- `/missions?project=goal` 与 `/missions` 默认页视觉和文本完全一致，没有解释 query 来源、推荐目标或筛选条件。
- 移动端任务大厅可展示完整任务链，但每张任务卡很长，底部控灵和黑色浮层压在第一张卡的“再次挑战”区域附近。

问题：

- P1：任务卡存在整卡链接与内部按钮重复交互目标。键盘和读屏路径会先读整张长卡，再读内部“再次挑战/开始挑战”，任务启动动作不够单一。
- P1：任务筛选缺少结果变化播报。切换“可挑战/已完成”后没有 `role=status`/`aria-live` 告知当前筛选和结果数量。
- P1：学习路径 query 上下文被忽略。`/missions?project=goal` 没有体现来自哪个目标、哪条路径或为什么推荐这些任务。
- P2：移动端任务卡过长且浮层贴近主操作。任务目标、成绩和按钮被压在长卡内，底部浮层容易干扰第一屏操作。

建议：

- 任务卡保留一个明确交互目标：整卡链接或按钮二选一，另一个改为非交互说明。
- 筛选切换后写入状态区，例如“已显示 2 个可挑战任务”。
- 对学习路径生成的 query 参数做显式解释或转化为筛选状态，例如“来自控制纠偏目标推荐”。
- 移动端任务卡把目标摘要、状态和主按钮压缩到首屏可扫结构，细节进入展开区。

## 3. 任务启动目标

证据：

- `04-missions-start-target-desktop.png`

观察：

- 点击可挑战任务后落到 `/simulations/destroyer?mission=cmjm54tp10005qs9d715501pg`，说明 mission id 被带到 URL。
- 仿真页标题为“军用驱逐舰战术机动仿真”，右侧控制面板显示“任务选择：直角转向任务”，没有显示刚才点击的“海况挑战：大浪”任务标题、目标或海况要求。
- 页面没有“来自任务大厅”“任务进度将回写”“完成后返回任务大厅”的说明。
- 结构化快照仍为 `alerts=0`、`liveRegion=false`，没有任务加载或上下文继承状态。

问题：

- P1：任务启动后缺少任务上下文继承。URL 保留 `mission`，但仿真界面没有展示任务大厅中的任务名称、目标、解锁/完成口径或保存规则。
- P1：任务标题与仿真内任务选择不一致。学生从“海况挑战：大浪”进入后看到“直角转向任务”，会怀疑自己是否进入了正确挑战。
- P1：任务完成回写路径不清。页面没有说明开始、完成、成绩、证据和任务大厅进度之间的关系。

建议：

- 仿真页读取 mission 参数后，在顶部或任务面板展示任务大厅标题、目标、海况、完成标准和返回入口。
- 当 mission 参数不能匹配时，应显示任务加载失败或降级说明，而不是静默显示默认仿真任务。
- 完成按钮或评估结果应明确写入“任务大厅进度/学习证据/作品集”的哪一类记录。

## 4. 作品集课堂作品、仿真设计与伦理整改

证据：

- `06-portfolio-classworks-empty-desktop.png`
- `07-portfolio-classworks-action-target-desktop.png`
- `08-portfolio-simulations-tab-desktop.png`
- `09-portfolio-simulation-action-target-desktop.png`
- `10-portfolio-ethics-tab-desktop.png`
- `11-portfolio-ethics-action-target-desktop.png`
- `14-portfolio-simulations-tab-mobile.png`

观察：

- 作品集默认“课堂作品”为空，动作是“进入互动课程”，落到通用 `/interactive-learning`。
- “仿真设计”为空，动作是“开始仿真”，落到通用 `/simulations/destroyer`，没有作品集来源或保存回流提示。
- “伦理整改”为空，动作是“了解工程伦理”，落到 `/ethics` 的伦理决策沙盘；该页面是决策体验，不是“整改记录”创建流。
- 三个空态都没有说明什么行为会被收录、收录阈值、最近一次未收录原因或保存状态。
- 空态动作后的目标页均无“返回学习档案/完成后收录到档案”的上下文。
- 移动端作品集标签换行成多行按钮，当前标签可见，但没有 tablist/selected 语义；底部浮层靠近空态卡片。

问题：

- P1：课堂作品空态动作过于泛化。点击“进入互动课程”后只是到课程总入口，没有连接能产出课堂作品的具体课程、课堂或提交动作。
- P1：仿真设计空态动作没有保存回流合同。落到 `/simulations/destroyer` 后看不到“完成后进入仿真设计档案”的承诺或任务条件。
- P1：伦理整改空态动作与“整改记录”语义不一致。`/ethics` 是决策沙盘，但作品集需要已整改案例、整改动作和保存回流。
- P1：作品集空态没有说明收录规则。用户不知道什么分数、什么提交、什么审核状态会进入对应标签。
- P2：作品集移动端标签是普通按钮组。视觉上像标签页，但缺少明确 tab/selected 语义，换行后扫描成本上升。

建议：

- 每个作品集空态动作都应带 `source=portfolio` 与目标类型，目标页显示保存回流说明。
- 课堂作品应进入具体可提交课程或最近课堂，而不是泛化入口。
- 仿真设计应进入带作品集保存条件的仿真任务，完成后给“已收录/未达收录条件”状态。
- 伦理整改应连接到违规复盘、整改表单或伦理案例改写，而不仅是重新学习伦理沙盘。
- 作品集标签使用 tablist/tabpanel 语义，并在移动端保留当前标签和操作区的稳定位置。

证据：

- `12-portfolio-prompts-tab-after-history-desktop.png`

API 证据：

- `/api/evaluation/prompt-history/cmjm5lkjk0000t69bqiupz5am` 本批返回 200，`history=[]`、`total=0`。

观察：

- 本批提示词设计标签仍为空，空态动作仍是“练习提示词设计”。
- 该动作落点已在第三十五批确认会跳到缺失的 `/evaluation`，本批不重复点击。
- 页面没有说明“暂无高质量提示词”是因为没有记录、没有达到 70 分、还是历史数据未同步到作品集。

问题：

- P1：Prompt 档案空态仍缺少来源解释。用户无法区分没有评估历史、分数不足、还是档案同步未完成。
- P1：Prompt 空态动作仍沿用第三十五批已确认的错误目标。当前页面继续展示“练习提示词设计”，但目标路由仍需改为 `/evaluation/prompt-assessment`。

建议：

- 提示词标签应显示最近评估历史、收录阈值和未收录原因。
- 修正空态动作路由，并在 Prompt 评估完成后明确回写作品集状态。
