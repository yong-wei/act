# 功能状态流审计续篇（十）

日期：2026-06-20
范围：管理员删除教师账号时的关联影响范围量化、删除确认、删除后反馈。
截图证据：`screenshots/45-function-state-flows-batch10/`。
采集清单：`screenshots/function-state-flows-batch10-manifest.json`。

## 1. 覆盖范围

本轮新增 3 张功能状态截图，使用本地临时教师账号构造可量化关联数据：

- 教师账号：`audit_delete_20260620050651`
- 教师姓名：`审计关联删除教师0651`
- 删除前关联：1 个班级、1 个非预置教案、1 个资源、1 个教案环节、1 个课堂会话、1 条 StudentState。

数据库复核显示，管理员确认删除后，用户本身与上述 6 类关联记录均变为 0。截图负责证明管理员 UI 的可见状态，manifest 中的 `beforeCounts` 与 `afterCounts` 负责证明实际删除影响。

## 2. 删除前列表：只显示身份，不显示影响范围

证据：

- `screenshots/45-function-state-flows-batch10/01-admin-users-search-associated-teacher-before-delete.png`

健康度：可找到账号，但危险操作上下文不足。

观察：

- 管理员通过工号搜索能准确定位临时教师。
- 列表显示姓名、邮箱、工号、角色、创建时间和操作入口。
- 页面顶部总览显示用户总数、教师总数、活跃会话等聚合数字，但当前行没有关联数据摘要。

问题：

- P1：删除入口与账号行同屏出现，但没有提示该教师下存在班级、教案、资源、课堂和状态数据。
- P2：管理员无法在列表中区分“空账号”和“有教学资产账号”的删除风险。

建议：

- 用户列表至少为教师账号展示“关联班级/教案/课堂/资源”摘要或风险标记。
- 删除按钮应在有教学资产时进入影响确认流程，而不是直接触发浏览器原生 confirm。

## 3. 账号详情：敏感操作区仍缺少关联影响

证据：

- `screenshots/45-function-state-flows-batch10/02-admin-users-associated-teacher-detail-before-delete.png`

健康度：详情可读，但不支持安全决策。

观察：

- 账号详情卡显示姓名、邮箱、角色、学号、班级、工号和创建时间。
- 详情卡提供“修改密码”和“删除账号”两个敏感操作。
- 对教师账号来说，“学号”和“班级”均为 `-`，但这不代表该教师没有负责班级；教师拥有的班级不在详情中展示。

问题：

- P1：详情页把教师拥有的班级、教案、资源、课堂会话完全隐藏，管理员无法判断删除会影响什么。
- P1：教师详情卡使用学生字段“学号/班级”，容易让管理员误以为没有班级关联。
- P2：删除操作与修改密码并列，没有更高风险层级或二次确认入口。

建议：

- 教师详情应单独展示“拥有班级、创建教案、创建资源、进行中/历史课堂、Arena 发布”等关联资产。
- 删除前应提供影响清单：将删除或解绑哪些对象、哪些对象会保留、是否可恢复。

## 4. 删除确认与删除后状态

证据：

- `screenshots/45-function-state-flows-batch10/03-admin-users-after-associated-teacher-delete.png`
- `screenshots/function-state-flows-batch10-manifest.json` 中 `dialogs`、`beforeCounts`、`afterCounts`

健康度：删除可执行，但确认和反馈不足。

观察：

- 原生 confirm 文案为“确认删除账号 审计关联删除教师0651？”。
- 管理员接受确认后，页面显示“账号已删除”绿色通知。
- 搜索结果为空，顶部用户总数从 296 变为 295，教师数从 5 变为 4。
- manifest 记录删除前后计数：
  - user：1 -> 0
  - classes：1 -> 0
  - lessonPlans：1 -> 0
  - resources：1 -> 0
  - lessonItems：1 -> 0
  - sessions：1 -> 0
  - studentStates：1 -> 0

问题：

- P1：确认文案没有披露实际会删除的 6 类关联数据，风险范围被压缩成“账号”。
- P1：删除成功后只显示账号已删除，没有影响摘要、审计记录入口或撤销/恢复说明。
- P2：使用浏览器原生 confirm，无法提供结构化影响列表、勾选确认、风险等级、键盘焦点管理或读屏说明。

建议：

- 将删除改为系统内确认对话框，先调用影响预览 API，展示关联数据数量和处理方式。
- 高风险删除应要求二次确认，例如输入教师姓名或工号。
- 删除后展示影响摘要和审计日志入口，至少说明删除了哪些教学资产或哪些资产被保留。

## 5. 本轮结论

- 后端删除路径确实会清理教师名下多类教学数据；本轮临时教师删除后，用户、班级、非预置教案、资源、教案环节、课堂会话和状态记录均从 1 变为 0。
- 管理员 UI 没有把这些影响暴露给操作者。列表、详情、confirm 和成功通知都只围绕“账号”表达。
- 删除影响范围量化已经从“待补证据”变为“已确认的 P1 风险”：真实影响范围大于 UI 提示范围。
