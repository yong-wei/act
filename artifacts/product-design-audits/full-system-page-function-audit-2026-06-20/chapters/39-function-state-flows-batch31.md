## 2. 数据治理风险处置与刷新

证据：

- `01-admin-data-governance-overview-desktop.png`
- `02-admin-data-governance-after-refresh-desktop.png`
- `03-admin-data-governance-session-quality-desktop.png`
- `04-admin-data-governance-evidence-source-desktop.png`
- `07-admin-data-governance-mobile.png`

API 证据：

- `/api/admin/data-governance/status` 返回 200。

观察：

- 页面显示系统状态、数据新鲜度、学习事实总量、待处理风险和课堂质量卡片。
- 本批截图中数据新鲜度为 `3055 分钟前`，待处理风险为 `170`，课堂质量为 `3/16`。
- 风险清单能列出学生、风险类型、级别、触发时间和说明。
- “刷新状态”可点击，manifest 记录点击成功；刷新后截图仍没有可见完成 toast、status 区或失败/完成播报。
- “课堂质量”和“证据源”标签页可切换，但标签内容仍是风险和分布阅读态，没有近场处置按钮。
- 结构化快照在数据治理 4 个桌面状态和 1 个移动状态中均记录 `disposition=false`、`export=false`。

问题：

- P1：风险清单没有直接处置动作。管理员能看到“谁、何时、为什么被标记”，但不能从行内查看证据、分派负责人、标记处理、创建修复任务或导出风险。
- P1：刷新动作缺少完成播报。点击后时间戳会变化，但没有 `role=status`、toast 或可被读屏捕获的成功/失败结果。
- P1：数据治理导出入口缺失。页面文案强调治理链路和风险清单，但本批 DOM 没有发现风险导出、摘要下载或报告交付动作。
- P2：移动端风险表仍不可读。表格列在窄屏下被压成细列，风险类型和说明逐字竖排，管理员难以快速判断优先级。

建议：

- 在风险行增加“查看证据”“标记已处理”“分派”“创建待办”和“导出当前风险”动作，并保留操作审计记录。
- 刷新应产生明确状态：开始、完成、失败、更新时间、刷新影响范围，并用 `role=status` 或 `aria-live` 暴露。
- 移动端风险清单应改成卡片或横向可滚动表格，首屏保留级别、学生、风险类型、最近触发和一个主动作。

## 3. 用户批量导入治理

证据：

- `05-admin-users-batch-operations-desktop.png`
- `08-admin-users-batch-operations-mobile.png`

API 证据：

- `/api/admin/users?search=admin` 返回 200。
- `/api/admin/users/template` 返回 200，content-type 为 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`，content-disposition 为 `attachment; filename="users-template.xlsx"`。

观察：

- 操作区提供“新建账号”“下载模板”“批量导入”和“打开系统配置”。
- 账号列表提供查看、改密、删除等单账号操作。
- 模板下载 API 正常，说明后端模板能力可用。
- 批量导入入口存在，但当前页面没有导入前预览、字段映射确认、失败行下载、通知发送、撤销/回滚或批次审计入口。
- 隐藏 file input 仍记录为 `type=file`、`accept=.xlsx`，但 `ariaLabel` 是“搜索管理员功能”，与实际上传语义不匹配。
- 移动端保留操作区和账号列表，但表格列密度很高，行操作按钮挤在右侧。

问题：

- P1：批量导入缺少批次治理闭环。管理员能上传 Excel，但不能在同一页面确认导入预览、失败行、通知范围、撤销窗口和批次审计。
- P1：批量导入上传控件语义错误。上传控件的可访问名称仍是“搜索管理员功能”，读屏用户无法正确理解该控件。
- P1：导入后账号治理动作与批次脱节。页面只出现普通账号列表，不知道哪些账号来自哪个批次、是否已通知、是否可回滚。
- P2：移动端账号操作密度过高。查看、改密、删除按钮在窄屏中可见，但批量导入和批次结果不具备移动优先的确认体验。

建议：

- 批量导入应形成“选择文件 -> 预览校验 -> 确认导入 -> 发送通知 -> 可撤销窗口 -> 批次详情”的完整状态机。
- 成功/失败导入都应落入批次审计卡：创建数、更新数、跳过数、失败行下载、操作者、时间和撤销状态。
- 修正 file input 的 `aria-label`，上传按钮与隐藏控件应共享“批量导入用户 Excel”语义。

## 4. 系统配置保存与影响反馈

证据：

- `06-admin-system-config-actions-desktop.png`
- `09-admin-system-config-actions-mobile.png`

API 证据：

- `/api/admin/system-usage` 返回 200。

观察：

- 页面提供平台名称、默认密码、每班最大学生数、维护模式、首页动态模型渲染、数据中心演示来源标签等基础设置。
- AI 供应商与模型区域可选择供应商、模型、端点、密钥引用、能力开关和测试按钮。
- 顶部有“重置为默认”和“保存配置”。
- DOM 快照显示 `configSave=true`，但没有 alerts/status/live region。
- 页面没有明确区分“已保存配置”和“当前未保存草稿”，也没有说明保存会影响登录、课堂、AI route 或数据中心演示标签。

问题：

- P1：配置保存缺少影响范围说明。管理员不知道保存后会影响哪些运行时路径、是否立即生效、是否需要重启或是否会影响当前课堂。
- P1：保存/测试动作缺少可见完成播报。本批没有点击写入配置，但静态页面也没有预留状态区；已有“测试”按钮同样缺少明显结果槽位。
- P2：移动端配置长页没有固定保存区。保存按钮位于顶部，管理员滚动到供应商目录、通知设置和伦理监测后需要回到顶部保存。

建议：

- 增加配置差异摘要和影响范围面板，至少覆盖认证、课堂、AI route、数据中心演示和通知设置。
- 保存、重置、测试模型应写入同一个 status 区：开始、成功、失败、最后保存人、最后保存时间和恢复入口。
- 移动端应提供底部固定保存/重置/测试摘要条，避免长页中丢失关键动作。

## 5. 本批新增优先问题

138. P1：数据治理风险清单仍缺少行内处置动作。
     风险表显示学生、风险类型、级别、触发时间和说明，但没有查看证据、分派、标记处理、创建待办或导出风险。

139. P1：治理刷新缺少完成播报。
     “刷新状态”可点击，截图时间戳更新，但 DOM 没有 status/live 区域，管理员和读屏用户都缺少明确结果反馈。

140. P1：数据治理导出入口缺失。
     `/api/admin/data-governance/status` 可返回治理数据，但页面没有风险清单导出、摘要下载或报告交付动作。

141. P1：用户批量导入缺少可逆批次状态机。
     现有入口只有下载模板和批量导入，缺预览、失败行导出、通知、撤销/回滚和批次审计。

142. P1：用户导入 file input 可访问名称错误仍存在。
     隐藏上传控件的 `aria-label` 为“搜索管理员功能”，与批量导入 Excel 上传不一致。

143. P1：系统配置保存缺少影响范围和完成状态。
     保存/重置/测试按钮存在，但页面没有差异摘要、影响路径、保存结果或 live/status。

144. P2：管理员移动端关键治理动作没有固定操作区。
     数据治理、用户管理和系统配置都能访问，但刷新、导入、保存和处置动作在长页中容易与内容表格混在一起。
